## 2. 목표와 성공 기준

**목표:** README 첫 화면만 보고도 *"이건 꼭 써보고 싶다"* 가 들게 한다.

1. **첫 3초 훅** — README 최상단 히어로 영상이 "한 문장 → 동작하는 앱 → 에이전트 보드 → 배포"를
   10~15초 안에 영화처럼 보여준다(Blender 합성).
2. **모든 이미지가 v0.1.50 실화면** — 목업·가짜 UI 금지. 영상의 UI 픽셀은 실제 앱 캡처 그대로이고,
   Blender는 카메라·프레이밍·강조만 더한다.
3. **기능마다 "무엇이 좋아지는지" 한 줄 + 짧은 움직이는 화면** — 기능 나열이 아니라 사용자 이득 중심.
4. **4개 언어 README + 2개 가이드가 같은 구조·같은 자산**을 가리킨다. 깨진 이미지 링크 0개.
5. **개인정보 유출 0** — 모든 PNG·GIF 프레임을 OCR로 검사해 실명·호스트명·홈 경로·이메일이 없음을 확인.
6. **가벼운 로딩** — 기능 GIF 1개당 ≤ 7 MB, 히어로 ≤ 8 MB(고화질은 MP4로 별도 제공). *(진행 중 조정: 처음 잡은 `docs/assets` 전체 ≤ 40 MB는 GIF 9종 + 히어로 2벌로 약 50 MB가 되어, 저장소 총량 대신 "README 한 페이지가 실제로 불러오는 용량" 기준으로 바꿨습니다.)*

## 4. 영상 제작 파이프라인

```
 ① 실화면 캡처 (Playwright → Electron v0.1.50, 격리 userData + 격리 HAPPY_HOME)
      - webContents.capturePage() 로 프레임 녹화 (webview 포함 합성)
      - DOM 가짜 커서 + 클릭 리플, 프레임마다 TreeWalker 텍스트 마스킹
 ② Blender 합성 (blender-mcp 소켓 → execute_code 로 씬 구성, .blend 저장)
      - 프레임 시퀀스를 Emission 이미지 텍스처로 쓴 "앱 창" 오브젝트(둥근 모서리·그림자)
      - 브랜드 그라데이션 배경(#6d5df6 → #0ea5e9), 카메라 키프레임으로 포커스 줌·패닝
      - 히어로: 3D 틸트된 창 여러 장이 겹쳐 흐르는 시네마틱 + 카피 텍스트(ko/en 2벌)
 ③ 렌더 — Blender CLI 백그라운드 렌더(-b -a)로 PNG 시퀀스 (EEVEE, 1440×900 · 24fps)
 ④ 인코딩 — ffmpeg palettegen(stats_mode=diff)/paletteuse → GIF(1200px, 12fps) + MP4(h264, 고화질 링크용)
 ⑤ 검증 — OCR 유출 검사, 용량 검사, 모든 README 링크 존재 검사
```

원칙
- **UI 픽셀은 절대 다시 그리지 않는다.** Blender는 프레이밍·카메라·자막만 담당.
- 기능 GIF는 자막 없이(언어 중립) 포커스 줌만 넣고, 설명은 README 텍스트가 담당한다.
  텍스트가 들어가는 히어로만 ko/en 두 벌 렌더(zh·ja README는 en 사용).
- 카메라는 포커스 전환 구간에서만 움직여 GIF 프레임 간 차이를 최소화(용량 절감).

## 9. 실행 기록 (2026-09-30)

### Blender 파이프라인 — 실제 구성
- **blender-mcp 연결**: 이 세션에는 MCP 도구가 노출되지 않아, blender-mcp 서버가 쓰는 것과 같은 애드온 소켓(`localhost:9876`, `execute_code`)에 직접 붙어 씬을 구성했습니다. 씬 생성·저장은 MCP로, 프레임 렌더는 같은 `.blend`를 Blender CLI(`-b -a`)로 백그라운드 렌더.
- **기능 클립**(7종): 녹화 프레임 → PIL로 맥 창 크롬(신호등·타이틀·둥근 모서리) 합성 → Blender 직교 카메라 씬(브랜드 그라데이션 배경 + 소프트 섀도 + 창 평면에 이미지 시퀀스)에서 포커스 줌 키프레임 → EEVEE 1440×900 렌더 → GIF(1200px·10fps·128색) + MP4. 줌은 ≤1.4배로 제한해 글자 선명도 유지, 카메라는 창 경계 안으로 clamp.
- **히어로**(ko/en): 원근 카메라 3D 씬. 실제 녹화 시퀀스 3개(빌드·보드·마무리)를 부채꼴로 띄우고, 인트로 카피 → 창 등장 → 창별 카메라 이동(look-at 쿼터니언, Y-up) → 엔드 카드. 1600×900·15fps 210프레임 → GIF 1000px·12fps·96색(≈6.6 MB) + MP4.
- 시행착오: Track-To 제약은 월드 Z-up 기준이라 측면 뷰가 90° 돌아감 → 쿼터니언 직접 계산으로 교체. 반투명 그림자 판은 BLENDED 정렬 문제로 창 앞에 그려져 히어로에서는 제거. Pretendard에 이모지가 없어 캡션 이모지 제거.

### 캡처 환경
- v0.1.50 소스(`4cee8145a`)를 격리 worktree에서 `electron-vite build`, 런타임(`happy-server/cli/node-runtime`)은 v0.1.50 릴리스 DMG에서 arm64 사본을 가져와 사용.
- `APLUS_DESKTOP_USER_DATA_DIR` + `APLUS_STANDALONE_HAPPY_HOME_DIR`로 사용자의 실제 데이터와 완전 격리. 모든 에이전트 작업은 실제 Claude Code / Codex 호출(편집 없는 실화면).
- 마스킹은 프레임 직전 TreeWalker 방식이 React 재렌더와 경합해 누락이 생겨, 렌더 직전에 동작하는 **MutationObserver** 방식으로 교체. 사용량 팝오버의 실제 계정 이메일 9개, 잘린 호스트명(`buzzni-sha…`), 머신 UUID까지 치환.

### 범위 조정
- **메신저 채널 설정 화면**: Guest(로컬 전용) 환경설정에는 탭이 나타나지 않아 촬영하지 못함 → README/가이드에서는 외부 연동 화면과 텍스트로 소개.
- **로그인·머신 등록 코드 화면**: 실계정 2FA가 필요해 이번엔 재촬영하지 않음. 옛 UI인 `login-modal.png`, `register-machine-*.png`는 삭제하고, UI 변화가 적은 `org-console.png`, `settings-connectors.png`만 유지.

### 캡처 중 발견한 앱 이슈 (후속 확인 필요)

### 버그로 보이는 것
1. **Chat(Work) 문서 형식·템플릿 칩 전송 실패** — "안전하지 않은 첨부 경로입니다."로 첫 메시지가 전송되지 않음. 칩 없이 보내면 정상. (`src/sync/chatFileUpload.ts` `validatedChatUploadRelPath`)
2. **요소 선택 모드가 풀리지 않음** — 요소를 채팅에 첨부하고 새 대화 탭을 열어도 브라우저 패널에 hover 하이라이트(`section.panel 568×1094`)가 계속 남음.
3. **Work(Chat) 화면에 프로젝트 작업 탭이 따라옴** — 프로젝트 없는 Chat인데 오른쪽 작업 영역에 다른 프로젝트의 터미널·변경·App.jsx 탭이 그대로 보이고, 파일 패널은 "파일을 보려면 프로젝트를 선택하세요".
4. **파일 패널 자동 갱신 안 됨** — 에이전트가 스캐폴딩으로 파일을 만든 뒤에도 파일 패널이 "파일이 없습니다"에 머묾(탭을 다시 열어야 보임).
5. **첫 메시지 토스트** — 새 프로젝트 첫 대화에서 "관련 프로젝트 목록을 불러오지 못해 자동 마운트 없이 세션을 시작했습니다."가 매번 뜸(Guest).
6. **머신 이름 이중 말줄임** — 설정 → 머신에서 호스트명이 JS로 잘린 뒤 CSS ellipsis까지 붙어 `buzzni-sha....`처럼 점 4개로 표시.
7. **메신저 채널 설정 진입 불가(Guest)** — Telegram 어댑터를 설치·권한 승인·활성화해도 환경설정에 메신저 채널 탭이 나타나지 않음. 릴리스 노트상 로컬 전용 모드 수신은 지원되는 것으로 보여 확인 필요.
8. **한국어 UI 속 영어 문구** — 메모리 설정 "This project is not assigned to a remote machine.", 미리보기 패널 헤더 "DETECTED PREVIEW".
9. **한국어 요청에 영어 답변** — 일부 Claude 대화(셀프 리뷰 결과, DOCX 생성 결과)가 한국어 프롬프트에도 영어로 답함.

### UX 개선 제안
1. **자동 선택 배지가 hover에서만 보임** — "요청당 최대 ~90% 절약"이 핵심 가치인데, Guest에서는 배지가 마우스를 올려야 보이고 절감률도 없이 "Opus 5.5 · low"만 표시. 세션 헤더의 누적 절감 표시를 기본 노출하면 가치 전달이 쉬워짐.
2. **에이전트 선택이 다음 새 대화로 조용히 이어짐** — 한 탭에서 Codex를 고르면 다음 새 탭도 Codex로 시작해, Claude로 보낼 요청이 Codex로 가기 쉬움. 새 탭 입력창에서 현재 에이전트를 더 눈에 띄게 하거나 한 번만 적용 옵션 제안.
3. **"바로 커밋" 비활성 이유가 tooltip뿐** — worktree가 아닌 대화에서는 버튼이 회색이고 이유는 title 속성으로만 보임. 인라인 안내 + "worktree로 옮기기" 액션 제안.
4. **확장 권한 승인이 이중** — 권한마다 "승인" 버튼을 누른 뒤 다시 "권한 승인 및 활성화"를 눌러야 함. 한 번에 검토·승인하는 흐름이면 충분.
5. **보드 폭** — 사이드바를 펼친 1600px 창에서 여섯 번째 컬럼(PR 병합됨)이 잘려 가로 스크롤 필요. 컬럼 최소 폭 축소 또는 빈 컬럼 접기 제안.
6. **요소 첨부 + 사용자 문장 구분** — 요소를 첨부하면 입력창이 긴 셀렉터 텍스트로 채워지고, 사용자가 덧붙인 문장이 구분 없이 붙어 전송됨. 첨부 정보를 칩으로 분리하면 읽기 쉬움.
7. **"90초 넘게 새 출력 없음" 토스트** — 보드를 보는 동안 정상 작업 중인 대화에도 떠서 불안감을 줌. 카드 배지로만 표시하는 편이 조용함.
8. **사용량 팝오버 높이** — Codex 계정이 많으면 팝오버가 화면 높이를 넘음. 현재 계정 + 요약 위주로 접기 제안.
9. **Codex가 질문 도구 대신 평문으로 질문** — "입력 대기" 컬럼이 비어 있게 되어 보드의 가장 중요한 신호가 동작하지 않음. Codex에도 질문 도구 경로가 있으면 좋음.
