## 1. 설치와 첫 실행

**[최신 DMG를 내려받아](https://github.com/buzzni/saycode-desktop-releases/releases/latest)**
열고 **Saycode**를 Applications 폴더로 드래그하세요 (Apple Silicon용과 Intel Mac용 x64
DMG가 모두 있습니다). 앱은 서명·공증되어 있고 자동으로 업데이트됩니다.

처음 실행하면 두 가지만 고릅니다.

1. **언어** — 한국어 / English / 中文 / 日本語
2. **어떻게 사용하시겠어요?**
   - **개인 사용** — 나만의 프로젝트를 AI와 함께 만들고 관리합니다. 로그인 없이 **Guest
     로컬 작업공간**으로 바로 들어갑니다.
   - **조직 사용** — 팀원과 프로젝트를 공유합니다. saycode.ai 로그인과 이 컴퓨터 등록으로
     이어지고, 속한 조직이 하나면 자동으로 선택됩니다.

<img src="assets/language-select.png" alt="첫 실행 언어 선택 화면" width="480" />

개인 사용을 고르면 Saycode가 알아서 **내장 서버**(릴레이·데이터베이스)를 이 Mac 안에서
띄우고, 이 Mac을 **로컬 머신**으로 등록한 뒤, 작업공간을 엽니다. 이 상태에서는 데이터가
한 바이트도 Mac 밖으로 나가지 않습니다.

<img src="assets/first-run.gif" alt="첫 실행: 언어 → 개인 사용 → 자동 온보딩 → 첫 프로젝트 추가 → 홈" width="920" />

## 2. 온보딩 체크리스트

작업공간이 열리면 **"첫 작업까지 함께 준비해요"** 체크리스트가 **자동으로 진행**됩니다.

<img src="assets/onboarding-checklist.png" alt="자동 온보딩 체크리스트 — Saycode CLI, AI 도구, 알림" width="760" />

| 단계 | 하는 일 |
|---|---|
| **① Saycode CLI** | 에이전트가 실제로 돌아가는 로컬 런타임을 확인합니다. 앱에 내장돼 있어 바로 *설치됨*으로 표시되고, 여러 계정 도구(codex-multi-auth, claude-swap)도 함께 준비합니다. 터미널에서 `saycode` CLI를 쓰고 싶다면 전역 설치를 선택할 수 있습니다. |
| **② AI 도구** | Claude Code와 Codex의 설치·로그인 상태를 감지합니다. 아직이라면 터미널에서 `claude` → `/login`, `codex login`을 마친 뒤 **상태 다시 확인**을 누르세요. 둘 중 하나만 있어도 시작할 수 있습니다. |
| **③ 알림** | 에이전트가 **입력을 요청할 때**와 **작업을 마쳤을 때** 소리로 알릴지 고르고, **테스트 알림 보내기**로 확인합니다. |

마지막 **첫 프로젝트 추가** 버튼이 [4장](#4-프로젝트-추가하기)으로 이어집니다. 중간에 오류가
나면 같은 단계에서 다시 시도하면 되고, 이미 끝난 단계는 유지됩니다. **나중에 하기**로 닫았다면
**환경설정 → 온보딩 체크리스트**에서 단계를 고르고 **이 단계부터 자동 진행**을 누르세요.

<img src="assets/settings-onboarding.png" alt="환경설정 → 온보딩 체크리스트" width="820" />

| **외부 연동** | 확장과 메신저 채널 어댑터 설치 ([13장](#13-외부-연동--확장과-메신저-채널)) |

## 4. 프로젝트 추가하기

온보딩 마지막 버튼, 사이드바의 **새 프로젝트**, 또는 홈의 시작 카드로 엽니다.

<img src="assets/first-project-dialog.png" alt="프로젝트 추가 — 호스트 선택, 기존 폴더 열기, 새 프로젝트, Git, ZIP" width="480" />

먼저 **호스트**(에이전트가 일할 머신)를 확인합니다. 내 컴퓨터는 **이 컴퓨터**로 표시되고,
온라인인 머신만 고를 수 있습니다. 그다음:

| 방식 | 이런 때 |
|---|---|
| **기존 폴더 열기** (기본, ↵) | 이미 있는 코드베이스를 그대로 연결. git 저장소면 브랜치·worktree·Commit & PR까지 사용 |
| **새 프로젝트 만들기** | 이름만 정하면 빈 폴더(Git 저장소로 초기화)에서 시작. 템플릿 확장을 설치하면 사내 대시보드 같은 템플릿도 고를 수 있습니다 |
| **Git URL에서 복제** | 원격 저장소를 선택한 머신에 클론 |
| **ZIP으로 가져오기** | 압축 파일에서 로컬 프로젝트 생성 |

프로젝트 제목 옆 ⋯ 또는 대화 헤더의 ⚙에서 **프로젝트 설정**(기본 정보·태그·실행·자동화)을
엽니다.

## 5. 첫 대화 — 에이전트에게 일 시키기

프로젝트를 열면 *"rental-dashboard에서 무엇을 만들까요?"* 와 함께 **코드 이해하기 · 기능
만들기 · 코드 리뷰 · 버그 고치기** 시작 카드가 보입니다. 처음 대화를 열 때 **Saycode 기본
지시**를 쓸지 한 번 묻습니다.

<img src="assets/system-prompt-choice.png" alt="Saycode 기본 지시 사용 여부" width="520" />

### 입력창 해부

| 요소 | 설명 |
|---|---|
| **+** | 파일·사진(⌘U)·폴더 첨부, 기존 경로에서 시작 |
| **AI 선택** | Claude Code · Codex · Opencode · Grok, 그리고 AI 프로필 ([9장](#9-에이전트와-모델-선택-ai-잔량)) |
| **모델** | Default(자동 선택) 또는 특정 모델 고정 |
| **⚡ / ⋯** | 추가 실행 옵션 |
| **핀(Quick Commands)** | 자주 쓰는 프롬프트를 저장해 한 번에 채우기 |
| **↑ 키** | 입력창이 비어 있을 때 이전에 보낸 프롬프트를 차례로 불러오기·검색 |
| **작업 사본 (worktree)** | 대화 전용 브랜치·작업 폴더에서 격리해 작업 |
| **파일 체크포인트 보호** | (worktree를 끈 macOS 대화) 에이전트가 파일을 바꾸기 전 상태를 남기고 안전하게 복원 |

### 한 문장으로 앱 만들기

> *"사내 장비 대여 현황 대시보드를 만들어줘. Vite + React로 상태별 요약 카드, 검색·상태 필터,
> 대여 목록 표(더미 데이터 20건)를 넣고 깔끔한 라이트 테마로. 개발 서버를 5173 포트로 켜두고
> 미리보기로 볼 수 있게 해줘."*

<img src="assets/build-by-chat.gif" alt="새 프로젝트 → 한 문장 요청 → 에이전트 작업 → 미리보기 자동 감지" width="920" />

에이전트는 실제 머신에서 파일을 만들고, `npm install`과 빌드를 돌리고, 개발 서버를 띄웁니다.
모든 도구 호출이 카드로 보이고, 답변은 쓰이는 대로 화면에 나타납니다. 개발 서버가 뜨면 오른쪽
작업 영역에 **미리보기가 자동으로 감지**되어 열립니다. HTML 결과물은 채팅 안에서도 인라인으로
미리 볼 수 있습니다.

> 개발 서버를 원한다면 요청에 *"개발 서버를 켜두고 미리보기로 볼 수 있게"* 를 꼭 넣으세요.
> 그렇지 않으면 에이전트가 HTML 파일 하나로 끝낼 수 있습니다.

## 6. 프로젝트 없이 일하기 — Chat과 문서 템플릿

홈의 **Chat** 탭(또는 사이드바 Chat → **새 chat 시작**)은 프로젝트 없이 바로 일하는
곳입니다. 로그인하지 않은 로컬 작업공간에서도 대화가 저장되고 이어집니다.

<img src="assets/work-docs.gif" alt="Chat에서 DOCX 보고서를 만들고 앱 안에서 바로 열람" width="920" />

- *"3분기 사내 장비 대여 현황 보고서를 DOCX 파일로 만들어줘"* 처럼 요청하면 결과 파일이
  **작업 폴더**에 생기고, 앱 안의 뷰어로 바로 열립니다 (DOCX·PDF·HTML·마크다운 렌더링).
- **문서 선택**(또는 `+`)에서 **문서(DOCX) · 스프레드시트(XLSX) · 프레젠테이션(PPTX) · PDF**
  형식을 고르면 템플릿 목록이 열립니다. *디자인 보고서*, *기본 레터헤드* 같은 기본 템플릿이나
  **내 템플릿 만들기**로 저장한 Office 파일과 작성 지침을 실제 작업에 전달합니다.
- `+` → **기존 경로에서 시작**을 고르면 이 컴퓨터의 기존 폴더를 작업 경로로 씁니다.

<img src="assets/doc-templates.png" alt="문서 형식 선택과 템플릿 갤러리" width="820" />

## 7. 작업 영역 — 파일·변경·터미널·브라우저

프로젝트 화면은 **가운데 대화**와 **오른쪽 작업 영역**으로 나뉩니다. 가운데 위쪽 탭으로 여러
대화를 오가고, 오른쪽 탭으로 도구를 씁니다. 경계를 드래그해 너비를 조절하세요.

<img src="assets/workspace.gif" alt="터미널 → 변경 diff → 작업 영역 전체화 → 파일 내용 검색" width="920" />

| 탭 | 할 수 있는 것 |
|---|---|
| **변경** | 이 대화(worktree)에서 바뀐 파일 목록과 **좌우 비교 diff**. 변경된 줄에 리뷰 코멘트를 달아 에이전트에게 보냅니다 |
| **파일** | 파일 트리 탐색, 파일명 필터, 프로젝트·worktree 전체 **내용 검색**(Enter). 결과를 누르면 해당 줄이 열리고, 새 산출물에는 표시가 붙습니다 |
| **터미널** | 그 머신에 붙은 실제 셸. 탭을 바꿔도 살아 있고 스스로 재연결합니다 |
| **브라우저 / 미리보기** | 실행 중인 앱 열기, 요소 선택, 뷰포트 프리셋 ([8장](#8-보면서-고치기--요소를-집어-채팅으로)) |

오른쪽 위 **+ (작업 패널 추가)** 로 Files · Terminal · 브라우저 · Review · 미리보기 실행을
추가하고, **작업 패널 전체화**로 크게 보거나 **분할 화면으로 복원**합니다.

<img src="assets/workspace-diff.png" alt="작업 영역 전체화 — 좌우 비교 diff" width="920" />

## 8. 보면서 고치기 — 요소를 집어 채팅으로

작업 영역의 **브라우저**에서 `http://localhost:5173` 같은 주소를 열면 내 머신에서 돌아가는
앱이 그대로 뜹니다. 도구줄의 **요소를 선택해 채팅으로 보내기**를 누르고 화면의 요소를

## 17. 팁과 문제 해결

**대화 상태 한눈에 보기** — *응답 중* · *대기*(다음 지시 대기) · *입력 대기*(질문·권한 응답
필요 — 에이전트가 멈춘 게 아니라 여러분을 기다리는 중) · *완료*(보관됨).

**완료한 대화 이어가기** — 보드나 대화 헤더의 **완료 해제**로 다시 살릴 수 있습니다.

**worktree 활용** — 여러 대화를 동시에 돌릴 땐 `작업 사본(worktree)`을 켜세요. 대화마다
격리된 브랜치에서 일해 서로 부딪히지 않습니다. worktree·Commit & PR은 프로젝트가 git
저장소일 때 쓸 수 있고, 새 프로젝트는 Git 저장소로 초기화된 상태로 시작합니다.

**AI 도구가 "설치 필요"나 "확인 실패"로 뜬다면** — 터미널에서 `claude` → `/login`,
`codex login`을 마친 뒤 온보딩 체크리스트에서 **상태 다시 확인**을 누르세요.

**터미널에서 pager가 열렸다면** — `q`로 빠져나오거나 `git --no-pager log`처럼 실행하세요.
