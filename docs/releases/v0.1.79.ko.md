## 새 기능

### 번호 단축키로 고정 대화 전환

고정한 프로젝트 대화의 첫 네 항목을 번호 단축키로 바로 열 수 있습니다. 드래그로 정한 순서와 작성 중인 초안을 유지하며, 입력 중 전환하면 새 대화의 입력창에서 바로 이어 쓸 수 있습니다.

#### 사용 방법

Project 목록에서 대화를 고정하고 고정 영역에서 드래그해 순서를 정하세요. macOS는 ⌘1~4, Windows/Linux는 Ctrl+1~4를 누릅니다. 내 설정 → 일반 → 단축키에서 키를 바꿀 수 있습니다.

### 병합된 PR 대화를 사이드바 호버 창에서 바로 보관

사이드바 프로젝트 대화에 마우스를 올리면 뜨는 위치 창에서, PR이 병합된 대화는 `PR #번호` 옆에 `병합됨` 배지가 보입니다. 그 아래 작은 `보관하기` 버튼으로 대화를 바로 보관할 수 있습니다.

#### 사용 방법

사이드바 Project 목록에서 PR이 병합된 대화 위에 마우스를 올리고 `보관하기`를 누르세요. 행 메뉴(⋮)의 보관과 같은 확인·되돌리기 흐름을 따릅니다.

### 허브 CLI에서 대화의 작업 맥락과 연락 가능 여부 확인

`happy agent ls --status`가 사람 표시 정보, 실제 작업트리 브랜치, 최근 작업 목록, 관측 시각과 prompt·steer·stop 가능 여부를 함께 보여 줍니다. 사람 정보는 클라이언트 주장이고 소유권 증명이 아닙니다. 저장소 정보가 없거나 제목이 임시 ID이면 값을 만들지 않으며, 최근 50개 메시지에 작업 목록이 없으면 사유와 함께 unknown으로 표시합니다. Codex의 빈 계획은 이전 목록을 지우며 개인 Chat에서도 빈 작업 목록 카드를 표시하지 않습니다. 연락 거부는 기존 소유권 게이트를 그대로 따릅니다. Claude TodoWrite의 출처는 호출 시 입력 목록이며 쓰기 성공 증명이 아닙니다. 현재 런타임은 개별 도구 오류 정보를 보내지 않아, 개별 TodoWrite 실패는 검증할 수 없고 완료된 턴에서는 관측한 목록이 유지될 수 있습니다.

#### 사용 방법

Saycode 세션 안에서 `happy agent whoami`로 실행 환경을 확인하고 `happy agent ls --status`를 실행하세요. 전체 세션 ID로 대상을 고르며, 오래된 관측은 연락 전에 다시 확인하세요. 능력을 광고하지 않는 기존 런타임은 unknown으로 표시됩니다. P1 실앱 수락 범위는 Claude 비 mandatory·Codex account broker 허브입니다. Gemini·opencode·grok 직접 허브는 P1 실앱 수락 범위 밖이며 활동은 unknown, steer는 미지원입니다. mandatory Claude는 `not_agent_env`로 거부됩니다.

### AI 브라우저에서 런타임 업데이트 확인

AI 브라우저 미지원 안내에서 조직 관리자가 작업PC의 런타임 업데이트를 확인하고 요청할 수 있습니다. 진행 상태와 실패·복구 안내를 구분하고 완료 후 콘솔을 다시 열 수 있습니다. 서버와 작업PC의 업데이트 지원 배포가 필요하며 구형 PC는 관리자 최초 설치가 필요할 수 있습니다.

#### 사용 방법

대화의 AI 브라우저에서 미지원 안내가 보이면 브라우저 런타임 업데이트를 누릅니다. PC·버전을 확인하고 업데이트 시작과 확인창의 업데이트 시작을 누르세요. 완료 후 콘솔 다시 열기를 누릅니다. 결과가 불확실하면 다시 확인으로 조회하세요.

## 변경된 기능

### 대화 더보기 메뉴의 '보관'을 '보관하기'로 변경

사이드바 대화와 채팅의 더보기(⋮) 메뉴에서 '보관' 항목 이름이 '보관하기'로 바뀌었습니다. 동작은 그대로입니다.

#### 사용 방법

사이드바에서 대화나 채팅에 마우스를 올리고 ⋮ 버튼을 누른 뒤 '보관하기'를 고릅니다.

### 대화 목록에 마우스를 올려도 제목이 더 길게 보입니다

사이드바 대화 행에 마우스를 올리면 더보기와 고정 버튼이 나타나는데, 그동안 버튼보다 넓은 자리를 비워 두어 제목이 일찍 잘렸습니다. 이제 제목이 더보기 버튼 바로 앞까지 보여 같은 너비에서 더 많은 글자를 읽을 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 사이드바에서 연 대화도 PR 번호와 작업트리 아이콘을 그대로 보여 주기

사이드바에서 지금 열려 있는 대화는 배경색만 달라지고, 다른 대화와 똑같이 PR 번호와 작업트리(분기) 아이콘을 보여 줍니다. 제목도 굵게 바뀌지 않으며, 다크 모드에서는 선택 배경을 더 또렷하게 바꿔 배경만으로도 지금 연 대화를 알아볼 수 있습니다. 더보기와 고정 버튼은 마우스를 올렸을 때나 키보드로 그 행에 이동했을 때만 나타납니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 상세 정보 펼침 UI를 통일했어요

설정·설치 도구·복구 로그·사용량의 상세 펼침에서 제목, 화살표, 클릭 영역과 내용 간격을 맞췄습니다. 같은 역할의 고급 설정 버튼도 같은 표현을 사용합니다. 오류 시 자동 펼침과 기존 키보드 조작은 유지됩니다. 상세를 접으면 안쪽의 복사 결과 안내도 함께 사라집니다.

#### 사용 방법

기존 상세 정보 제목을 클릭하거나 키보드로 펼치고 접으세요. 별도 설정 없이 자동 적용됩니다.

### 입력창 '/' 명령 목록이 한 줄짜리 깔끔한 메뉴로 바뀌었습니다

입력창에 `/`를 입력하면 뜨는 명령·스킬 목록이 다른 메뉴와 같은 모양이 되었습니다. 항목마다 이름과 설명을 한 줄에 보여 주어 한 화면에 더 많은 명령이 보이고, 고른 항목은 파란 막대·테두리 대신 라이트·다크 모두에서 잘 보이는 옅은 회색으로 표시됩니다. 긴 스킬 이름은 말줄임되고, 마우스를 올리면 전체 이름과 설명을 볼 수 있습니다.

#### 사용 방법

Chat이나 프로젝트 대화의 입력창에 `/`를 입력하세요. 방향키·Enter·Tab·Esc 동작은 그대로입니다.

### 자세히 펼침이 있는 알림을 더 깔끔하게 정리했습니다

AI가 오래 응답하지 않을 때 뜨는 알림처럼 `자세히`를 펼칠 수 있는 알림의 모양을 다듬었습니다. 위아래 여백을 맞추고 아이콘·닫기 버튼을 첫 줄에 정렬했으며, `자세히`는 큰 버튼 대신 작은 화살표가 붙은 글자로, 펼친 설명은 작은 글씨로 묶어 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 작업 마무리의 `보관&완료`, PR이 머지된 대화에서도 사용

작업 마무리 메뉴의 `완료로 이동`을 `보관&완료`로 이름을 바꿨습니다. 대화를 보관하면서 작업보드 `완료`로 옮기는 동작이라는 점이 이름에 드러납니다. 또 PR이 이미 머지된 대화에서 "이미 PR이 머지되었습니다"로 막혀 사이드바에서 따로 보관해야 하던 문제를 고쳤습니다. 작업 마무리 메뉴와 창 상단의 완료 버튼 모두 머지된 대화를 바로 보관할 수 있습니다.

#### 사용 방법

프로젝트 대화에서 입력창 위 줄의 로봇 아이콘(작업 마무리)을 누르고 `보관&완료`를 고릅니다. 확인창은 고급 설정…의 `보관&완료 전에 확인`으로 켜고 끕니다.

### 저장소가 없는 프로젝트도 입력창 위에서 연결 상태와 다음 할 일을 보여 줘요

기획으로 만든 프로젝트처럼 코드 저장소가 아직 연결되지 않은 프로젝트에서는 입력창 위 저장소 바가 비어 있거나 새 대화에서 아예 보이지 않았어요. 이제 새 대화와 기존 대화 모두 바에 "저장소 연결 안 됨"을 표시하고, 상황에 맞는 버튼 하나를 함께 보여 줘요. 저장소가 없으면 "저장소 연결하기", 상태 확인에 실패하면 "다시 확인"이 나와요. 작업 PC 폴더가 이미 원격 저장소에 연결돼 있으면 연결 버튼 없이 브랜치와 상태만 보여 줘요. 연결하지 않아도 대화와 미리보기는 그대로 쓸 수 있어요.

#### 사용 방법

입력창 위 저장소 바에서 "저장소 연결하기"를 누르면 프로젝트 설정의 코드 저장소 화면이 열리고, 바로 입력할 칸에 커서가 놓여요. "다시 확인"을 누르면 작업 폴더 상태를 다시 읽어요. 연결과 생성 버튼은 프로젝트를 만든 사람에게만 보여요.

### 표와 상세 정보를 읽기 편하게 맞췄어요

사용량·도구 등급 표의 행 높이와 정렬을 맞췄습니다. 앱·프로젝트·저장소·메모리·작업PC 상세의 라벨과 값은 같은 글자 크기와 간격을 사용하며, 긴 경로와 좁은 창에서도 읽을 수 있게 줄바꿈합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### AI가 작업 중일 때 누른 리뷰·PR 요청은 작업이 끝난 뒤 차례로 실행

AI가 응답하는 중이거나 작업 리뷰를 반복하는 중에 작업 마무리 메뉴의 리뷰나 PR 요청을 누르면 진행 중인 작업에 끼어들지 않습니다. 요청은 입력창 위 대기열에 들어가고, 지금 작업이 끝나면 넣은 순서대로 자동 실행됩니다. 반복 리뷰가 진행 중이면 대기열은 반복이 끝날 때까지 기다립니다. 메뉴 이름도 쉬운 말로 바꿨습니다. `셀프 리뷰`는 `작업 리뷰하기`가 되었고, `Commit & PR`은 `PR 올리기`가 되었습니다.

#### 사용 방법

AI가 응답 중이거나 작업 리뷰를 반복하는 중에 입력창 위 로봇 아이콘(작업 마무리)을 열면 `작업 리뷰하기`·`PR 올리기` 아래에 `지금 작업이 끝나면 이어서 실행해요`가 보입니다. 누르면 대기열에 `작업 리뷰하기 · 최대 N회`나 `PR 올리기`로 추가됩니다. 대기열 항목은 끌어서 순서를 바꾸거나 삭제할 수 있습니다. AI가 쉬고 있을 때는 지금처럼 바로 실행됩니다.

### Commit & PR이 모든 확인을 통과하면 머지까지 합니다

작업 마무리 메뉴·작업보드·오토파일럿의 Commit & PR이 PR을 만든 뒤 CI 실패 수정, 리뷰 봇 지적 반영, 충돌 해결을 마치고 base 브랜치에 머지까지 합니다. 이 PR 브랜치를 base로 한 PR 중 리뷰 봇 수정 PR은 반영할 필요가 있을 때만 먼저 머지하고, 필요 없으면 이유를 남기고 닫습니다. 그 밖의 PR이 남아 있으면 머지하지 않고 알려 줍니다. 머지 뒤 CI를 다시 확인하고 모두 통과했을 때만 base에 머지합니다. 확인한 커밋과 base 브랜치가 그대로일 때만 머지하고, 보호 규칙을 우회하지 않습니다. 봇 판정이 오지 않거나, 같은 CI 실패가 반복되거나, 판단이 필요한 충돌·필수 승인 리뷰가 남거나, 90분 안에 끝나지 않으면 머지하지 않고 남은 상태를 보고합니다. 이때 PR 지킴이가 이어받아도 "머지 가능"까지만 처리하고 머지는 하지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 입력창 위 작업 마무리 메뉴의 PR 올리기나 작업보드 카드의 Commit & PR을 누르면 됩니다. 머지를 직접 하고 싶다면 PR 올리기 대신 대화에서 PR 생성만 요청하세요.

## 수정된 문제

### 개인 Claude 사용을 꺼도 조직 계정 새 대화가 바로 시작돼요

사용량 팝오버에서 "이 컴퓨터에서 개인 Claude 계정 사용 허용"을 끄면, 조직 계정으로 새 대화를 시작해도 첫 메시지에서 "이 대화를 시작하지 못했습니다. 개인 사용이 꺼져 있어요" 오류가 나던 문제를 고쳤어요. 이제 앱이 조직 계정으로 띄운 대화는 첫 메시지부터 그대로 보내져요. 조직 계정임을 확인할 수 없는 대화는 지금처럼 막아요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 다른 곳에서 생기거나 다시 꺼낸 대화가 목록에서 ID로 보이고 열리지 않던 문제를 고쳤습니다

다른 창·기기에서 만들거나 보관함에서 다시 꺼낸 대화가 사이드바 목록에 먼저 나타나면,
제목 대신 `cmvp0mq2` 같은 ID 앞자리가 보이고 눌러도 열리지 않았습니다. 이제 이름이 없는 대화는
다른 새 대화처럼 "새 대화"로 보이고, 누르면 프로젝트 대화 목록을 다시 불러와 그 대화를 엽니다.
다시 불러와도 열 수 없는 대화면 로딩을 멈추고 열 수 없다고 알려 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 사이드바의 대화를 평소처럼 누르면 됩니다.

### 다른 대화로 옮겨도 "대화 여는 중…"이 계속 떠 있던 문제를 고쳤습니다

아직 불러오지 못한 대화를 누른 뒤 이미 열어 본 다른 대화로 옮기면, 앞 대화의 "대화 여는 중…"
표시가 사라지지 않고 화면 가운데에 남아 있었습니다. 이제 이미 불러온 대화로 옮기면 이전 대화의
로딩 표시가 바로 사라집니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 다른 조직 Chat 알림이 그 조직 창에서 열려요

다른 조직에서 만든 Chat의 완료 알림을 누르면 화면이 "이 화면을 표시하지 못했어요"로만 나오던 문제를 고쳤습니다. 이제 그 조직 창이 이미 열려 있으면 그 창으로 이동해 해당 대화를 보여 주고, 없으면 그 조직으로 바뀐 새 창을 띄워 대화를 엽니다. 다른 조직 Chat을 지금 창에서 열 때도 답변 속 링크 때문에 화면이 깨지지 않습니다.

#### 사용 방법

사이드바의 최근 알림이나 알림 센터에서 다른 조직 Chat 알림을 누르면 됩니다. 별도 설정 없이 자동 적용됩니다.

### 도구 승인이 많은 턴에서도 다른 창에서 답한 질문이 끝난 상태로 남습니다

같은 대화를 두 창(또는 다른 기기)에 열어 두고 한쪽에서 AI 질문에 답한 뒤, AI가 같은 턴에서 도구를 많이 쓰면(도구 승인 60여 건 이상) 답하지 않은 창의 그 질문이 다시 "답변 대기 중"과 제출 양식으로 돌아가고, "작업 중..." 표시도 사라지던 문제를 고쳤습니다. 이제 도구 승인이 아무리 많이 쌓여도 다른 창에서 답한 질문은 "답변 제출됨"으로, 답 없이 끝난 질문은 "이 요청은 이미 끝났어요"로 남고, AI가 이어서 일하는 동안 "작업 중..."도 계속 보입니다. 계획 승인 기록도 같은 방식으로 보존됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 새로고침 없이 누락된 대화 답변 복구

실시간 알림을 놓쳤을 때 이미 열어 본 대화의 새 답변이 새로고침 전까지 보이지 않던 문제를 수정했습니다. 서버의 작업 상태와 관계없이 새 메시지가 확인되면 답변과 완료 상태를 다시 불러옵니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 작업PC 상태가 잠깐 이전 값으로 되돌아가던 문제 수정

작업PC가 재시작 준비를 알리거나 도구 규칙·자동화 지원을 바꾼 직후, 그보다 먼저 출발한 목록 새로고침이 늦게 도착하면 화면이 이전 상태로 되돌아가 최대 몇 분 동안 그대로 남을 수 있었습니다. 이제 더 오래된 목록은 방금 받은 작업PC 상태를 덮지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 작업PC의 예약 대화·결과 전달 지원 변경이 화면에 반영되지 않던 문제 수정

작업PC를 업데이트해 예약 작업의 대화 이어가기나 결과 전달 지원만 달라진 경우, 다른 상태가 함께 바뀌거나 앱을 다시 시작하기 전까지 이전 지원 상태가 그대로 보였습니다. 이제 바뀐 지원 상태가 바로 반영됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 조직 Chat을 프로젝트로 전환하면 그 조직의 프로젝트 목록에 나타납니다

조직에서 쓰던 Chat을 프로젝트로 전환하면 전환은 성공해도 새 프로젝트가 개인 프로젝트로 만들어져, 조직 프로젝트 목록에서 찾을 수 없었습니다. 이제 Chat이 속한 조직의 프로젝트로 만들어지고, 전환 직후 목록에 바로 나타납니다. 개인 Chat은 전과 같이 개인 프로젝트가 됩니다.

#### 사용 방법

Chat의 대화 더보기 메뉴에서 프로젝트로 전환을 선택하고 파일을 고른 뒤 전환하고 프로젝트 열기를 누릅니다. 별도 설정 없이 자동 적용됩니다.

### 조직 Claude 계정 한도 뒤 응답 멈춤과 계정 전환 개선

내장 Happy 런타임을 `.359`로 갱신했습니다. 조직 Claude 계정이 한도에 걸린 뒤 다른 계정으로 바꾸는 과정에서, 다음 메시지에 답이 오지 않고 "작업 중"에 멈추던 문제를 고쳤습니다. 다른 계정으로 바꾸기 전에는 그 계정의 사용량을 확인해서, 이미 한도에 걸린 계정으로 옮기지 않습니다. 수집 담당 PC는 Desktop이 꺼져 있어도 조직 계정 사용량을 주기적으로 측정합니다. Windows에 함께 설치되는 claude-swap도 `0.27.0b3`로 갱신했습니다.

#### 사용 방법

이 변경을 포함한 Desktop 업데이트를 설치하면 별도 설정 없이 적용됩니다.

### AI가 스스로 승인한 질문을 '답변 제출됨'으로 표시하지 않기

모든 작업을 자동 승인하는 모드에서 AI 런타임이 질문을 스스로 승인하면, 대화 기록의 그 질문 행이 누군가 답한 것처럼 "답변 제출됨"으로 보였습니다. 이제 런타임이 남기는 자동 승인 표시를 읽어 "이 요청은 이미 끝났어요"로 보여 주고, 그 요청에 늦게 답해도 다른 곳에서 응답했다고 안내하지 않습니다. 자동 승인 표시는 이 수정을 담은 런타임으로 업데이트된 뒤부터 적용되며, 그 전 런타임에서는 지금처럼 동작합니다.
