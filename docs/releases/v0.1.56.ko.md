## 새 기능

### 대화마다 작성 중인 내용을 자동으로 보관합니다

Chat 홈과 대화 탭, 프로젝트의 각 대화에서 작성 중인 내용을 따로 보관합니다. 다른 화면으로 이동하거나 기존 대화 탭을 닫고 다시 열어도 입력이 복원되며, 앱을 다시 시작하면 본인 계정과 조직의 입력 및 Chat 문서 형식만 복원됩니다. 전송 실패 시 초안을 유지하고, 이전 전송이 늦게 완료되어도 새로 작성한 내용을 지우지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 대화 입력창에서 작성한 뒤 다른 대화로 이동했다가 돌아오면 이어서 작성할 수 있습니다. 첨부 파일은 같은 앱 실행 중 화면 이동에서 유지되며, 앱을 다시 시작한 뒤에는 다시 첨부해야 합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1519)

### 대화의 작업물 확인과 저장을 더 편리하게

개인 Chat 왼쪽 상단의 작은 작업물 버튼에서 이전 대화의 문서를 다시 찾고, 미리보기·저장·이어서 수정할 문서 선택을 할 수 있습니다. 파일이 많으면 목록 안에서 스크롤하며 미리보기를 열면 목록은 닫힙니다. 작업물이 없을 때는 빈 배너를 표시하지 않습니다.

#### 사용 방법

문서가 있는 개인 Chat에서 왼쪽 상단의 파일명 또는 작업물 개수 버튼을 누르세요. 문서를 선택한 뒤 수정 요청을 입력하거나 내 PC에 저장하세요. 원본 변경 안내가 나오면 다시 저장하고, 확인 실패 시 다시 확인을 누르세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1524)

### AI 연결 실패의 원인과 다음 조치를 확인할 수 있습니다

시작준비에서 AI 연결에 실패하면 오류 아이콘이나 안내 문구를 눌러 원인, 오류 코드, 다음 조치와 실패 단계를 확인할 수 있습니다. 앱·CLI 버전과 필요한 연결 기능의 지원 여부도 확인하며, 진단 정보를 복사해 개발자에게 전달할 수 있습니다. 원문 로그나 계정 비밀정보는 포함하지 않습니다.

#### 사용 방법

시작준비 화면의 오류 아이콘 또는 실패 안내 문구를 누르세요. 계속 실패하면 오류 상세를 캡처하거나 `진단 정보 복사`로 복사한 내용을 개발자에게 전달하세요. 조직 키 설정 안내가 나오면 조직 소유자 또는 보안 관리자에게 해당 설정을 요청한 뒤 다시 확인하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1518)

## 변경된 기능

### 대화의 AI 연결 설정 진입을 통일

Chat과 Project의 현재·과거 오류에서 AI 연결 설정을 누르면 같은 작은 모달을 엽니다. 다시 연결 버튼은 일반 버튼으로 표시합니다. 과거 오류의 설정을 열어도 이전 요청을 자동으로 다시 보내지 않습니다. 내 설정의 전체 AI 연결 설정은 그대로 사용할 수 있습니다.

#### 사용 방법

대화에 표시된 AI 연결 설정을 눌러 연결 상태와 필요한 조치를 확인하세요. 전체 설정은 내 설정 또는 모달의 추가 설정에서 확인하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1524)

### 열린 대화 탭을 더 쉽게 구분하고 닫기

대화 상단에 `열린 대화`와 `+ 새 대화`를 표시합니다. 새 대화는 기존 대화와 초안을 유지한 채 새 탭으로 열립니다. 대화가 없는 프로젝트의 첫 새 대화는 빈 안내 탭에서 시작합니다. 현재 탭을 닫으면 같은 화면의 왼쪽 대화로 이동하고, 왼쪽이 없으면 오른쪽 대화로 이동합니다. 마지막 탭을 닫으면 시작 화면으로 돌아갑니다.

#### 사용 방법

상단의 `+ 새 대화` 또는 프로젝트 옆 새 대화 버튼을 누르세요. 탭의 닫기 버튼은 대화 기록을 삭제하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1520)

## 수정된 문제

### 다른 작성자의 프로필 위치 수정

Chat과 Project에서 다른 작성자의 메시지도 내 메시지처럼 프로필을 말풍선 오른쪽에 표시합니다. 작성자 정보와 프로필 팝오버는 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1524)

### 빠진 공용 AI 계정 연결을 다시 준비합니다

내장 Happy CLI를 1.1.10-aplus.300으로 갱신합니다. 이 PC의 공용 AI 계정 저장소가 비어 있으면 이전 연결 완료 기록만으로 재적용을 생략하지 않고, 기존 권한 확인을 거쳐 배정된 계정을 다시 가져옵니다. 개인 계정과 기존 PC 신원은 유지합니다.

#### 사용 방법

이 변경을 포함한 새 Desktop 버전을 설치한 뒤 필요한 시작준비를 진행하거나 AI 연결에서 다시 연결하세요. 계정이 이미 준비돼 있으면 기존 상태를 재사용합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1525)

### 새 대화 시작 화면의 배치 개선

새 대화 탭의 제목이 상단에 붙던 문제를 수정했습니다. 제목·입력창·작업 안내를 화면 중앙보다 조금 위에 배치하고, 낮은 창에서는 스크롤로 모든 안내에 접근할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1520)

### 시작준비의 AI 도구 설치 실패를 복구합니다

최신 main의 공식 Saycode용 claude-swap 패키지 설치 복구를 반영했습니다. 설치 후 필요한 실행 기능을 확인하고, 실패하면 원인에 맞는 조치를 안내합니다. 호환되는 기존 설치와 계정 자료는 유지합니다.

#### 사용 방법

설치 실패 시 다시 시도를 누르세요. 원인이 필요하면 i 버튼이나 안내 문구를 누르고, 계속 실패하면 진단 정보를 개발자에게 전달하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1523)

### 프로젝트를 오가도 개인 새 대화 초안 유지

프로젝트 화면을 보고 개인 새 대화 탭으로 돌아와도 작성한 글·첨부·문서 형식·업무 프로필·AI 옵션을 유지합니다. 작업 PC가 바뀌면 이전 PC의 예시 파일만 정리하고 내 파일과 문장은 보존합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 초안 내용은 앱 실행 중 열린 탭에서 유지되며, 탭을 닫거나 앱을 종료하면 초기화됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1520)

### Telegram 백그라운드 작업 완료 응답 전달

Telegram에서 백그라운드 작업을 시작한 뒤 초기 안내만 도착하고 작업 완료 결과가 누락되던 문제를 수정했습니다. 작업 완료 후 이어지는 응답도 같은 대화로 전달됩니다.

#### 사용 방법

별도 설정 없이 Telegram에서 기존처럼 백그라운드 작업을 요청하면 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1507)

### Windows 재설치 후 빠진 준비를 이어갑니다

Windows 설치·재설치 후 첫 실행에서 도구와 AI 연결 상태를 한 번 확인합니다. 빠진 항목이 있으면 기존 시작준비 화면에서 설치·연결을 이어가며, 준비된 항목은 재사용합니다. 같은 설치의 일반 재실행에서는 이 점검을 반복하지 않습니다.

#### 사용 방법

설치 후 앱을 실행하고, 시작준비가 나타나면 안내에 따라 진행하세요. 기존 로그인·PC 신원·대화는 유지합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1522)

### Windows 조직 setup-token 연결 실패 원인을 바로잡습니다

Windows에서 일반 `cswap`가 설치되어 있으면 조직 setup-token 연결을 지원하지 않는데도 CLI가 준비된 것으로 표시될 수 있었습니다. 이제 Saycode setup-token capability를 실제로 확인하고, 지원하지 않는 runtime은 Happy `.299`가 고정한 `saycode-claude-swap==0.27.0b2`를 설치한 뒤 다시 검증합니다. 이전 빌드가 존재하지 않는 upstream `claude-swap==0.27.0b1`을 요청하던 문제도 수정했습니다. 연결 상태도 setup-token runtime, Desktop daemon, 전용 머신 문제를 구분해 안내합니다.

#### 사용 방법

Desktop을 업데이트한 뒤 조직 AI 연결에서 다시 시도하세요. 기존 일반 cswap tool 환경은 승인된 SayCode runtime으로 교체하지만, 계정 저장소와 credential은 유지합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1509)
