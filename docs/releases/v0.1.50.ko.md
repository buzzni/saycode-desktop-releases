## 새 기능

### 머신 상세 정보와 업데이트 관리

등록된 머신의 상세 상태를 확인하고 지원되는 머신의 Aplus CLI 업데이트를 Desktop에서 실행할 수 있습니다.

#### 사용 방법

환경설정의 머신 목록에서 머신을 선택해 상세 정보를 엽니다. 업데이트가 표시되면 대상 머신을 확인하고 업데이트 동작을 실행합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/498)

### 메신저를 Desktop 없이 다른 머신에서 실행

Telegram·Slack·Discord 연결을 Desktop 대신 다른 머신의 Saycode(happy-cli)가 받도록 옮길 수 있습니다. 옮긴 머신은 Desktop이 꺼져 있거나 설치되지 않아도 메시지를 받고 개인 대화를 시작합니다. 봇 토큰은 선택한 머신의 키로만 암호화해 보내며, 이 Desktop의 사본은 지웁니다. 기존 Desktop 수신(로컬 전용 모드 포함)은 그대로입니다.

#### 사용 방법

설정의 메신저 채널에서 각 메신저의 ‘실행 위치’ 옆 ‘다른 머신에서 실행’을 누르고, 머신과 지문을 확인한 뒤 토큰을 다시 입력하세요. 옮긴 뒤에는 같은 화면에서 다시 페어링합니다. ‘Desktop으로 되돌리기’로 언제든 돌아올 수 있습니다. 서버와 해당 머신의 Saycode가 이 기능을 지원하는 버전이어야 선택지가 보이며, 지금은 개인 대화만 시작할 수 있습니다. 화면 잠금 키체인이 없는 Linux 서버(headless)는 아직 지원하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1179)

### 사용 방식 선택과 자동 온보딩 체크리스트

첫 실행과 로그아웃 후 개인 사용 또는 조직 사용을 선택할 수 있습니다. 개인 사용은 Guest 로컬 작업공간으로, 조직 사용은 로그인과 이 컴퓨터 등록으로 이어집니다. 첫 온보딩에서 Saycode CLI, codex-multi-auth, claude-swap과 Claude Code·Codex CLI 설치를 순서대로 진행하고, 조직이 하나면 자동으로 선택합니다. AI 계정 로그인과 알림 권한은 필요한 사용자 입력을 안내합니다.

#### 사용 방법

앱 첫 화면에서 사용 방식을 선택하세요. 진행 중 오류가 나면 같은 단계에서 재시도할 수 있으며 이미 성공한 등록과 설치는 유지됩니다. 나중에 설정을 이어가려면 환경설정의 온보딩 체크리스트에서 단계를 고르고 이 단계부터 자동 진행을 누르세요.

### 홈·사이드바·대화 입력 흐름 개선

사이드바에서 Chat과 Project 목록을 전환해도 열린 화면을 유지하고, 각 목록의 검색은 필요할 때만 펼칠 수 있습니다. 공유받은 프로젝트는 기본 목록에서 숨기되 보기 옵션으로 찾을 수 있습니다. 프로젝트 생성 화면은 시작 경로와 온라인 머신 선택을 간결하게 정리했습니다.

#### 사용 방법

사이드바의 Chat/Project 탭으로 목록을 바꾸고 각 목록 하단의 검색 아이콘을 사용하세요. 공유받은 프로젝트는 `프로젝트 보기 옵션`에서 선택할 수 있습니다.

### CLI 업데이트 알림 하루 숨김

Aplus CLI 업데이트 알림의 닫기 왼쪽에 **하루동안 안보기**를 추가했습니다. 같은 사용자·서버·조직 범위에서 24시간 동안 알림을 숨기며 앱 재실행에도 유지합니다. 직접 여는 업데이트 관리 화면은 계속 사용할 수 있습니다.

### CLI 업데이트 알림에서 여러 머신을 한 번에 업데이트합니다

Aplus CLI 업데이트 알림 배너에서도 업데이트가 필요한 온라인 머신을 한 번에 예약할 수 있습니다. 지금까지는 이 일괄 업데이트가 업데이트 관리 모달에만 있어, 알림을 보고 머신마다 버튼을 눌러야 했습니다.

#### 사용 방법

업데이트가 필요한 온라인 머신이 두 대 이상이면 알림에 "모두 업데이트" 버튼이 나타납니다. 한 번 누르면 대상 머신 수를 확인하는 문구가 뜨고, 다시 확인하면 해당 머신들에만 업데이트를 예약합니다. 오프라인이거나 버전을 확인하지 못한 머신은 대상에서 제외됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/860)

### saycode CLI 0.7.0

Desktop 없이 메신저(Telegram·Slack·Discord)를 받는 채널 호스트 `saycode channel-host`가 들어갑니다. Happy CLI daemon이 이 명령을 자식으로 실행해, 그 머신에서 Desktop이 꺼져 있거나 설치되지 않아도 메시지를 받고 개인 대화를 시작합니다. 어댑터는 별도 파일(`channel-extension-host.mjs`)로 OS 샌드박스 안에서만 실행되며, 호스트 키·자격·세션 키는 OS 키체인으로 봉인해 보관합니다.

#### 사용 방법

직접 실행하는 명령이 아닙니다. 이 버전을 번들한 Happy CLI 런타임으로 올리면 daemon이 자동으로 호스트를 띄우고, Desktop 설정의 메신저 채널에서 ‘다른 머신에서 실행’으로 옮길 수 있습니다. 화면 잠금 키체인이 없는 Linux 서버(headless)는 아직 지원하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1186)

### saycode CLI 0.7.1

Desktop 없이 메신저를 받는 채널 호스트가 앱과 같은 공식 어댑터로 동작합니다. 0.7.0은 설치할 어댑터를 서명된 원격 카탈로그에서만 받게 되어 있었는데, 카탈로그가 아직 운영되지 않아 호스트가 실행할 메신저가 없었습니다. 이제 앱에 함께 들어 있는 Telegram·Slack·Discord 공식 어댑터(해시로 고정 검증)를 CLI에 함께 싣고, 카탈로그가 운영되면 카탈로그 쪽을 우선합니다. 어댑터는 이전과 같이 OS 샌드박스 안에서만 실행됩니다.

#### 사용 방법

이 버전을 번들한 Happy CLI 런타임으로 올리면, Desktop 설정의 메신저 채널에서 그 머신을 ‘다른 머신에서 실행’ 대상으로 고를 수 있습니다. Desktop과 이 CLI의 어댑터 버전이 같아야 옮길 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1191)

## 변경된 기능

### 닫은 파일 탭과 접은 작업 도구가 다른 대화에서도 그대로 유지됩니다

오른쪽 작업 도구에서 파일 탭을 닫거나 도구 패널을 접어도, 다른 대화를 열 때마다 파일 탭과 패널이 다시 열리던 불편을 고쳤습니다. 이제 닫은 파일 탭과 접은 패널은 이 기기에서 기억해 다른 대화로 이동하거나 앱을 다시 켜도 닫힌 채로 시작합니다.

#### 사용 방법

파일 탭의 닫기 버튼이나 도구 접기 버튼을 누르면 다음 대화부터 그대로 적용됩니다. 다시 쓰려면 오른쪽 `+` 또는 대화의 `…` 메뉴에서 Files를 고르거나, `도구 펼치기`를 누르세요. 다시 연 상태도 다음 대화부터 기억됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1210)

### 대화 고정을 중앙 추가 메뉴에서 사용할 수 있습니다

#### 사용 방법

기존 대화를 연 뒤 중앙 헤더의 … 메뉴에서 핀 아이콘이 있는 대화 고정을 누르세요. 같은 위치의 대화 고정 해제로 취소할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1208)

### 대화 상태 확인에 쓰는 데이터가 크게 줄었습니다

앱은 사이드바에 보이는 대화들의 상태(작업 중 여부, 제목 등)를 몇 초마다 서버에 확인합니다. 지금까지는 확인할 때마다 모든 대화의 전체 정보를 받아 한 번에 수 MB가 오갔습니다. 이제는 변경 여부를 알려주는 작은 정보만 받고, 실제로 바뀐 대화만 전체 정보를 다시 받습니다. 네트워크 사용량과 서버 부하가 줄어듭니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1122)

### 대화와 파일 작업 영역을 분리했습니다

중앙에서 여러 대화를 탭으로 전환하고 우측에서 파일·변경 내역·터미널을 사용할 수 있습니다. 프로젝트 설정과 기존 도구는 대화 헤더의 설정 메뉴에서 접근합니다.

#### 사용 방법

프로젝트 대화를 열고 우측 파일·변경·터미널 탭을 선택하세요. 파일을 선택하면 본문에 열리며, 작업 영역의 경계를 드래그해 너비를 조절할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1198)

### 로그인 데스크톱의 조직 전용 머신 등록

로그인한 데스크톱 앱에서 신규 개인 머신 등록을 조직 전용 머신 등록으로 변경했습니다. 선택한 조직의 로그인 사용자에게 배정되는 전용 머신을 등록합니다. standalone의 개인 등록과 조직 공용 등록은 유지합니다.

#### 사용 방법

로그인 후 조직을 선택하고 머신 설정의 전용 머신 등록을 사용하세요. 조직을 선택하지 않으면 신규 등록을 진행하지 않습니다. 기존 머신의 인증을 자동 전환하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1167)

### 메신저 연결 후 앱을 종료해도 수신 유지

상시 실행 설정 기록이 없는 설치에서 처음 메신저를 연결하면 앱 종료 후 연결 유지가 자동으로 켜집니다. 기존에 꺼져 있던 설정은 그대로 유지합니다. 컴퓨터가 깨어 있고 인터넷에 연결되어 있어야 합니다.

#### 사용 방법

설정의 메신저 채널에서 연결을 완료하면 자동 적용됩니다. 기존 사용자도 ‘앱 종료 후에도 연결 유지’에서 직접 켜거나 끌 수 있습니다. 서비스 등록에 실패하면 표시된 상태를 확인한 뒤 다시 켜세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1154)

### 사이드바 대화와 프로젝트 정렬 개선

프로젝트 탭은 핀된 대화, 핀된 프로젝트, 프로젝트 순서로 표시합니다. 고정 대화는 프로젝트 안에서 중복 표시하지 않습니다. 대화는 한 줄로 표시하고 프로젝트·대화·Work는 드래그로 순서를 바꿀 수 있습니다. 작업 상태가 바뀌어도 순서는 유지합니다. 선택 배경과 로딩 표시, 생성 버튼 여백도 정리했습니다.

#### 사용 방법

각 목록 안에서 행을 드래그해 순서를 바꾸세요. 순서는 이 데스크톱 앱에 저장됩니다. 프로젝트 … 메뉴에서 프로젝트 설정을 열 수 있습니다.

#### 사용 방법

대화 헤더의 커넥터 상태를 누르면 설정한 커넥터의 상태가 먼저 표시됩니다. 다른 MCP를 확인하려면 ‘고급: 다른 MCP 진단’을 펼치세요. 설정 조회에 실패하면 새로고침으로 다시 확인할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1147)

### 프로젝트 대화를 최신 활동순으로 표시

왼쪽 프로젝트 아래의 대화가 중앙 대화 목록과 다른 오래된 순서로 남던 문제를 고쳤습니다. 이제 직접 순서를 바꾸지 않은 프로젝트 대화는 최근 활동순으로 표시되며, 사용자가 드래그해 정한 순서는 새로고침 후에도 유지됩니다.

#### 사용 방법

### Happy CLI 업데이트 확인이 실패해도 화면을 가리지 않습니다

Happy CLI 최신 버전 확인이 실패하면(오프라인, 서버에 닿지 않음 등) 앱을 열자마자 화면 전체를 가리는 창이 떴습니다. 이제 확인 실패는 작은 알림으로만 표시되고, 알림에서 업데이트 관리 화면을 열 수 있습니다. 실제로 업데이트가 있을 때는 이전처럼 안내 창이 뜹니다.

#### 사용 방법

별도 설정은 필요 없습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1166)
