## 새 기능

### 다른 프로젝트의 대화 제목 검색

AI가 내 대화 제목으로 현재 프로젝트를 먼저 찾고, 없으면 같은 GitHub 저장소의 프로젝트,
그 뒤 같은 조직의 다른 프로젝트로 검색을 넓힙니다. 후보를 찾는 단계에서는 본문을 읽지 않습니다.
Codex의 구조화된 MCP 호출도 검색·읽기 요청으로 인식해 처리합니다.

#### 사용 방법

업데이트된 Common MCP 서버와 Desktop이 필요합니다. Desktop을 실행하고 Project 대화에서
찾을 대화 제목을 알려 주세요. 후보가 여러 개면 프로젝트와 대화를 골라 주세요.
서버가 요청 대화와 읽을 본문 대상의 내 소유를 확인할 수 있어야 합니다.
현재 계정·조직에 로드된 메타데이터만 검색하며 Web·모바일만으로는 이 검색을 처리하지 않습니다.
Codex의 live 요청은 해당 MCP 이벤트 전달 보완이 포함된 Happy CLI도 필요합니다.

### 변경·브라우저 도구를 단축키로 열기

프로젝트 대화에서 단축키로 오른쪽 작업 패널의 변경 도구를 열거나 새 브라우저를 열 수 있습니다. 작업 패널 추가 메뉴의 변경·브라우저 옆에도 키가 표시됩니다. 파일을 열지 않은 파일 화면은 작업 폴더 경로 없이 아이콘과 안내만 보여 주고, 파일 트리를 숨겼을 때만 `파일 트리 열기` 버튼이 나옵니다. 변경 도구의 빈 화면은 옆의 변경 목록에서 파일을 고르라고 안내합니다.

#### 사용 방법

변경은 Control+Shift+G(Windows는 Ctrl+Shift+G), 브라우저는 Control+Shift+O(Windows는 Ctrl+Shift+O)를 누르세요. 키는 내 설정 → 일반 → 단축키에서 바꿀 수 있습니다. 브라우저는 브라우저 기능을 쓰는 조직에서만 열립니다.

### 사내 LLM으로 새 Claude 대화를 시작할 수 있습니다

조직 관리자가 등록하고 나에게 배정한 사내 LLM으로 Desktop에서 새 Claude 대화를 시작할 수 있습니다. 새 대화의 사용 연결에서 기존 방식 대신 사내 LLM을 고르면, 각 사내 LLM의 사내망·공개 주소와 모델, 응답 중·열린 대화·슬롯 수가 보이고 붐빌 때는 응답이 느릴 수 있다고 알려 줍니다.

사내 LLM 대화는 이 PC에 Claude 로그인이 없거나 개인 Claude 사용을 꺼 두었어도 시작하고 이어갈 수 있고, 사내 LLM의 인증 오류에 Claude 로그인 안내가 뜨지 않습니다. 사내 LLM 대화는 PC의 Claude 로그인이나 조직 계정으로 넘어가지 않으며, 시작하거나 이어가지 못하면 다른 연결로 바꾸는 대신 그 이유를 보여 줍니다.

#### 사용 방법

조직의 내 전용 작업PC에서 새 대화를 열고 AI를 Claude로 고른 뒤, 입력창의 모델 메뉴(Claude Code) 맨 아래 사용 연결에서 사내 LLM을 고르고 첫 메시지를 보냅니다. 고르면 모델 메뉴 버튼이 "Claude Code · 사내 LLM · 이름"으로 바뀝니다. 사내 LLM은 조직 관리자가 웹에서 등록하고 배정해야 목록에 나옵니다. 시작한 대화의 연결은 바꿀 수 없으니 다른 연결이 필요하면 새 대화를 시작해 주세요.

### 설정에서 폴더나 드라이브 전체를 허용해 그 안에서 대화할 수 있어요

홈 폴더 밖의 경로는 새 프로젝트를 만들다 "이 폴더는 열 수 없어요" 안내가 나올 때만 하나씩 허용할 수 있었고, 드라이브 전체는 허용할 수 없었습니다. 또 허용한 폴더라도 그 안에서 새 대화를 시작하거나 대화에 폴더를 더하면 막혔습니다. 이제 설정에서 폴더를 직접 고르거나 C 드라이브, D 드라이브처럼 드라이브 전체를 허용할 수 있고, 허용한 경로에서는 대화를 시작하고 이어갈 수 있습니다. macOS에서는 허용한 경로에 AI가 쓸 때 대화마다 승인하지 않아도 됩니다. 드라이브를 허용하면 같은 계정으로 연결된 다른 기기에서도 그 드라이브에 접근할 수 있으니 필요한 드라이브만 허용하세요.

#### 사용 방법

내 설정 → 개발 → 작업PC → 이 PC에서 허용한 경로에서 경로 추가를 누르고, 폴더 선택…으로 폴더를 고르거나 목록의 드라이브를 누른 뒤 허용을 누르세요. 같은 목록에서 허용 취소를 누르면 다시 막힙니다.

### 파일 트리 검색이 내용까지 찾고, 대화 찾기에 대/소문자 구분과 Enter 이동이 생겼습니다

파일 트리 검색란에서 Enter를 누르면 프로젝트 전체의 파일 이름과 함께 파일 내용도 찾아, 결과를 파일별로 묶어 줄 번호와 일치 수, 강조된 검색어와 함께 보여 줍니다. 줄을 누르면 그 줄에서 파일이 열립니다. 검색 중에도 검색란 오른쪽 아이콘으로 결과 묶음과 폴더를 한꺼번에 접고 펼 수 있습니다. 대화 내 찾기에는 대/소문자 구분 버튼이 생기고, 결과가 보이면 Enter는 더 새로운 결과로, Shift+Enter는 더 이전 결과로 이동합니다.

#### 사용 방법

파일 트리 검색란에 입력하고 Enter → 파일별 결과에서 줄을 누르세요. 접기·펼치기는 검색란 오른쪽 아이콘입니다. 대화에서 Cmd+F(Windows는 Ctrl+F) → 입력 후 Enter, 이어서 Enter·Shift+Enter로 이동하고 대/소문자는 입력란 오른쪽 버튼으로 켭니다.

## 변경된 기능

### 개인 계정 사용 허용을 끄면 개인 계정 영역을 숨겨요

AI 사용량의 Claude 탭에서 "이 PC에서 개인 계정 사용 허용"이 꺼져 있으면, 선택할 수 없는 개인 계정 목록과 안내 문구를 더 이상 보여 주지 않아요. 지금 대화가 개인 계정으로 실행 중이면 조직 계정으로 돌아갈 수 있도록 "조직 계정으로 돌아가기"만 남겨요.

#### 사용 방법

입력창 아래 AI 사용량 → Claude 탭에서 "이 PC에서 개인 계정 사용 허용"을 켜면 개인 계정 영역이 다시 나타나요.

### 내 설정 맨 아래에서 앱 정보를 바로 찾기

내 설정의 `정보` 메뉴 이름을 `Saycode 정보`로 바꾸고 사이드바 맨 아래에 고정했습니다. 오른쪽에 현재 앱 버전이 함께 보이고, 일반·개발 어느 쪽을 보고 있어도 같은 자리에 있습니다.

#### 사용 방법

내 설정을 열고 사이드바 맨 아래의 `Saycode 정보`를 누르면 앱 버전, 업데이트 확인, 문제 해결을 볼 수 있습니다.

### 대화 속 회색 상자를 더 밝게

대화에서 도구 실행 결과, 코드 블록, 생각 과정, 작업 결과, 인라인 코드, 승인·권한 요청 카드의 회색 면이 짙게 보이던 문제를 고쳤습니다. 이제 입력창 위 git 상태 바와 같은 밝은 회색을 씁니다. 회색 상자 안에서 마우스를 올린 항목은 흰색으로 표시됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 버튼·스위치·입력칸 모양을 한 가지로 맞추고 파란 테두리를 옅은 면으로 바꿈

화면마다 조금씩 달랐던 켜기/끄기 스위치, 보기 전환 칸, 버튼, 아이콘 버튼, 입력칸, 뱃지, 메뉴, 창의 모서리·높이·글자 크기를 웹 Saycode와 같은 모양 하나로 맞췄습니다. 글자 버튼은 둥근 알약 모양이고, 창 아래의 취소 같은 보조 버튼과 창 바깥에는 옅은 테두리가 다시 보입니다. 키보드로 이동하거나 항목을 고를 때 나타나던 굵기가 제각각인 파란 테두리 대신 옅은 파란 면으로 표시하고, 글을 입력하는 칸은 대화 입력창처럼 얇고 옅은 파란 선으로 표시합니다. 고대비 설정을 켜면 테두리 표시를 그대로 씁니다. 버튼과 기능은 그대로이고 모양만 바뀝니다. 내 설정 › Saycode 정보의 디자인 가이드도 새 기준으로 고치고 겹치던 항목을 합쳐 짧게 정리했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 변경된 파일 목록을 한 장짜리 카드로 정리

AI 답변 아래의 변경된 파일 목록이 짙은 회색 상자 대신 흰 카드 한 장으로 바뀌었습니다. 카드 머리줄에 변경된 파일 수와 전체 줄 수, `이 턴 변경 보기` 버튼이 함께 있습니다. 파일 행은 폴더를 흐리게, 파일 이름을 진하게 보여 줍니다. 파일 행과 `N개 파일 더 보기` 줄은 마우스를 올리면 줄 전체가 밝아집니다. 행마다 보이던 `리뷰` 버튼은 그 행에 마우스를 올리거나 키보드로 이동했을 때만 나타납니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 카드 머리줄을 누르면 파일 목록이 접히거나 펼쳐지고, 파일 행을 누르면 지금처럼 변경 내용이 열립니다.

### 사이드바에서 PR 상태를 색으로 표시

사이드바 대화 줄 오른쪽의 작업트리 아이콘이 연결된 PR 상태에 따라 색이 바뀝니다. PR이 열려 있으면 초록, 병합되면 파랑, 병합 충돌이 있으면 빨강입니다. 입력창 위 git 상태 바의 PR 표시와 같은 색이라 대화 목록에서 바로 상태를 알 수 있습니다. PR이 없거나 닫힌 대화는 지금처럼 회색입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 충돌 표시는 사이드바가 PR 상태를 확인한 열린 PR에만 나타납니다.

### 생각 과정 줄을 웹과 같은 모양으로

대화의 `생각 과정 보기` 줄이 웹 채팅과 같은 모양이 되었습니다. 앞의 점이 잘 보이는 6px 원으로 커졌고, 줄 글자는 작고 흐리게 바뀌었습니다. 마우스를 올리면 진해집니다. 펼친 생각 내용은 얇은 테두리가 있는 밝은 회색 상자 안에 작은 흐린 글자로 보여 답변과 쉽게 구분됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 작업PC 목록 줄을 간단하게 정리

내 설정 › 개발 › 작업PC 목록의 각 줄에는 이름, 연결 상태, 운영체제와 마지막 활동, CPU·메모리·디스크 사용량만 세로 가운데에 맞춰 보입니다. 이름 아래 정보는 한 줄로 보이고 길면 끝을 줄이며, 연결 상태는 줄마다 같은 자리에 있습니다. 사용량은 일반 글씨의 이름과 작은 막대로 촘촘하게 표시합니다. 작업PC ID, 폴더 경로, 소유자와 접근, 연결 프로그램 버전, 등록·백그라운드 프로그램 상태는 작업PC 이름 쪽에 마우스를 올리면 뜨는 카드와 줄의 상세 정보 창에서 확인할 수 있고, ID 복사 버튼은 상세 정보 창으로 옮겼습니다. 줄여 보인 이름과 정보도 그 카드에 전부 나옵니다. 줄의 버튼은 상세 정보, 이름 옆 연필(이름 변경), 오른쪽 끝 휴지통(삭제)만 남기고, PC 공유 설정·다른 PC에서 작업 받기·진단·업데이트·AI CLI 같은 나머지 동작은 줄 오른쪽 더보기(⋮) 메뉴로 옮겼습니다. 없어진 동작은 없습니다. 삭제는 줄 안의 삭제 확인 버튼 대신 확인 창에서 한 번 더 묻습니다.

#### 사용 방법

내 설정 › 개발 › 작업PC에서 확인하려는 작업PC 이름 쪽에 마우스를 올리거나, 그 줄의 상세 정보를 누르세요. 다른 동작은 줄 오른쪽 더보기(⋮)에서 고르세요.

### 저장소가 없는 프로젝트의 저장소 바에 연결 버튼만 남김

코드 저장소가 아직 없는 프로젝트에서는 입력창 위 저장소 바에 `저장소 연결 안 됨` 글자와 `연결하기` 버튼이 함께 보였습니다. 이제 프로젝트 소유자에게는 `저장소 연결하기` 버튼 하나만 보입니다. 버튼에 마우스를 올리면 지금처럼 연결하지 않아도 대화·미리보기를 쓸 수 있다는 안내가 나옵니다. 소유자가 아니어서 연결할 수 없는 사람에게는 지금처럼 `저장소 연결 안 됨`이 보입니다.

#### 사용 방법

입력창 위 저장소 바에서 `저장소 연결하기`를 누르면 프로젝트 설정의 코드 저장소가 열립니다.

### 접은 사이드바가 아이콘만 남아 창 버튼과 겹치지 않아요

사이드바를 접으면 왼쪽 막대의 회색 면과 오른쪽 선이 창 맨 위까지 올라가, macOS의 빨강·노랑·초록 창 버튼 사이를 선이 가로질렀습니다. 이제 접은 막대는 면과 선 없이 아이콘만 남습니다. 대화 화면에서는 맨 위 탭 줄이 창 왼쪽 끝까지 한 줄로 이어집니다. macOS에서는 사이드바 펼치기 버튼이 창 버튼 옆에서 막대 맨 위(창 버튼 바로 아래)로 옮겨져, 대화 탭이 창 버튼 바로 뒤에서 시작해 탭 줄이 더 넓어집니다.

#### 사용 방법

사이드바를 접으세요(Cmd+B). 다시 펼칠 때는 왼쪽 막대 맨 위의 사이드바 펼치기 버튼을 누르거나 Cmd+B를 누릅니다.

### 하단 터미널 탭이 오른쪽 작업 패널 탭과 같은 모양이 돼요

하단 터미널의 탭 줄을 오른쪽 작업 패널의 탭 줄과 같은 모양으로 맞췄습니다. 탭 높이·글자·선택과 마우스를 올렸을 때의 색·닫기 버튼 크기가 같고, 라이트·다크 모드도 같은 색을 따릅니다. 하단 탭은 +로 추가하고 좌우로 끌어 순서만 바꿀 수 있으며, 오른쪽 패널 탭과 달리 끌어서 화면을 나누지는 않습니다.

### AI 사용량 창의 모든 PC 요약은 개발자 기능에서 켠 사용자에게만, 더 볼 것이 있을 때만 나타납니다

AI 사용량 창의 "모든 PC" 요약("계정별 사용량" 포함)은 PC가 두 대 이상이면 항상 나타나서, 조직 계정만 쓰는 경우에는 바로 아래 계정 목록과 같은 내용을 한 번 더 보여 주곤 했습니다. 이제는 개발자 기능 설정의 "모든 PC 사용량 보이기"(기본 꺼짐)를 켠 사용자에게만 보이고, 켜도 다른 PC에 이 PC 목록에 없는 계정이 있고 그 계정의 사용량이 확인될 때만 그 AI 탭에 나타납니다. 여러 PC에서 함께 쓰는 조직 계정만 있으면 요약 없이 이 PC의 계정 목록만 보입니다.

사용량 수치가 없는 계정은 "계정별 사용량" 막대 칸과 계정 수, "같은 계정인지 확인할 수 없어…" 안내에서 뺍니다. 입력창에 /usage만 보냈을 때 붙는 모든 PC 요약도 같은 기준을 따릅니다.

#### 사용 방법

내 설정의 개발자 기능 설정에서 "모든 PC 사용량 보이기"를 켭니다.

### AI 사용량에서 고른 조직 계정이 지금 대화에도 바로 적용됨

AI 사용량 창에서 다른 조직 Claude 계정을 고르면 이제 새 대화뿐 아니라 보고 있는 대화도 그 계정으로 이어집니다. 쉬고 있는 대화는 바로 바뀌고, 응답 중인 대화는 그 응답이 끝난 뒤 다음 응답부터 바뀝니다. 바뀌는 동안 계정 행에 `다음 응답부터 적용`이 보이고, 대화에는 계정을 전환했다는 안내 한 줄이 남습니다. 그 계정을 지금 쓸 수 없으면 대화는 그대로 두고 새 대화에만 적용한다고 알려 줍니다. 이전 버전 실행 도구로 실행 중인 대화, 개인 계정으로 실행 중인 대화, 공용 PC의 대화는 지금처럼 새 대화에만 적용됩니다.

#### 사용 방법

조직 계정으로 대화 중인 화면에서 입력창 아래 AI 사용량 버튼을 누르고, 조직 계정 목록에서 쓰려는 계정을 누르세요. 목록에 없으면 다른 조직 계정 N개를 펼쳐 고릅니다.

### PR 지킴이가 GitHub가 막고 있는 PR의 처리를 대화에 요청

#### 사용 방법

### PR 지킴이의 머지 가능 알림이 GitHub의 머지 차단이 풀린 뒤에 옴

### Windows 업데이트가 바뀐 부분만 받아 재시작이 훨씬 빨라집니다

설치하느라 재시작부터 새 창이 뜰 때까지 수 분이 걸렸습니다. 이제 새 버전이 바뀐 부분만 담은 작은 파일(보통 수 MB)을
받아, 앱을 쓰는 동안 설치 폴더 옆에 새 버전을 미리 만들어 둡니다(그동안 업데이트 카드에는 "업데이트 준비 중"이 보입니다). "재시작해서 업데이트"를 누르면 폴더만 바꿔 끼우고
바로 새 버전을 실행합니다. 받은 파일과 새 버전은 모두 서명과 해시로 확인하며, 준비나 전환이 실패하면 이전 버전을 그대로
두고 지금처럼 설치 파일로 업데이트합니다. 이 방식은 이 버전 다음 업데이트부터 적용됩니다.

### 같은 커밋에서 검사가 다시 돌아도 PR CI 상태가 실패로 남지 않음

라벨을 붙이거나 Draft를 검토 준비로 바꾸거나 실패한 job을 다시 돌리면, 같은 커밋에서 검사가 새로 돕니다. 이때 앞선 실행의 취소·실패 결과가 함께 남아, PR 카드와 PR 지킴이가 새 검사가 통과해도 그 PR을 CI 실패로 보고 수정 지시를 보낼 수 있었어요. 이제는 같은 워크플로의 같은 이름 검사는 가장 최근 것만 셉니다.

#### 사용 방법

### 대화를 열 때 파일 복원지점 오류 토스트가 잠깐 떴다 사라지지 않습니다

대화를 열 때 작업PC에서 파일 복원지점 상태를 처음 읽지 못하면, 입력창 위에 `파일 복원지점을 불러오지 못했어요` 토스트가 잠깐 떴다가 8초 뒤 사라졌습니다. 상태를 모르면 복원할 수 있는 것도 없어 이 알림은 눈길만 끌었습니다. 이제 첫 조회가 실패하면 알림 없이 패널을 숨기고, 다음 조회에 성공하면 접힌 패널이 나타납니다. 한 번 읽은 뒤의 재조회 실패는 지금처럼 패널 안에서 알려 줍니다.

#### 사용 방법

별도 조작은 없습니다. 패널이 보이지 않으면 응답이 시작되거나 끝날 때 다시 확인하며, 바로 확인하려면 다른 대화로 갔다가 돌아오세요.

### 라이트 모드 하단 터미널에서 검은 화면과 어두운 선이 보이지 않아요

라이트 모드에서 하단 터미널을 열면 처음에 잠깐 검은 화면이 보이고, 탭 줄 아래 터미널 위쪽에 어두운 가로선이 남던 문제를 고쳤습니다. 터미널 바탕이 처음부터 밝은 색으로 칠해집니다. 다크 모드와 오른쪽 작업 패널의 터미널은 달라지지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 명령 실행 결과와 내부 지시문이 내 메시지처럼 보이던 문제를 고쳤습니다

`/compact`(대화 요약)나 `/model` 같은 명령을 실행하면 `<local-command-stdout>Compacted …` 같은 실행 결과와 훅 명령 원문이
파란 내 메시지 말풍선으로 길게 표시되던 문제를 고쳤습니다. 요약 완료 결과는 더 이상 보이지 않고, `Set model to …`처럼
알아둘 만한 명령 결과는 조용한 안내 한 줄로 보입니다. 응답을 멈췄을 때 남던 `[Request interrupted by user]` 표시도
내 메시지로 보이지 않습니다.

보관된 Codex 대화를 이어가거나 앱 밖 Codex 대화를 가져올 때 지난 내 메시지 앞뒤에 붙어 보이던 Saycode 턴 지시문·프로젝트
레슨 참고와 제목 지정 지시도 걷어냅니다(기억 참고 블록이 붙은 메시지는 그 부분이 남을 수 있습니다). 이미 이렇게 표시되던 지난 대화에도 적용됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 실행기 재시작을 기다리는 요청이 다른 대화로 옮겨도 사라지지 않아요

작업PC 실행기가 다시 시작하는 동안 보낸 요청은 "실행기 재시작 중 — 끝나면 자동으로 시작"으로 기다렸다가 한 번 자동으로 보내집니다. 그런데 기다리는 사이 다른 대화를 보고 오면 아무 표시 없이 자동 시작이 취소돼, 돌아와서도 보내졌는지 알 수 없었습니다. 이제는 다른 대화로 옮겨도 기다림이 이어지고, 보고 있지 않은 대화를 대신 보내지는 않습니다. 끝난 프로젝트 대화로 돌아왔을 때 실행기가 다시 요청을 받고 있으면 그때 한 번 보냅니다. 기다릴 시간이 지난 뒤 돌아오거나, 끝난 Chat에서 다른 Chat에 갔다 오면 "보내지 않았어요 — 실행기 재시작을 기다리는 동안 다른 곳에 있었어요"가 보이고 입력한 내용은 그대로 남아 있습니다.

#### 사용 방법

재시작을 기다리는 동안 다른 대화를 봐도 됩니다. 돌아왔을 때 "보내지 않았어요" 줄이 보이면 줄 오른쪽의 지금 보내기를 누르거나, 안내 닫기(X)로 닫으세요.

### 앱 안 브라우저에서 새 탭으로 여는 링크를 기본 브라우저로 열 수 있습니다

앱 안 브라우저에서 새 탭이나 새 창으로 열리도록 만든 링크(예: "Learn more" 같은 도움말 링크)를 눌러도 아무 일도 일어나지 않던 문제를 고쳤습니다. 이제 브라우저 위에 `이 페이지가 새 창을 열려고 해요: (사이트 주소)` 줄이 뜨고, `기본 브라우저에서 열기`를 누를 때만 이 컴퓨터의 기본 브라우저에서 열립니다. 페이지가 클릭 없이 새 창을 열려고 해도 묻기 전에는 아무것도 열리지 않습니다. 같은 창에서 이동하는 링크는 지금처럼 앱 안 브라우저에서 열립니다.

#### 사용 방법

새 탭으로 열리는 링크를 누른 뒤 브라우저 위에 뜬 줄에서 `기본 브라우저에서 열기`를 누르세요. 열지 않으려면 `닫기`를 누르거나 다른 페이지로 이동하면 됩니다.

### 업데이트 다운로드가 네트워크 문제로 끊겨도 자동으로 다시 받습니다

업데이트 파일을 받는 도중 네트워크 연결이 끊기거나 업데이트 서버가 잠시 응답하지 않으면, 지금까지는 바로
"업데이트하지 못했어요"로 끝나서 처음부터 다시 눌러야 했습니다. 이제 이런 경우에는 잠시 기다렸다가 두 번까지
자동으로 다시 받습니다. 그래도 받지 못하면 그때 실패를 알려 드립니다. 끊긴 지점부터 이어서 받지는 않고 처음부터 다시 받습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 조직에서 허용한 OpenCode를 정상적으로 선택

조직이나 사용자 정책에서 OpenCode를 허용해도 AI 목록에서 사라지거나 무료 모델이 차단되던 문제를 수정했습니다. 별도 정책이 없는 조직·개인 사용자는 기본으로 OpenCode를 사용할 수 있으며, 명시적인 제한 정책은 유지됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. OpenCode 무료 모델은 내 설정 → AI Models → opencode에서 설치하거나 다시 확인할 수 있습니다. 무료 모델의 제공 기간과 한도는 공급사 조건을 따릅니다.

### 파일 보기 버튼이 겹쳐 보이던 문제 수정

변경 내용이나 파일을 여러 개 열면 위쪽 줄의 나란히 보기·변경 보기 버튼이 연 파일 수만큼 겹쳐 보이던 문제를 고쳤습니다. 이제 지금 보고 있는 파일의 버튼만 한 벌 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 파일 복원지점을 쓰지 않는 대화에서 '보호되지 않음' 패널이 깜빡이지 않습니다

파일 복원지점을 켜지 않은 대화에서도 입력창 위 오른쪽에 `파일 복원지점 · 보호되지 않음`이 잠깐 나타났다 사라지기를 반복했습니다. 대화를 열 때, 응답이 시작되거나 끝날 때처럼 상태를 다시 확인할 때마다 생겼습니다. 이제 기록이 없는 대화는 다시 확인하는 동안에도 패널이 나타나지 않습니다. 조회에 실패한 뒤 새로고침으로 다시 확인할 때는 지금처럼 결과가 나올 때까지 패널을 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 파일 트리를 연 채 파일을 고르기 전 화면이 파일 트리 밑으로 넓어지지 않습니다

작업 패널의 파일·변경 탭에서 파일 트리를 열어 두면, 파일을 고르기 전의 "파일 열기" 안내가 프로젝트 경로가 길 때
파일 트리 밑까지 넓게 잡혀 가운데가 오른쪽으로 밀리고 경로가 트리 경계에서 잘렸습니다. 이제 안내는 파일 트리를 뺀
파일 보기 너비 안에서 가운데 정렬되고, 긴 경로는 끝이 말줄임표로 줄어듭니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### Claude 구독 계정의 원본 PC 갱신 안내

원본 PC가 인증을 갱신하는 Claude 구독 계정에서 인증 오류가 발생하면, 원본 PC의 연결 상태를 확인하도록 안내합니다. 이 PC의 로그인 복구로 잘못 연결되지 않습니다.

#### 사용 방법

안내가 나타나면 원본 PC가 켜져 있고 Saycode에 연결돼 있는지 확인한 뒤 다시 보내 주세요. 갱신 담당 방식은 지원하는 작업PC와 서버가 준비된 뒤 적용됩니다.

### Mac에서 Codex 계정 변경이 실패하던 문제 수정

Mac에서 사용량 창의 다른 Codex 계정을 선택하면 계정 목록은 보이는데도 "계정 변경에 실패했어요. 다시 선택해 주세요."가 나오던 문제를 고쳤습니다. 이제 계정 목록을 읽을 때와 같은 위치의 Codex 계정 관리 도구로 계정을 바꿉니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 사용량 창의 Codex 탭에서 바꿀 계정을 선택하세요.

### saycode 플랜 사용량이 실제로 적용되는 한도만 보여 줍니다

월 한도 하나만 쓰는 조직 플랜에서 사용량 창에 쓰지 않는 `이번 주`·`5시간` 줄이 0%로 보이고, 사용 연결 선택에는 이번 주 남은 사용량이 늘 100%로 보이던 문제를 고쳤습니다. 이제 이런 조직은 `이번 달` 한 줄만 보이고, 남은 사용량도 이번 달 기준으로 보입니다. 한도가 아니라 조직 계약 상태 때문에 플랜을 쓸 수 없을 때는 "한도에 도달했어요" 대신 관리자에게 문의하라는 안내가 나옵니다.

상위 모델(Terra·Sol)이나 Astra로 대화할 때는 그 모델의 이번 주 사용량 줄이 함께 보여, 다른 막대가 남아 있는데 한도로 표시되는 이유를 알 수 있습니다.

#### 사용 방법

대화 입력창 아래 `saycode 플랜` 버튼을 누르면 사용량을 볼 수 있습니다. 별도 설정 없이 자동 적용됩니다.

### Windows에서 실행기가 켜져 있어도 "재시작해서 업데이트"가 진행됩니다

Windows에서 이 PC를 작업PC로 쓰는 중에 "재시작해서 업데이트"를 누르면, 약 20초 뒤
`Still running from the install directory: … node.exe` 문구가 나오며 업데이트가 멈추는 문제가 있었습니다.
이 PC의 실행기와 실행기가 띄운 대화는 Saycode에 들어 있는 Node로 돌아가는데,
업데이트 전 정리 단계가 이 프로세스들을 끝내지 않았기 때문입니다.

이제 업데이트가 이 프로세스들을 직접 끝내고 설치를 이어 갑니다. 진행 중이던 AI 응답은 업데이트 때 중단되고,
새 버전이 열리면 실행기가 다시 시작됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 이 수정이 들어간 버전으로 올라간 뒤의 업데이트부터 적용됩니다.
그 전 버전에서 같은 문구가 나오면 작업 관리자에서 Saycode 폴더의 `node.exe`를 끝낸 뒤 다시 눌러 주세요.
