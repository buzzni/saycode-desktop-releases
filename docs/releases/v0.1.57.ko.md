## 새 기능

### 데스크톱에 조직 AI 모델 정책 적용

조직 또는 멤버에게 적용된 AI 모델 정책을 데스크톱의 모델 선택창과 기본값에 반영합니다. 허용된 수동 선택은 유지하고 자동 선택이나 허용되지 않은 선택은 사용 가능한 정책 기본값으로 바꿉니다. 정책 조회가 지연되거나 실패해도 기존 선택 또는 마지막 유효 정책을 유지하며 백그라운드에서 다시 확인합니다.

#### 사용 방법

조직에 로그인한 뒤 대화·프로필·리뷰·자동화의 AI 및 모델 선택창을 사용하세요. 조직 정책은 자동으로 반영됩니다. 기존 대화의 AI는 유지하며, 정책상 허용된 모델이 이 컴퓨터에 없을 때는 선택 불가 안내가 표시됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1545)

### 보낸 첨부 자료를 대화에서 다시 확인하고 저장

Chat과 Project 대화에 보낸 파일을 원래 이름으로 표시하고, 이름을 눌러 열거나 다운로드 아이콘으로 내 PC에 저장할 수 있습니다. 폴더는 파일 탐색기로 열립니다. 파일 접근 실패에는 짧은 안내와 재시도를 제공하며 저장 알림이 대화 내용을 가리지 않도록 개선했습니다.

#### 사용 방법

파일을 첨부해 메시지를 보내고, 대화에 표시된 파일명을 눌러 내용을 확인하세요. 옆의 다운로드 아이콘으로 저장할 수 있습니다. 원래 이름이 기록되지 않은 이전 첨부는 기존 저장 이름으로 표시됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1528)

## 수정된 문제

### 다시 연 Chat에서 같은 AI로 대화 이어가기

앱 재시작이나 Chat 재진입 시 실제 대화의 AI를 확인해 모델 선택과 후속 질문에 사용합니다. 확인 중에는 질문·첨부를 유지하며 전송을 기다립니다. 확인 실패 시 입력창의 `다시 확인`으로 복구합니다. 유효한 수동 모델 선택을 유지하고 다른 AI의 모델이 전송되는 것을 막습니다.

#### 사용 방법

기존 Chat을 다시 열고 후속 질문을 보내세요. AI 확인에 실패했다면 작성한 질문을 그대로 둔 채 `다시 확인`을 누르고, 확인이 끝난 뒤 직접 전송하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1534)

### 다시 연 Chat의 AI 모델 복원 오류 수정

Codex로 시작한 Chat을 다시 열었을 때 다른 AI의 모델이 선택되어 전송에 실패하던 문제를 수정했습니다. 대화의 AI 정보를 확인한 뒤 해당 AI에 맞는 모델을 표시하고 전송합니다. 확인에 실패하면 입력창 위에 짧게 안내하며 작성한 질문은 유지됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. AI 정보 확인에 실패하면 작성한 질문을 다시 전송해주세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1531)

### 답변 중단 뒤 채팅 입력을 다시 사용할 수 있습니다

답변이 끝났는데도 채팅이 계속 작업 중으로 표시되거나 중지 버튼이 응답하지 않아 새 메시지를 보낼 수 없던 문제를 수정했습니다. 중단 요청이 응답하지 않는 경우에도 잠시 후 채팅 입력을 다시 사용할 수 있으며, 원격 중단을 확인하지 못한 경우에는 안내를 표시합니다.

#### 사용 방법

답변 중 `중지`를 누르세요. 작업PC 또는 연결 상태 때문에 중단 확인이 늦거나 실패해도 채팅 입력은 잠시 후 다시 활성화됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1547)

### 답변이 끝난 뒤 입력한 메시지를 바로 보냅니다

답변이 화면에 표시된 직후 입력한 후속 메시지가 대기열에 남지 않고 바로 전송됩니다. 답변 종료 신호와 화면 동기화 순서가 달라도 프로젝트 대화와 개인 채팅에서 같은 동작을 합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 답변이 끝난 뒤 입력창에 메시지를 입력하고 보내면 바로 다음 요청으로 전송됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1530)

### 사라진 첨부를 교체해 같은 요청을 이어갑니다

누락된 파일이나 폴더를 AI 연결 설정에서 직접 교체할 수 있습니다. 업로드만으로 요청을 보내지 않으며 문서 지침과 다른 첨부, 작성 중 새 초안을 유지합니다.

#### 사용 방법

파일 교체 또는 폴더 교체를 눌러 다시 첨부한 뒤 같은 요청 다시 시도를 누르세요. 취소나 업로드 실패는 기존 요청을 유지합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1544)

### 사용할 수 없는 모델의 오류 안내 개선

Chat과 Project에서 지원하지 않는 모델 오류를 연결 오류와 구분해 안내합니다. 모델을 변경한 뒤 직접 다시 시도할 수 있고, 오류 원문은 접힌 상세에서 확인할 수 있습니다. 예전 오류 기록에도 같은 안내를 적용합니다.

#### 사용 방법

사용할 수 없는 모델 안내가 나오면 입력창에서 다른 모델을 선택한 뒤 오류 아래의 `다시 시도`를 누르세요. 원래 질문을 선택한 모델로 다시 보냅니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1534)

사이드바의 Chat·Project 목록 글자를 키워 대화와 프로젝트 이름을 더 쉽게 읽을 수 있게 했습니다.

#### 사용 방법

사이드바에서 Chat 또는 Project 탭을 선택하면 커진 제목을 볼 수 있습니다. 이름을 변경할 때도 같은 글자 크기를 사용합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1526)

### 시작준비에서 전체 도구 상태 확인

시작준비에서 선행 도구와 AI 도구 7개의 상태·순서를 함께 확인할 수 있습니다. 실행되지 않는 선행 도구를 준비 완료로 처리하지 않고, 각 도구의 정보 아이콘에서 실패 단계·오류와 조치·설치 안내를 확인하고 진단 정보를 복사할 수 있습니다.

#### 사용 방법

시작준비의 도구 준비 상세를 열어 상태를 확인하세요. 실패하면 같은 화면에서 다시 시도를 누릅니다. 정보 아이콘에서 상세 오류와 설치 안내를 확인하세요. 필요한 선행 도구를 직접 설치하는 환경에서는 안내대로 준비한 뒤 다시 시도합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1539)

### 예약 작업을 쉽게 만들고 실행 상태 확인하기

새 예약은 이미 선택한 작업PC 또는 준비된 이 컴퓨터를 자동으로 사용하고 다른 PC 선택은 세부 설정에 모았습니다. 실행할 수 없는 PC의 새 예약 저장을 막고 준비 화면을 제공합니다. 첫 실행 전 대화에도 지정된 PC를 표시하며 예약 화면으로 바로 돌아갈 수 있습니다. 지금 실행으로 예약을 시험하고, 요청 접수·PC 전달·첫 실행 대기·최근 실행 결과를 구분해서 확인할 수 있습니다.

#### 사용 방법

예약 작업에서 새 예약을 누르고 할 일과 시간을 입력하세요. 준비가 필요한 경우 이 컴퓨터 준비를 선택하고, 다른 PC나 기존 대화는 세부 설정에서 고르세요. 목록의 지금 실행과 대화 보기에서 실제 실행 결과를 확인하세요. 전체 실행 이력은 더보기에 있고 일시정지한 예약은 목록에서 바로 재개할 수 있습니다. 매일 예약은 실행 PC의 시간대를 기준으로 입력하세요. 실행 PC에 AI가 연결돼 있어야 작업이 시작됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1535)

### 응답이 끊긴 요청의 중복 실행을 방지합니다

전송 응답이 끊기거나 접수 번호가 없으면 서버의 접수 여부를 확인합니다. 확인하지 못한 같은 요청을 다시 시도할 때 기존 요청 ID를 유지해 중복 접수를 막습니다. 작성 중 초안은 유지합니다.

#### 사용 방법

전송 실패 안내 뒤 같은 요청 다시 시도를 누르세요. 접수가 확인된 경우에는 새 요청을 자동으로 보내지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1543)

### 조직 선택 후 연결 중임을 안내합니다

시작할 때 조직을 선택한 뒤 나타나는 안내를 `조직 변경 중...`에서 `조직에 연결 중…`으로 바꿨습니다. 첫 조직 선택과 이후 조직 전환에 같은 안내를 사용하며 연결 완료·실패 처리와 로딩 표시 모양은 유지합니다. 영어·일본어·중국어 안내도 함께 반영했습니다.

#### 사용 방법

로그인 후 조직을 선택하면 연결이 끝날 때까지 화면 중앙에서 진행 상태를 확인할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1526)

### AI 연결 복구 후 같은 요청을 다시 시도합니다

AI 오류를 해결한 뒤 원래 질문과 첨부를 보존해 다시 시도합니다. 첨부를 확인하지 못하면 전송을 멈추고 해당 파일을 안내합니다. 작성 중인 새 초안과 첨부는 유지하며, 재시도 중 전송이 실패해도 복구 화면에서 다시 시도할 수 있습니다.

#### 사용 방법

실패한 답변의 AI 연결 설정에서 연결을 확인한 뒤 `같은 요청 다시 시도`를 누르세요. 첨부가 없어졌다면 다시 첨부하고, PC 연결이나 접근 권한 문제라면 표시된 안내에 따라 해결한 뒤 재시도하세요. 원래 질문을 찾을 수 없는 오류에서는 재시도 버튼을 표시하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1532)

### AI 질문에 답변한 뒤 요청을 다시 시도합니다

확인 질문에 답변하는 동안 같은 요청의 재시도와 계정 변경을 막습니다. 연결 상태 확인과 오류 상세 보기는 유지합니다. 이미 답변한 질문의 오래된 상태는 새 요청을 막지 않습니다.

#### 사용 방법

AI 연결 설정에 질문 대기 안내가 보이면 창을 닫고 AI 질문에 답변한 뒤 다시 시도하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1542)

### PC 연결 확인의 다음 행동을 분명하게 안내합니다

PC 연결 확인 화면에서 다음을 누를 수 있는 상태를 빈 원 대신 파란 체크로 안내합니다. 체크는 연결을 진행할 준비가 되었음을 뜻하며 기존 `다음` 버튼과 연결 설명은 유지합니다.

#### 사용 방법

`PC 연결 확인` 화면에서 `다음`을 누르면 연결을 시작합니다. 확인 전에는 자동으로 연결되지 않으며 오류가 발생하면 기존 정보 버튼에서 상세를 확인할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1526)

### PC 온라인 확인 실패 후 같은 PC로 복구합니다

PC 연결 확인에서 로컬 실행 도구는 응답하지만 서버가 이 PC를 온라인으로 확인하지 못하면, 같은 PC 등록 신원으로 실행 도구를 다시 시작해 연결을 복구합니다. 온라인 확인에 계속 실패하면 오류 상세에 `SETUP_MACHINE_ONLINE_TIMEOUT`, PC 등록·온라인 확인 단계와 다음 조치를 표시합니다.

#### 사용 방법

실패 시 네트워크를 확인하고 `다시 시도`를 누르세요. 계속 실패하면 정보 아이콘을 눌러 진단 정보를 복사해 개발자에게 전달할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1526)

### Windows 암호화 로그인 저장 복구

기존 로그인 저장 폴더의 보호가 거부될 때, 현재 Windows 사용자에게 귀속되는 암호화 로그인과 키를 검증하여 보호된 저장 폴더에 복구합니다. 원본과 기존 머신 식별자를 보존합니다. 평문·귀속 미확인·머신 신원 권한 문제는 자동 복구 성공으로 처리하지 않습니다.

#### 사용 방법

검증 가능한 자료는 앱 시작 때 자동 복구됩니다. 여전히 로그인 저장 경고가 표시되면 조직 관리자에게 앱 버전과 오류 진단을 전달하세요. 기존 파일을 삭제하지 마세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1539)

### Windows 업데이트 재시작이 보조 프로세스 때문에 멈추지 않습니다

일부 Windows 환경에서 `재시작해서 업데이트`를 눌렀을 때 앱의 Chromium 보조 프로세스를 남은 실행 중인 프로세스로 잘못 판단해 업데이트가 진행되지 않던 문제를 수정했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 업데이트 알림에서 `재시작해서 업데이트`를 누르면 됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1537)

### Windows 자격증명 저장소 fallback 안정성 강화

Windows에서 회사 보안 정책으로 기존 앱 데이터 폴더에 로그인 정보를 저장하지 못할 때, 보호된 사용자 전용 저장소 fallback을 더 안전하게 선택합니다. 이전 실행에서 남은 빈 폴더가 실제 자격증명 저장소를 가리지 않도록 상태가 있는 저장소를 우선 재사용하고, 두 저장소에 모두 상태가 있으면 자동으로 선택하지 않습니다. ACL 시간 초과나 원인을 확인할 수 없는 오류에서는 다른 저장소로 전환하지 않아 계정 신원이 갈라지지 않게 합니다.

#### 사용 방법

별도 설정 없이 적용됩니다. Windows에서 로그인 저장 경고가 계속 표시되면 앱을 종료하지 말고 회사 보안 정책과 두 보호 저장소의 접근 권한을 확인하세요. 기존 저장소가 모호한 경우 기존 자격증명을 자동으로 덮어쓰거나 이전하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1538)

### Windows에서 컴퓨터 제어 권한 확인이 진행됩니다

Windows에서 `OS 권한 확인`을 실행하면 Cua Driver의 daemon 상태를 확인하고 필요한 경우 자동 시작한 뒤 권한 상태를 검사합니다. Chrome 프로필 조회·연결 명령에는 브라우저 broker가 허용하는 필드만 전달해 브라우저 설정 흐름도 유지합니다.

#### 사용 방법

온보딩 또는 내 설정의 컴퓨터·브라우저 제어 단계에서 `OS 권한 확인`을 누르세요.
