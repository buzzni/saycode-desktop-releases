## 새 기능

### 긴 에이전트 작업의 관측을 이어갈 수 있습니다

지원하는 direct CLI와 서버 조합에서 짧은 대기 호출 사이에 끝난 응답을 같은 기준점과 체크포인트로 다시 찾을 수 있습니다. 대기 시간 초과가 작업 중단을 뜻하지 않으며 결과 구간을 페이지로 읽을 수 있습니다. 관측 모드에서 지원하지 않는 옵션이나 여러 대상을 함께 넣으면 오류를 반환합니다. 잘못된 인자와 이력 접근 거절은 재시도로 풀리지 않는 별도 오류로 알립니다. 현재 broker v1은 명시적으로 미지원 응답을 반환합니다.

#### 사용 방법

whoami에서 resumableObservation v1 능력을 확인한 경우에만 agent wait/read의 after-seq 옵션을 사용합니다. timeout 뒤에는 원래 기준점과 반환된 checkpoint를 유지합니다. 이 기능은 서버 관측 계약 활성화와 호환 CLI가 필요하며 이번 변경만으로 설치판에 활성화되지 않습니다.

### 다른 저장소의 연결된 PR도 지켜보고 상태를 보고받기

대화에 연결된 다른 저장소의 PR도 지켜볼 수 있습니다. Saycode Desktop이 작업PC의 GitHub CLI로 그 PR을 그 저장소에서 직접 읽고, CI 실패·충돌·리뷰 봇 지적이 생기면 대화가 쉴 때 저장소 이름을 밝힌 후속 지시를 보냅니다. 이 프로젝트 저장소가 아닌 PR의 지시는 보고 전용입니다: 그 저장소의 작업 폴더가 아니면 코드를 고치거나 push하지 않고, PR 머지·닫기·코멘트·새 PR 만들기 같은 GitHub 쓰기도 하지 않은 채 상태와 필요한 조치만 알려 줍니다. 작업PC가 그 저장소를 연달아 읽지 못하면 감시가 `저장소 권한 없음`으로 멈춥니다.

#### 사용 방법

입력창 위 PR 버튼(+N)으로 연결된 PR 목록을 열고, 다른 저장소 PR 줄 끝 ⋮에서 지켜보기 시작을 고릅니다. 작업PC의 GitHub CLI가 그 저장소를 읽을 수 있어야 합니다.

### 답변이 안내한 /명령을 눌러 입력창에 넣어요

AI 답변에 `/review`처럼 코드 표시나 링크로 적힌 명령 중 지금 대화에서 쓸 수 있는 명령은 누를 수 있게 표시됩니다. 누르면 입력창에 쓰던 내용 끝에 그 명령이 들어가고 바로 이어서 쓸 수 있습니다. 바로 보내지는 않습니다. 일반 문장 속 /명령, 코드 블록, 이 대화에서 쓸 수 없는 명령은 그대로 둡니다.

#### 사용 방법

프로젝트 대화나 개인 Chat의 답변에서 파란색으로 표시된 /명령을 누르거나, Tab으로 이동해 Enter를 누릅니다. 입력창에 명령이 들어가면 필요한 내용을 덧붙여 보냅니다.

### 대화마다 한 PC가 연결된 PR을 맡아 지켜보기

대화에 연결된 PR을 AI에게 "지켜봐 줘"라고 하거나 목록에서 지켜보기를 켜면, 켜져 있는 Saycode Desktop 하나가 그 요청을 맡아 PR 지킴이로 지켜봅니다. CI 실패·충돌·리뷰 봇 지적이 생기면 대화가 쉴 때 한 번에 하나씩 후속 지시를 보내고, 한 대화가 받는 자동 지시는 모두 합쳐 12번까지이고, 다 써서 멈춘 감시는 목록에서 다시 지켜보기를 누르면 이미 보낸 지시는 빼고 새로 12번을 씁니다. 여러 PC에서 Desktop을 켜 두어도 한 대화의 PR은 한 PC가 모두 지켜보고, 다른 PC는 그 PR로 지시를 보내지 않습니다. 맡은 PC가 30분 넘게 응답하지 않으면 다른 Desktop이 이미 보낸 지시 기록과 함께 이어받습니다. 목록 맨 위에 어느 PC(이 PC·다른 PC)가 지켜보는지와 마지막 확인 시각이 보입니다.

#### 사용 방법

입력창 위 PR 버튼(+N)으로 연결된 PR 목록을 열고, PR 줄 끝 ⋮에서 지켜보기 시작 또는 지켜보기 중지를 고릅니다. 설정의 PR 후속 자동 처리가 켜져 있고 작업PC가 연결된 Desktop이 지켜보기를 맡습니다.

### 대화별 세션 유지 시간 선택

다른 에이전트의 작업을 기다리는 대화에서 실행 세션의 유지 시간을 선택할 수 있습니다. 기본값, 1·4·8·24시간, 자동 종료 안 함을 제공하며 선택한 대화에만 적용됩니다. 이 기능을 지원하는 작업PC 런타임과 본인 소유가 확인된 대화가 필요합니다.

#### 사용 방법

실행 중인 Project 대화의 프로젝트 도구(⋮) 또는 Chat 대화 더보기(⋮) → 세션 유지 시간에서 시간을 선택하고 저장하세요. 자동 종료 안 함은 일반 유휴 종료를 막으며, 직접 종료·보관·권한 철회·운영 제한과 PC/AI 자체 종료에는 적용되지 않습니다.

### 대화에 PR을 여러 개 연결해 입력창 위 PR 버튼에서 모아 봅니다

한 대화에 다른 저장소 PR을 포함해 여러 PR을 연결할 수 있습니다. 연결된 PR이 있으면 입력창 위 PR 버튼의 번호와 상태 배지 뒤에 `+N`이 붙고, 버튼을 누르면 `연결된 PR` 목록이 열립니다. 목록에서 각 PR을 브라우저로 열거나, 이 프로젝트 저장소의 PR은 PR 화면으로 열고, 연결을 해제할 수 있습니다. 다른 저장소의 PR은 여기서 머지할 수 없다는 이유가 함께 보입니다. 연결 목록은 대화에 저장되어 다른 PC의 Desktop에서도 같게 보입니다. AI에게 PR을 지켜봐 달라고 요청했다면 그 요청 상태도 목록에 보이지만, 이번 버전의 Desktop은 연결된 PR을 직접 지켜보지는 않습니다.

#### 사용 방법

프로젝트 대화의 입력창 위 오른쪽 PR 버튼(`+N`)을 누르고, 목록 아래 `PR 연결…`에 `https://github.com/owner/repo/pull/123` 형식의 주소를 붙여 넣은 뒤 `연결`을 누릅니다. 아직 연결된 PR이 없으면 대화 머리글 ⋮ 프로젝트 도구의 `PR 연결…`로 같은 입력 칸을 엽니다. 각 줄 끝 ⋮에서 `PR 화면 열기`·`GitHub에서 열기`·`연결 해제`를 고릅니다. 연결된 PR이 없으면 PR 버튼은 지금처럼 브랜치 PR을 바로 엽니다.

### 대화의 도구 행에서 누가·언제 허용하거나 거절했는지 볼 수 있습니다

승인 요청이 끝난 도구 호출의 행에 `사용자 · 허용 · 3분 전`처럼 결정한 주체(사용자·AI 심사·런타임)와 결정(허용·이 대화에서 허용·거절), 몇 분 전인지가 붙습니다. 마우스를 올리면 정확한 시각과 사유가, 행을 펼치면 거절 사유나 AI 심사 요지가 한 줄로 접혀 보이고 누르면 전체가 보입니다. 응답이 없어 거절된 요청은 펼친 줄에 시각이 보입니다. 새로고침이나 앱을 다시 켠 뒤에도 같은 표시가 남고, AI 심사가 답한 요청은 이 PC에 남은 심사 기록으로 다시 AI 심사로 보입니다.

#### 사용 방법

대화의 도구 행 배지에 마우스를 올리거나 행을 펼친 뒤 접힌 사유를 누릅니다.

### 도구 카드에서 도구가 돌려준 결과 확인하기

프로젝트 대화의 도구 카드를 펼치면 명령 출력, 검색·파일 읽기 결과, 연결 도구의 응답처럼 도구가 돌려준 결과를 결과 · N줄 한 줄로 접어 보여 줍니다. 실패한 결과는 오류 결과로 따로 표시합니다. 누르면 앞뒤 20줄씩 발췌가 열리고, 전체 보기로 저장된 결과 전체를 스크롤해 볼 수 있으며 복사도 됩니다. 비밀번호·토큰처럼 보이는 부분은 가린 뒤 보여 주고 복사합니다. 아주 긴 결과는 앞 6,000자와 뒤 10,000자만 남기고 중간에서 몇 자를 줄였는지 알려 줍니다. 대화 검색에는 결과 내용이 잡히지 않습니다. 새 버전의 작업PC 실행 도구가 결과를 보내야 보이며, 그 전 대화와 이전 버전에서는 카드가 지금과 같습니다.

#### 사용 방법

계정 메뉴 → 개발자 기능 설정에서 도구 결과 보이기를 켭니다(기본 꺼짐). 프로젝트 대화에서 도구 카드를 펼친 뒤 결과 · N줄(실패면 오류 결과 · N줄)을 누르고, 필요하면 전체 보기나 복사 버튼을 누르세요.

### 메시지 보내기 키를 Enter 또는 ⌘Enter(Ctrl+Enter)로 고를 수 있어요

여러 줄을 쓰다가 Enter로 실수로 보내지 않도록, 입력창에서 메시지를 보내는 키를 고를 수 있습니다. 기본값은 지금처럼 Enter로 보내고 Shift+Enter로 줄을 바꾸는 방식입니다. ⌘Enter(Windows는 Ctrl+Enter)로 바꾸면 Enter는 줄바꿈이 되고 ⌘Enter로 보냅니다. 프로젝트 대화·개인 Chat·새 대화 입력창에 모두 적용되고, 한글처럼 글자를 조합하는 중에 누른 Enter로는 보내지 않습니다. ⌘Enter로 보내기를 고르면 AI가 응답하는 동안 다른 방식으로 보내는 키는 ⌘⇧Enter(Ctrl+Shift+Enter)가 되고, 보내기 버튼 안내도 같은 키로 바뀝니다.

#### 사용 방법

내 설정 → 단축키 → 메시지 보내기 키에서 Enter로 보내기 또는 ⌘Enter로 보내기를 고릅니다. 고르는 즉시 이 컴퓨터에 저장됩니다.

### 메신저 연결의 최근 실패와 진단 정보 복사

메신저 연결마다 최근 기록에 남은 실패를 최대 5개까지 확인하고, 같은 기록을 비밀값 없는 진단 정보로 복사할 수 있습니다. 읽기 실패 시 새로고침으로 다시 확인할 수 있습니다.

#### 사용 방법

내 설정 → 일반 → 메신저 채널에서 생성된 연결의 최근 실패를 확인하고 진단 정보 복사를 누르세요.

### 문서 하단 작업 통일과 내 문서에 넣기

문서 하단을 파일명·저장·공개 링크·더보기로 정리했습니다. 공유 권한을 설정하지 않고 문서를 내 문서에 넣을 수 있습니다.

#### 사용 방법

클라우드 계정에서 문서 하단 더보기(…) → 내 문서에 넣기를 누르세요. 저장 후 현재 대화가 유지됩니다.

### 승인 카드가 숨은 문자·자동 처리 이유·MCP 접속 주소를 보여 주고, 거절하며 다른 지시를 보낼 수 있습니다

권한 카드와 준비 스크립트 확인 창이 화면에 보이지 않는 문자(폭 없는 문자·양방향 제어·태그 문자·ANSI 이스케이프·단독 CR)와 명령 끝을 밀어내는 긴 공백·빈 줄을 ⟨U+200B⟩·⟨공백 ×300⟩ 같은 표시로 드러내고, 몇 개를 드러냈는지 한 줄로 알려 줍니다. 이모지·한글·들여쓰기는 그대로 보입니다.

Claude 대화의 권한 카드에 `아니요, 대신 이렇게`가 생겨, 요청을 거절하면서 AI가 대신 할 일을 적어 보내면 같은 응답 안에서 그 지시대로 방향을 바꿉니다.

AI 심사나 이 창에서 보낸 "이 대화에서 허용" 규칙으로 사람에게 묻지 않고 처리된 도구 호출에는 대화의 도구 행에 `자동 허용`/`자동 거절` 표시와 이유(판정 요지·규칙)가 붙습니다. 프로젝트 MCP 서버와 커스텀 커넥터 행은 접속 주소를 비밀값을 가린 채 보여 줍니다.

#### 사용 방법

권한 카드에서 아니요, 대신 이렇게를 누르고 할 일을 적은 뒤 지시하고 거절(또는 Enter)을 누릅니다. 자동 처리 이유는 도구 행의 배지에 마우스를 올리거나 행을 펼쳐 봅니다.

### 실패한 대화를 빨간 점으로 알리고, 읽지 않음으로 표시할 수 있어요

사이드바 대화의 응답이 실패로 끝나면 초록 테두리 점 대신 빨간 마름모 점(`실패함 · 아직 안 열어봄`)이 붙어요. 그 대화를 읽으면 점이 사라지고, 다시 실패하면 또 붙어요. 상태 점은 이제 직접 대화를 읽었을 때만 사라져요 — 그 대화로 들어가거나, 이미 연 대화의 행·탭을 다시 누르거나, 입력창을 누르거나, 메시지를 보낼 때예요. 창으로 돌아오거나 앱을 다시 켜서 마지막 대화가 열린 것만으로는 사라지지 않고, 대화를 열어 둔 채 응답이 끝나도 다음에 조작할 때까지 남아요. 대화 메뉴에 `읽지 않음으로 표시`가 생겨, 다 읽은 대화를 나중에 다시 보도록 되돌릴 수 있어요. 기다리는 대화로 점프(Cmd/Ctrl+Shift+J)와 빠른 열기의 `완료·미확인`도 사이드바 점과 같은 기준을 써요.

#### 사용 방법

프로젝트 대화에 마우스를 올리고 점 세 개 버튼 → `읽지 않음으로 표시`를 누르세요. 상태순 정렬과 `안 열어본 완료 대화` 필터에서 실패한 대화도 함께 찾을 수 있어요.

### 앱 밖에서 시작한 Codex 대화도 이어가기

`앱 밖에서 시작한 대화 이어가기` 목록에 터미널이나 Codex 앱에서 이 프로젝트 폴더로 돌린 Codex 대화도 함께 보입니다. 줄마다 Claude·Codex 표시와 Codex 대화의 메시지 수가 붙고, 이어가면 그 Codex 대화를 그대로 잇는 앱 대화가 시작됩니다. 한 번 가져온 Codex 대화는 다시 보이지 않습니다. 작업PC의 Saycode CLI가 오래돼 Codex 대화를 이어갈 수 없으면 이유를 알려 주고 읽기 전용으로 최근 메시지를 볼 수 있습니다.

#### 사용 방법

프로젝트 대화의 `프로젝트 도구`에서 `앱 밖에서 시작한 대화 이어가기`를 여세요. Codex 표시가 있는 줄의 `이어가기`를 누르면 앱에서 이어집니다. `읽기 전용으로 보기`가 보이는 줄은 눌러 최근 메시지를 확인하고, 다시 눌러 닫으세요.

### 앱 안 PR 파일 탭에서 쓴 리뷰 코멘트 초안을 GitHub 리뷰 하나로 한 번에 제출할 수 있습니다

PR 화면 파일 탭에 리뷰 제출 단추가 생겼습니다. 이 PC에 써 둔 줄·범위·파일 코멘트 초안을 리뷰 하나로 묶어 GitHub에 한 번에 올리며, 리뷰 종류(코멘트·승인·변경 요청)와 리뷰 본문을 함께 정할 수 있습니다. 코멘트는 모두 함께 올라가거나 하나도 올라가지 않아 일부만 올라간 상태가 생기지 않습니다. 제출 창은 작업PC에 로그인된 GitHub 계정(@계정)을 먼저 보여 주고, 제출 직전에 PR에 새 커밋이 올라왔거나 GitHub에 제출하지 않은 내 리뷰가 있으면 아무것도 올리지 않고 멈춰 이유를 알려 줍니다. GitHub이 거절하면 그 이유를 보여 주고 초안은 그대로 남아 다시 시도할 수 있습니다. 작업PC 응답이 끊겨 제출됐는지 알 수 없으면 같은 리뷰가 두 번 올라가지 않게 보낸 초안을 잠그고, 제출 확인으로 GitHub에서 그 리뷰를 찾아 정리합니다. 이를 위해 리뷰 본문 끝에 화면에는 보이지 않는 표지(`<!-- saycode-review-attempt:… -->`)가 붙으며, 원문 Markdown이나 알림 메일에는 보일 수 있습니다. 위치를 다시 정해야 하는 초안은 빠지고 이 PC에 남습니다.

#### 사용 방법

프로젝트 대화에서 GitHub PR 링크를 눌러 오른쪽 PR 화면을 열고 파일 탭을 누르세요. 줄에 초안을 남긴 뒤 파일 목록 위 오른쪽, 좌우 비교 버튼 옆의 리뷰 제출 (N)을 누르면 제출 창이 열립니다. 제출할 계정을 확인하고 리뷰 종류를 고른 뒤 리뷰 본문을 쓰고 제출을 누르세요. 코멘트와 변경 요청은 본문이 필요하고 승인은 비워도 됩니다. 내 PR은 승인·변경 요청을 할 수 없습니다. 제출됐는지 확인하지 못했다는 안내가 보이면 제출 확인을 누르세요. 작업PC에 gh가 설치되고 로그인돼 있어야 합니다.

### 앱 안 PR 파일 탭에서 줄마다 리뷰 코멘트 초안을 남길 수 있습니다

PR 화면의 파일 탭에서 diff의 줄(삭제된 줄 포함)이나 줄 범위, 파일 전체에 리뷰 코멘트 초안을 남길 수 있습니다. 초안은 이 PC에만, 로그인한 계정과 PR마다 저장돼 탭을 닫거나 앱을 다시 켜도 남습니다. PR에 새 커밋이 올라와 diff가 바뀌면 초안이 같은 내용의 줄을 따라 옮겨 가고, 따라갈 수 없으면 지우지 않고 그 파일 머리 아래 위치를 다시 정해야 하는 초안 묶음에 원래 줄과 함께 모아 줄을 다시 고르거나 파일 코멘트로 바꿀 수 있게 합니다. PR이 병합되거나 닫히면 새 초안은 막고, 남은 초안을 모두 복사하거나 모두 삭제할 수 있습니다.

이번 변경은 초안 작성과 보관까지입니다. GitHub에 리뷰로 제출하는 기능은 다음 업데이트에서 추가되며, 그 전까지 초안은 GitHub에 올라가지 않습니다.

#### 사용 방법

프로젝트 대화에서 GitHub PR 링크를 눌러 오른쪽 PR 화면을 열고 파일 탭을 누르세요. 코멘트를 남길 줄을 누르면 그 줄 아래 입력창이 열립니다. Shift를 누른 채 다른 줄을 누르면 범위가 넓어집니다. 내용을 쓰고 Enter(또는 초안 저장)를 누르면 저장되고, Shift+Enter는 줄바꿈, Esc는 취소입니다. 파일 머리의 말풍선 단추(파일에 코멘트)는 파일 전체에 코멘트를 남깁니다. 키보드로는 diff 안을 누르거나 Tab으로 들어간 뒤 ↑·↓로 줄을 옮기고(좌우 보기는 ←·→로 열 전환) Enter로 입력창을 엽니다. 작업PC에 gh가 설치되고 로그인돼 있어야 파일 탭이 diff를 보여 줍니다.

### 앱 안 PR 화면에 AI 리뷰 가이드 탭이 생겼습니다

PR 화면에 활동·파일 다음 가이드 탭이 생겼습니다. 가이드 작성을 누르면 작업PC의 Claude가 그 PR을 읽기 전용으로 읽고, 어떤 순서로 읽으면 좋은지 단계별로 정리해 줍니다. 단계마다 요약, 꼼꼼히 볼 곳, 바뀐 코드의 해당 부분(발췌)과 그 줄 아래 메모, 그 단계가 다루는 파일, 리뷰어가 물어볼 만한 질문이 보이고, 바뀐 파일은 모두 어느 한 단계에 들어갑니다. 발췌의 코드는 파일 탭과 같은 diff에서 가져오고, 파일 탭에서 보기를 누르면 파일 탭의 그 줄로 이동합니다.

발췌의 줄을 누르면 파일 탭과 같은 리뷰 코멘트 초안을 쓸 수 있고, 질문 옆 코멘트로 쓰기는 그 질문을 채운 입력창을 엽니다. 초안은 파일 탭의 초안과 같은 곳에 저장되며 마지막 단계 아래 리뷰 제출로 파일 탭과 같이 리뷰 하나로 제출합니다.

실행은 작업PC에서 따로 돌아 몇 분 걸려도 앱을 닫았다 열면 이어서 진행을 확인합니다. 가이드는 이 PC에 저장되며, PR에 새 커밋이 올라오면 이전 버전으로 표시하고 바뀐 파일 수와 다시 작성을 보여 줍니다. Claude는 PR의 코드·스크립트·훅을 실행하지 않고 git diff·log·show와 파일 읽기만 하며, GitHub에는 아무것도 쓰지 않습니다. AI가 만든 안내이므로 승인 여부는 직접 판단해 주세요.

#### 사용 방법

프로젝트 대화에서 GitHub PR 링크를 눌러 오른쪽 PR 화면을 열고 가이드 탭을 누르세요. 모델(Sonnet·Opus)을 고르고 가이드 작성을 누르면 진행 중 표시와 경과 시간이 보이고, 취소로 멈출 수 있습니다. 완성되면 단계 제목을 눌러 접거나 펼치고, [·] 키로 단계 사이를 옮깁니다. 머리 줄의 ⋮에서 다시 작성하거나 삭제할 수 있습니다. 발췌의 줄을 누르거나 질문 옆 코멘트로 쓰기로 리뷰 코멘트 초안을 쓰고, 마지막 단계 아래 리뷰 제출로 제출합니다. 작업PC에 Claude가 설치·로그인돼 있고 그 프로젝트 폴더가 PR 저장소의 git checkout이어야 하며, 실행은 작업PC Claude 계정의 사용량을 씁니다.

### 에이전트가 띄워 둔 백그라운드 작업 보고 하나씩 멈추기

에이전트가 백그라운드로 띄운 셸·모니터·터미널이 돌고 있으면 입력창 위에 "백그라운드 작업 N개 실행 중"이 보입니다. 누르면 작업마다 설명·명령·경과 시간을 확인할 수 있고, 응답 전체를 끊지 않고 하나만 멈출 수 있습니다. 끝난 작업은 잠시 "끝남"으로 남았다가 사라지며, 사이드바와 대화 탭에도 "백그라운드 작업 중"으로 표시됩니다. 개별 중지는 새 Saycode CLI가 필요하며, 이전 버전에서는 목록만 보이고 응답 중단으로 안내합니다.

#### 사용 방법

대화의 입력창 위 "백그라운드 작업 N개 실행 중"을 누르고, 멈출 작업의 "멈추기"를 누르세요. 끝난 작업은 X로 목록에서 지울 수 있습니다.

### 예약마다 작업PC가 놓친 회차를 돌아온 뒤 1회 실행할지 고를 수 있어요

예약 편집 화면의 고급에 "놓친 실행" 선택이 생겼어요. "돌아오면 1회 실행"을 고르면 작업PC가 꺼져 있거나 잠자기·연결 끊김으로 예약 시각을 놓쳤을 때, 다시 연결된 뒤 놓친 회차 중 가장 최근 1회만 늦게 실행하고 나머지는 실행 이력에 놓침으로 남겨요(8일 이내). 저장 직후 꺼진 1회 예약도 돌아오면 한 번 실행돼요. "기본"은 지금처럼 실행하지 않고 놓침으로 남기며, "건너뜀"은 나중에 기본 동작이 바뀌어도 실행하지 않아요. 실행 이력에는 예정 시각보다 5분 넘게 늦게 시작한 회차에 "늦게 실행됨"이 붙어요. 이 기능을 지원하지 않는 작업PC에서는 선택이 잠겨 있고 업데이트 안내가 보여요.

#### 사용 방법

사이드바 예약에서 새 예약을 만들거나 예약 행의 더보기(⋮) → 편집을 연 뒤, 고급을 펼쳐 "놓친 실행"에서 고르고 저장해요. 작업PC의 SayCode 런타임과 서버가 이 기능을 지원하는 버전이어야 고를 수 있어요. 예전 버전 앱에서 이 예약을 편집하면 선택이 기본으로 돌아갈 수 있어요.

### 원격 Mac의 AI 브라우저를 앱 안에서 확인

지원 런타임이 설치되고 데스크톱에 로그인된 원격 Mac에서는 현재 대화의 AI 브라우저 페이지를 앱 안에서 보고 직접 조작할 수 있습니다. 로컬 Mac은 기존 전용 Chrome 창을, Linux는 기존 화면 연결을 사용합니다. 지원 서버·런타임의 배포와 원격 PC 적용이 필요합니다.

화면 갱신과 입력을 순서대로 처리하고 스크롤 뒤 새 화면을 확인해, 빠르게 연속 스크롤할 때 조작이 끊기는 문제를 수정했습니다. 정상적으로 제어권을 반납하는 중 연결 오류가 잠깐 표시되는 현상도 수정했습니다. 대기 중 문서나 화면 크기가 바뀐 입력은 폐기하며, 처리 결과가 불명확한 입력을 자동으로 다시 보내지 않습니다.

#### 사용 방법

원격 Mac을 사용하는 대화에서 AI 브라우저를 열고 작업과 페이지를 고르세요. 제어권 가져오기를 누른 뒤 직접 조작하고, 마치면 제어권 반납과 계속 진행을 누르세요. 연결이 끊기거나 입력 상태를 확인해야 할 때는 다시 연결을 사용하세요. 입력 결과가 불명확하면 AI는 자동으로 재개하지 않습니다.

### 입력창에서 @diff·@staged·@git:N으로 git 변경을 첨부할 수 있습니다

Project 대화의 입력창에서 @를 입력하면 'Git 변경' 묶음에 @diff(커밋 안 한 변경 전체), @staged(스테이지한 변경), @git:N(최근 커밋 N개, 최대 20개)이 함께 나옵니다. 고르면 입력창 위에 칩으로 붙고, 보낼 때 작업PC에서 실제 diff를 가져와 파일로 첨부합니다. 보낸 메시지의 칩에는 파일 수와 추가·삭제 줄 수가 보이고, 누르면 보낸 diff를 열 수 있습니다. 변경이 없으면 "변경 없음" 한 줄을 적고, 200KB를 넘는 부분은 생략한 줄 수만 남깁니다. 작업 폴더가 Git 저장소가 아니거나 작업PC가 응답하지 않으면 항목이 이유와 함께 흐리게 보입니다.

#### 사용 방법

Project 대화의 입력창에 @diff, @staged 또는 @git:3처럼 입력하고 'Git 변경' 묶음에서 항목을 고른 뒤 요청을 적어 보내세요. 칩의 X로 참조를 뺄 수 있습니다.

### 작업PC가 실행하지 못하고 지나간 예약 회차가 실행 이력에 남아요

작업PC가 꺼져 있거나 잠자기·연결 끊김으로 예약 시각을 놓치면, 다시 연결된 뒤 그 기간의 회차를 한 줄로 실행 이력에 남겨요. 실행 이력과 대화의 회차 줄에는 "놓침 ×3 · 작업PC가 예약 시각에 실행하지 못함"처럼 놓친 회차 수와 첫 번째로 놓친 예정 시각이 보이고, 예약 목록의 "최근 기록에 놓친 예약 N건"은 줄 수가 아니라 놓친 회차 수를 셉니다. 1,000회를 넘으면 "1000+"로 표시해요. 놓친 회차를 나중에 대신 실행하지는 않아요.

#### 사용 방법

사이드바 예약에서 예약 행의 더보기(⋮) → 실행 이력을 열면 보여요. 별도 설정 없이 자동 적용되며, 작업PC의 SayCode 런타임과 서버가 이 기능을 지원하는 버전이어야 기록돼요.

### 최근에 작업한 폴더를 골라 프로젝트를 한 번에 만들기

첫 프로젝트를 추가할 때 이 컴퓨터에서 최근 30일 동안 Claude Code·Codex로 작업한 폴더를 찾아 보여 줍니다. 하위 폴더나 워크트리에서 한 작업은 저장소 폴더 하나로 묶고, 이미 프로젝트인 폴더와 홈 폴더는 빼요. 대화가 3개 이상인 폴더는 미리 체크돼 있고, 고른 폴더는 한 번에 프로젝트로 만들어집니다. 세션 내용은 읽지 않고 폴더 경로만 확인해요.

#### 사용 방법

시작준비 마지막 단계에서 프로젝트 추가하기를 누르면 프로젝트 추가 창에 최근에 작업한 폴더가 보입니다. 이미 프로젝트가 있다면 새 프로젝트 → 기존 폴더 탭에서 접힌 최근에 작업한 폴더를 펼치세요. 원하는 폴더를 체크하고 선택한 폴더로 프로젝트 만들기를 누릅니다. 작업PC가 이 컴퓨터일 때만 보여요.

### 컨텍스트 창을 무엇이 차지하는지 보고, 압축 전에 남길 내용을 정할 수 있어요

Claude 대화의 ‘컨텍스트 N%’를 누르면 사용률 아래에 ‘구성 (추정)’이 함께 보여요. 시스템 프롬프트, 기본 도구, MCP 도구, 메모리 파일, 스킬, 대화, 자동 압축 여유분, 남은 공간이 각각 몇 토큰인지 막대와 목록으로 보여 주고, 필요할 때만 불러오는 도구는 ‘창 밖’으로 따로 알려 줘요. 마지막 응답이 끝난 시점의 추정이라 위의 사용률과 조금 다를 수 있어요. 대화 압축도 이제 바로 보내지 않고 한 번 확인해요. 확인 단계에서 요약에 남길 내용을 ‘압축 지침’에 적을 수 있고, 기본으로 켜진 ‘보존 지침 포함’은 확인되지 않은 가설은 가설로 표시하고 아직 답이 없는 질문과 내가 말한 제약을 요약에 남기도록 요청해요. 확인 단계를 연 사이에 응답이 시작되거나 다른 대화로 바꾸면 확인 단계는 닫히고 아무것도 보내지 않아요. 보내기에 실패하면 적은 지침을 그대로 둔 채 확인 단계로 돌아와요.

#### 사용 방법

Claude 대화에서 입력창 아래 정보 줄의 ‘컨텍스트 N%’를 누르면 ‘구성 (추정)’이 보여요. 압축하려면 대화 압축을 누르고, 필요하면 압축 지침을 적은 뒤 압축을 누르세요. 취소나 Esc를 누르면 아무것도 보내지 않아요.

### 터미널에서 선택한 출력을 대화 입력창 카드로 추가

대화의 작업 도구 영역 터미널에서 출력을 선택하면 선택 끝 근처에 대화에 추가 버튼이 보입니다. 버튼·단축키·오른쪽 클릭 메뉴로 그 출력을 터미널이 속한 대화의 입력창에 터미널 · N줄 카드로 넣습니다. 비밀번호·토큰처럼 보이는 값은 가린 뒤 넣고, 40,000자가 넘으면 마지막 출력만 줄 단위로 담습니다. 자동으로 보내지는 않습니다. 이전 버전 Desktop에서는 이 카드가 원문 블록으로 보입니다.

#### 사용 방법

대화에서 작업 도구 → 터미널을 열고 출력을 드래그해 선택한 뒤 대화에 추가를 누릅니다. 터미널을 클릭한 채 Cmd+L(Windows는 Ctrl+L)을 누르거나 오른쪽 클릭 메뉴의 대화에 추가를 골라도 됩니다. 선택이 없을 때 이 단축키는 셸로 갑니다. 단축키는 내 설정 → 일반 → 단축키에서 바꿀 수 있습니다.

### 폴더 ZIP 다운로드 진행 상태와 취소

폴더 ZIP을 받는 동안 현재 단계·파일 수·처리한 용량을 확인하고 취소할 수 있습니다. 취소는 임시 저장 정리까지 기다리며 기존 저장 파일을 보존합니다.

#### 사용 방법

프로젝트 대화의 파일 목록에서 폴더 다운로드를 누릅니다. 목록 위 진행 상태의 취소 버튼으로 중단하고 정리 완료 뒤 다시 시도할 수 있습니다. 마지막 파일 저장 중에는 취소가 잠시 비활성입니다.

### AI 질문에 스크린샷·파일을 붙여 답할 수 있습니다

AI가 선택지를 주며 질문했을 때, 질문 폼에서 바로 스크린샷이나 파일을 붙여 답할 수 있습니다. 이전에는 질문 폼이 글만 받아, 화면을 보여 주려면 질문을 건너뛰고 일반 메시지로 다시 보내야 했습니다. 붙인 파일은 그 질문의 답에만 들어가고, 보내기를 누르면 일반 메시지의 첨부와 같이 작업PC에 먼저 올라간 뒤 답과 함께 AI에게 전달됩니다. 보낸 답 요약에는 답한 글과 보낸 파일이 따로 보이며 파일을 눌러 열 수 있습니다.

#### 사용 방법

질문 폼의 직접 답변 칸 왼쪽 + 를 누르고 파일 또는 사진 추가로 파일을 고릅니다. 입력란에 이미지를 붙여 넣거나 대화 화면 위로 파일을 끌어 놓아도 지금 보이는 질문에 붙습니다. 파일만 붙이고 보내도 답이 됩니다. 업로드가 실패하면 답은 보내지 않고 폼이 남으니 다시 보내기를 누르세요. 작업PC가 연결되어 있어야 하며 폴더는 붙일 수 없습니다.

### Claude 대화에도 작업 목록 카드 표시

Claude가 여러 단계 작업을 하며 할 일 목록을 쓰면, 지금까지 `작업 목록 업데이트` 도구 줄로만 보이던 그 목록이 Codex 대화와 같은 `작업 목록 n/m 완료` 카드로 답 아래에 보입니다. 한 턴에는 가장 최근 목록 하나만 보이고, AI가 일하는 동안 펼쳐져 있다가 다음 메시지를 보내면 접힙니다. 프로젝트 대화와 개인 Chat 모두, 이미 저장된 대화에도 적용됩니다. 목록 쓰기가 실패한 경우에는 도구 줄과 오류가 그대로 보입니다. 개인 Chat에서는 Codex 작업 목록도 이제 한 턴에 하나만 보입니다.

#### 사용 방법

Claude 대화에서 AI가 일하는 동안 답 아래의 작업 목록 줄을 보고, 눌러서 단계별 상태를 펼치거나 접습니다.

### Claude 대화에서 "계획 먼저"를 켜고 계획 승인 때 실행 방식을 고릅니다

Claude 대화 입력창에 "계획 먼저" 버튼이 생겼습니다. 켜 두면 Claude가 파일을 고치기 전에 계획부터 보여 줍니다. 계획 카드에는 승인 뒤 실행 방식(전체 허용 / 편집만 자동 승인)을 고르는 선택이 생겼고, 승인하면 "계획 먼저"는 꺼집니다. 수정을 요청하면 계속 켜져 있어 다음 메시지도 계획부터 받습니다. 조직 권한 상한이 있으면 그 이하 방식으로만 실행됩니다.

#### 사용 방법

Claude 대화 입력창에서 "계획 먼저"를 누르고 요청을 보냅니다. 계획 카드에서 "승인 뒤 실행 방식"을 고른 뒤 "작업 시작"을 누릅니다. 앱을 다시 열면 꺼진 상태로 시작합니다.

### Codex 목표가 멈춘 상태를 알려 주고, 중지하면 같이 멈추며, 다시 시작할 수 있습니다

Codex 대화의 목표 줄에 목표의 상태가 보입니다. 일시정지, 막힘, 사용량 한도일 때 "목표" 옆에 작은 상태 표시가 붙습니다. 응답 중에 중지를 누르면 진행 중이던 목표도 함께 일시정지되어, 중지한 뒤 Codex가 목표를 이어 가며 저절로 다시 일하지 않습니다. 일시정지된 목표에는 줄의 재생 버튼("목표 다시 시작")이 생겨 목표를 그대로 두고 이어 갈 수 있습니다. 작업PC의 happy-cli가 이 기능을 아직 지원하지 않으면 지금처럼 목표만 보이고 새 버튼은 나타나지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. Codex 대화에서 `/goal`로 목표를 건 뒤 중지를 누르면 목표 줄에 "일시정지"가 보입니다. 이어 가려면 줄의 "목표 다시 시작" 버튼을 누르세요. 막힘이나 사용량 한도 상태는 표시만 하며, 원인을 풀면 Codex가 이어 갑니다.

### Slack 입력 첨부와 후속 댓글을 설정에서 선택

Slack 연결에 입력 첨부·활성 스레드 후속 댓글 설정을 추가했습니다. 모두 기본 켜짐이며 기존에 직접 끈 설정은 유지합니다. 필요한 Slack 권한과 AI 제공자에게 전달되는 정보가 표시됩니다. 받는 기기의 전역 제한·지원 상태를 안내하고 저장 실패 시 이전 선택을 유지합니다. 연결을 해제하면 수신을 멈추며 새 연결은 기본 켜짐입니다. 기본 Slack 앱 manifest에도 필요한 권한과 이벤트가 포함됩니다.

#### 사용 방법

내 설정 → 일반 → 메신저 채널 → 페어링된 Slack 연결에서 선택합니다. 받는 기기가 지원하고 전역 제한이 없으면 기본으로 동작합니다. 안내된 Slack 권한·이벤트를 추가하고 워크스페이스에 앱을 다시 설치하세요. 선택 기능을 포함한 manifest 복사도 제공합니다. 끄면 추가 수신·다운로드를 멈추며 이미 받은 파일은 남습니다. 토글 자체는 Slack 권한이나 전역 제한을 바꾸지 않습니다.

### Telegram·Discord 답변에도 에이전트가 만든 파일 첨부

Slack에서만 되던 파일 첨부 답변이 Telegram과 Discord에서도 됩니다. 봇에게 파일을 만들어 달라고 요청하면 답변이 먼저 오고, 에이전트가 만든 파일이 같은 대화(Telegram 토픽, Discord 스레드 포함)에 요청 메시지에 대한 답글로 이어서 옵니다. Telegram에서는 이미지도 화질이 바뀌지 않도록 파일(문서)로 보냅니다. 프로젝트 폴더 밖·숨김·키 파일과 20MB를 넘는 파일은 보내지 않고, 한 답변에 최대 5개까지 첨부하는 규칙은 Slack과 같습니다. Discord 서버의 업로드 상한(기본 10MB)을 넘어 거부된 파일은 첨부하지 못한 개수를 알리는 한 줄 안내에 포함됩니다. 메신저 채널 설정의 개인정보 안내도 세 메신저 모두에 파일이 전송될 수 있다고 바뀌었습니다.

#### 사용 방법

Telegram이나 Discord에서 봇에게 "보고서를 CSV 파일로 만들어 줘"처럼 요청하세요. 이번 업데이트 전에 서버에 초대한 Discord 봇은 서버 설정에서 봇 역할에 파일 첨부(Attach Files) 권한을 주어야 합니다. 설정의 메신저 연결에서 새로 받는 Discord 초대 링크에는 이 권한이 포함됩니다. Telegram은 추가 설정이 필요 없습니다.

### VS Code에서 이 컴퓨터의 폴더 열기

VS Code 확장에서 로컬 폴더 원본을 기존 워크스페이스에 추가해 파일을 탐색할 수 있습니다.
파일 복사·업로드나 AI 폴더 권한 추가 없이 같은 물리 폴더의 중복 추가를 피합니다.

#### 사용 방법

VS Code 명령 팔레트에서 Saycode: 이 컴퓨터의 폴더 열기를 실행하고 폴더를 선택합니다.
macOS·Windows의 로컬 VS Code 창에서 사용합니다. Desktop 무비밀번호 연결은 아직 검증 중인 별도 프리뷰입니다.

## 변경된 기능

### 공개 설정을 확인한 뒤 링크 만들기

공개 링크 버튼을 누르면 먼저 공개 범위와 만료를 선택합니다. 공개하기를 눌러야 링크가 생성되며, 생성된 주소 옆에서 링크를 복사할 수 있습니다. 확장 설치만으로 공개되지 않습니다.

공개 성공 후 버튼은 원형 체크 아이콘으로 바뀝니다. 앱을 다시 켜도 서버에서 기존 링크를 확인해 표시를 복원합니다. 해당 파일의 모든 링크가 중지되거나 만료되면 일반 링크 아이콘으로 돌아갑니다. 공개 중 다른 파일로 이동해도 완료 상태를 보존하며, 공개 중지 뒤 늦은 설정 응답이 도착해도 공개 상태를 되살리지 않습니다.

#### 사용 방법

HTML 결과물의 공개 링크를 누르고 공개 범위와 만료를 선택한 뒤 공개하기를 누르세요. 주소 옆 링크 복사로 공유할 수 있습니다.

### 답변이 쓰이는 동안 글자가 덩어리로 튀지 않아요

에이전트가 답변을 쓰는 동안 글자가 몇십 자씩 한꺼번에 튀어나오던 표시를, 남은 분량에 맞춰 속도를 조절하며 고르게 이어 쓰도록 바꿨습니다. 한글·이모지가 반쯤 깨진 채 보이지 않으며, 복사 버튼은 언제나 받은 전체 텍스트를 복사합니다. macOS·Windows의 "동작 줄이기" 설정을 켜 두었다면 이전처럼 받은 글을 바로 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 대화 상단 AI 브라우저 버튼을 하나로 합치고 표시 설정으로 켜고 끕니다

대화 상단에 상황에 따라 `AI 브라우저 열기` 또는 `AI 브라우저`로 다르게 보이던 버튼을 `AI 브라우저` 하나로 합쳤습니다. 이제 이 버튼은 개발자 기능 설정의 `대화 상단 AI 브라우저 바로가기 표시`를 켰을 때만 보입니다. 이전에는 내 대화의 `AI 브라우저` 버튼이 설정을 꺼도 계속 보였습니다. 누르면 내 대화에서는 이 대화의 브라우저 작업과 승인 방식을, 다른 사람의 대화에서는 전체 AI 브라우저 화면을 엽니다. 브라우저 작업 승인 카드의 `AI 브라우저` 버튼과 입력창 `+` 메뉴의 브라우저 사용은 설정과 상관없이 계속 표시됩니다.

#### 사용 방법

계정 메뉴 → 개발자 기능 설정에서 `대화 상단 AI 브라우저 바로가기 표시`를 켜거나 끕니다. 기본값은 꺼짐입니다.

### 모델 메뉴에서 사용 연결 선택

모델 메뉴에 API 토큰·작업PC 토큰 탭을 합쳤습니다. 새 대화는 관리자 기본 연결을 따르고 현재 입력창에서 고른 연결은 유지합니다. API 강도는 Medium으로 표시하며 PC 강도 저장값은 보존합니다. 연결 확인에 실패하면 자동으로 다른 연결을 쓰지 않고 다시 확인할 수 있습니다.

### 승인 카드가 명령 전체를 줄바꿈 그대로 보여 주고, 긴 명령은 끝부분을 남깁니다

### 연결된 PR 목록에서 각 PR의 상태를 봅니다

입력창 위 PR 버튼(+N)으로 여는 `연결된 PR` 목록이 이제 연결된 PR마다 열림·병합됨·닫힘과 CI 실패를 PR 버튼과 같은 배지로 보여 줍니다. 지켜보는 중인 PR은 감시가 본 상태를 쓰고, 지켜보지 않는 PR은 목록을 열 때 한 번 작업PC의 GitHub CLI로 그 PR의 저장소에서 읽습니다. 목록이 열려 있는 동안 반복해서 읽지 않으며, 다시 열면 다시 읽습니다. 읽지 못한 PR(작업PC가 꺼져 있음, 그 저장소 권한 없음 등)은 줄에 `상태 확인 못 함`이라고 보입니다.

#### 사용 방법

### MongoDB 메모리 동기화를 같은 코드 저장소끼리 주고받음

MongoDB 메모리 동기화가 Saycode 프로젝트가 아니라 프로젝트 폴더의 코드 저장소(git origin)를 기준으로 메모리를 주고받습니다. 같은 저장소를 머신마다 다른 Saycode 프로젝트로 쓰고 있어도 서로 올린 메모리를 내려받아 검색할 수 있습니다. 저장소 루트가 아니거나 origin이 없는 폴더는 지금처럼 같은 프로젝트끼리만 주고받고, 같은 프로젝트의 다른 작업PC가 다른 범위로 동기화하면 카드에 경고가 표시됩니다. 업데이트 뒤 첫 동기화에서는 각 머신이 자기 메모리를 새 공유 공간에 다시 올리고 다른 머신의 메모리를 내려받아 검색 준비를 하므로 평소보다 오래 걸릴 수 있습니다.

#### 사용 방법

내 설정 → 개발 → 메모리 → MongoDB 메모리 동기화 카드에서 켜 둔 머신은 별도 설정 없이 적용됩니다. 카드의 공유 범위에서 어떤 저장소의 프로젝트와 메모리를 나누는지 확인할 수 있습니다.

### PR 머지·닫힘 자동 보관이 대화에 연결된 PR까지 봅니다

`PR 머지·닫힘 시 자동 보관` 규칙이 대화에 연결된 PR까지 함께 봅니다. 브랜치 PR과 연결된 PR 중 하나라도 열려 있으면 이 규칙으로는 보관하지 않고, 모두 머지됐거나 닫혔을 때만 보관합니다. 이 Desktop이 상태를 모르는 연결 PR이 있어도 이 규칙으로는 보관하지 않습니다. 지켜보지 않는 연결 PR은 이 PC가 하루 안에 본 상태만 쓰고(머지는 기한 없음), 보관하기 직전에 한 번 더 읽어 확인합니다. `활동이 없으면 자동 보관` 규칙은 PR 상태와 상관없이 이전과 같습니다. 연결된 PR이 없는 대화도 이전과 같습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 지켜보지 않는 연결 PR의 상태는 `연결된 PR` 목록을 열 때와 자동 보관 직전에 작업PC에서 읽습니다.

### Saycode 계정으로 로그인하면 공개 링크 확장이 기본으로 설치돼요

Saycode 계정으로 로그인해 쓰면 이 PC에 공개 링크 확장이 처음 한 번 자동으로 설치되고 켜집니다. 따로 설치하지 않아도 AI가 만든 HTML 결과물 옆의 `공개 링크`에서 공개 범위와 만료를 선택하고 `공개하기`로 링크를 만듭니다. 허용하는 권한은 결과물의 공개 링크 만들기 하나뿐이며, `공개하기`를 직접 누를 때만 링크가 만들어집니다. 나중에 확장을 끄거나 지우면 다시 설치하지 않습니다. 로컬 사용과 체험 모드에는 적용되지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 끄거나 지우려면 `내 설정 → 개발 → 확장`에서 공개 링크 확장을 관리하세요.

### Windows에서 보안 설정 때문에 시작 준비가 멈추지 않습니다

Windows에서 로그인·PC 연결 정보를 저장할 때 Saycode가 폴더 권한을 따로 바꾸지 않고, Windows 사용자 폴더의 기본 권한으로 저장합니다. 그래서 회사 보안 프로그램이 권한 변경을 막거나 늦추는 PC에서도 시작 준비가 멈추지 않습니다.

이전에 묻던 "이 PC에 로그인 정보를 저장할까요?" 확인 창과, 설정의 "로그인 정보 저장" 항목은 없어졌습니다. 이전 버전이 다른 위치에 저장한 정보는 그 자리에서 계속 씁니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

## 수정된 문제

### / 만 치고 Enter를 눌러도 되돌릴 수 없는 명령이 들어가지 않아요

입력창에 / 를 치면 열리는 명령 목록에서 맥락을 지우는 /clear, 대화를 요약으로 바꾸는 /compact, AI 심사가 거절한 요청을 허용하는 /approve가 목록 맨 아래로 옮겨졌습니다. 그동안 Codex 새 대화처럼 /clear가 첫 줄에 오는 경우 / 와 Enter만으로 /clear가 들어갔습니다. 이제 기본 선택은 항상 되돌릴 수 있는 명령입니다. 화살표로 고른 항목은 그 검색어에서만 유지되어, 글자를 지웠다 다시 쳐도 예전 선택이 되살아나지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 이 명령들이 필요하면 화살표로 고르거나 /cl 처럼 이름을 적어 좁힌 뒤 Enter를 누르세요.

### 갈래 만들기의 연속 클릭과 전환 중 늦은 결과 보호

갈래 만들기를 빠르게 다시 눌러도 복제와 새 대화 생성을 반복하지 않고, 먼저 나온 오류를 유지합니다. 계정·조직·PC·작업 폴더가 바뀐 요청의 늦은 결과가 현재 화면에 반영되지 않도록 했습니다. 생성 요청 전 실패한 복사본은 같은 대상에서 재사용합니다.

#### 사용 방법

대화의 프로젝트 도구 → 대화 이어가기 → 같은 AI로 갈래 만들기를 사용하거나 내 메시지의 여기서 다시 쓰기를 누릅니다. 실패 직후 같은 요청은 0.5초 뒤 다시 실행할 수 있으며, 이미 처리 중인 요청은 끝날 때까지 반복 실행하지 않습니다.

### 같은 답변이 두 번 나오던 문제 수정

v0.1.84부터 AI가 답변을 마친 뒤 같은 답변을 한 번 더 쓰는 일이 잦았습니다. 응답 언어를 점검하라는 지침이 이미 보낸 답을 다시 써서 보내라는 뜻으로 읽혔기 때문입니다. 이제 처음부터 설정된 언어로 답하고, 이미 보낸 답을 다시 쓰거나 반복하지 않도록 지침을 고쳤습니다. 설정된 응답 언어를 유지하는 동작은 그대로입니다.

#### 사용 방법

업데이트 후 다음 요청부터 자동 적용됩니다. 별도 설정은 필요하지 않습니다.

### 개인 AI 브라우저를 필요할 때만 실행

#### 사용 방법

파일을 수정했다면 수정본 공개에서 공개 범위·만료를 확인한 뒤 공개하기를 누르세요. 이전 링크를 먼저 중지할 필요는 없습니다.

### 남은 Git 잠금 때문에 새 대화를 계속 시작하지 못하던 문제를 확인 후 풀 수 있습니다

작업 PC가 Git 작업 도중 재시작되면 저장소에 잠금 폴더가 남을 수 있었습니다. 이 잠금은 저절로 풀리지 않아서, 별도 작업 공간으로 새 대화를 시작할 때마다 다시 시도해도 "같은 저장소에서 다른 Git 작업이 진행 중입니다"로 실패했습니다. 이제 남은 지 10분이 넘은 빈 잠금이면 언제 생긴 잠금인지 알려 주고, 확인을 누르면 잠금을 지운 뒤 바로 다시 만듭니다. 최근 10분 안에 생긴 잠금은 지우지 않으며, 지우기 직전에 작업 PC가 한 번 더 확인합니다. 작업 PC가 잠금을 지우지 못하면 기다리지 않고 바로 알려 줍니다.

#### 사용 방법

새 대화 시작이 남은 잠금에 막히면 확인 창이 뜹니다. 데스크탑 앱이나 다른 창에서 진행 중인 Git 작업이 없다면 확인을 누르세요.

### 다른 AI로 이어갈 때 중복 실행을 막아요

다른 AI도구로 이어가기를 연속해서 눌러도 대화 기록 저장과 새 대화 시작을 한 번만 실행합니다. 빠르게 실패한 뒤 다시 누르면 기존 오류와 선택을 유지하며, 준비 중 계정·작업PC·폴더가 바뀌면 이전 작업을 새 대상에 반영하지 않습니다.

#### 사용 방법

프로젝트 대화의 프로젝트 도구 → 대화 이어가기 → 다른 AI도구로 이어가기에서 별도 설정 없이 적용됩니다.

### 다른 Git 작업 중에 새 대화를 시작해도 잠시 기다렸다가 이어서 시작합니다

코드 받아오기 같은 다른 Git 작업이 같은 저장소에서 진행되는 동안 별도 작업 공간으로 새 대화를 시작하면, 대화가 바로 실패하고 `API error 409: {...}` 같은 내부 오류가 그대로 보였습니다. 이제 그 작업이 끝나기를 잠시 기다렸다가(최대 세 번, 약 17초) 다시 시도합니다. 그래도 끝나지 않으면 "다른 Git 작업이 진행 중이에요. 끝난 뒤 다시 시도해 주세요."라는 안내를 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 답변이 끝나는 순간 대화 화면이 출렁이지 않아요

에이전트 답변이 끝날 때 맨 아래 "작업 중" 줄이 사라지면서 대화 내용이 한 번 아래로 밀리던 현상을 없앴습니다. 줄이 사라진 자리는 같은 높이로 남아 읽던 위치가 그대로 유지됩니다. 답변 완료 신호가 최종 답변보다 먼저 도착해도, 쓰이던 답변이 사라졌다가 다시 나타나지 않고 정식 답변으로 바로 이어집니다.

#### 사용 방법

### 대화 보관·삭제의 빠른 반복 실행 방지

보관이나 삭제를 빠르게 반복해 눌렀을 때 같은 요청이 중복 실행되는 문제를 수정했습니다. 삭제 확인 중에는 같은 대화의 보관·복원이 겹치지 않으며, 확인 취소는 이전 실행의 짧은 반복 방지 시간을 지우지 않습니다. 복원의 기존 처리 공유와 자동 보관 동작은 유지합니다.

#### 사용 방법

### 데이터베이스 주소의 비밀번호가 승인 카드·진단 파일·로그에서 가려집니다

`postgres://`·`redis://`·`mongodb+srv://`·`amqp://`·`mysql://`처럼 http가 아닌 주소에 든 비밀번호(`사용자:비밀번호@`)가 승인 카드, 문제 해결용 진단 파일, AI 심사로 보내는 요청, 데몬 로그, 터미널 선택 카드에 그대로 보이던 문제를 고쳤습니다. 이제 주소 형식과 상관없이 `postgres://[redacted]@db:5432/app`처럼 가려지고, 비밀번호에 `@`가 들어 있어도 남는 조각이 없습니다. 비밀번호가 없는 `ssh://git@github.com` 같은 주소는 그대로 보입니다.

승인 카드에서는 비밀값을 넣는 변수 바로 뒤에 `;`·`|`·`&`로 이어 붙인 명령이 비밀값과 함께 가려져 보이지 않던 문제도 고쳐, 이어서 실행될 명령이 보입니다.

#### 사용 방법

### 메신저 답장이 잠시 막혀도 기다렸다가 다시 도착합니다

Slack·Telegram·Discord가 보낸 답장을 "너무 많이 보냈다"(429)나 일시적인 서버 오류(5xx)로 잠깐 거절하면, 지금까지는 답 대신 "답장을 여기로 보내지 못했어요" 안내만 오고 끝났습니다.

이제 최종 답변은 플랫폼이 알려 준 시간(알려 주지 않으면 1분, 서버 오류는 30초·2분·5분)을 기다린 뒤 같은 대화·스레드로 다시 보냅니다. 기다리는 동안에는 대화에 아무것도 보내지 않고, 그사이 들어온 다음 질문의 답은 앞 답이 나간 뒤에 순서대로 나갑니다. 답의 앞부분이 이미 도착했거나 서버 오류였다면 "앞부분이 이미 도착했을 수 있어요" 표시를 한 번 먼저 보냅니다.

최대 3번, 처음 거절부터 15분 안에서만 다시 보냅니다. 그래도 못 보내거나 플랫폼이 5분 넘게 기다리라고 하면 지금처럼 안내를 한 번 보내고, 설정의 메신저 연결 "최근 실패"에 "플랫폼이 일시적으로 답장을 막아 보내지 못했어요"로 남습니다. 차단된 봇·삭제된 대화·권한 오류처럼 다시 보내도 안 되는 거절은 지금처럼 바로 안내합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 연결 상태는 내 설정 → 일반 → 메신저 채널 → 연결 칸의 "최근 실패"에서 확인합니다.

### 메신저로 보낸 너무 긴 메시지에 안내를 보냅니다

Slack·Telegram 같은 메신저에서 글자 수 상한을 넘는 긴 메시지를 보내면, 이전에는 아무 답도 없이 그 메시지가 사라졌습니다. 이제 "메시지가 너무 길어요(최대 약 N자). 나눠서 보내 주세요"라는 안내를 한 번 보내고, 그 메시지는 실행하지 않습니다. 첨부 파일과 함께 보낸 긴 설명글도 같은 안내를 받습니다. 같은 메시지가 다시 전달돼도 안내는 한 번만 갑니다. 연결된 사람이 아닌 발신자에게는 안내하지 않습니다. 상한은 지금 4,096바이트(한글 약 1,365자)이고, 새 Slack 확장이 반영되면 Slack은 16KiB(한글 약 5,461자)까지 받습니다.

내부 Desktop 연결 프리뷰에서 기존과 같이 새 대화를 시작합니다. 파일 보호 지원 안내가 나오면 Desktop의 머신과 실행기 버전을 확인하세요.

### VS Code Git 동기화에서 서버 포트를 구분

같은 호스트와 저장소 경로라도 명시한 서버 포트가 다르면 VS Code 프로젝트 동기화를 중단합니다. 다른 Git 서버의 저장소를 같은 origin으로 판단하던 문제를 수정했습니다.

사용자 정보가 포함된 URL도 같은 규칙으로 비교하며, 잘못된 주소는 원문 대신 고정 안내로 거절합니다. 호스트가 있는 파일 공유 주소도 같은 호스트·경로의 네트워크 Git 주소와 구분합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 동기화할 로컬 폴더와 대상 프로젝트의 origin을 확인하세요.

### VS Code에서 연결할 작업PC가 없을 때 바로 안내

Desktop 연결로 프로젝트 폴더를 열 때 연결 가능한 작업PC가 없으면 빈 선택창 대신 바로 안내합니다. 프로젝트에 지정된 작업PC가 오프라인일 때 다른 PC로 바꾸지 않으며, 프로젝트를 고르는 도중 Desktop 연결이 바뀌면 이전 PC 목록을 열지 않습니다.

#### 사용 방법

기존 `Saycode: 원격 프로젝트 열기` 명령을 사용합니다. 온라인 작업PC가 없다는 안내가 나오면 대상 작업PC의 연결 상태를 확인한 뒤 다시 실행하세요.

### Windows에서 설치된 Desktop을 찾지 못하는 문제 수정

VS Code Desktop 연결 프리뷰에서 Windows 설치 정보에 설치 폴더가 없으면 탐색이 중단되던 문제를 수정했습니다. 기본 사용자 설치 폴더를 계속 확인하고 게시자 서명을 검증합니다.

#### 사용 방법

내부 연결 프리뷰를 사용하는 환경에 자동 적용됩니다. 일반 사용자용 Desktop 연결 기능은 아직 활성화되지 않습니다.

### Windows의 VS Code 프로젝트 동기화 수정

Windows 작업PC의 Git 동기화에서 사전 검사와 pull에 맞지 않는 셸 명령이 사용되던 문제를 수정했습니다. 미커밋 변경·브랜치·origin을 확인하고 기존 Git 잠금을 지키며 fast-forward pull만 실행합니다.

#### 사용 방법

VS Code에서 Saycode의 로컬 변경 동기화 명령을 사용합니다. Desktop 연결 프리뷰에서는 호환되는 Desktop 설치판도 필요합니다.

### Xcode 때문에 Mac 시작준비가 멈추면 무엇을 해야 하는지 알려 줍니다

Xcode가 설치된 Mac에서 라이선스에 동의하지 않았거나 Xcode가 오래돼 Git을 실행하지 못하면, 시작준비가 Git 항목에 "확인 실패"만 보여 주고 멈췄습니다. 이제 Git 항목에 "Xcode 라이선스 동의 필요" 또는 "Xcode 업데이트 필요"를 표시하고, 오류 안내와 Git 오류 상세에서 무엇을 하면 되는지 알려 줍니다. 명령줄 도구가 macOS 업데이트 뒤 망가진 경우에는 "Xcode 명령줄 도구 필요"와 설치 버튼을 보여 줍니다.

Git이 실패하며 남긴 첫 줄도 진단용 준비 기록(setup.log)에 남아, 지원 담당자가 원인을 확인할 수 있습니다.

#### 사용 방법

안내에 따라 Xcode를 열어 라이선스에 동의하거나, App Store에서 Xcode를 업데이트하고 한 번 연 뒤 시작준비에서 **다시 시도**를 누릅니다.
