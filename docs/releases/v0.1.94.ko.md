## 새 기능

### 쓰던 폴더를 그대로 프로젝트로 가져오기

이미 터미널이나 다른 도구로 작업하던 폴더를 옮기거나 복사하지 않고 그대로 프로젝트로 연결하는 가져오기 흐름이 생겼어요. 폴더를 고르면 Git 브랜치·원격, CLAUDE.md·AGENTS.md, 스킬·명령, MCP 설정, 이전 대화, .env 키 개수를 값 없이 먼저 보여 줍니다. 환경 변수 값, MCP 설정 안의 토큰, Git 주소에 섞인 사용자 정보는 이 컴퓨터 밖으로 보내지 않아요. 지침 파일·스킬·MCP 설정은 AI가 폴더 안에서 그대로 읽으므로 따로 복사하지 않고, 연결을 마치면 첫 질문 제안과 이전 대화 이어가기로 바로 시작할 수 있어요.

#### 사용 방법

프로젝트가 없으면 Project 홈 Develop 화면 위 카드에서 내 폴더 가져오기를 누르세요. 프로젝트 추가 창에서 이 컴퓨터를 골랐을 때의 내 폴더 가져오기, 새 프로젝트 창 기존 폴더 탭의 여러 폴더 살펴보고 가져오기로도 열 수 있어요. 폴더는 목록에서 고르거나 다른 폴더 고르기, 또는 그 영역에 끌어다 놓아 더할 수 있어요. 살펴보기 → 다음 → 연결하기를 누르면 끝납니다. 지금은 buzzni 조직에서만 보이며, 작업PC가 이 컴퓨터이고 온라인일 때 열려요.

### 외부 연동에서 Claude·ChatGPT 계정을 연결할 수 있습니다

외부 연동 화면의 연결됨 영역에서 이 컴퓨터에 연결된 Claude·ChatGPT 계정을 다른 서비스와 함께 볼 수 있습니다. 새로고침하는 동안 기존 연결을 표시합니다. 연결이나 상태 확인이 필요한 계정은 AI 계정 영역에 표시됩니다. 내 설정의 AI Models와 같은 계정 정보를 쓰므로 어느 쪽에서 바꿔도 같은 상태로 보입니다.

#### 사용 방법

사이드바 위쪽 메뉴에서 외부 연동을 누릅니다. AI 계정 영역에서 연결할 AI의 연결 버튼을 누르면 AI 연결 창이 열립니다. 연결됨 영역에서는 AI 계정의 관리(⋮) 메뉴에서 다시 확인, 계정 추가, 연결 해제를 고를 수 있습니다.

### 작업PC 선택 메뉴에서 내 작업PC 이름 바로 바꾸기

프로필 메뉴의 작업PC 목록에서 내가 등록한 작업PC 줄에 마우스를 올리면 연필 버튼이 보여요. 연필을 누르면 이름 변경 창이 열려 설정 화면으로 가지 않고 바로 이름을 바꿀 수 있어요.

#### 사용 방법

사이드바 아래 프로필 버튼 → 작업PC → "내가 등록한 작업PC"의 작업PC 줄에 마우스를 올리고 연필(이름 변경)을 누른 뒤, 새 이름을 입력하고 저장을 누르세요. 이름 변경 창은 입력칸 하나로 간소해졌고, 칸을 비우고 저장하면 원래 이름으로 돌아가요.

### 최근에 작업한 폴더를 골라 프로젝트를 한 번에 만들기

첫 프로젝트를 추가할 때 이 컴퓨터에서 최근 30일 동안 Claude Code·Codex로 작업한 폴더를 찾아 보여 줍니다. 하위 폴더나 워크트리에서 한 작업은 저장소 폴더 하나로 묶고, 이미 프로젝트인 폴더와 홈 폴더는 빼요. 대화가 3개 이상인 폴더는 미리 체크돼 있고, 고른 폴더는 한 번에 프로젝트로 만들어집니다. 세션 내용은 읽지 않고 폴더 경로만 확인해요.

#### 사용 방법

시작준비 마지막 단계에서 프로젝트 추가하기를 누르면 프로젝트 추가 창에 최근에 작업한 폴더가 보입니다. buzzni 조직에서는 내 폴더 가져오기의 첫 화면에 보입니다. 이미 프로젝트가 있다면 새 프로젝트 → 기존 폴더 탭에서 접힌 최근에 작업한 폴더를 펼치세요. 원하는 폴더를 체크하고 선택한 폴더로 프로젝트 만들기를 누릅니다. 작업PC가 이 컴퓨터일 때만 보여요.

### 커넥터 권한이 만료된 대화에 재연결 버튼이 생겼어요

하루를 넘겨 이어 쓰는 대화에서 커넥터 권한을 연장하지 못하고 만료되면, 대화 안에 「커넥터 권한이 만료됐어요」 안내가 나옵니다. 안내 오른쪽의 재연결을 누르면 대화 내용은 그대로 두고 새 권한으로 대화를 다시 시작해, Slack·Notion·Gmail 같은 커넥터를 다시 쓸 수 있습니다. 재연결한 뒤에는 버튼이 사라집니다.

#### 사용 방법

대화 안의 「커넥터 권한이 만료됐어요」 안내 오른쪽에서 재연결을 누르세요. 응답 중이거나 백그라운드 작업·질문·승인 대기가 있으면 끝난 뒤에 누를 수 있고, 작업PC가 켜져 있어야 합니다. 대화 안에 열어 둔 브라우저 같은 실행 중 상태는 다시 시작할 때 닫힙니다.

## 변경된 기능

### 검색 결과의 명령 상세와 생각 과정을 자동으로 펼침

프로젝트 대화에서 명령 인자와 생각 과정 본문은 상세를 펼칠 때 처리합니다. 검색 결과로 이동하면 해당 상세가 자동으로 펼쳐집니다.

#### 사용 방법

명령 실행 행이나 ‘생각 과정 보기’를 누르면 상세가 열립니다. 대화 검색에서 해당 항목을 찾으면 상세가 바로 열립니다.

### 내장 Happy 런타임을 1.1.10-aplus.424로 올렸습니다

Desktop에 내장된 Happy 런타임을 `1.1.10-aplus.424`로 올렸습니다. 작업PC가 Codex 자동 모델의 GPT-6.2 Sol 단계를 알아보고, 조직이 GPT-6.2를 아직 허용하지 않았으면 같은 단계의 허용된 이전 모델(예: GPT-6.1 Sol)로 실행합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 내장 Happy 런타임을 1.1.10-aplus.426으로 올렸습니다

Desktop에 내장된 Happy 런타임을 `1.1.10-aplus.426`로 올렸습니다. `/compact` 후에도 대화가 무진행 상한까지 '응답 중'으로 머물던 문제가 끝나면 바로 닫힙니다. 조직 계정 한도·인증 거부는 '이 PC에서 시작하지 못함' 대신 실제 거절 사유로 표시되고, 이미 답이 온 대화에 빈 실패 턴이 덧붙지 않습니다. Codex로 같은 대화를 잇다가 일시적인 잠금 충돌을 만나면 한 번 다시 시도합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 대화의 ‘새 메시지’ 구분선 제거

프로젝트 대화와 개인 Chat에서 자리를 비운 사이 도착한 답변이 구분선 없이 대화 기록에 이어서 표시됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 대화의 중간 작업을 한 줄로 접어 보기

프로젝트 대화에서 완료된 도구 실행과 생각 과정을 한 줄로 접어 보여줍니다. 파일 읽기, 파일 수정, 명령 실행처럼 작업 종류와 횟수를 펼치기 전에 확인할 수 있습니다. 실행 중인 도구는 바로 보이고, 완료되면 요약 줄에 포함됩니다. 답변과 작업 과정 주변 간격을 줄여 이전 대화를 쉽게 훑을 수 있습니다.

#### 사용 방법

작업 과정 줄을 눌러 도구와 생각 과정을 펼칩니다. 같은 줄을 다시 누르면 접힙니다. 대화 검색에서 접힌 항목으로 이동하면 해당 과정이 자동으로 열립니다.

### 파일 복원지점 조회 안내를 패널 안에서 확인

파일 복원지점을 다시 불러오지 못했을 때, 패널을 펼치면 실패 안내와 새로고침 버튼이 보여요.

#### 사용 방법

대화 입력창 위의 파일 복원지점을 펼친 뒤 오른쪽 위 새로고침을 누르면 다시 불러와요.

### Codex 자동 모델과 독립 리뷰가 GPT-6.2를 사용합니다

Codex에서 AI 자동을 쓰면 보통·어려운 요청과 막힌 대화의 단계가 GPT-6.1 Sol 대신 GPT-6.2 Sol로 실행됩니다. 강도는 이전과 같습니다. 독립 리뷰가 Codex로 자동 선택될 때는 GPT-6.2 Astra · Medium을 씁니다. ChatGPT 계정이 GPT-6.2 Sol을 쓸 수 없으면 GPT-6.1 Sol로 자동으로 내려갑니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### Codex에서 GPT-6.2 Sol·GPT-6.2 Astra를 고를 수 있습니다

Codex 모델 목록 맨 위에 GPT-6.2 Sol과 GPT-6.2 Astra가 추가됩니다. 두 모델 모두 기본 강도는 Low이고 Ultra까지 고를 수 있습니다. GPT-6.1 Sol과 GPT-6 Astra는 이전 모델 묶음으로 옮겨지며, 이미 이 모델로 정해 둔 대화는 그대로 이어집니다.

#### 사용 방법

입력창 아래 AI 버튼에서 Codex를 열고 GPT-6.2 Sol 또는 GPT-6.2 Astra를 고릅니다. 실행하는 컴퓨터의 Codex CLI가 0.166.0 이상이어야 합니다.

### Google 로그인 버튼을 로그인 바로 아래로 옮겼습니다

`Google로 계속하기` 버튼이 `로그인` 바로 아래에 표시되며, 문구 앞에 Google 아이콘이 붙습니다. Shift를 누른 동안에도 기본 버튼에는 `로그인`이 표시됩니다.

#### 사용 방법

로그인 화면에서 `로그인` 아래의 `Google로 계속하기`를 누릅니다. Google 로그인을 지원하는 서버에서 버튼이 표시됩니다.

### Windows 설치 중 진행 상황이 더 자세히 보입니다

Windows 설치 프로그램이 설치 중 지금 하는 일을 진행 막대 위에 한 줄로 보여줍니다. 압축을 푸는 동안에는 "압축 해제 중 57% (120 / 210 MB)"처럼 진행률과 용량이 함께 올라갑니다. 기존 버전 정리나 설치 폴더로 파일을 옮기는 단계처럼 시간을 미리 알 수 없는 구간에서도 막대가 계속 움직여서, 설치가 멈춘 것처럼 보이지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

## 수정된 문제

### 개인 Claude를 끈 PC에서 조직 계정 대화가 잠깐 신호를 놓쳐도 메시지를 보냅니다

개인 Claude 사용을 끈 PC에서 조직 계정으로 실행 중인 대화에 메시지를 보낼 때, "이 대화가 조직 계정으로 실행되는지 확인하지 못해 보내지 않았어요"라며 전송이 막히는 경우가 있었습니다. 대화가 실제로는 조직 계정으로 돌고 있었는데도, 실행 계정 확인 신호가 30초 동안 앱에 도착하지 않으면 막혔습니다. 이제 지금 실행 중인 대화에서 조직 계정을 한 번 확인했다면, 그 실행이 끝나거나 연결이 다시 맺어질 때까지 그대로 보냅니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 긴 대화의 이전 기록을 한 번에 표시

접힌 작업 묶음은 요약만 표시하고, 펼칠 때 도구 실행과 생각 과정 행을 만듭니다. 프로젝트의 ‘이전 대화’를 한 번 누르면 도구 기록 사이에 흩어진 본문을 묶어서 표시합니다. 이미 받은 기록을 우선 사용하고, 읽던 위치와 재시도 버튼의 자리를 유지합니다.

#### 사용 방법

대화 상단의 ‘이전 대화’를 누릅니다. 개별 실행 내역은 작업 요약을 눌러 확인할 수 있습니다.

### 긴 프로젝트 대화를 최신 답변부터 빠르게 열어요

프로젝트 대화는 최신 기록부터 짧게 열립니다. 기록을 받아오는 동안 대화 본문에서 진행 상태를 볼 수 있습니다. 이전 대화를 불러오면서 읽던 메시지가 작업 그룹에 들어가면 해당 그룹을 펼쳐 같은 자리에 표시합니다.

#### 사용 방법

프로젝트에서 대화를 선택하세요. 과거 기록이 더 필요하면 본문 맨 위의 ‘이전 대화’를 누르세요. 이전 기록을 불러오지 못하면 같은 버튼에서 재시도할 수 있고, 첫 기록 조회에 실패하면 본문의 ‘대화 다시 불러오기’를 누르세요.

### 앱을 다시 열고 보낸 메시지가 예전 실패 때문에 멈춘 것처럼 보이던 문제 수정

앱이 꺼져 있거나 잠든 사이 다른 기기에서 실패한 응답이 있었으면, 앱을 다시 열고 메시지를 보냈을 때 그 예전 실패가 방금 보낸 메시지의 응답을 닫는 경우가 있었습니다. 그러면 새 응답이 실제로는 진행 중인데도 '작업 중' 표시가 잠깐 꺼졌습니다. 이제 예전 실패는 예전 대화의 결과로만 표시되고, 방금 보낸 메시지의 응답은 끝날 때까지 '작업 중'으로 유지됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 응답 완료 뒤 대기 중인 요청 자동 전송

응답이 끝났는데도 다음 요청이 대기열에 남는 경우를 수정했어요. 응답 완료가 확인되면 가장 오래된 요청 하나를 자동으로 보내요.

#### 사용 방법

### 이름만 적힌 결과 파일을 하위 폴더에서도 찾아 내 문서에 넣기

AI 답변이 `documents/` 폴더에 만든 파일을 폴더 없이 `report.csv`처럼 이름만 적으면, 파일이 있는데도 "파일 없음"으로 표시됐습니다. 이때 "내 문서에 넣기"를 누르면 `ENOENT: no such file or directory` 원문 오류가 떴습니다. 프로젝트가 크거나 `.gitignore`에 들어간 폴더(예: `documents/`)에 파일이 있으면 생기던 문제입니다. 이제 작업 PC에서 같은 이름의 파일을 직접 찾아 열고, 저장하고, 내 문서에 넣습니다. 같은 이름의 파일이 여러 개면 고르라고 안내합니다. 파일을 정말 찾지 못하면 원문 오류 대신 원본이 만들어졌는지 확인하라는 안내를 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 답변 속 파일 이름 옆의 더보기(…) → 내 문서에 넣기를 누르세요.

### Codex CLI 자동 업데이트가 대화에서 쓰는 Codex를 실제로 올리도록 수정

새 모델을 고르면 이 컴퓨터의 Codex CLI가 오래됐다는 이유로 실패할 때가 있어요. 이때 Saycode가 Codex CLI를 자동으로 업데이트하고 요청을 한 번 다시 보내요. 그런데 npm으로 설치한 Codex는 업데이트가 다른 폴더에 설치돼, 완료 안내가 나와도 대화가 쓰는 Codex는 그대로인 경우가 있었어요. 이제 대화가 쓰는 Codex를 올리고, 버전이 실제로 올랐을 때만 완료 안내를 보이고 다시 보내요. Windows에서 npm으로 설치한 Codex도 자동 업데이트를 실행할 수 있게 했어요. alpha 버전은 정식 버전으로 내려가지 않도록 자동 업데이트하지 않아요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 자동 업데이트가 실패하면 안내에 나온 이유를 확인하고 터미널에서 Codex CLI를 업데이트한 뒤 다시 시도하세요.
