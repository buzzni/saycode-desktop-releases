## 새 기능

### 교훈과 검토 후보를 메모리 화면에서 관리합니다

메모리 화면에서 대화 교훈과 검토 후보를 조회하고, 후보를 승인·거절하거나 교훈을 다음 대화의 회수 대상에서 제외할 수 있습니다. 조회 실패를 빈 저장소로 잘못 표시하던 문제도 수정합니다.

#### 사용 방법

메모리 화면의 교훈 탭에서 내용을 확인합니다. 호환되는 서버·실행 도구 설치가 필요하며 현재 변경은 통합 검증 중입니다. 로그인된 Claude Code·Codex 세션에서는 교훈 후보를 자동으로 만들며 이 기능은 기본으로 켜져 있습니다. 후보는 사용자가 승인해야 다음 대화에서 쓰입니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1034)

### 대화에서 실행 머신의 자원 사용량을 확인할 수 있습니다

프로젝트 대화와 개인 대화의 헤더에서 실행 머신의 CPU 사용률, 메모리 사용량과 load average를 확인할 수 있습니다. 여러 대화나 창이 같은 머신을 표시해도 측정 결과를 공유하며, 연결이 끊겼다가 복구되면 다시 갱신합니다.

#### 사용 방법

자원 수집을 지원하는 Happy CLI로 실행 머신을 업데이트한 뒤 대화 헤더의 자원 표시를 열어 상세 정보를 확인하세요. 연결 상태나 지원 여부에 따라 측정값을 표시하지 못할 수 있습니다. Desktop에 포함되는 런타임은 해당 CLI 릴리스와 runtime pin 갱신 후 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1030)

Web과 공통인 프로젝트·Work 탐색, 프로젝트 생성, 설정과 입력창의 배치를 통일했습니다. 프로젝트 도구는 더보기로 모으고 미리보기는 연속된 분할 화면으로 정리했습니다. 코드 리뷰, 자동화, 에이전트 보드, Model Auto Router와 AI 계정 기능은 계속 사용할 수 있습니다.

#### 사용 방법

## 수정된 문제

### 개발 실행 시 기존 로컬 서버의 서명을 자동으로 준비합니다

기존에 빌드한 로컬 서버의 서명이 잘못된 경우, 개발 앱을 시작하기 전에 복구하고 검증합니다. 소스 업데이트 후에도 예전 실행 파일을 사용해 로컬 모드가 계속 실패하던 경로를 보완했습니다.

#### 사용 방법

수정된 코드에서 `npm run dev`를 실행하면 자동 적용됩니다. 이번 서명 복구를 위해 Happy 원본 저장소를 받거나 서버 전체를 재빌드할 필요는 없습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1023)

### 개발 환경에서 로컬 전용 모드가 서명 문제로 시작되지 않던 문제를 고쳤습니다

개발 실행(`npm run dev`)에서 내장 서버 실행 파일의 코드 서명이 실제 바이트와 어긋나 있으면 macOS가 실행 즉시 프로세스를 강제 종료해, 아무 로그 없이 "happy-server migrate terminated by SIGKILL"만 표시됐습니다. 이제 시작 전에 서명을 확인하고 개발용 런타임은 ad-hoc 서명으로 복구하며, 복구되지 않으면 다시 스테이징하라는 안내를 표시합니다. 설치된 앱의 서명은 건드리지 않습니다.

#### 사용 방법

개발 환경에서 로컬 전용 모드를 다시 시작하면 자동으로 적용됩니다. 별도 조작은 필요 없습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1041)

### 개인·전용 머신과 대화 이어가기에서도 커넥터가 연결됨

등록된 머신에서 새 대화를 시작하거나 기존 대화를 다시 이어갈 때, Notion·Slack·Google Drive·Gmail 같은 개인 커넥터가 연결되지 않은 채로 세션이 시작될 수 있던 문제를 수정했습니다. 이전에는 공용 머신과 일부 조직 채팅에서만 사용자 증명이 전달되어, 개인·전용 머신의 프로젝트 대화나 잠시 멈췄다가 다시 이어가는 대화에서 커넥터 도구가 조용히 빠졌습니다. 이제 사용자 증명이 필요한 경우에는 준비에 실패하면 커넥터 없는 대화를 만드는 대신 이유를 알려주며 시작을 중단합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 머신의 Saycode 실행기가 오래되어 사용자별 커넥터를 전달할 수 없으면 대화 시작 시 업그레이드 안내가 표시되며, 안내대로 머신에서 실행기를 갱신하고 다시 시작하면 됩니다.

### 기존 Codex 대화에서 로그인 다시 적용

Codex 인증 또는 사용량 오류 후 로그인을 변경했을 때, 기존 대화에 새 로그인을 다시 적용하는 복구 기능을 추가했습니다. 복구는 기존 대화 문맥을 유지하며 실패한 요청을 자동으로 다시 보내지 않습니다.

#### 사용 방법

대화를 실행하는 머신에서 Codex 로그인을 변경한 다음, 오류 아래의 로그인 복구 안내에서 다시 적용을 선택하세요. 응답이나 승인 요청이 진행 중이면 먼저 종료해야 합니다. 복구 결과를 확인한 뒤 메시지를 보내세요. 구형 런타임이나 조직 관리 인증에서는 복구가 제공되지 않으며, 프록시 인증은 실제 사용 계정과 한도를 별도로 확인해야 합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1050)
