## 새 기능

### 문서 양식 확장으로 채팅 입력창에 양식을 추가할 수 있습니다

문서 양식 확장을 설치하면 이미 진행 중인 개인 대화와 프로젝트 대화 입력창의 "문서 양식" 버튼에서 기본 제공 양식과 내 개인 양식을 고를 수 있습니다.

#### 사용 방법

새 Work 대화 홈에서는 기존처럼 입력창의 문서 형식 선택에서 양식을 고릅니다. 이 화면에는 확장 버튼이 따로 나오지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1182)

### Windows: Node.js·uv·Git이 없으면 Saycode가 자동으로 설치합니다

지금까지는 Windows에서 Node.js(npm)·uv·Git이 없으면 첫 실행 준비가 설치 안내에서 멈췄고, 사용자가 세 도구를 직접 설치해야 했습니다. 이제는 자동 진행이 없는 도구를 직접 설치합니다.

#### 사용 방법

별도 설정 없이 첫 실행 준비에서 자동으로 진행됩니다. 직접 설치하려면 "필수 도구 자동 설치" 카드에서 **직접 설치할게요**를 누르세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1261)

## 변경된 기능

### 내가 등록한 머신을 쉽게 찾기

머신 설정과 머신 선택 메뉴를 ‘내가 등록한 머신 / 다른 머신’으로 구분하고, 이 컴퓨터를 내 목록 맨 위에 표시합니다. 기존 머신 이름은 유지합니다. 온보딩으로 새로 등록하면 이메일 앞부분을 사용한 ‘000 작업 공간’ 이름을 기본으로 저장합니다.

#### 사용 방법

설정의 머신 또는 계정 메뉴의 머신 선택에서 확인할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1228)

### 대화 탭과 프로젝트별 복원

Chat과 프로젝트에서 여러 대화를 탭으로 열 수 있습니다. 프로젝트별로 열린 대화와 마지막 선택을 기억하며, 다른 프로젝트로 이동하거나 앱을 다시 열면 복원합니다. 탭에는 대화 제목만 표시합니다.

#### 사용 방법

사이드바에서 대화를 선택하면 탭이 추가되고, 이미 열린 대화는 해당 탭으로 이동합니다. 대화 헤더의 새 대화 아이콘으로 새 탭을 열 수 있습니다.

### 미리보기와 작업 도구가 대화별로 복원됩니다

프로젝트 미리보기의 탭 이름에 프로젝트명을 표시하고, 본문 조작 행을 브라우저와 같은 크기의 아이콘 행으로 정리했습니다. 리슨 포트 목록은 현재 대화의 작업 사본에 속한 포트만 중앙 창에 표시합니다. 다른 대화로 이동하면 그 대화에서 열었던 우측 도구 탭을 보여주며, 연 탭이 없는 대화에서는 우측 패널을 닫습니다.

#### 사용 방법

미리보기 탭의 리슨 포트 아이콘을 눌러 목록을 확인하세요. 로컬 프로젝트는 선택한 포트를 브라우저에서 직접 열고, 클라우드 프로젝트는 기존 터널 연결을 사용합니다. 터미널과 브라우저 탭은 왼쪽에 먼저 표시됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1218)

#### 사용 방법

업데이트 카드의 버튼으로 다운로드와 재시작을 진행합니다. Release notes를 누르면 우측 패널에서 릴리스 내용을 볼 수 있습니다.

### 온보딩 필수 준비와 추가 설정을 구분했습니다

CLI 도구 준비 뒤 컴퓨터를 등록하고, 필수 설정이 끝나면 완료를 표시합니다. 조직이 하나면 자동 선택합니다. macOS와 Windows에서 uv·Git·Node.js/npm을 확인하며 Claude Code·Codex도 CLI 준비 단계에서 설치합니다. 추가 도구는 설치 수만 표시하고 펼친 목록에서 진행 상태를 확인할 수 있습니다.

#### 사용 방법

온보딩에서 CLI 도구를 준비한 뒤 컴퓨터 등록을 완료하세요. 추가 도구 제목을 눌러 설치 상태를 펼치거나 설치 개수 오른쪽의 다시 확인 버튼으로 상태를 갱신할 수 있습니다. 필수 설정이 끝나면 계속으로 추가 설정을 확인하거나 완료로 온보딩을 마칠 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1272)

### 온보딩에서 현재 AI 계정 자동 등록

이 컴퓨터에서 로그인한 Claude/Codex 계정을 계정 관리 도구에 등록하고 현재 계정으로 선택합니다. Claude는 cswap, Codex는 codex-multi-auth를 사용합니다. 이미 등록된 계정은 중복 추가하지 않으며 기존 Codex 저장 토큰을 유지합니다. 등록 중·실패·인증 갱신 필요 상태와 재시도를 제공합니다. 하나의 AI가 준비되면 계속 진행합니다.

#### 사용 방법

온보딩 자동 진행을 시작하세요. Codex 로그인 정보가 만료됐거나 OAuth 정보를 가져올 수 없으면 codex-multi-auth login으로 로그인 후 다시 시도하세요. 좌측 하단 … → AI 잔여량 보이기에서 중앙 패널 우측 상단 표시를 켜고 눌러 계정을 전환할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1228)

### 온보딩에서 Saycode 지시 사용 여부 선택

앱을 처음 열 때 별도 모달 대신 온보딩의 추가 설정에서 Saycode 지시 사용 여부를 선택합니다. 기본값은 사용 안 하기이며, 선택한 버튼에 테두리와 체크 표시가 나타납니다. 필수 설정을 마치면 선택 단계를 나중에 진행하고 바로 시작할 수 있습니다.

#### 사용 방법

온보딩의 추가 설정 → Saycode 지시 사용에서 사용하기 또는 사용 안 하기를 선택하세요. 나중에는 환경설정 → 시스템 프롬프트에서 변경할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1269)

### 웹 기준으로 채팅 가독성과 실행 표시를 개선했습니다

프로젝트와 개인 채팅의 본문·목록·코드 간격과 읽기 폭을 웹 기준으로 맞췄습니다. Saycode 로고와 Working 진행 표시, 도구별 실행 아이콘과 완료 체크를 제공하고 일반 실행 내역은 간결한 행으로 정리했습니다. Thinking은 기본으로 접혀 있으며 검색 결과가 있으면 펼쳐집니다.

#### 사용 방법

별도 설정 없이 적용됩니다. 실행 내역과 Thinking을 눌러 상세 내용을 확인할 수 있습니다. 움직임 줄이기 설정에서는 진행 로고가 정적으로 표시됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1242)

### 작업공간 탭 이동과 터미널 단축키 개선

우측 도구 탭을 드래그해 순서를 바꿀 수 있습니다. 중앙과 우측 탭의 닫기 버튼에 Cmd + W를 표시하며, 단축키는 마지막으로 조작한 영역의 탭을 닫습니다. 마지막 대화 탭을 닫아도 창은 유지됩니다.

#### 사용 방법

탭을 원하는 위치로 드래그합니다. 닫을 탭이 있는 영역을 클릭하거나 키보드로 포커스한 뒤 Cmd + W를 누릅니다. 새 터미널은 Ctrl + 백틱 또는 추가 메뉴에서 엽니다.

### 조직 검색(Elasticsearch) 설정을 계정 메뉴에서 바로 엽니다

조직 관리 메뉴는 웹 관리 페이지로 열리지만, 웹 관리 페이지에는 Elasticsearch 연동 설정이 없습니다. 사내망 Elasticsearch 연결 확인과 대화 색인은 데스크톱에서 이뤄지므로, 조직 검색 설정은 데스크톱 창에서 계속 열 수 있게 했습니다. 연결 테스트, 인덱스 생성, 색인 진행률, 권한 동기화, 검색 품질 평가, 연결 해제를 이 창에서 할 수 있습니다.

#### 사용 방법

조직 owner 또는 admin 계정으로 사이드바 아래 계정 메뉴를 열고 `조직 검색 설정`을 누릅니다. 조직 선택 메뉴에도 같은 항목이 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1288)

C:\ 드라이브 루트에 `BUILTIN\Users` 모든 권한이 걸린 PC가 있습니다(Windows 기본값은 읽기·실행). 이런 PC에서는 로그인이 끝나도 "Credential ancestor permits replacement by another principal" 오류로 로그인 정보가 저장되지 않았습니다. Saycode는 로그인 정보를 저장하기 전에, 다른 계정이 그 경로를 바꿔치기할 수 있는 상위 폴더가 있는지 검사합니다. 이 검사가 루트의 넓은 권한을 위험으로 판단했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1249)

### Windows에서 "AI 계정·사용량" 패널과 계정 전환이 동작합니다

Windows 컴퓨터에서 "AI 계정·사용량" 패널이 사용량 대신 아주 긴 명령과 "Command failed"를 보여 줬습니다. 사용량을 확인하는 스크립트를 명령줄에 통째로 실어 보냈는데, 그 길이(28,755자)가 Windows 명령줄 한도(8,191자)를 넘었기 때문입니다. 이제 스크립트를 그 컴퓨터에 파일로 보내고 짧은 명령으로 실행합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.
