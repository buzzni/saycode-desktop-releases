## 새 기능

### 검색 결과에서 대화로 바로 이동

전체 검색의 의미 기반 결과를 클릭하면 그 대화가 속한 프로젝트를 찾아 대화를 바로 엽니다. 다른 프로젝트나 공유받은 범위의 대화도 정확히 열립니다.

#### 사용 방법

검색 결과를 클릭합니다. Saycode 대화와 연결되지 않은 결과는 기존처럼 내용만 보여줍니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/434)

### 내 채팅에서 모델과 effort 선택

프로젝트 대화에서 쓰던 모델·effort 선택 바를 내 채팅에도 적용했습니다. 선택은 대화별로 저장되어 다음 메시지에 반영됩니다.

#### 사용 방법

내 채팅 대화 화면의 입력창 위에서 모델과 effort를 고릅니다. 기본값을 유지하면 자동 선택이 그대로 동작합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/428)

### 내 채팅이 만든 파일 자동 미리보기

내 채팅에서 에이전트가 파일을 만들어 응답을 마치면 오른쪽 미리보기 패널이 자동으로 열립니다. 지난 메시지를 불러오거나 화면을 다시 그릴 때는 열리지 않고, 사용자가 닫은 결과는 다시 열지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/420)

### 답변 속 파일 경로를 눌러 미리보기 열기

에이전트 답변에 나오는 파일 경로가 자동으로 링크로 표시되고, 클릭하면 오른쪽 파일 미리보기에서 그 파일이 열립니다. 프로젝트 경계를 벗어나는 경로는 열리지 않습니다.

#### 사용 방법

답변에 표시된 파일 경로를 클릭합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/427)

### 브라우저 오류 전달, 작업 완료 신호, 반복 감지, 스킬 카탈로그

앱 안 브라우저에서 발생한 콘솔·네트워크 오류를 민감한 값을 가린 채 채팅 입력창 초안으로 옮길 수 있습니다. 에이전트가 작업 완료를 명시적으로 알리는 신호를 도입해, 자동 Commit & PR이 그 신호 없이는 실행되지 않도록 했습니다. 같은 도구 호출이나 같은 문장을 반복하며 맴도는 상태를 감지해 알려주고(자동 중지는 기본 꺼짐), 자주 쓰는 절차를 스킬로 만들어 원격 머신에 배포할 수 있습니다. CI 실패 중 형식·린트 문제는 에이전트를 부르지 않고 정해진 명령으로 바로 처리합니다.

#### 사용 방법

브라우저 패널의 오류 전달 버튼, 보드의 반복 감지 설정, 설정 화면의 스킬 카탈로그를 각각 사용합니다. 반복 자동 중지는 켜야 동작합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/449)

### 자동화와 GitHub 트리거의 실행 에이전트 선택

항상 Claude로만 실행되던 예약 자동화와 GitHub 트리거를 등록할 때 원하는 에이전트로 고를 수 있습니다. 이전에 등록해 둔 자동화는 그대로 동작합니다.

#### 사용 방법

프로젝트 설정에서 자동화나 트리거를 등록하거나 편집할 때 에이전트를 선택합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/407)

### 프로젝트 대화 목록 검색

선택한 프로젝트의 대화 목록에서 제목, 내가 보낸 내용, 에이전트 답변을 검색할 수 있습니다. 제목이 가장 위에, 그다음 내가 보낸 내용, 답변 순으로 정렬됩니다.

#### 사용 방법

프로젝트의 대화 목록 위 검색란에 찾을 내용을 입력합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/456)

### GitHub 트리거의 실행 계정 선택

회사 프로젝트의 GitHub 트리거에서 어떤 GitHub 자격 증명으로 실행할지 고를 수 있습니다. 선택한 토큰은 그 세션에만 전달되고, 삭제되었거나 권한이 회수된 경우 사람 계정으로 대신 실행하지 않고 실패 처리합니다.

#### 사용 방법

프로젝트 설정의 GitHub 트리거에서 실행 계정을 선택합니다. 프로젝트 저장소로 범위를 제한한 토큰 사용을 권장합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/453)

### PR 리뷰 + 후속 수정 프리셋

리뷰만 하던 기존 PR 자동 리뷰 프리셋에 더해, 확인된 지적 사항에 한해 수정 커밋까지 만드는 프리셋을 추가했습니다. PR 상태에 따라 동작이 갈리는데, 이미 병합된 PR은 새 브랜치와 초안 PR을 만들고, 열려 있는 내 PR은 승인을 받은 뒤에만 반영하며, 다른 사람의 PR과 닫힌 PR은 수정하지 않습니다.

#### 사용 방법

프로젝트 설정의 GitHub 트리거 편집 화면에서 프리셋 삽입 버튼을 누릅니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/409)

### VS Code 확장과 Saycode CLI 공개

원격 머신에 로그인된 에이전트를 VS Code 안에서 쓸 수 있는 확장과, 터미널에서 세션을 보고 대화할 수 있는 Saycode CLI를 공개했습니다. 데스크탑 앱과 같은 계정·프로젝트·대화에 접근합니다. 데스크탑 앱의 동작에는 영향이 없습니다.

#### 사용 방법

VS Code 확장은 Marketplace에서 설치하고, CLI는 npm으로 설치합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/410)

#### 사용 방법

## 수정된 문제

### 다른 조직에서 만든 내 채팅의 내용이 비어 보이던 문제

내 채팅 목록은 계정 단위인데 대화 내용은 조직 단위로 관리되어, 다른 조직에서 만든 대화를 열면 제목만 있고 본문이 텅 빈 화면이 아무 설명 없이 나오던 문제를 수정했습니다. 이제 해당 조직으로 전환해 내용을 불러옵니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/411)

### 대화 검색에서 결과가 누락되던 문제

검색 결과가 실제 일치하는 대화보다 훨씬 적게 나오던 문제 세 가지를 수정했습니다. 아직 불러오지 않은 대화가 내 대화 범위에서 통째로 빠지던 문제, 답변이 긴 대화 하나가 결과 상한을 차지해 다른 대화를 가리던 문제, 색인 작업이 오랫동안 진행되지 않던 문제입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 업데이트 후 첫 실행 시 검색 색인을 다시 만듭니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/406)

### 대화 창 헤더에 프로젝트 설정 버튼이 없던 문제

집중형 대화 창에서만 프로젝트 설정 버튼이 더보기 메뉴 뒤에 숨어 있던 것을, 다른 화면과 같이 제목 옆에 항상 보이도록 했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/412)

### 대화를 열기만 해도 최근 대화 날짜가 지금으로 바뀌던 문제

오래된 대화를 열어보기만 해도 목록의 시각이 방금 전으로 바뀌어, 대화한 적 없는 항목이 최신으로 올라오던 문제를 수정했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/400)

### 독립 리뷰가 이전 결과나 안내 문구를 결과로 잡던 문제

리뷰 대화의 마지막 메시지가 결과가 아닌 안내 문구여도 앞선 실제 리뷰 결과를 고르도록 하고, 이번 실행보다 앞선 메시지는 결과로 쓰지 않도록 했습니다.

#### 사용 방법
