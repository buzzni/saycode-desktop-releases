## 새 기능

### 내 설정에서 AI 브라우저 상태와 사용 방법을 확인해요

내 설정 AI 그룹에 `AI 브라우저` 항목이 생겼습니다. 맨 위에서 이 PC의 AI 브라우저가 준비됐는지 입력창과 같은 기준으로 보여 주고, Chrome이 필요하면 `다시 확인`, 준비에 실패하면 `다시 시도`를 바로 누를 수 있습니다. 아래에는 준비 → 사이트 직접 로그인 → 입력창에서 요청하기 세 단계와 복사해 쓸 수 있는 예시 요청이 있습니다. AI 브라우저는 내 Chrome과 분리된 전용 창이라, 로그인이 필요한 사이트는 그 창에서 한 번 직접 로그인하면 이 PC의 AI 브라우저에 유지된다는 점도 안내합니다.

#### 사용 방법

내 설정 → AI → AI 브라우저를 여세요. 예시 요청의 `예시 요청 복사`를 누른 뒤 입력창 `+ → 이번 요청에 브라우저 사용`을 고르고 붙여 넣어 보내면 됩니다.

### 다른 작업PC에 일 맡기기

작업PC 설정에서 두 작업PC를 연결하면, 한 PC의 대화(AI)가 연결된 다른 PC에 새 대화를 만들어 일을 맡기고 결과를 확인할 수 있습니다. 예를 들어 노트북 대화에서 공용 빌드 PC에 전체 테스트를 맡기거나, macOS 대화에서 Windows PC에 설치본 빌드를 맡길 수 있습니다. 맡겨진 대화는 받는 PC의 정책(샌드박스·AI 계정)으로 실행되고, 보낸 대화의 자식 AI도구 목록에 작업PC 이름과 함께 보이며, 권한 요청은 받는 PC의 대화에서 직접 답합니다. 대화가 받는 PC에서 종단간 암호화된 경우, 보낸 쪽 AI는 그 대화를 시작·중단할 수 있지만 내용을 읽거나 이어서 지시하는 일은 Desktop에서 직접 확인해야 합니다. 작업PC 연결은 이 버전에 들어 있는 실행 도구에서 동작하지만, AI가 다른 PC에 대화를 만들어 일을 맡기는 부분은 이 기능을 담은 다음 Saycode 실행 도구 업데이트 뒤에 동작합니다.

#### 사용 방법

내 설정 → 개발 → 작업PC에서 일을 받을 PC의 행에 있는 **다른 PC에서 작업 받기**를 누르고, 일을 보낼 PC의 스위치를 켭니다. 두 PC 모두 켜져 있고 최신 Saycode여야 합니다. 끄면 받는 PC가 즉시 거절합니다.

### 변경 요약에서 그 턴의 변경을 바로 열 수 있어요

Project 대화의 "파일 N개를 편집했습니다" 요약 줄 오른쪽에 "이 턴 변경 보기" 버튼이 생겼습니다. 누르면 오른쪽 변경 탭이 "턴별 · 이 턴" 범위로 열립니다. 예전 턴의 요약에서 누르면 그 턴의 변경을 열고, "최근 턴으로"를 누르면 가장 최근 턴으로 돌아갑니다. 턴별 범위를 쓸 수 없는 대화와, 기록이 남지 않은 예전 턴에는 버튼이 없습니다.

#### 사용 방법

Project → 대화 → "파일 N개를 편집했습니다" 줄의 "이 턴 변경 보기" → 오른쪽 변경 탭에서 파일 확인.

### 보안 강화 작업PC의 AI 브라우저 화면을 다른 PC에서도 볼 수 있어요

보안 강화(strict) 모드인 원격 Mac 작업PC에서 실행된 대화는 다른 PC에서 "AI 브라우저"를 눌러도 콘솔이 열리지 않았어요. 이제 대화의 원격 Mac 브라우저 화면을 다른 PC에서도 보고 제어권을 가져와 직접 입력할 수 있어요. 화면과 입력은 작업PC 키로 암호화돼 오가서 Saycode 서버가 내용을 볼 수 없어요.

#### 사용 방법

대화 오른쪽 위나 승인 카드의 "AI 브라우저"를 누르면 원격 Mac 화면이 열려요. 작업PC의 Saycode가 이 기능을 지원하는 버전이어야 해요. 지원하지 않으면 업데이트 안내가 보여요. 대화 없이 여는 전체 콘솔은 보안 강화 작업PC에서 열 수 없어요.

### 사이드바에서 시작준비 진행률을 확인해요

시작준비가 끝나지 않았으면 사이드바 아래쪽 계정 바로 위에 진행률 링과 `시작준비 2/3` 같은 한 줄이 보입니다. 이 컴퓨터 연결, AI 연결, 알림 설정 세 가지를 실제 상태로 확인해 세며, 모두 끝나면 저절로 사라집니다. AI 로그인을 확인하지 않는 Windows 버전에서는 이 컴퓨터 연결과 알림 설정 두 가지만 셉니다. 설정 메뉴를 찾지 않고 남은 준비를 바로 이어갈 수 있습니다.

#### 사용 방법

사이드바의 `시작준비` 줄을 누르면 내 설정의 시작준비가 열립니다. 보지 않으려면 줄에 마우스를 올리고 `사이드바에서 숨기기`를 누르세요. 시작준비 화면은 내 설정에 그대로 있습니다.

### 새 대화를 프로젝트 하위 폴더에서 시작

새 프로젝트 대화를 프로젝트 루트가 아닌 하위 폴더에서 시작할 수 있어요. AI가 그 폴더의 `CLAUDE.md`와 `.claude` 설정을 처음부터 읽어서, 모노레포에서 폴더마다 다른 규칙을 쓸 수 있어요. AI가 파일을 고칠 수 있는 범위와 파일 패널·미리보기·Git은 그대로 프로젝트 루트 기준이에요. 그 대화를 이어가거나 다른 AI로 이어가면 같은 하위 폴더에서 다시 시작해요.

#### 사용 방법

새 프로젝트 대화의 입력창 위 옵션 줄에서 `프로젝트 루트` 폴더 버튼을 누르고, 시작할 하위 폴더로 이동한 뒤 `이 폴더 선택`을 누릅니다. 버튼 옆의 X를 누르면 다시 프로젝트 루트에서 시작해요. 고른 폴더는 앱을 닫을 때까지 같은 프로젝트의 다음 새 대화에도 쓰여요.

### 스킬을 잠가 AI가 고치거나 지우지 못하게 할 수 있어요

내 설정 → 스킬에 "스킬 잠금" 목록이 생겼어요. 이 PC의 내 스킬(`~/.claude/skills` 등)과 이 PC에 있는 프로젝트의 스킬이 보이고, 스킬마다 잠금 스위치를 켤 수 있어요. 잠근 스킬은 Claude 대화에서 AI가 파일 편집 도구나 터미널 명령(리다이렉션·복사·이동·삭제·`sed -i`·압축 해제·인라인 코드 등)으로 고치거나 지울 수 없고, 자동 승인 모드에서도 막혀요. 읽기와 스킬 스크립트 실행은 그대로 돼요. 실행한 스크립트가 스스로 쓰는 것까지 막는 샌드박스는 아니며, Codex 대화에는 아직 적용되지 않아요. 잠금 설정 파일이 손상되면 사람이 보지 않는 자동 실행에서는 모든 스킬을 잠근 것으로 다뤄요.

#### 사용 방법

내 설정 → 일반 → 스킬 → 스킬 잠금에서 스킬 이름 옆 스위치를 켜요. "이 작업PC는 잠금을 지원하지 않아요"가 보이면 이 PC의 SayCode 런타임을 업데이트해야 적용돼요.

### 실행기가 다시 시작돼도 같은 PC 터미널 유지

터미널 유지를 지원하는 실행기에서는 업데이트·재시작·비정상 종료 뒤에도 같은 PC로 연 터미널의 셸·dev 서버·tmux가 계속 실행되고, 같은 탭이 새 실행기에 다시 붙어 그동안의 출력을 이어 보여 줍니다. 재시작을 준비하는 동안 터미널 위쪽 줄에 "실행기가 다시 시작돼도 이 터미널은 유지돼요"가 보이고, 유지되지 않는 터미널은 닫히기까지 남은 시간과 이유(다른 PC를 거치는 연결, 실행기 종료, 계정 전환 등)를 보여 줍니다. 작업PC 상세 정보에는 터미널 유지 상태(워커 수·버전·마지막 입양 결과)가 표시됩니다.

#### 사용 방법

별도 조작 없이 자동 적용됩니다. 실행기(happy-cli)의 터미널 유지는 첫 배포에서 선택 사항이며, 지원하지 않거나 켜지 않은 실행기에서는 지금처럼 재시작 전에 닫힘 예고만 보입니다.

### 웹에서 만든 회차별 새 문맥 예약을 앱에서 보고 고칠 수 있습니다

웹에서 "회차마다 새 AI 문맥"으로 만든 예약이 이제 앱의 예약 화면, 대화 머리의 예약 내용, 프로젝트 자동화 설정에 다른 예약과 함께 보입니다. 이런 예약에는 상태 옆에 "격리" 표시가 붙고, 대화 안 예약 화면과 프로젝트 자동화 카드에는 "회차마다 새 AI 문맥으로 실행 · 결과는 이 대화에 기록"과 참고 자료(없음·직전 완료 결과·지정 메모)가 함께 보입니다.
- 할 일·이름·반복과 시각·놓친 실행·결과 보내기·일시정지·삭제·지금 실행을 앱에서 바꿀 수 있고, 저장해도 AI 문맥 방식과 참고 자료·AI·모델은 그대로 유지됩니다. AI 문맥 방식과 참고 자료는 웹에서 바꿉니다.
- 예약을 실행하는 PC의 Saycode가 이 방식을 지원하지 않으면 저장·재개·지금 실행이 잠기고 업데이트 안내가 보입니다. 일시정지·삭제·실행 이력은 그대로 쓸 수 있습니다.
- 이 버전의 앱이 아직 표시하지 못하는 새로운 종류의 예약만 있을 때, 예전처럼 "예약을 불러오지 못했습니다"와 다시 확인을 반복하지 않고 "이 버전의 앱이 아직 표시하지 않는 예약 N개가 있어요" 안내만 보입니다. 사이드바의 시계 표시도 켜집니다.

#### 사용 방법

사이드바 → 예약에서 "격리" 표시가 붙은 예약을 찾습니다. 행의 더보기(⋮) → 편집에서 할 일·시각 등을 고치고 고급을 펼치면 읽기 전용 "AI 문맥" 줄에서 현재 참고 자료를 확인할 수 있습니다. 회차별 새 문맥 예약을 새로 만드는 것은 웹에서 합니다.

### 컴퓨터 제어 설정에서 macOS 권한을 하나씩 확인해요 (개발자 기능)

개발자 기능 설정에서 `컴퓨터·브라우저 제어 설정 보이기`를 켜면 내 설정 AI 그룹에 `컴퓨터·브라우저 제어` 항목이 생깁니다. macOS에서는 `손쉬운 사용`과 `화면 기록`을 한 줄씩 보여 주고, 각 줄의 `시스템 설정 열기`가 해당 개인정보 보호 화면을 바로 엽니다. 권한 상태는 화면을 열 때, Cua Driver 설치나 OS 권한 확인이 끝났을 때, 시스템 설정에서 돌아올 때 다시 확인하며, 이 확인은 OS 확인창을 띄우지 않습니다. `허용 필요`인 줄의 `허용 요청`을 누르면 Cua Driver가 macOS에 권한을 요청하고(Cua Driver 창과 macOS 확인창), 해당 시스템 설정 화면과 함께 화면 오른쪽 아래에 작은 안내 패널이 뜹니다. 패널의 Cua Driver 아이콘을 시스템 설정 목록으로 끌어다 놓을 수 있고, 권한이 허용되면 패널은 저절로 닫힙니다. 아직 설치판 검수 중인 기능이라 기본으로는 숨겨져 있습니다.

#### 사용 방법

프로필 메뉴 → 개발자 기능 설정 → `컴퓨터·브라우저 제어 설정 보이기`를 켠 뒤 내 설정 → AI → 컴퓨터·브라우저 제어를 여세요. 권한이 `허용 필요`이면 그 줄의 `허용 요청`을 누르고 macOS 확인창에서 허용하거나, 열린 시스템 설정 목록에서 Cua Driver를 켜세요(목록에 없으면 안내 패널의 아이콘을 끌어다 놓으세요). 끝나면 앱으로 돌아오세요.

### 확장이 새 대화에 환경변수·MCP 서버를 넣고 새 작업트리를 준비합니다

확장(Extension API 4)이 `sessionHooks`로 새 대화·재연결마다 환경변수와 MCP 서버를, `worktreeHooks`로 새 작업트리에 원본의 Git이 무시한 파일을 복사하도록 선언할 수 있습니다. 확장 카드의 `sessions.launchEnvironment`·`worktrees.prepare` 권한 행에 넣을 이름, 비밀 표시, MCP 실행·접속 줄, 복사할 경로가 보이며 승인은 이 선언에 묶입니다. 값은 Saycode가 OS 키체인으로 암호화해 보관하고, 비밀 값은 화면·로그·대화 정보에 남지 않습니다. 훅이 실패하거나 이름이 겹쳐도 대화와 작업트리는 그대로 시작하고 안내만 표시합니다. 작업PC 실행 도구가 MCP 주입을 지원하지 않으면 환경변수만 넣습니다.

#### 사용 방법

내 설정 → 개발 → 확장에서 이 기능을 쓰는 확장을 설치하고, 권한 행에서 넣을 항목을 확인한 뒤 승인합니다. 값이 필요한 이름은 입력칸에 넣고 저장을 누릅니다. 새 대화 화면의 옵션 줄 '확장 · env N · MCP M'에서 이 대화에 들어갈 항목을 미리 볼 수 있습니다. MCP 서버 주입은 작업PC의 실행기가 이 Desktop에 들어 있는 버전(Happy CLI 1.1.10-aplus.402) 이상일 때 적용되고, 그보다 오래된 원격 작업PC에는 환경변수만 들어갑니다.

### AI 답변에서 바로 "여기까지 갈래"를 만들 수 있어요

Project의 Claude 대화에서 한 턴의 마지막 AI 답변에 마우스를 올리면 "여기까지 갈래" 버튼이 보입니다. 누르면 "같은 AI로 갈래 만들기" 창이 그 답변까지 남기도록 미리 골라진 채 열려서, ⋮ 메뉴를 거치지 않고 한 번에 다른 방향을 시도할 수 있습니다. 화면의 대화와 AI 기록이 맞지 않으면 추측하지 않고 직접 고르게 안내합니다. 원래 대화는 그대로 남습니다.

#### 사용 방법

Project → 대화 → 갈라 낼 AI 답변 위에 마우스를 올리고 갈래 아이콘(여기까지 갈래) → 갈래 만들기.

## 변경된 기능

### 대기열 "지금 반영" 버튼이 하는 일을 툴팁에서 알려 줘요

입력창 위 대기열 항목의 "지금 반영" 버튼에 마우스를 올리면, 이름만 보이던 툴팁이 "지금 반영 — 응답을 멈추지 않고 이 요청을 바로 전달해요 (⌘Enter)"처럼 버튼이 하는 일을 함께 보여 줍니다. 버튼 모양과 동작은 그대로입니다.

#### 사용 방법

AI가 응답하는 동안 요청을 대기열에 넣고 → 항목의 "지금 반영" 버튼에 마우스를 올려 설명 확인 → 누르면 응답을 멈추지 않고 바로 전달.

### 대화의 도구 줄 이름을 읽기 쉽게 바꿨어요

Project 대화에서 AI가 쓴 도구 줄이 더 알아보기 쉬운 이름으로 보입니다. 도구 검색은 "도구 사용" 대신 "도구 검색"으로, Saycode가 제공하는 도구는 "Saycode · 대화 제목 바꾸기"처럼 무엇을 했는지로 보입니다. 다른 서비스의 도구는 "서비스 이름 · 도구 이름"으로 보입니다. 줄 옆에 도구의 원래 이름("… call")이 한 번 더 나오던 것도 없앴습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 시작준비 AI 단계에서 연결하지 않은 AI도 함께 보여요

개인 사용의 시작준비 AI 도구 단계에서 Claude Code나 Codex 중 하나만 연결해도 다른 하나가 사라지지 않고 `연결 안 됨`으로 남습니다. 각 행의 `연결`을 누르면 그 AI의 로그인 단계가 바로 열려, 설정 메뉴를 찾지 않고 두 번째 AI까지 연결할 수 있습니다. 이 컴퓨터에서 확인하지 못한 AI는 `확인 필요`로 표시합니다.

#### 사용 방법

내 설정 → 시작준비 → AI 도구에서 연결하지 않은 AI 행의 `연결`을 누르세요. 조직 계정을 쓰는 화면은 그대로입니다.

### 작업 중 표시에 경과 시간과 진행 중인 도구 수가 보여요

Project 대화에서 AI가 작업하는 동안 보이는 "작업 중..." 줄에, 3초가 지나면 "· 18초"처럼 지금까지 걸린 시간이 붙습니다. AI가 여러 도구를 동시에 쓰고 있으면 "자료 2개 확인 중 · 명령 1개 실행 중"처럼 종류별 개수로 보여 줍니다. 명령이나 파일 경로는 이 줄에 나오지 않습니다. 화면 읽기 프로그램은 경과 시간을 매초 다시 읽지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 조직 AI 계정의 사용자 정원 연결 준비

공식 작업PC 실행기 .401을 고정하고 조직 Claude 요청에 실제 작성자 확인을 연결했습니다. 지원하는 서버와 작업PC 실행기에서 같은 사용자의 여러 대화를 한 명으로 집계하고 계정당 최대 4명 정책을 적용할 수 있도록 준비합니다.

#### 사용 방법

관리자가 서버와 작업PC 실행기를 먼저 업데이트하고 정책을 활성화해야 적용됩니다. 정원이 찬 경우 대화에 대기 안내가 표시됩니다. 사용자를 확인할 수 없는 구버전 입력은 업데이트가 필요합니다.

## 수정된 문제

### 공용 PC 계정이 바뀐 뒤에도 기존 대화를 이어 쓸 수 있습니다

여러 사람이 함께 쓰는 작업PC에서 관리자가 조직 Claude 계정 배정을 바꾸면, 그 전에 시작한 대화는 더 이상 그 PC에 없는 계정을 계속 쓰려고 했습니다. 그래서 메시지를 보낼 때마다 "조직 Claude 계정을 시작할 수 없다"는 오류만 나오고, 새 대화를 열어야만 다시 쓸 수 있었습니다.

이제 그런 대화는 그 PC가 가진 다른 조직 계정으로 자동으로 옮겨 보낸 메시지를 그대로 실행합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 작업PC의 실행기가 이 버전으로 업데이트된 뒤부터 적용됩니다.

### 대화 이동의 빠른 반복 실행 방지

대화 이동을 빠르게 다시 눌러도 같은 작업은 한 번만 실행합니다. 빠른 실패 뒤의 짧은 재입력은 기존 확인과 오류를 유지하며, 작업 중에는 반복 실행되지 않습니다.

#### 사용 방법

프로젝트 대화의 프로젝트 도구 → 대화 이어가기 → 작업트리로 옮기기 또는 본 폴더로 되돌리기에서 자동 적용됩니다. 기존 취소·되돌리기와 재시도 방식은 같습니다.

### 대화의 AI 브라우저 화면에서 입력이 다른 작업으로 새지 않습니다

대화에서 연 AI 브라우저 화면에서 한 작업에서 시작한 한글 조합이 다른 작업 화면에 들어가거나, 이전 작업의 늦게 실패한 입력이 새 화면을 막던 문제를 고쳤습니다. 입력 결과를 확인하지 못했거나 입력 중이면 계속 진행을 막고, 권한이 만료되면 화면 갱신을 멈추고 만료로 표시합니다. 작업 공간 버튼은 별도 관리 화면으로 이동하며 "대화 화면으로"로 돌아옵니다. 인증 실패를 "지원 안 함"으로 다루지 않아 권한이 넓어지지 않습니다.

#### 사용 방법

자동으로 적용됩니다. 별도 설정은 필요 없습니다.

### 승인 카드·알림·진단 파일이 `TOKEN`·`DB_PASS`처럼 이름만으로 비밀인 값을 가립니다

`GITHUB_TOKEN`처럼 앞에 다른 이름이 붙은 비밀 환경 변수는 값이 가려졌지만, `TOKEN`·`PASSWORD`·`SECRET`·`API_KEY`처럼 비밀 단어만으로 된 이름과 `DB_PASS`·`MYSQL_PWD`·`SSHPASS`처럼 `pass`·`pwd`·`auth`로 끝나는 이름에 넣은 값은 권한 승인 카드에 그대로 보였습니다. 이제 승인 카드, 묶음 카드, 플로팅 승인 패널, OS 알림, 에이전트 보드, AI 심사 알림에서 이 값들을 `[redacted]`로 가립니다. `psql` 연결 문자열과 `Server=db;Pwd` 형식 데이터베이스 연결 문자열의 비밀번호 항목도 가립니다. 값 뒤에 이어지는 명령(`;`·`&&`·`|` 뒤)은 그대로 보여 무엇을 허용하는지 확인할 수 있습니다. Codex 대화의 명령도 같은 기준으로 가립니다.

지원 담당자에게 보내는 진단 파일(문제 해결 zip)과 앱 로그에서도 같은 이름의 값(8자 이상)을 가립니다. `PWD`·`OLDPWD` 같은 폴더 경로는 그대로 둡니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 실행기가 다시 시작될 때 저장소 잠금이 남아 새 대화가 막히던 문제를 줄였습니다

실행기가 종료 정리를 시작한 뒤 들어온 명령이 저장소 쓰기 잠금을 잡은 채 끊기면, 그 잠금이 남아 같은 저장소의 새 대화가 "작업 트리 작업 진행 중"으로 실패할 수 있었습니다. 이제 실행기는 종료를 시작하면 새 명령을 받지 않고 다시 시도하도록 돌려보내며, 실행 중인 명령은 최대 5초 기다린 뒤 종료합니다.

#### 사용 방법

별도 조작 없이 자동 적용됩니다. 5초보다 오래 걸리는 명령이 종료 시점에 돌고 있었다면 잠금이 남을 수 있고, 이 경우 Saycode가 확인 후 정리합니다.

### 이동 중 대상이 바뀌면 이전 작업을 안전하게 마칩니다

대화를 옮기는 도중 계정·조직·작업PC·폴더가 바뀌면 이전 요청이 새 대상을 계속 조작하거나 늦은 결과를 표시하지 않도록 했습니다. 이미 시작한 작업의 잠금 해제와 정리는 원래 대상으로 마치며, 새 대화가 생성됐을 수 있는 경우에는 작업 폴더를 보존합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 저장한 프롬프트 삭제 후 키보드 탐색 유지

Quick Commands에서 항목을 삭제한 뒤 화살표 키가 작동하지 않던 문제를 수정했습니다. 다음 항목에서 계속 선택할 수 있으며 선택할 항목이 없으면 메뉴를 닫고 책갈피 버튼으로 돌아옵니다.

#### 사용 방법

입력창의 책갈피 메뉴에서 프롬프트를 삭제한 뒤 화살표 키로 다른 항목을 고르세요. 작성 중인 내용이 있으면 `입력 저장`도 계속 선택할 수 있습니다.

### 조직 계정 사용량이 정상인데도 "N분 전 관측"으로 흐리게 보이던 문제를 고쳤습니다

머신 사용량 팝오버의 조직 계정 목록에서, 사용량을 제때 수집하고 있는데도 계정이 자주
흐리게 바뀌고 "N분 전 관측"이 붙었습니다. Desktop이 관측 후 20분이 지나면 무조건 오래된
값으로 봤는데, 계정이 많은 공용 PC는 계정마다 30분 넘는 간격으로 수집하기 때문입니다.

이제 Studio가 알려 주는 시각까지 최신으로 보여 줍니다. 그 시각은 그 PC의 수집 간격의
1.5배입니다. 한도에 걸린 계정은 회복 시각까지 마지막 값을 그대로 최신으로 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 프롬프트 메뉴의 역방향 키보드 이동 유지

Quick Commands 안에서 Shift+Tab을 누르면 메뉴가 바로 닫히던 문제를 수정했습니다. 이름 변경·삭제 버튼과 프롬프트 사이를 앞뒤로 이동할 수 있습니다.

#### 사용 방법

입력창의 책갈피 메뉴에서 Tab으로 다음 버튼, Shift+Tab으로 이전 버튼에 이동하세요. 첫 항목에서 Shift+Tab을 누르면 메뉴를 닫고 책갈피 버튼으로 돌아옵니다.

### 프롬프트 저장 뒤 바로 이어서 작성

Quick Commands에서 입력을 저장한 뒤 첫 글자가 입력되지 않던 문제를 수정했습니다. 같은 입력창의 커서와 선택 위치가 유지됩니다.

#### 사용 방법

입력창의 책갈피 아이콘에서 `입력 저장`을 누른 뒤 바로 이어서 작성하세요.

### AI 브라우저 콘솔이 열리지 않는 이유를 정확히 알려 줘요

AI 브라우저 콘솔이 열리지 않으면 패널에 영어 오류 문구가 보이고, 원인과 상관없이 "작업PC의 Saycode가 켜져 있는지 확인"하라는 안내가 나왔어요. 이제 원인을 구분해 알려 줘요. 보안 강화(strict) 작업PC라 다른 PC에서 열 수 없는 경우, 작업PC가 Saycode에 연결되지 않은 경우, 작업PC의 AI 브라우저가 실행 중이 아닌 경우, 권한이 없는 경우가 각각 다르게 안내돼요. 보안 강화 작업PC는 콘솔 연결을 시도하기 전에 바로 알려 줘요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 안내에 따라 작업PC의 Saycode를 확인하거나 업데이트한 뒤 콘솔을 다시 여세요.

### AI가 하위 대화의 답을 기다리다 10분 동안 멈추던 문제를 고쳤습니다

AI가 하위 대화를 만든 뒤 답을 기다릴 때, 하위 대화가 기다리기 시작하기 전에 답을 끝내면 그 답을 알아보지 못하고 10분을 다 기다렸습니다. 이제 마지막 요청 뒤에 이미 끝난 답도 바로 알아봅니다. 또 쉬고 있던 하위 대화는 질문을 받고 첫 반응까지 20초 남짓 걸리는데, 이어서 질문할 때 5초 만에 "반응 없음"으로 실패하던 문제도 고쳤습니다. 이제 최대 60초까지 반응을 기다립니다. 작업PC에는 Saycode CLI 새 버전과 이를 묶은 happy-cli가 올라간 뒤 적용됩니다.

#### 사용 방법

사용자 조작은 없습니다. AI가 하위 대화를 만들고 기다릴 때 자동으로 적용됩니다.

### Dock·Finder에서 연 Saycode에서도 개인 Claude로 이어가기가 보입니다

조직 Claude 계정이 모두 한도에 걸렸을 때 오류 아래 개인 계정으로 이어가기가 켜져야 하는데, Dock이나 Finder에서 연 Saycode에서는 개인 계정을 찾지 못해 보이지 않았습니다. 터미널에서 연 앱과 똑같이 개인 계정을 찾아 제안합니다.

#### 사용 방법

별도 조작 없이 자동 적용됩니다. 이 컴퓨터의 실행기를 새 버전으로 올려야 합니다.

### PGP·age 개인 키도 화면·로그·진단 파일에서 가립니다

`-----BEGIN RSA PRIVATE KEY-----` 같은 PEM 개인 키는 가려졌지만, PGP 개인 키(`-----BEGIN PGP PRIVATE KEY BLOCK-----`)와 age 개인 키(`AGE-SECRET-KEY-1…`)는 그대로 보였습니다. 이제 권한 승인 카드·패널·알림, 터미널 선택 카드, AI 심사 입력, 브라우저 콘솔 캡처, 앱 로그, 진단 파일(문제 해결 zip)에서 PEM 개인 키와 같은 방식으로 가립니다. PGP 키는 `[redacted private key]` 한 줄로 바뀌고 키 뒤의 내용은 그대로 남습니다. PGP 공개 키·서명·암호화된 메시지와 age 공개 수신자 키(`age1…`)는 비밀이 아니라 그대로 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.
