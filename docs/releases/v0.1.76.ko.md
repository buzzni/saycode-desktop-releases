## 새 기능

### 메인 창을 열지 않고 승인·질문에 답하는 플로팅 승인 패널

여러 대화를 동시에 돌릴 때, 모든 대화에서 기다리는 승인·질문 요청을 다른 창 위에 떠 있는 작은 패널에 카드로 모아 보여 줍니다. 패널은 지금 쓰고 있는 앱의 포커스를 가져가지 않으며, 카드에서 바로 허용·거절하거나 질문에 선택지·직접 답변으로 답할 수 있습니다. 처리하면 메인 창과 패널 양쪽에서 함께 사라지고, 메인 창에서 먼저 처리해도 패널 카드가 사라집니다. AI 심사가 검토 중인 요청은 "심사 중"으로 표시되고 결과가 나올 때까지 패널에서 답할 수 없습니다. 계획 승인과 여러 질문은 `앱에서 열기`로 해당 대화를 열어 처리합니다.

#### 사용 방법

설정 > 알림에서 `플로팅 승인 패널`을 켭니다(기본은 꺼짐). 요청이 생기면 화면 오른쪽 위에 패널이 나타나고 요청이 없으면 숨습니다. 패널은 끌어서 옮길 수 있고 위치를 기억하며, 닫기를 누르면 지금 요청들은 숨겼다가 새 요청이 오면 다시 나타납니다.

### 앱 안 PR 화면에서 머지 가능 여부 확인과 머지

앱 안 PR 화면 아래쪽에 머지 상태가 생겼어요. 검사가 통과했는지(실패하면 실패한 검사 이름), base 브랜치와 충돌이 있는지, 리뷰 판정, 초안·GitHub 보호 규칙·뒤처짐 때문에 막혔는지를 브라우저로 나가지 않고 볼 수 있어요. PR이 연결된 대화가 있고 프로젝트가 그 저장소와 GitHub 연동돼 있으면 같은 자리의 `머지`로 작업보드와 같은 확인 창을 거쳐 squash 머지할 수 있고, 머지되면 PR이 `병합됨`으로 바뀌어요. 작업보드처럼 그 대화에서 올리기 같은 다른 작업이 도는 동안에는 `머지`가 꺼져요. 그렇지 않으면 `GitHub에서 머지`로 브라우저에서 머지해요.

#### 사용 방법

프로젝트 대화에서 열린 GitHub PR 링크를 눌러 PR 탭을 열고, 화면 아래 머지 상태를 확인하세요. 머지할 수 있으면 `머지`를 누르고 확인 창에서 `병합`을 누르면 돼요. 작업PC에 gh가 설치되고 로그인돼 있어야 해요.

### 연동이 필요한 스킬을 고르면 먼저 연결을 안내

프로젝트 대화 입력창의 / 목록에서 외부 연동이 필요하다고 선언한 Saycode 공식 스킬을 고를 때, 그 연동이 아직 연결되지 않았으면 스킬을 넣기 전에 알려 줍니다. `연결하고 계속`을 누르면 연동 화면이 열리고 고른 명령은 그 대화의 입력창에 남아 있습니다. `그냥 계속`을 누르면 지금처럼 명령을 넣고, 앱을 다시 열 때까지 같은 대화에서는 다시 묻지 않습니다. 로컬 모드이거나 이 Saycode 서버가 제공하지 않는 연동이면 연결 대신 이유를 보여 줍니다. 목록에서 고를 때만 묻고, 명령을 직접 입력해 보내거나 개인 Chat에서 쓸 때는 묻지 않습니다.

#### 사용 방법

프로젝트 대화의 입력창에 `/`와 스킬 이름 일부를 입력하고 목록에서 스킬을 고릅니다. 안내 창에서 `연결하고 계속`·`그냥 계속`·`취소` 중 하나를 고릅니다. 연결한 뒤 대화로 돌아와 입력창에 남은 명령을 보내면 됩니다.

### 외부 연동에서 Figma 연결

외부 연동 화면과 설정의 커넥터 목록에 Figma가 추가됐습니다. 연결하면 대화에서 Figma 파일·팀 라이브러리·폴더를 읽고 프레임을 이미지로 받아 볼 수 있으며, 요청하면 AI가 댓글을 남기거나 개발 리소스 링크를 붙일 수 있습니다. 입력창에 연결하지 않은 Figma를 언급하면 연결하기 제안도 함께 보입니다.

#### 사용 방법

사이드바의 외부 연동에서 Figma 줄의 연결을 누르고, 열리는 웹 브라우저에서 Figma에 로그인해 허용합니다. Saycode 계정으로 로그인한 경우에만 보입니다.

### 자동으로 보낸 메시지에 보낸 곳 표시

대화에서 내가 이 컴퓨터에서 직접 보내지 않은 메시지 위에 누가 보냈는지 작은 표시가 붙습니다. 예약 작업, GitHub 트리거, 오토파일럿, 셀프 리뷰, PR 지킴이, 작업PC 자동화, 메신저 채널, 모바일·웹 앱, 에이전트가 보낸 메시지를 구분할 수 있습니다. 내가 직접 보낸 메시지에는 표시가 붙지 않고, 이 업데이트 전에 이 컴퓨터에서 자동으로 보낸 메시지에는 표시가 없을 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 대화의 내 메시지 말풍선 위에서 확인하세요.

### 진행 중인 대화를 작업트리로 옮기기 / 본 폴더로 되돌리기

본 폴더에서 일하던 대화를 지금 변경사항과 함께 새 작업트리로 옮기거나, 작업트리의 대화를 본 폴더로 되돌릴 수 있습니다. 새 작업트리 만들기 → 변경 옮기기 → 옮긴 변경 확인 → 대화 옮기기를 단계별로 보여 주고, 중간에 실패하면 이미 한 단계를 거꾸로 되돌립니다. 되돌리지 못한 것이 있거나 변경만 옮겨지고 대화는 옮기지 못하면 그 상태를 그대로 알려 줍니다. 원래 폴더의 변경은 지우지 않고, 옮길 곳에 git 이 무시하는 같은 이름의 파일이 있거나 서브모듈 안에 바뀐 파일이 있으면 쓰기 전에 멈춥니다. 되돌릴 때는 그 사이 다른 대화가 고친 파일을 건드리지 않고 알려 줍니다.

#### 사용 방법

대화 머리글의 프로젝트 도구(⋮) → 대화 이어가기 → 이 대화를 작업트리로 옮기기(작업트리의 대화면 이 대화를 본 폴더로 되돌리기) → 옮기기. Claude·Codex 대화에서 응답이 끝난 뒤 쓸 수 있고, Windows 작업PC는 아직 지원하지 않습니다.

### 토큰 사용량에서 출처별 대화 턴 보기

토큰 사용량 화면에 `출처별` 보기가 추가됐습니다. 선택한 기간에 이 컴퓨터에서 보낸 대화 턴을 직접 보낸 것과 오토파일럿·예약 작업·GitHub 트리거 등 자동으로 보낸 것으로 나눠 턴 수와 비중을 보여 줍니다. 작업PC가 직접 시작한 예약 작업·GitHub 트리거 턴과 메신저 채널 턴은 세지 않습니다. 이 업데이트 이후 보낸 턴부터 세며, 그보다 앞선 기간을 고르면 집계 시작 날짜를 함께 보여 줍니다.

#### 사용 방법

내 설정 > 일반 > 토큰 사용량에서 `출처별`을 누르세요. 조회 기간은 다른 보기와 같이 바꿀 수 있습니다.

### 하위 에이전트에게 정해진 JSON 형식으로 답하게 하기

Saycode 세션 안의 에이전트가 하위 Claude 에이전트를 띄울 때 JSON Schema를 지정할 수 있습니다. 그 하위 세션의 모든 턴은 schema에 맞는 JSON으로 답하고, 기다리기(wait)·읽기(read) 결과에 검증된 값이 함께 담깁니다. 턴이 끝났는데 schema에 맞는 값이 없으면 실패로 알려 주고, 이 기능을 지원하지 않는 런타임이나 에이전트면 세션을 만들지 않고 이유를 알려 줍니다.

#### 사용 방법

에이전트가 `happy agent spawn --prompt "<할 일>" --output-schema '<JSON Schema>'`(또는 schema 파일의 절대 경로)로 실행합니다. 런타임 업데이트가 적용된 머신에서만 동작하며, 그 전에는 지원하지 않는다는 오류로 안내됩니다.

## 변경된 기능

### 작업PC 런타임의 Claude Code 업데이트와 도구 정책 차단 강화

앱에 포함되는 작업PC 런타임을 Happy CLI 1.1.10-aplus.353으로 업데이트합니다. 원격으로 실행하는 Claude 대화는 Claude Code 2.1.308로 실행됩니다. 이 원격 대화에서는 도구 정책 확인이 시작되지 못하거나 중간에 비정상 종료·시간 초과되면, 확인을 거치지 않은 도구 호출을 그대로 실행하지 않고 막습니다. 터미널(로컬) 모드나 `HAPPY_CLAUDE_PATH`로 지정한 대화는 작업PC에 설치된 Claude Code를 쓰므로, 이 보호를 받으려면 Claude Code 2.1.295 이상이 필요합니다. Claude 대화 안의 하위 에이전트 분기(fork)는 Claude Code 기본값에 따라 켜집니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 이 변경이 포함된 Desktop 버전으로 업데이트한 뒤 새로 시작하는 대화부터 적용되며, 이미 실행 중인 이전 런타임 대화는 재시작하지 않습니다. 하위 에이전트 분기를 끄려면 작업PC 환경 변수 `CLAUDE_CODE_FORK_SUBAGENT=0`을 설정합니다.

## 수정된 문제

### 격리된 대화에서 하위 에이전트 작업트리 생성 복구

모델과 실행 환경 확인 뒤에도 하위 에이전트의 별도 작업트리 생성이 거절되던 문제를 수정했습니다. 격리된 대화에서도 관리형 작업트리를 만들어 자식을 실행할 수 있습니다.

#### 사용 방법

수정된 CLI가 포함된 런타임에서 `happy agent spawn --worktree --prompt "작업 내용"`을 사용합니다. 부모의 미커밋 변경을 먼저 커밋해야 하며, 생성 실패 시 같은 폴더에서 자동 실행하지 않습니다.

### 연 뒤에 바뀐 파일은 저장할 때 덮어쓰지 않음

작업 영역에서 파일을 열어 편집하는 동안 AI나 다른 곳에서 같은 파일을 바꾸면, 저장할 때 그 변경을 덮어쓰지 않고 "이 파일은 연 뒤에 다른 곳에서 바뀌어 저장하지 않았습니다."라고 알려 줍니다. 파일이 그사이 삭제됐으면 삭제됐다고 알려 줍니다. 어느 경우든 편집한 내용은 편집기에 그대로 남습니다. 이전에는 저장 직전에 파일을 다시 읽어 비교했기 때문에, 파일을 연 뒤에 생긴 변경을 알아채지 못하고 덮어썼습니다.

저장 응답이 끊겨 다시 저장했는데 파일에 이미 그 내용이 들어 있으면 저장된 것으로 처리합니다. 최신 PC 프로그램을 쓰는 PC에서는 끊긴 저장을 자동으로 한 번 다시 보내고, 같은 저장으로 처리합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 충돌 안내가 보이면 편집한 내용을 복사해 둔 뒤 편집기의 새로고침 버튼으로 최신 내용을 불러와 다시 반영하세요.

### 조직 AI 계정이 바뀌어도 대화를 그대로 이어가요

쉬고 있던 대화에 쓰던 조직 AI 계정이 PC 배정에서 빠지면, 메시지를 보낼 때 같은 대화를 지금 배정된 다른 조직 계정으로 이어서 답해요. 대화 기록에는 "이 대화에 쓰던 조직 AI 계정이 바뀌어 새 연결로 이어서 진행합니다." 안내 한 줄이 남아요. 바꿔 쓸 계정이 없으면 그 이유를 알려 주고, 보낸 메시지는 입력창에 그대로 남겨요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 이 PC의 연결 프로그램이 이 기능을 지원하는 버전으로 업데이트돼 있어야 해요.
