## 새 기능

### 데스크탑 앱에서 회원가입

앱에서 이메일 인증 코드를 받고 비밀번호를 설정해 회원가입할 수 있습니다. 가입 후 로그인과 시작준비로 이어지며, 소속이나 받은 조직 초대가 없으면 이름을 입력해 직접 조직을 만듭니다. 조직 주소는 자동으로 준비합니다. 가입 결과를 확인하지 못하면 중복 가입 대신 로그인으로 확인할 수 있습니다.

개발 서버 주소 설정이 잘못된 경우 인증 코드 요청·확인과 회원가입 요청을 전송하지 않습니다.

#### 사용 방법

로그인 화면에서 ‘계정 만들기’를 누르고 이메일 인증 코드와 비밀번호를 입력하세요. 이미 가입한 이메일은 로그인으로 안내합니다.

### 시작 화면에서 작업PC 선택

Chat과 Build 시작 화면에서 입력창 아래 오른쪽 머신명을 눌러 작업PC를 선택할 수 있습니다. 선택을 바꿔도 작성 중인 글은 유지됩니다. 상세 화면에서는 머신을 바꿀 수 없으며, 시작 중 선택이 잠겼다가 풀려도 모달이 자동으로 다시 열리지 않습니다.

#### 사용 방법

시작 화면의 머신명을 클릭하고 선택 창에서 사용할 작업PC를 고르세요.

### 앱에서 조직에 참여하거나 새 조직 만들기

소속과 초대가 없으면 이름만 입력하는 작은 중앙 모달이 바로 열립니다. 창 전체를 가리지 않고 내용에 맞는 크기로 표시됩니다. 제목 아래 반복 표현을 줄여 입력은 ‘이름’, 생성 버튼은 ‘만들기’로 표시합니다. 초대 코드 입력 위의 중복 라벨도 숨겼습니다. 조직이 없는 계정은 조직을 만들거나 참여를 완료해야 시작할 수 있습니다. 조직 화면의 닫기를 제거하고 Escape·바깥 클릭으로 건너뛰지 못하게 했습니다. 다시 로그인하거나 앱을 열어도 필요한 조직 설정을 이어갑니다. 조회 중이거나 실패한 상태에서는 새 조직 생성을 안내하지 않습니다. 조직 목록 응답을 읽지 못하면 조회를 끝내고 다시 확인할 수 있도록 안내합니다.

로그인 후 시작 화면에서 초대 코드로 조직에 참여하거나 새 조직을 만들 수 있습니다. 소속 조직을 확인한 뒤 기존 PC·AI 시작 준비를 이어갑니다. 처리 결과가 확인되지 않으면 입력을 보존하고 조직 목록을 다시 확인해 중복 요청을 막습니다. 재확인에 성공하면 이전 조회 오류 안내도 사라집니다.

필수 조직 화면에서도 다른 계정으로 로그인할 수 있으며 로그아웃 확인을 거칩니다. 코드 참여의 응답을 받지 못한 경우 요청을 반복하지 않고 조직 목록을 다시 확인한 뒤 표시된 소속을 선택해 계속할 수 있습니다. 선택한 소속은 서버에서 다시 검증합니다. 조직 전환에 실패하면 다음 버튼에 키보드 포커스를 복원해 다시 시도할 수 있습니다.

#### 사용 방법

로그인 후 시작 화면에서 ‘초대 코드로 참여’ 또는 ‘조직 만들기’를 선택하세요. 확인된 조직을 선택하고 ‘다음’을 누르면 시작 준비가 이어집니다. 관리자 초대의 기존 보안 검증은 유지됩니다.

### 오토파일럿 독립 리뷰 AI 선택

오토파일럿을 독립 리뷰로 켤 때 어떤 AI·모델·Effort로 리뷰할지 고를 수 있습니다. 켤 때의 값이 그 실행이 끝날 때까지 유지됩니다.

#### 사용 방법

내 설정 → 개발 → 개발 자동화의 `오토파일럿 독립 리뷰 AI`에서 AI를 고르고, 이어서 나오는 리뷰 모델과 리뷰 Effort를 고릅니다. 기본값을 고르면 이전과 같은 리뷰어를 씁니다.

### 오토파일럿이 추천안 질문에 대신 답하기

오토파일럿 중에 AI가 추천안을 제시하며 "진행할까요?"처럼 묻고 멈추면, 오토파일럿이 "추천안대로 진행"으로 대신 답합니다. 권한·비용·외부 전송·되돌리기 어려운 변경은 진행하지 말라는 조건을 함께 붙이고, 한 번 켤 때 최대 2번까지만 답합니다. 추천안이 없는 질문, 계획 승인, AI가 띄운 질문 창은 지금처럼 사용자의 답을 기다립니다.

#### 사용 방법

기본으로 켜져 있습니다. 내 설정 → 개발 → 개발 자동화의 `오토파일럿이 추천안 질문에 대신 답하기`에서 끌 수 있습니다.

### PR 지킴이: PR의 CI·리뷰 봇·충돌을 지켜보고 대화에 후속 처리를 맡기기

PR을 만든 대화가 쉬고 있을 때, Desktop이 그 PR을 1분마다 확인하고 처리할 일을 같은 대화에 지시합니다. 처리하는 일은 리뷰 봇의 수정 PR 반영, 봇이 반영하지 못한 지적, base 브랜치와의 충돌, CI 실패입니다. 모두 통과하면 "머지 가능" 알림을 보냅니다. PR이 머지되면 남은 스택 PR을 정리하고, 원하면 spec의 남은 작업을 이어가라고 지시합니다. base 브랜치로의 머지는 하지 않습니다. 같은 실패가 반복되거나 자동 지시가 한도에 이르면 멈추고 카드에 이유를 표시합니다.

#### 사용 방법

작업보드에서 PR이 열린 카드의 `PR 지킴이`를 누르면 켜집니다. 오토파일럿은 Commit & PR을 보낸 뒤 자동으로 켭니다. 이 동작과 `머지되면 남은 작업 이어가기`는 내 설정 → 개발 → 개발 자동화에서 끌 수 있습니다. 작업PC에 gh가 로그인돼 있어야 합니다.

### Saycode 사용법을 물으면 AI가 앱 안내를 보고 답합니다

채팅이나 프로젝트 대화에서 "작업보드는 어떻게 켜요?"처럼 Saycode 자체의 사용법을 물으면, 이 버전의 메뉴 위치·순서·필요한 조건을 담은 안내가 그 질문에 함께 전달됩니다. 바로 맞는 항목이 없으면 AI가 대화의 작업 폴더에 놓인 전체 안내서 파일(`.aplus/saycode-guide/`, 저장소에는 올라가지 않음)을 직접 찾아봅니다. AI는 화면에 보이는 이름 그대로 단계를 안내하고, 안내서에 없는 기능은 지어내지 않고 확인할 수 없다고 답합니다. 사용법 질문인지는 이 기기에서만 판단하며, 질문으로 판단되지 않은 요청에는 아무것도 덧붙지 않습니다. 사용법 질문이 아닌데 안내가 붙더라도 AI는 원래 요청만 처리하도록 안내받습니다. 안내를 받아도 AI가 설정을 대신 바꾸지는 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 끄려면 내 설정 → 일반 → 시스템 프롬프트에서 "Saycode 사용 안내"를 끕니다.

### Slack 채널에서 페어링 없이 본인 멘션에 답변

Slack 봇과 이미 연결(페어링)한 사람이 봇을 초대한 채널에서 봇을 멘션하면, 그 채널을 따로 연결하지 않아도 그 글의 스레드로 답합니다. 채널에서 처음 답할 때 "이제 이 채널에서도 답하며 답변은 채널 멤버 모두에게 보인다"는 안내를 한 번 보냅니다. 연결하지 않은 다른 사람의 멘션에는 지금처럼 답하지 않고, 다른 회사와 공유된 Slack Connect 채널은 지금처럼 그 채널에서 연결해야 합니다.

#### 사용 방법

봇을 채널에 초대한 뒤 `@봇이름 질문`처럼 멘션하세요. 별도 설정은 필요 없습니다.

## 변경된 기능

### 가입과 시작준비를 더 간편하게

온라인 작업PC가 없으면 시작 영역에 연결 안내와 그 아래 작업PC 설정 버튼만 표시합니다. 연결 확인이 필요한 상태를 CLI 미설치로 안내하지 않으며, 필수 조직 생성·참여 중에는 배경의 연결 안내를 숨깁니다. PC가 연결되면 채팅 입력창과 작업 예시가 나타나며, 잠시 연결이 끊겨도 작성하던 초안과 첨부를 보존합니다.

이메일 입력, 6자리 코드 인증, 비밀번호 설정을 단계별 화면으로 나누고, 단계 번호 안내를 제거해 필요한 입력만 표시합니다. 코드 입력칸에는 메일로 받은 인증코드를 입력하도록 가운데 정렬된 문구로 안내합니다.
이메일 반복 표시와 변경 버튼, 중복 설명, 가입 화면 제목을 제거했습니다. 필요한 수정은 ‘이전’에서 할 수 있습니다. 코드는 6자리 입력 후 확인하며 재시도가 필요할 때만 계속 버튼을 표시합니다. 비밀번호 보기는 입력칸 안으로 옮기고 보조 행동의 강조를 줄였습니다. 회원가입의 인증 코드 입력을 웹과 같은 6칸으로 바꿨습니다. 숫자 입력·붙여넣기·이동·삭제를 지원하고, 이미 입력한 칸의 숫자를 직접 교체할 수 있으며, 비밀번호 보기와 입력 위치에 맞는 오류 안내를 제공합니다. 같은 이메일의 코드 입력으로 돌아올 때 재발송과 비밀번호 재입력을 요구하지 않습니다. 기본 조직이 하나면 바로 확인하고 다음 단계로 진행하며, 추가 조직 선택·참여는 필요할 때 펼칠 수 있습니다.

#### 사용 방법

‘계정 만들기’에서 이메일을 인증하고 비밀번호를 설정하세요. 가입 후 소속이 없으면 조직을 만들거나 초대로 참여하세요. 확인된 조직에서 ‘다음’을 누르면 시작준비로 이어집니다. 다른 조직이 필요하면 ‘다른 조직 선택·참여’를 누르세요.

### 계정 연결과 개인 토큰을 저장소 설정에서 관리

GitHub·GitLab 계정과 개인 PAT를 내 설정의 저장소에서 함께 관리합니다. GitHub 저장소 접근 관리는 시스템 브라우저의 App 설치 관리로 연결됩니다. 생성 모달에서 설정을 다녀와도 작성 내용이 유지됩니다.

#### 사용 방법

새 프로젝트 → Git 저장소 하단의 저장소 설정 또는 내 설정 → 저장소를 엽니다. GitHub 접근 범위는 저장소 접근 관리에서 확인합니다.

### 기존 폴더 목록과 새로운 경로 선택

프로젝트 생성의 기존 폴더 탭과 입력창 +의 별도 선택창에서 폴더 목록을 제공합니다. 내 PC에서는 목록 아래 새로운 경로에서 시작으로 운영체제 폴더 선택창을 열 수 있습니다.

#### 사용 방법

기존 폴더를 탐색해 선택하거나, 목록 아래 새로운 경로에서 시작을 누르세요. 취소하면 작성 중 내용이 유지됩니다.

### 남은 스택 PR이 있으면 머지 전에 확인

머지나 자동 머지를 켜기 전에 이 PR 브랜치에 아직 반영하지 않은 스택 PR(리뷰 봇 수정 PR 포함)이 있는지, 리뷰 봇이 아직 일하는 중인지 확인합니다. 남은 것이 있으면 무엇이 남았는지 보여 주고 머지할지 묻습니다. 지금 머지하면 그 PR들이 고아가 되기 때문입니다. 확인하지 못했을 때도 그 사실을 알리고 묻습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 확인 창에서 `그래도 머지` 또는 `취소`를 고르면 됩니다.

### 대화 공간을 유지하는 프로젝트 안내와 작업 메뉴

프로젝트 제목 아래의 안내와 오류는 플로팅 토스트로 표시합니다. 실행 중인 포트와 자식 AI도구, 부모·리뷰 원본 대화와 PR은 더보기에서 확인하며 대화 본문을 아래로 밀지 않습니다. 이전 대화 조회도 본문 하단의 떠 있는 컨트롤로 표시합니다.

#### 사용 방법

프로젝트 대화 오른쪽 더보기에서 포트·자식 AI도구·관련 대화를 여세요. 자식의 지시 전달과 중단, 포트 열기는 기존처럼 사용할 수 있습니다. 알림은 닫기 버튼으로 지울 수 있습니다.

### 사이드바 계정 표시 간소화

사이드바 하단 조직명 아래의 유저명 앞 아이콘을 제거했습니다. 아바타와 계정 메뉴는 그대로 사용할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 자동순환계정 설정을 한 줄로 정리했어요

AI 사용량의 Claude 계정 설정을 작은 왼쪽 스위치와 ‘자동순환계정’ 문구로 정리했어요. 아래 설명은 정보 아이콘의 툴팁으로 옮겼어요. 도움말을 읽다가 Escape를 누르면 도움말만 닫혀 사용량 창을 계속 사용할 수 있어요.

#### 사용 방법

AI 사용량을 열고 Claude 계정 아래 스위치를 사용하세요. 정보 아이콘에 마우스를 올리거나 키보드로 포커스하면 현재 순환 상태의 설명을 확인할 수 있어요.

### 작업PC 채널 호스트가 초대된 Slack 채널의 본인 멘션에 답합니다

앱에 들어가는 Happy 실행기를 1.1.10-aplus.321로 올렸습니다. 작업PC에서 Desktop 없이 메신저를 받는 채널 호스트도 이제 Slack 봇과 이미 연결한 사람이 봇을 초대한 채널에서 멘션하면, 그 채널을 따로 연결하지 않아도 그 글의 스레드로 답합니다. 함께 들어간 1.1.10-aplus.320에서는 공용 작업PC에서 Claude를 쓰는 구성원의 조직 사용량을 그 작업PC 기준으로 수집합니다.

#### 사용 방법

앱을 업데이트하면 적용됩니다. 작업PC의 실행기가 새 버전으로 바뀐 뒤부터 채널 호스트에 반영됩니다.

### 조직 초대 확인 버튼을 오른쪽 아래로 옮겼어요

#### 사용 방법

화면 오른쪽 아래의 조직 초대 버튼을 누르면 기존처럼 받은 초대나 다시 확인 안내를 볼 수 있어요.

### 채팅과 예약 메뉴에서 같은 예약 관리

채팅의 예약 작업에서 해당 대화의 예약을 예약 메뉴와 같은 목록·편집·실행 이력으로 관리합니다. 넓은 본문 예약 내용은 제목 영역 가운데의 작은 일정 버튼으로 바뀌며 클릭하면 내용 모달이 열립니다. 좁은 헤더에서 AI 브라우저 버튼과 함께 표시되는 배치를 보완하고, 예약 삭제로 내용 버튼이 사라지면 상단 메뉴로 포커스를 돌려줍니다. 저장 응답이 불확실한 경우 설정을 닫았다 다시 열어도 작성 내용을 복구하고 중복 등록을 막습니다. 이전 대화 기록을 불러오지 못해도 제목·예약·상단 도구가 겹치지 않습니다. 기존 AI 선택·조건 실행·스크립트 자동화는 고급 자동화 설정에서 사용할 수 있습니다.

#### 사용 방법

대화 제목 영역에서 예약할 일을 짧게 확인하고 누르면 전체 내용·일정·상태를 볼 수 있습니다. 긴 내용은 마우스를 올려서도 확인할 수 있으며 모달에서 이름과 요청이 같으면 한 번만 표시합니다. 할 일과 예약 상태는 여백을 둔 별도 줄로 표시하고 머신명은 모달 왼쪽 아래에서 확인합니다. 예약을 읽지 못하면 다시 확인을 눌러 복구하며, 확인 전에는 실행 PC를 추정해 표시하지 않습니다. 대화 상단의 예약 작업을 열어 새 예약을 추가하거나 기존 예약을 관리하세요. 전체 예약 보기를 누르면 여러 대화의 예약을 확인할 수 있습니다.

### Chat 문서 템플릿 직접 사용 복원

새 Chat에서 문서 형식을 고르면 기본·개인 템플릿을 바로 선택할 수 있습니다. 별도 문서 양식 확장 설치나 활성화 없이 개인 템플릿 추가·편집·삭제를 사용할 수 있습니다. 양식을 고르면 입력창에 양식 작성 안내와 `내 작업은` 문구가 채워집니다. 작성 중인 글은 양식을 바꾸거나 해제해도 보존됩니다. 개인 템플릿 등록·편집·삭제 창은 제목과 입력칸의 여백을 바로잡고 저장·삭제 버튼을 구분해 표시합니다. 원본 파일 선택 줄에는 선택한 파일명이 표시됩니다.

#### 사용 방법

### Commit & PR이 PR을 머지 가능한 상태까지 처리

작업보드·작업 완료 화면·오토파일럿의 Commit & PR은 이제 PR을 만든 뒤에도 같은 대화에서 후속 처리를 이어갑니다. CI 실패를 고치고, 리뷰 봇의 판정과 수정 PR을 반영하고, base 브랜치와의 충돌을 해결합니다. 마지막에 CI·봇 판정·봇 수정 PR 반영·충돌 상태를 한 줄씩 보고하고, 모두 통과하면 "머지 가능"이라고 알려 줍니다. CI 실패 링크를 붙여 넣거나 충돌 해결을 따로 요청하지 않아도 됩니다. base 브랜치로의 머지는 이전처럼 사용자가 합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 작업보드 카드나 작업 완료 화면에서 Commit & PR을 보내면 됩니다.

### saycode CLI 0.9.3: 메신저 채널 호스트가 초대된 Slack 채널의 본인 멘션에 답변

Desktop 없이 메신저를 받는 채널 호스트(작업PC의 Happy 실행기에 함께 들어 있음)가 Slack에서 이미 연결한 사람이 봇을 초대한 채널에서 멘션하면, 그 채널을 따로 연결하지 않아도 그 글의 스레드로 답합니다. 연결하지 않은 다른 사람의 멘션과 다른 회사와 공유된 Slack Connect 채널은 지금처럼 답하지 않습니다.

#### 사용 방법

### Slack에서도 질문에 이모지로 진행 상태를 보여 줍니다

Slack에서 봇에게 요청하면 Telegram처럼 사용자 메시지에 이모지 반응으로 진행 상태를 보여 줍니다. 접수 👀 → 작업 중 ✍ → 권한 대기 🤔 → 완료 👍 / 실패 💔 / 중단 🙈 순서로 바뀌며, 단계가 바뀔 때 이전 이모지는 지워집니다. Slack·Telegram 모두 메시지를 받는 즉시 👀가 붙어, 작업 준비 중에도 입력이 접수됐는지 바로 알 수 있습니다. 스레드에 "작업 중" 안내 메시지를 따로 올리지 않고, 답변은 지금처럼 스레드로 옵니다.

#### 사용 방법

Slack 앱에 `reactions:write` 권한이 필요합니다. 이미 만든 Slack 앱은 이 권한을 추가한 뒤 워크스페이스에 다시 설치하세요. 설정의 메신저 연결에서 새로 만드는 Slack 앱에는 처음부터 포함됩니다. 작업PC의 채널 호스트는 Happy 실행기가 이 변경을 포함한 버전으로 업데이트된 뒤 적용됩니다.

#### 사용 방법

수정된 Saycode CLI를 포함한 Happy 실행 도구가 필요합니다. Desktop만 갱신하면 기존 실행 도구에는 적용되지 않습니다.

### 머신 키로 보호되는 작업PC에서도 원격 터미널 열기

조직 공유 키가 생긴 뒤 연결한 작업PC처럼 머신 키로 보호되는 작업PC에서 원격 터미널이 `Failed to decrypt open params`로 열리지 않던 문제를 고쳤습니다. 터미널 입출력을 그 작업PC의 머신 키로 암호화합니다. 보안 강화(strict) 작업PC는 아직 원격 터미널을 열지 않고 이유를 안내합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 새 대화 제목이 첫 요청 앞부분으로만 보이던 문제 수정

대화 암호화(dataKey)가 켜진 PC에서 새로 시작한 대화의 제목이 AI가 지은 제목 대신 첫 요청의 앞부분으로 표시되던 문제를 고쳤습니다. 이미 만들어진 대화도 목록을 다시 불러오면 AI 제목으로 표시됩니다.

#### 사용 방법

### 새 에이전트의 생성과 응답 조회 복구를 실행 도구에 포함

이 컴퓨터에서 새 에이전트를 실행할 때 암호 해독 오류로 실패하거나 생성된 대화의 응답을 읽지 못하던 문제의 수정본을 앱 내장 실행 도구에 포함했습니다.

#### 사용 방법

업데이트된 앱의 실행 도구가 적용된 뒤 새 에이전트를 실행하세요. 별도로 설치한 실행 도구를 사용하는 작업PC는 해당 실행 도구도 업데이트해야 합니다.

### 암호화된 대화의 답변·중단과 에이전트 생성 수정

암호화된 대화에서 질문에 답하거나 응답을 중단·수정할 때 요청이 전달되지 않던 문제를 수정했습니다. 로컬 에이전트의 새 대화 생성도 해당 작업 PC의 암호화 키를 사용합니다. 제어 요청이 거부되면 성공으로 처리하지 않습니다.

#### 사용 방법

### 원격 터미널: 보안 모드 확인과 키 폐기 처리 강화

머신 키로 보호되는 작업PC의 원격 터미널을 열 때, 서버가 알려준 정보가 아니라 작업PC가 직접 알린 보안 모드를 확인합니다. 보안 강화(strict) 작업PC나 모드를 알리지 않는 오래된 CLI의 작업PC에서는 터미널을 열지 않고 이유를 안내합니다. 로그아웃·계정 키 잠금·조직 전환으로 앱이 머신 키를 버리거나, 입력을 암호화하지 못하면 열려 있던 터미널을 바로 닫습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 모드를 알리지 않는 작업PC는 happy CLI를 최신 버전으로 업데이트하세요.

### 이전 대화 버튼 위치 복원

#### 사용 방법

프로젝트 대화 상단 중앙의 ‘이전 대화’를 누르세요.

### 일부 대화에서 제목을 바꾸면 "Unable to decrypt message" 오류가 나던 문제를 고쳤습니다

세션별 키로 보호되는 대화는 사이드바에서 제목을 바꿔 저장하면 "Unable to decrypt message" 오류가 나고 제목이 바뀌지 않았습니다. 이제 이런 대화도 제목이 정상적으로 저장됩니다. 계정 키가 잠겨 있어 대화를 열 수 없으면, 알 수 없는 오류 대신 잠금을 해제하라는 안내가 나옵니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 사이드바에서 대화 제목을 편집해 저장하면 됩니다.
