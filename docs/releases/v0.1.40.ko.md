## 새 기능

### 대화 상단에서 최근 Pull Request를 바로 열 수 있습니다

대화에서 에이전트가 Pull Request 링크를 남기면, 해당 링크가 있는 가장 최근 답변의 PR들이 대화 제목 옆에 표시됩니다. 이후 답변에 PR 링크가 없더라도 이전의 최신 PR 링크를 계속 빠르게 찾을 수 있습니다.

#### 사용 방법

대화 제목 옆의 `PR #번호` 링크를 누르면 해당 GitHub Pull Request가 열립니다. 별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/729)

## 변경된 기능

### 계정 없이 바로 시작하는 로컬 온보딩

계정이 없어도 Saycode가 로컬 작업공간으로 바로 시작됩니다. 사이드바의 Guest 메뉴에서 필요할 때 로그인할 수 있으며, Saycode CLI·Claude Code와 Codex·알림을 확인하는 3단계 안내와 첫 프로젝트 추가 흐름이 이어집니다. Cloud에서는 Saycode CLI 설치와 업데이트를 온보딩에서 직접 실행하고, Standalone에서는 포함된 런타임을 `설치됨`으로 표시합니다.

#### 사용 방법

앱을 실행하면 로컬 작업공간과 시작 안내가 자동으로 열립니다. 안내를 마친 뒤 이 컴퓨터 또는 원격 머신을 고르고 기존 폴더, 새 프로젝트, Git URL 또는 ZIP 파일로 시작하세요. 이 컴퓨터의 기존 폴더는 macOS 파일 탐색기에서 직접 고를 수 있습니다.

## 수정된 문제

### 답변한 대화의 알림 표시가 남아 있던 문제

입력 대기 중이던 대화에 답변을 보낸 뒤에도 사이드바의 빨간 알림 점과 탭의 "입력 대기" 표시가 사라지지 않던 문제를 고쳤습니다. 답변이 전달되면 표시가 바로 사라집니다.

별도 설정 없이 적용됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/796)

### 인코딩된 채팅 파일 링크를 정확하게 엽니다

채팅의 파일 링크에 인코딩된 폴더 구분자나 줄 번호가 있어도 올바른 프로젝트 파일과 위치를 열고, 인코딩된 외부 주소는 로컬 파일로 오인하지 않습니다. 파일명 자체에 percent·hash·query 문자가 있는 자동 링크도 그대로 보존합니다.

#### 사용 방법

기존처럼 응답의 파일 링크를 클릭하면 됩니다. 별도 설정은 필요하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/792)

### 저장소 연결과 코드 저장 상태를 구분해 안내합니다

저장소 연결은 완료됐지만 머신 오프라인, 빈 워크스페이스, 자격 증명 문제 등으로 코드 저장이 지연된 경우 연결 실패로 오해하지 않도록 성공 상태와 후속 조치 안내를 함께 표시합니다.

#### 사용 방법

프로젝트 환경설정의 코드 저장소에서 안내에 따라 머신·워크스페이스·자격 증명을 확인한 뒤 `코드 저장`을 다시 실행합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/791)

### Worktree 관리 화면 레이아웃 안정화

Worktree 목록을 불러올 때 관리 화면의 크기와 위치가 흔들리지 않고, 긴 목록에서도 정보와 작업 버튼이 서로 겹치지 않도록 수정했습니다.
