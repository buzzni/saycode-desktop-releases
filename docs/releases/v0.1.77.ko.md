## 새 기능

### 교훈 갱신 제안을 승인할 때 지금 교훈과 나란히 보고 확인한다

에이전트가 비슷한 교훈을 새로 만드는 대신 기존 교훈을 고쳐 쓰자고 제안하면, 교훈 승인 카드에 "기존 교훈 갱신"으로 표시되고 지금 교훈의 이름과 단계가 제안된 내용 옆에 함께 보입니다. 승인하면 그 교훈이 같은 자리에서 새 내용으로 바뀌고 이력은 남습니다. 그사이 교훈이 바뀌었거나 더는 볼 수 없으면 승인 대신 안내가 나오고, 그 제안은 거절한 뒤 다시 받을 수 있습니다.

#### 사용 방법

교훈 승인 카드에서 "기존 교훈 갱신" 표시가 있는 제안은 지금 교훈과 제안 내용을 비교한 뒤 승인하거나 거절하세요.

### 메신저 승인 버튼이 만료되면 한 번 안내

메신저에서 보낸 대화의 승인 버튼은 5분 뒤 누를 수 없게 됩니다. 그때까지 아무도 답하지 않았으면 그 메신저 대화에 "버튼이 만료됐어요 · N분 뒤 자동 거절돼요 · Desktop에서 답할 수 있어요"를 한 번 보냅니다. 이 PC의 런타임이 자동 만료를 지원하지 않으면 남은 시간 문장은 빼고 보냅니다. 그 사이 Desktop이나 버튼으로 답했거나, 이미 자동 거절됐거나, 작업이 끝났으면 보내지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 메신저 문구는 한국어·영어로 보냅니다.

### 실행기가 다시 시작될 때 터미널이 닫힌다는 예고와 이유를 보여 줍니다

원격 터미널은 작업PC 실행기 안에서 돌아서 실행기가 다시 시작되면 닫힙니다. 재시작을 준비하는 동안 열린 터미널 위에 "실행기가 다시 시작되면 이 터미널이 닫혀요 · 약 N초"가 보이고, 닫힌 뒤에는 "실행기가 다시 시작되어 터미널이 닫혔어요"와 다시 열기 버튼이 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 닫힌 터미널은 다시 열기로 새로 엽니다.

### 예약 작업 실행 이력에 승인 대기 만료와 대기로 건너뛴 회차 표시

예약 작업이 승인을 기다리다 시간이 지나 자동으로 거절된 회차에는 실행 이력에 `승인 대기 만료`가 붙고, 계획 승인이 거절돼 아무것도 하지 않고 끝난 회차는 `승인 대기 만료 · 계획 승인 없이 종료`로 보입니다. 이전 회차가 답변·승인을 기다리는 동안 건너뛴 회차는 `이전 작업 실행 중` 대신 대기 때문에 건너뛰었다고 보입니다.

#### 사용 방법

프로젝트 설정의 예약 작업 목록, 또는 Chat 예약 작업의 실행 이력에서 확인합니다. 별도 설정은 없습니다.

### 오래 기다린 작업PC 실행기 교대를 "지금 교대"로 바로 진행할 수 있습니다

작업PC 실행기가 새 버전으로 바뀌기를 사용 중인 터미널 때문에 24시간 넘게 기다렸다면, 작업PC 행에 "새 실행기로 바꾸기를 기다리는 중 · 사용 중인 터미널 N개 · 바꾸면 터미널이 닫혀요"와 지금 교대 버튼이 보입니다. 누르면 이미 설치된 새 실행기로 바로 바꿉니다.

#### 사용 방법

내 설정 → 개발 → 작업PC에서 해당 작업PC 행의 지금 교대를 누릅니다. 바꾸면 그 작업PC의 터미널이 닫힙니다.

### 자동 만료를 지원하지 않는 런타임 안내

이 PC의 런타임이 자동 만료를 지원하지 않으면 예약 작업 설정에 "이 PC의 런타임은 자동 만료를 지원하지 않아요"가 보입니다. 이런 런타임에서는 지켜보는 사람이 없는 예약 작업의 승인 요청이 자동으로 거절되지 않고 계속 기다리므로, 안내를 보고 런타임을 업데이트할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 프로젝트 설정의 예약 작업 목록에서 가장 최근 실행한 런타임이 자동 만료를 지원하지 않을 때만 보입니다.

### 작업PC 실행기가 다시 시작하는 동안 보낸 요청을 끝난 뒤 자동으로 시작합니다

작업PC 실행기가 다시 시작하려고 진행 중인 응답을 마무리하는 동안에는 작업PC 상태 줄과 작업PC 목록에 "재시작 준비 중 · 진행 중 응답 N개 · 터미널 N개"가 보입니다. 이때 새 대화를 시작하거나 끝난 대화(Chat·프로젝트 대화)를 이어 보내면 오류 대신 입력창 위에 "실행기 재시작 중 — 끝나면 자동으로 시작"이 보이고, 재시작이 끝나면 같은 요청을 한 번 자동으로 보냅니다. 재시작이 예상보다 오래 걸리거나 다시 거절되면 기존 오류가 보이며 입력한 내용은 그대로 남습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 자동 시작을 원하지 않으면 입력창 위 줄의 X(자동 시작 취소)를 누르거나 입력을 고치면 됩니다. 작업PC 실행기가 이 기능을 지원하는 버전일 때 동작합니다.

### 지켜보는 사람이 없는 실행의 승인 요청에 남은 시간 표시

예약 작업·메신저처럼 지켜보는 사람이 없는 실행에서 승인·질문·계획 승인 요청이 오면, 카드와 플로팅 승인 패널에 "N분 뒤 자동 거절"이 보입니다. 시간 안에 아무도 답하지 않아 자동으로 거절된 요청은 대화의 그 도구 자리에 "승인 대기 시간이 지나 자동 거절됨" 한 줄이 남아, 왜 그 작업을 하지 않았는지 알 수 있습니다. 사람이 직접 보낸 대화의 요청에는 시간 제한이 없으므로 표시하지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 이 PC의 런타임이 자동 만료를 지원할 때 표시됩니다.

### 회의 후속 정리 스킬 추가

Saycode 공식 스킬에 `meeting-follow-up`이 추가되었습니다. KNOI에 기록된 최근 회의를 읽어 결정 사항, 담당자·기한이 있는 액션 아이템, 남은 질문을 한 장의 후속 정리로 만들어 줍니다. 이 스킬은 KNOI 연동이 필요합니다.

#### 사용 방법

프로젝트 설정에서 1st-party 스킬 팩을 켜거나 대화 프로필에서 이 스킬을 고른 뒤, 대화 입력창에 `/meeting-follow-up`을 입력해 씁니다. 프로젝트 대화의 / 목록에서 고를 때 KNOI가 연결되어 있지 않으면 먼저 연결 안내가 나옵니다.

### AI 답변의 Mermaid 다이어그램을 그림으로 보기

AI 답변에 Mermaid로 쓴 흐름도·순서도 코드블록이 있으면 코드 대신 그림으로 보여줍니다. 코드 상자 위쪽의 `그림 | 코드` 전환으로 원문 코드도 볼 수 있습니다. 답변이 아직 쓰이는 중이면 코드로만 보이다가 코드블록이 끝나면 그림으로 바뀌고, 문법이 틀렸거나 너무 큰 다이어그램은 오류 없이 코드로 남습니다. 라이트·다크 테마를 따릅니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 그림 위쪽의 코드를 누르면 원문과 복사·줄바꿈 아이콘이 나옵니다.

### AI 사용량 창에서 모든 PC의 사용량을 한 번에 봅니다

PC를 여러 대 쓰면 AI 사용량 창 맨 위에 "모든 PC" 요약이 나타납니다. Claude·Codex마다 5시간·7일 막대가 계정별 칸으로 나뉘어 어느 계정에 얼마나 남았는지 보이고, 평균 남은 양, 다음 초기화 때 돌아오는 양, 가장 여유 있는 계정과 그 PC를 함께 알려 줍니다.

같은 조직 계정이 여러 PC에 있어도 한 번만 셉니다. 같은 계정인지 확인할 수 없는 개인 로그인과 Codex 계정은 PC별로 따로 세고 "구분 못 함"으로 표시합니다. 오프라인 PC는 마지막 값과 몇 분 전 기준인지 보여 줍니다. 입력창에 /usage만 보내면 같은 요약이 대화에 앱의 답으로 붙습니다.

#### 사용 방법

개발자 기능 설정에서 AI 잔여량 보이기를 켠 뒤 입력창 아래 AI 사용량 버튼을 누르면 창 맨 위에 "모든 PC"가 보입니다. 내가 소유했거나 조직에서 나에게 배정된 PC가 두 대 이상일 때만 나타나며, 그 아래의 PC별 계정 목록과 조직 계정 선택은 그대로입니다. Claude 대화에서는 Claude가 /usage를 직접 처리하므로 이 요약이 붙지 않습니다(의도된 제약).

## 변경된 기능

### 긴 메시지의 펼치기 버튼이 말풍선 안으로 들어갑니다

보낸 긴 메시지의 `펼치기`·`접기` 버튼을 말풍선과 시간 줄 사이가 아니라 말풍선 안 오른쪽 아래 모서리에 둡니다. 마우스를 올리면 회색 대신 말풍선 색에 맞춘 옅은 강조가 보이고, 펼치거나 접을 때 말풍선 높이가 부드럽게 바뀝니다. 시스템의 동작 줄이기 설정을 켜면 바로 바뀝니다.

#### 사용 방법

긴 메시지 말풍선 안 오른쪽 아래의 `펼치기`를 누르면 전체가 보이고, 같은 자리의 `접기`로 다시 접습니다.

### 대화 요약은 버튼을 누를 때만 열려요

대화 요약 패널을 고정해 두어도 다른 대화에 들어가거나 앱을 다시 열 때 패널이 저절로 열리지 않습니다. 고정은 패널을 열 때 대화 옆 고정 열로 열리게 하는 설정으로 남습니다.

#### 사용 방법

대화 요약이 필요할 때 프로젝트 대화 오른쪽 레일 맨 위의 대화 요약 버튼을 누르세요. 고정해 두었다면 대화 옆 고정 열로 열립니다.

### 로컬 전용 모드 업데이트가 진행 중인 응답을 마무리한 뒤 다시 시작합니다

macOS·Linux의 로컬 전용(이 컴퓨터에서만 사용) 모드에서 재시작해서 업데이트를 누르면, 진행 중인 응답이 끝날 때까지 최대 60초 기다린 뒤 다시 시작합니다. 기다리는 동안 업데이트 버튼 자리에 "진행 중인 응답을 마무리하는 중 · N개 · 지금 재시작"이 보입니다. 기다림이 끝나지 않아도 업데이트는 그대로 진행됩니다.

#### 사용 방법

계정 메뉴에서 재시작해서 업데이트를 누릅니다. 바로 다시 시작하려면 같은 자리의 "지금 재시작"을 누릅니다. Windows와 Saycode 계정 모드는 지금처럼 바로 다시 시작합니다.

### 링크로 받은 질문에서 보이지 않는 문자를 지웁니다

saycode-desktop://new 링크로 받은 질문에 화면에 보이지 않는 문자(폭 없는 문자, 태그 문자, 글자 방향 제어 문자)가 있으면 지운 뒤 입력창에 넣고 "링크에서 보이지 않는 문자를 제거했어요"라고 알려 줍니다. 보이지 않게 숨긴 지시가 질문에 섞여 들어가는 것을 막습니다. 질문은 지금처럼 자동으로 보내지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 빠른 열기에서 더 많은 명령을 바로 실행하고, > 로 명령만 볼 수 있습니다

빠른 열기(Cmd+P, Windows는 Ctrl+P)에서 실행할 수 있는 명령이 늘었습니다. 새 대화, 응답 중단, 터미널 열기, 오른쪽·아래에 터미널·대화·브라우저 분할, 환경설정과 자주 여는 설정(단축키·토큰 사용량·알림), 지금 보고 있는 대화의 고정·보관을 바로 실행할 수 있습니다. 명령은 지금 보고 있는 대화를 대상으로 하고, 지금 실행할 수 없는 명령은 목록에 나오지 않습니다. 맨 앞에 > 를 입력하면 프로젝트·대화·파일 없이 명령만 보입니다.

#### 사용 방법

빠른 열기를 열고 명령 이름을 입력하거나 > 를 입력한 뒤 오른쪽에 '명령'이라고 표시된 항목을 고릅니다.

### 사이드바에서 답변할 질문을 확인하세요

AI가 질문에 대한 답변을 기다리면 사이드바의 Chat과 프로젝트 대화에 주황색 질문 아이콘이 나타납니다. 개인 Chat이 응답 중일 때 다른 화면으로 이동해도 나중에 도착한 질문을 표시합니다. 제출한 답변은 항목과 내용을 가지런히 정렬하고 글자 굵기와 간격을 줄여 읽기 편하게 정리했습니다.

#### 사용 방법

사이드바의 질문 아이콘이 있는 대화를 열어 답변하거나 건너뛰세요. 아이콘에 마우스를 올리면 답변 대기 상태를 확인할 수 있습니다. 답변 전송이 성공하면 질문 표시가 사라집니다. 별도 설정 없이 자동 적용됩니다.

### 앱 종료 안내를 쉽게 설명해요

종료 확인 창에서 어려운 용어를 줄이고, 대화가 계속되는지 또는 중단되는지와 완료 알림·예약 작업·준비 중인 워크트리에 미치는 영향을 쉽게 설명합니다. macOS에서 종료 버튼이 잘리지 않도록 창 크기도 내용 영역에 맞춥니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 진행 중인 작업이 있을 때 키보드나 앱 메뉴로 종료하면 안내를 볼 수 있습니다.

모델을 Auto로 두고 개인 ChatGPT 로그인으로 Codex를 쓰면, 요금제가 지원하지 않는 모델(GPT-6.1 Sol)이 자동으로 골라져 "현재 AI에서 사용할 수 없는 모델이에요" 오류로 대화가 시작되지 않을 수 있었습니다. 이제 Saycode가 그 컴퓨터의 Codex 계정이 쓸 수 있는 모델을 확인해, 지원하지 않는 모델 대신 쓸 수 있는 한 단계 아래 모델(GPT-6 Sol 등)로 보냅니다. 이미 이 오류를 받은 대화도 다음 메시지부터는 같은 모델을 다시 고르지 않습니다. 직접 고른 모델은 그대로 유지합니다.

AI 심사가 늦게 답한 요청은 허용·거절로 기록하거나 안내하지 않습니다.

#### 사용 방법

### Codex가 방금 갱신한 로그인을 Saycode가 덮어쓰지 않음

Codex 사용량 확인 중 계정 자동 전환과 개인 AI 계정 등록이 Codex 로그인 파일을 바꾸기 직전에, Saycode는 그 사이 Codex가 로그인을 갱신했는지 다시 확인합니다. 갱신됐다면 예전 로그인으로 덮어쓰지 않고 최신 값으로 다시 시도합니다. 그래서 멀쩡하던 Codex 연결이 갑자기 "다시 로그인 필요"로 바뀌는 일이 줄어듭니다. 조직 인증 세트 적용에도 같은 확인이 들어가며, 다시 시도해도 계속 바뀌면 조직 AI 연결 화면에 "다른 프로그램이 방금 인증을 갱신해서 다시 시도했어요"가 보이고 잠시 뒤 자동으로 다시 확인합니다. 조직 인증 세트 쪽 동작은 PC의 Saycode 런타임이 이 버전에 맞춰 업데이트된 뒤부터 적용됩니다.

### MCP 도구 이름 중간의 삭제·생성 동사도 위험 표시에 반영

AI 도구 사용 규칙의 MCP 도구 목록이 도구 이름의 모든 단어를 보고 읽기·쓰기·항상 확인을 표시합니다. 이전에는 이름 앞 두 단어만 봐서 `mem-perspective-observation-delete`처럼 동사가 뒤에 오는 삭제·생성 도구가 "(읽기)"로 보였습니다. `get_latest_release`처럼 읽기 동사 뒤에 오는 release·email·message 같은 말은 동사로 보지 않아 읽기로 표시합니다. 표시는 지금 열린 대화가 도는 PC의 AI 런타임이 판정하는 규칙을 따르며, 이전 런타임이면 그 런타임이 실제로 판정하는 대로, 이 앱이 모르는 규칙이면 "판정 정보 없음"으로 표시합니다.

이 버전에 포함된 작업PC AI 런타임은 표시와 같은 규칙으로 실제 판정도 합니다. 이름 뒤쪽에 삭제·전송 같은 동사가 있는 MCP 도구는 이제 매번 사람이 확인해야 실행되고, 이름 뒤쪽에 생성·저장 같은 동사가 있는 도구는 "쓰기 도구도 실행 전에 묻기"를 켰을 때 확인을 받습니다. 지금까지는 이런 도구도 읽기로 판정돼 확인 없이 실행됐습니다. `edit_message`처럼 메시지를 바깥으로 보내는 쓰기 도구도 매번 확인합니다.

#### 사용 방법

설정 ▸ 보안 ▸ AI 도구 사용 규칙 ▸ MCP 도구에서 확인합니다. 별도 설정 없이 자동 적용됩니다. 실제 판정 변경은 이 버전으로 업데이트한 뒤 작업PC 런타임이 새 버전으로 다시 시작되면 적용됩니다.

### PC 연결이 다시 시작돼도 조직 AI 계정 적용이 20분 동안 막히지 않음

PC를 새로 등록한 직후처럼 연결 상태가 바뀌어 조직 AI 계정 적용이 중간에 다시 시작되면, 이전에는 적용이
'이미 진행 중'으로 최대 20분 동안 막히고 그동안 첫 대화가 시작되지 않을 수 있었습니다. 이제 진행 중이던
적용을 정상적으로 마무리한 뒤 다시 시도하므로 바로 적용됩니다. 네트워크 끊김이나 응답 지연으로 응답을
받지 못한 경우에도 같은 적용으로 한 번 더 요청해 중복으로 막히지 않습니다.

#### 사용 방법

### Windows standalone 모드에서 미리보기 이미지 받기·공유 링크용 검은 창이 뜨지 않습니다

창 없이 뒤에서 실행됩니다. 진행 기록은 전과 같이 앱 안의 로그에 남습니다.

### Windows에서 AI 작업이 실행 중이어도 재시작해서 업데이트할 수 있습니다

Windows에서 대화의 AI 응답이 진행 중일 때 업데이트 준비 완료 창의 재시작해서 업데이트를 누르면
"Still running from the install directory: … claude.exe" 오류가 나고 재시작되지 않는 경우가
있었습니다. Saycode가 함께 설치한 AI 도구가 아직 실행 중이라 설치 파일을 바꿀 수 없었기
때문입니다. 이제 업데이트 직전에 이 AI 도구를 직접 종료하고 업데이트를 이어 갑니다. 진행 중이던
AI 응답은 중단되며, 업데이트 후 같은 대화에서 다시 요청할 수 있습니다.

### Windows에서 cmd 창이 반복해서 떴다 사라지던 문제 수정

Windows에서 Saycode를 켜 두면 검은 명령 창이 20초쯤마다 잠깐 떴다 사라졌습니다. 작업PC 런타임이
설치된 AI CLI를 확인할 때마다 PowerShell을 실행해서 생긴 문제입니다. 이제 프로세스를 띄우지 않고
확인하므로 창이 뜨지 않습니다. 스크립트 자동화나 미리보기에서 Docker를 쓸 때 열리던 창,
AI가 명령을 실행할 때 열리던 창도 함께 숨겼습니다.
