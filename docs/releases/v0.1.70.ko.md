## 새 기능

### 단축키로 이전·다음 대화를 이동할 수 있습니다

입력 중에도 사이드바 순서에 따라 대화를 이동할 수 있습니다. 일반 대화는 현재 프로젝트의 표시 목록, 개인 Chat은 해당 목록, 고정 대화는 프로젝트를 넘는 전체 고정 목록을 사용합니다. 목록 끝에서는 멈추며 작성 중인 초안을 유지합니다.

#### 사용 방법

Mac에서는 Option+Shift+[ 또는 Option+Shift+]를, 다른 플랫폼에서는 Alt+Shift+[ 또는 Alt+Shift+]를 누르세요. 내 설정의 단축키에서 조합을 변경할 수 있습니다.

### 로그인 화면에서 비밀번호 찾기

로그인 화면에서 비밀번호 재설정 메일을 요청할 수 있습니다. 입력한 이메일을 이어받으며, 실패하면 다시 요청할 수 있습니다.

#### 사용 방법

로그인 → 비밀번호 찾기 → 이메일 입력 → 재설정 메일 요청을 누릅니다. 가입된 이메일의 받은편지함과 스팸함을 확인하고 메일 링크에서 새 비밀번호를 설정한 뒤, 앱의 로그인으로 돌아가기에서 로그인합니다.

### 시작 화면에서 조직 관리와 초대 열기

조직 관리자 시작 화면 오른쪽 아래에 조직 관리와 초대 버튼을 추가했습니다. PC나 AI 연결 전에도 관리 화면에 들어갈 수 있습니다. 일반 구성원에게는 표시하지 않으며 받은 초대 알림과 겹치지 않습니다. 조직 관리 아이콘은 계정 메뉴와 동일하게 맞췄습니다. 관리 화면을 열지 못한 경우에도 오류 안내와 받은 초대 알림이 겹치지 않습니다.

#### 사용 방법

Chat 또는 Project 시작 화면에서 조직 관리를 누르면 내장 관리자 창이 열립니다. 초대를 누르면 현재 앱 계정으로 재인증한 뒤 구성원 관리로 이동합니다. 그 화면에서 이메일 초대 또는 코드 발급 버튼을 누릅니다.

### 온보딩 뒤에도 조직 AI 계정 연결

AI 연결 설정에 조직 계정 연결 섹션을 추가했습니다. 온보딩을 마친 뒤에도 조직에서 배정한 AI 계정을 이 컴퓨터에 다시 가져올 수 있습니다. AI 연결 설정은 왼쪽 AI 그룹의 첫 항목에 표시됩니다. 홈에서 AI 연결 상태를 확인하지 못했을 때 다시 확인을 누르면 이 설정이 바로 열립니다.

#### 사용 방법

내 프로필 → 내 설정 → AI 연결 설정 → 조직 계정 연결하기를 누릅니다. 이 컴퓨터가 조직에 등록되어 온라인이어야 합니다. 개인 AI 계정은 바로 아래에서 연결합니다.

### 우측 도구 패널 단축키

우측 도구 패널을 키보드로 접고 펼칠 수 있습니다. 접기·펼치기 버튼에 마우스를 올리면 단축키도 표시됩니다. 충돌을 피하도록 브라우저 오른쪽 분할의 기본 단축키를 Cmd/Ctrl+Alt+B로 변경했습니다.

#### 사용 방법

대화 화면에서 macOS는 Cmd+Shift+B, Windows는 Ctrl+Shift+B를 누릅니다. 열린 도구와 작성 중 내용은 유지됩니다.

### 이 컴퓨터 등록 없이 시작하기

조직 시작준비 화면에 `이 컴퓨터 없이 시작` 버튼이 생겼습니다. 이 컴퓨터를 작업PC로 등록하지 않고도 앱을 쓸 수 있고, 컴퓨터 준비가 실패해 시작준비 화면에서 더 진행할 수 없을 때도 앱에 들어갈 수 있습니다. 건너뛴 뒤 앱을 다시 열어도 시작준비 화면이 다시 뜨지 않습니다. 조직에 대화에 쓸 수 있는 다른 온라인 작업PC가 있으면 그 PC 이름을 안내하고, 없으면 대화를 시작할 수 없다고 미리 알려 줍니다.

#### 사용 방법

시작준비 화면 아래쪽에서 `이 컴퓨터 없이 시작`을 누릅니다. 나중에 등록하려면 Chat 시작 화면의 `작업PC 설정 열기`를 누르거나 내 설정 → 작업PC → `내 컴퓨터 등록`을 누릅니다. 등록 전에는 다른 온라인 작업PC에서 대화할 수 있습니다.

### 조직 기기 승인 확인

관리자 승인과 이 컴퓨터의 확인 상태를 구분하고, 전체 지문을 비교한 뒤 로컬 확인을 진행할 수 있습니다. 지원 CLI와 서버가 필요합니다.

#### 사용 방법

내 설정 → 개발 → 작업PC → 이 컴퓨터의 상세 정보에서 조직 기기 승인을 엽니다. 관리자와 전체 지문·조직·기기 ID를 비교하고 확인을 누릅니다. 기기 승인은 AI 계정 연결 완료와 별개입니다.

### 조직 첫 화면에서 다음 행동 안내

조직의 Chat·Build 첫 화면에서 작업PC 없음·오프라인, AI 등록·배정 필요, 상태 확인 실패를 구분하고 필요한 행동을 안내합니다. 사용할 준비가 되면 기존 입력창을 제공하며, 작성 중 상태가 바뀌어도 글과 첨부를 유지하고 전송을 막습니다. AI가 없으면 내 AI 연결 또는 관리자용 조직 AI 연결을 선택할 수 있습니다. 같은 계정·작업PC로 돌아올 때 확인 결과를 유지해 반복 안내를 줄입니다. 오프라인 작업PC가 선택돼 있을 때 다른 온라인 PC가 있으면 바로 선택할 수 있습니다. 초기 준비 화면과 설치·등록·AI 적용 과정은 그대로 유지합니다.

#### 사용 방법

사이드바의 Chat 또는 Project → Build에서 안내 아래의 작업PC 설정 열기·작업PC 선택·다시 확인·내 AI 연결·조직 AI 연결을 누릅니다. 내 AI 연결은 기존 내 AI 계정 설정을 엽니다. 조직 관리는 현재 앱 계정으로 재인증한 뒤 AI 설정을 확인합니다.

## 변경된 기능

### 개발자 설정과 계정 메뉴 간소화

입력창·Develop 홈·작업보드·작업PC 목록의 개발자 기능 설정 아이콘 바로가기를 제거했습니다. 계정 메뉴의 조직 관리는 맨 위에 배치하고, 이 컴퓨터에서 개인 사용 메뉴는 제거했습니다.

#### 사용 방법

개발자 기능 설정은 사이드바 하단 계정 메뉴에서 엽니다. 로그인 전 시작 화면의 개인 사용 선택은 그대로 사용할 수 있습니다.

### 대화 삭제·보관에 예약 함께 정리

Chat을 삭제하면 연결된 예약도 취소하고 실행 중인 작업에 중단을 요청합니다. 보관하면 예약을 일시정지하며 대화를 복원해도 자동으로 재개하지 않습니다. Desktop 삭제창에서 연결된 예약 수와 함께 취소되는 영향을 확인할 수 있습니다. 예약 조회·정리에 실패하면 대화 삭제·보관을 완료하지 않습니다. 삭제·보관·복원 결과는 열려 있는 고급 예약 관리창에도 바로 반영됩니다.

#### 사용 방법

Chat의 더보기에서 삭제 또는 보관을 선택하세요. 삭제창에서 예약 영향을 확인한 뒤 삭제합니다. 실행 중 작업의 중단에는 지원하는 서버·CLI 업데이트가 필요하며 오프라인 PC는 재연결 후 반영합니다. 복원한 대화의 예약은 예약 작업에서 직접 재개하세요.

### 사이드바에서 프로젝트와 대화를 바로 만들 수 있습니다

사이드바 Chat/Project 탭의 너비를 줄이고 검색 왼쪽에 생성 버튼을 추가했습니다. 대화 항목에는 둥근 말풍선 아이콘을 표시하며 생성·검색 아이콘의 크기와 선 굵기를 맞췄습니다.

#### 사용 방법

사이드바 목록 탭에서 Project를 선택하면 큐브와 + 버튼으로 프로젝트를 만들 수 있습니다. Chat을 선택하면 작성 버튼으로 새 대화를 시작할 수 있습니다.

### 앱 디자인에 맞춘 확인창

삭제·보관·전송·앱 종료 등의 확인창이 앱 디자인에 맞춰 표시됩니다. 취소 또는 Escape를 누르면 작업을 진행하지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 앱 안에서 조직 관리자 로그인

조직 관리를 기본 제목 표시줄의 닫기 버튼이 있는 앱 전용 창에서 엽니다. 현재 앱 계정을 고정해 비밀번호만 다시 입력하며, 다른 조직 접근을 제한하고 창을 닫거나 앱 계정·조직이 바뀌면 관리자 웹 세션을 정리합니다. 앱 로그인 토큰은 웹에 전달하지 않습니다. 전용 웹 로그인 배포 후 사용할 수 있습니다.

관리자 화면이 비정상 종료되거나 열리지 않으면 창을 정리해 다시 로그인할 수 있습니다. 로그아웃 후 늦게 도착한 권한 조회 오류는 표시하지 않습니다.

앱 창을 먼저 닫아도 관리자 창과 임시 로그인 저장소를 안전하게 정리합니다.

#### 사용 방법

사이드바 하단 계정 메뉴 맨 위에서 조직 관리를 선택하고 표시된 현재 앱 계정을 확인하고 비밀번호를 입력합니다.

### 예약 결과를 일반 대화에서 이어보기

새 예약의 질문과 답변이 같은 일반 Chat에 쌓입니다. 웹에서도 기존 대화 화면으로 결과를 읽고 후속 질문을 할 수 있습니다. 대화 연결 결과가 불확실하면 준비한 동일 세션을 다시 확인해 중복 생성을 막습니다. 지원하지 않는 PC는 대화 생성 전에 안내합니다. 과거 예약 기록은 이전하지 않습니다. 지원하는 PC에 Happy CLI 1.1.10-aplus.323 이상이 필요하며 서버도 해당 기능을 지원해야 합니다.

#### 사용 방법

지원 버전으로 업데이트한 PC에서 새 예약을 등록하세요. 예약 시각마다 같은 대화에 질문과 답변이 추가됩니다. 지원하지 않는 PC에는 업데이트 안내가 표시됩니다.

### 예약 대화 실행을 지원하는 내장 런타임 갱신

내장 Happy CLI를 1.1.10-aplus.323으로 고정합니다. 이미 추가된 일반 대화 예약 기능에 필요한 실행기 지원을 포함합니다. Windows 재현 빌드용 의존성도 같은 버전으로 고정합니다.

#### 사용 방법

업데이트된 앱에 자동 적용됩니다. 연결된 작업PC와 서버도 지원 버전이어야 하며, 기존 예약 기록은 이전하지 않습니다.

### 예약 입력 화면 정리

예약 입력 화면의 반복 설명을 줄이고 요청·반복·시간을 간결하게 배치했습니다. 예약 이름·실행할 대화·PC는 접힌 고급 설정에서 확인할 수 있습니다. 저장 오류와 복구 안내는 유지합니다. 사이드바의 예약 대화는 앞쪽에 시계 아이콘 하나로 표시합니다.

#### 사용 방법

예약에서 새 예약을 열어 요청과 시간을 입력하세요. 이름·대화·PC를 확인하거나 변경하려면 고급을 펼치세요. 실행 시각은 선택한 PC 기준입니다.

### 외부 서비스 연결을 브라우저의 Saycode 연결 페이지에서 시작합니다

Gmail·Google Drive·Notion·Slack·Microsoft 365 커넥터와 GitHub·GitLab 계정을 연결하면, 시스템 브라우저에 Saycode 연결 페이지가 먼저 열립니다. 그 브라우저에 로그인된 계정을 확인한 뒤 「연결 계속」을 누르면 서비스 동의 화면으로 이어집니다.

연결을 시작한 브라우저와 동의를 마친 브라우저가 같은지 서버가 확인할 수 있게 하려는 보안 변경입니다. 다른 사람이 보낸 동의 링크로 내 외부 계정이 그 사람의 Saycode 계정에 연결되는 일을 막습니다.

#### 사용 방법

- 브라우저가 로그아웃 상태면 로그인한 뒤 연결 페이지로 돌아옵니다.
- 브라우저에 앱과 다른 Saycode 계정으로 로그인돼 있으면 연결을 시작하지 않고 안내합니다. 앱과 같은 계정으로 다시 로그인한 뒤 앱에서 연결을 다시 시작하세요.

### 외부 연동 목록을 먼저 표시합니다

외부 연동을 열면 서비스 목록과 검색이 먼저 표시됩니다. 연결 상태는 각 항목에서 확인하며, 한 서비스의 응답이 늦어져도 다른 서비스는 바로 사용할 수 있습니다. 조회 실패는 해당 항목에서 다시 확인할 수 있습니다.

#### 사용 방법

사이드바에서 외부 연동을 엽니다. 확인 중인 항목은 상태 확인이 끝난 뒤 연결할 수 있습니다.

### 종 아이콘으로 사이드바 알림 표시 전환

프로필 메뉴의 알림 보이기 스위치 대신 하단 종 아이콘으로 사이드바 최근 알림 영역을 켜고 끕니다. 켜면 아이콘이 브랜드색으로, 끄면 회색으로 표시되며 미확인 개수는 유지됩니다. 최근 알림 제목과 아이콘은 작고 차분한 톤으로 표시합니다. 알림 센터는 더 좁은 우측 패널로 부드럽게 열고 닫으며 상단 버튼은 작고 가지런하게 표시하며 닫기 버튼은 좁은 창에서도 오른쪽 위에 고정됩니다. 알림이 없어도 빈 상태와 전체보기를 확인할 수 있습니다. 닫힘 효과가 끝난 뒤 패널이 다시 나타나지 않도록 했습니다.

#### 사용 방법

사이드바 아래 프로필 옆 종 아이콘을 누르세요. 다시 누르면 알림 영역이 숨겨지고, 마지막 표시 상태가 저장됩니다. 전체 알림은 최근 알림 영역의 전체보기에서 확인하세요.

### 진한 회색 콘텐츠 배경을 밝게 개선

### 첫 화면 입력창 유지와 상태 안내 위치 개선

작업PC나 AI 준비가 필요해도 Chat과 Build의 입력창을 유지합니다. 입력·첨부·전송은 비활성화하고, 아래 사용 가이드 자리에 현재 상태와 연결 버튼을 표시합니다. 비활성 입력창은 회색 채움 대신 기본 배경과 옅은 글자·아이콘으로 표시합니다. 새 대화 패널과 조직 역할 확인 전의 PC 안내도 같은 위치로 통일했습니다. 숨겨진 AI 때문에 사용할 후보가 없으면 전송을 막고 표시 설정으로 안내합니다. 내 AI 연결은 제공자 선택으로 바로 열며, 닫은 연결 안내는 같은 PC의 새 대화에서 반복하지 않습니다. 배정과 구성원 PC 권한의 다음 행동도 명확히 했습니다. 관리자 화면을 재사용할 때 이전 탭 이동이 늦게 실패해도 최신 선택을 되돌리지 않습니다. 기존 초안과 첨부는 보존하며 초기 준비 모달은 그대로입니다.

Chat 또는 Project → Build를 열고 입력창 아래 안내에 따라 작업PC나 AI를 연결하세요. 조직 소유자·관리자에게만 조직 AI 연결이 표시됩니다. 일반 구성원은 내 AI를 연결하거나 관리자에게 조직 AI 연결·배정을 요청한 후 다시 확인하세요. 숨긴 AI는 AI 표시 설정에서 다시 켭니다. AI가 등록돼 있으면 관리자는 AI 배정 설정으로 인증 연결 관리를 확인합니다. 구성원의 PC 권한은 관리자에게 요청한 뒤 다시 확인합니다. 준비되면 입력창과 사용 가이드가 복원됩니다.

### PC 등록을 미루는 버튼명 개선

## 수정된 문제

### 개발 서버의 localhost 주소 유지

이 컴퓨터의 개발 서버는 localhost로 직접 엽니다. 다른 PC의 서버를 포워딩해 사용할 때도 미리보기 경로가 개발 화면에 섞이지 않도록 페이지와 로그인 callback 경로를 유지합니다. 원격 포워딩에는 localhost 전달을 지원하는 Happy 서버 업데이트가 필요하며, 미지원 서버에서는 오류를 표시합니다.

#### 사용 방법

미리보기의 리슨 포트 감지에서 포트를 선택하거나 직접 입력하세요. 다른 PC는 연결한 뒤 브라우저에서 열기를 누르세요. 포트가 사용 중이라 대체 포트를 받았다면 표시된 실제 포트에 맞춰 OAuth callback을 등록하세요.

### 공유 작업PC의 커넥터 준비 오류 수정

공유 작업PC가 사용자별 커넥터 전달을 지원해도 연결 프로그램 업데이트 안내로 대화 시작·재개가 막힐 수 있는 문제를 수정했습니다. 기존 머신 키 검증과 보안 보호는 유지됩니다.

#### 사용 방법

수정된 앱으로 업데이트한 뒤 같은 작업PC에서 대화를 다시 시작하거나 재개해 주세요. 별도 설정 없이 자동 적용됩니다.

### 기존 작업PC의 반복 권한 검사 줄임

#### 사용 방법

내장 조직 관리자 로그인에서 패스키 인증이 끝나지 않는 문제를 개선했습니다. 패스키 확인은 시스템 브라우저에서 진행하고, 인증 결과는 같은 계정·조직으로 고정된 관리자 창에서 확인합니다. 대기 중 취소·다시 시도와 브라우저 열기 실패 복구를 제공합니다.

### 다른 uv가 먼저 잡혀도 Saycode가 설치한 uv를 사용

Windows 시작 준비가 Saycode가 설치한 uv 대신, 사용자가 따로 설치해 Path에서 먼저 잡히는 uv(예: `%USERPROFILE%\.local\bin\uv.exe`)를 실행하던 문제를 고쳤습니다. 그 uv가 매번 느리게 실행되는 PC에서는 `실행 확인`이 시간 초과로 실패했습니다.

- 이제 uv는 Saycode가 설치한 고정 버전을 먼저 찾고, 없을 때만 Path에서 찾습니다.
- Node.js와 Git은 지금처럼 사용자가 설치한 것을 그대로 씁니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 도구 실행 확인이 시간 초과되면 보안 프로그램 검사 가능성을 안내

시작 준비에서 설치된 도구의 `실행 확인`이 시간 초과되면, 지금까지는 "네트워크를 확인한 뒤 다시 시도해 주세요"라고 안내했습니다. 이 단계는 네트워크를 쓰지 않기 때문에 잘못된 안내였습니다.

- 이제 "설치된 도구의 실행 확인이 제한 시간 안에 끝나지 않았어요"라고 표시하고, 회사 보안 프로그램이 새 실행 파일을 검사하는 중일 수 있으니 몇 분 뒤 다시 시도하도록 안내합니다.
- 반복되면 진단을 IT 담당자에게 전달해 예외 등록을 요청하도록 안내합니다.
- 오류 코드는 `TOOL_EXECUTION_TIMEOUT`으로 구분됩니다. 다운로드·설치 단계의 시간 초과는 기존 안내를 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 시작 준비에서 실패한 도구의 오류 상세를 열면 확인할 수 있습니다.

### 도구 폴더가 잠깐 사용 중이어서 claude-swap 준비가 실패하면 자동으로 다시 시도

- 이제 짧게 기다렸다가 몇 차례 자동으로 다시 시도합니다. 사용 중 상태가 금방 풀리면 설치가 그대로 이어집니다.
- 계속 막혀 있으면 이전처럼 "파일 사용 중"·"권한" 원인과 로그 위치를 함께 보여 줍니다.

별도 설정 없이 자동 적용됩니다.

### 설치 직후 보안 프로그램 검사로 도구 확인이 시간 초과되던 문제 수정

- 도구를 한 번 실행해 확인하는 단계는 이제 최대 2분까지 기다립니다.
- 2분을 넘겨도 한 번 더 실행해 확인합니다. 보안 프로그램은 보통 검사가 끝난 파일을 다시 검사하지 않아, 두 번째 실행은 바로 끝납니다.
- 실행 확인이 실패하면 걸린 시간과 오류가 setup.log에 남습니다.

### Windows 보안 프로그램이 claude-swap을 늦춰도 Claude 계정 연결·사용량·전환이 시간 초과되지 않음

보안 프로그램(AhnLab 등)이 있는 Windows PC에서는 Claude 계정 전환 도구(claude-swap)가 실행될 때마다 15~21초씩 늦어질 수 있습니다. 그래서 시작 준비의 Claude 계정 연결, Claude 사용량 표시, 계정 전환이 정해진 시간 안에 끝나지 못하고 실패로 보였습니다.

- Windows에서는 claude-swap을 한 번 실행할 때 최대 1분까지 기다립니다.
- 사용량 조회와 시작 준비의 Claude 계정 연결은 최대 2분 30초, 계정 전환은 최대 1분 30초(자동 전환 확인이 함께 있으면 2분 30초)까지 기다립니다.
- Windows 시작 준비는 늦은 성공 응답을 기다리며, 조회 중 다른 창의 중복 조회와 전환 중 자동 계정 변경을 막습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 보안 프로그램에 `%USERPROFILE%\.local\bin`과 `%APPDATA%\uv` 폴더를 예외로 등록하면 더 빨라집니다.

### Windows 보안 환경의 자동 PC 연결 개선

Windows에서 PC 연결을 준비할 때 자격증명 보호·복구와 실행 환경 조회가 PowerShell에 의존하지 않도록 변경했습니다. Happy 데몬은 Windows가 신뢰하는 인증서를 사용하며, 자동 등록 후 온라인 확인도 앱의 네트워크 경로를 사용합니다. 기존 자격증명 보호 검사와 연결 코드 자동 발급은 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### Windows 설치 파일 수를 약 35% 줄여, 보안 프로그램이 있는 PC의 설치 시간 단축

새 파일마다 검사하는 회사 보안 프로그램이 있는 Windows PC에서 Saycode 정식판 설치가 1시간 넘게 걸리던 문제를 줄였습니다. 설치 프로그램이 쓰는 파일은 약 2만 1천 개였고, 그중 7천여 개는 실행 중에 쓰이지 않는 개발용 타입 정의 파일이었습니다.

- 이 파일들을 설치판에서 뺐습니다. 설치되는 파일이 약 2만 1천 개에서 1만 4천 개로 줄어, 검사할 파일도 그만큼 줄어듭니다.
- 앱 동작은 달라지지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 설치 폴더(`%LOCALAPPDATA%\Programs\Saycode`)를 보안 프로그램 예외로 등록하면 설치가 더 빨라집니다.

### Windows 시작 준비가 저장 권한 문제로 멈추면 "이 PC에서 계속"을 바로 고를 수 있음

회사 보안 설정 때문에 로그인 정보는 저장됐지만 PC 연결 정보를 보호된 폴더에 저장하지 못하는 Windows PC가 있었습니다. 이 경우 시작 준비가 "설치 폴더 접근 권한" 오류에서 멈추고 "다시 시도"밖에 할 수 없었습니다.

- 이제 이 경우에도 "이 PC에 로그인 정보를 저장할까요?" 확인 창이 열립니다.
- "이 PC에서 계속"을 고르면 일반 앱과 같은 수준으로 저장하고, 멈췄던 시작 준비를 자동으로 다시 진행합니다.
- 취소한 뒤 다시 시도해서 같은 이유로 또 멈추면 다시 묻습니다.

#### 사용 방법

확인 창에서 원인과 차이를 확인한 뒤 "이 PC에서 계속"을 누르세요. 나중에 설정 > 일반의 "로그인 정보 저장"에서 되돌릴 수 있습니다.

### Windows 실행 대기 안내 개선

Windows에서 기존 로딩 화면이 오래 유지되거나 온보딩에서 PC를 준비할 때 보안 프로그램 검사로 실행이 지연될 수 있음을 안내합니다. 로딩 화면은 AhnLab MDS 실행을 확인한 경우 이를 함께 표시하며, 프로그램 응답 시간 초과와 접근 권한 오류를 구분합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 보안 프로그램 검사 알림이 있다면 검사 완료 후 다시 시도해 주세요.

### Windows Git 출력 오류 수정

Saycode가 설치한 Windows Git에서 `git branch`, `git log`, `git diff` 실행 시 `less`를 찾지 못하던 문제를 수정했습니다. 기본 출력을 터미널에 직접 표시하며 사용자 전역·저장소 Git 설정은 유지합니다.

#### 사용 방법

새 Git 설치에 적용됩니다. 기존 설치는 앱의 필수 도구 설치·복구 과정에서 보완됩니다.

### Windows PC 연결 중 자격증명 소유자 오류 수정

관리자 권한으로 실행한 Windows에서 사용자 전용 보호 저장소에 만들어진 파일 때문에 PC 연결이 접근 권한 오류로 멈추는 문제를 수정했습니다. 현재 사용자가 이미 모든 권한을 가진 관리자 소유 파일만 사용자 소유로 정리하고, 기존 로그인 정보와 PC 신원을 보존합니다.

#### 사용 방법

수정 버전을 설치한 뒤 시작준비에서 다시 시도하세요. 별도 권한 설정은 필요하지 않습니다.

### Windows에서 조직 Claude 계정 연결 복구

Windows에 실제 Claude 자격증명 없이 오래된 로그인 정보만 남아 시작 준비의 조직 계정 적용이 실패하던 문제를 수정했습니다. 이런 경우 오래된 로그인 정보만 정리하며 기존 자격증명과 사용자 설정은 보존합니다.

#### 사용 방법

업데이트 후 시작 준비를 다시 시도하면 자동 적용됩니다.
