## 새 기능

### 공용 PC가 조직 승인을 스스로 확인하고 계정 한도에서 자동으로 바꿉니다

공용 PC로 등록한 컴퓨터는 서버가 서명한 조직 기기 승인을 받으면, 신뢰하는 Saycode 주소가 알려주는 조직 키와 같은지 스스로 대조해 확인합니다. 관리자가 지문을 대조하지 않아도 됩니다. 공용 PC의 조직 Claude 계정이 한도에 닿으면 서버가 받아들이는 PC에서는 다른 계정으로 자동으로 바꿉니다. 서버가 아직 받지 않거나 미리 만든 대화는 기존 방식으로 실행합니다. 이렇게 시작한 대화도 첫 질문이 사라지지 않습니다.

#### 사용 방법

새 Desktop 빌드의 기본 런타임에 포함됩니다. 공용 PC로 등록한 컴퓨터에서 자동으로 적용됩니다. 전용 PC와 기존 런타임은 기존 확인 절차를 유지합니다.

### 긴 대화를 한눈에: 대화 요약 패널과 메시지 이동 레일

프로젝트 대화에서 내가 보낸 메시지가 두 개 이상이면 대화 스크롤바 오른쪽에 세로 레일이 생깁니다. 점 하나가 내 요청 하나이고, 커밋·PR·리뷰·미리보기·변경 파일이 나온 요청의 점은 채워져 보입니다. 점에 마우스를 올리거나 키보드로 고르면 요청 앞부분과 그 요청에서 나온 산출물이 보이고, 누르면 그 메시지로 바로 이동합니다.

레일 위쪽의 대화 요약 버튼은 이 대화의 계획, 산출물(PR·커밋·변경 파일·미리보기·리뷰), 곁질문, 백그라운드 작업, 자식 AI를 한 패널에 모아 보여 줍니다. 항목을 누르면 그 산출물이 나온 메시지로 이동합니다. 핀을 누르면 패널이 대화 옆에 고정되어 다른 대화로 옮기거나 앱을 다시 열어도 그대로 열려 있습니다.

#### 사용 방법

프로젝트 대화 오른쪽 레일의 점을 눌러 이동합니다(Tab으로 레일에 들어가 ↑/↓/Home/End로 고를 수 있습니다). 레일 맨 위 대화 요약 버튼으로 패널을 열고, 패널 머리의 핀 버튼으로 대화 옆에 고정하거나 풀 수 있습니다. 좁은 창에서는 고정해도 버튼으로 여는 떠 있는 패널로 보입니다.

### 내 개발·테스트 환경에서는 결제·계정 삭제 흐름도 확인 한 번 뒤 AI가 테스트합니다

AI가 브라우저·컴퓨터를 조작할 때 결제·계정 삭제 같은 행동은 원래 직접 하지 않고 사용자에게 넘기도록 안내합니다. 이제 사용자가 직접 만드는 앱의 그런 흐름을 테스트해 달라고 명시적으로 요청했고, 대상이 내 개발·테스트 환경(localhost·127.0.0.1·사설 IP·`.local` 주소·Saycode 프리뷰 주소)이며 테스트 데이터를 쓸 때는, AI가 실행 직전에 한 번 확인을 받은 뒤 진행하도록 안내합니다. 실제 결제 수단이나 실제 계정, 운영 중인 사이트, 어느 환경인지 밝히지 않은 요청은 지금처럼 사용자에게 넘깁니다. 이 규칙은 AI에게 주는 지시이며 실제 차단 장치는 아닙니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 테스트를 맡길 때 "localhost:3000에서 테스트 카드로 결제 흐름 확인해줘"처럼 환경과 테스트 데이터를 함께 알려 주세요.

### 내 AI 계정 로그인을 링크 버튼과 인증 코드 입력으로 간편하게

조직 AI 계정 없이 내 계정으로 Claude에 로그인할 때, 터미널에서 직접 명령을 입력하거나 링크를 찾아 누르지 않아도 됩니다. 로그인이 자동으로 시작되고, 나온 로그인 링크는 버튼으로, 인증 코드는 입력칸으로 바로 쓸 수 있습니다. 내 PC에서 로그인 상태를 확인하지 못한 경우에도 "다시 확인" 옆에 로그인 버튼이 나타납니다.

#### 사용 방법

AI Models에서 로그인을 누르면 "로그인 링크 열기" 버튼이 나타납니다. 브라우저에서 로그인한 뒤 표시되는 인증 코드를 입력칸에 붙여 넣고 "인증 코드 보내기"를 누르세요. 코드가 맞지 않으면 안내와 함께 "다시 시도" 버튼이 나타납니다. 터미널은 "터미널 보기"에서 확인할 수 있습니다.

### 내 AI 계정을 연결하면 계정 전환 목록에 등록

AI Models의 `연결하기`로 ChatGPT 또는 Claude 계정에 로그인하면, 이 컴퓨터가 그 제공처에 로그인된 것이 확인된 뒤 그 계정을 이 컴퓨터의 계정 전환 목록에 따로 표시 없이 등록합니다. 계정 전환 도구가 이 컴퓨터에 설치돼 있을 때만 등록하며, 같은 계정을 다시 연결해도 중복 등록되지 않습니다.

#### 사용 방법

내 설정 → AI Models → 연결하기에서 ChatGPT 또는 Claude를 고르고 브라우저에서 로그인하세요. 등록된 계정은 AI 사용량 창에서 바꿔 쓸 수 있습니다.

### 답 끝에 다음 단계 카드와 작업 목록 표시

AI가 파일을 바꾸거나 여러 단계 작업을 마치면 답 끝에 `다음 단계` 카드가 나타납니다. 무엇이 됐고 무엇이 남았는지 짧게 요약하고, 결정할 것이 있으면 질문 하나와 버튼을 보여 줍니다. 버튼은 지금 할 수 있는 것만 보이며 커밋 요청·PR 머지·AI로 CI 수정·리뷰 지적 반영·충돌 해결 요청·셀프 리뷰·완료로 보관은 기존 버튼과 같은 동작을 합니다. PR 머지·AI로 CI 수정처럼 시간이 걸리는 버튼은 진행 상황과 결과를 카드 아래 줄에 보여 주고 끝날 때까지 잠깁니다. 답장 버튼은 그 문장을 내 메시지로 보내며, 문장이 버튼 이름과 다르면 먼저 보여 주고 `이대로 보내기`로 확인합니다. 데스크톱 앱에서 보낸 메시지의 답에만 카드가 붙고, 모바일 앱이나 메신저에서 보낸 메시지의 답에는 요약과 질문이 본문에 그대로 남습니다. Codex 대화에서는 Codex가 관리하는 작업 목록과 진행 상황(n/m 완료)도 답 아래에 보입니다.

#### 사용 방법

대화에서 AI의 답이 끝나면 마지막 답 아래 카드를 확인하고 필요한 버튼을 누릅니다. 다음 메시지를 보내면 카드는 한 줄로 접힙니다. 작업PC의 Saycode CLI가 이 기능을 지원하는 버전으로 업데이트된 뒤부터 보입니다.

### 답변 속 `PR #번호`를 눌러 브라우저에서 PR 열기

GitHub 저장소와 연결된 프로젝트 대화에서 AI 답변에 `PR #2148`처럼 PR 번호가 쓰여 있으면, 그 글자가 프로젝트 저장소의 해당 PR 링크로 바뀝니다. 누르면 시스템 브라우저에서 PR이 열립니다. 글자는 쓰인 그대로 두고 상태 칩으로 바꾸지 않습니다. 직접 입력한 메시지, 이미 링크가 걸린 글자, 코드 표기 안의 글자, `#5`처럼 번호만 쓴 글자, `다른저장소/이름 PR #5`처럼 다른 저장소를 앞에 쓴 글자는 그대로 둡니다. 개인 Chat이나 GitHub 저장소가 없는 프로젝트에서는 링크로 바꾸지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 답변의 `PR #번호`를 누르면 브라우저에서 열립니다.

### 도구 정책 확인 카드와 "정책으로 막힘" 표시

작업PC의 Saycode 런타임이 AI의 컴퓨터 화면 조작이나 보내기·삭제 같은 MCP 도구 실행을 확인하라고 요청하면, 대화의 승인 카드가 "도구 정책 확인"으로 바뀌어 대상 앱·동작·이유를 한 줄로 보여 줍니다. "이번만 허용"은 그 한 번만 실행하고, "이 대화에서 <앱> 허용"은 같은 대화에서 그 앱을 다시 묻지 않게 합니다(런타임이 제안할 때만 보입니다). 대화 기록의 도구 카드에는 확인을 기다리는 동안 "승인 대기", 정책에 막히거나 거절되면 "정책으로 막힘"이 붙습니다. AI 심사 모드를 켜 두었어도 사람만 허용할 수 있는 요청(터미널 같은 앱의 첫 사용, 보내기·삭제·결제 도구 등)은 AI가 허용하지 않고 직접 확인하도록 넘깁니다. 여러 대화의 같은 요청을 한 번에 허용하는 묶음 카드에는 도구 정책 확인 요청이 들어가지 않고, 대화마다 따로 확인합니다. 이 기능을 모르는 이전 런타임에서는 지금과 같은 승인 카드가 그대로 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 확인 카드가 뜨면 "이번만 허용", "이 대화에서 <앱> 허용", "거절" 중 하나를 누릅니다. Enter는 "이번만 허용", Esc는 "거절"입니다. 작업PC의 Saycode 런타임이 도구 정책을 지원하는 버전이어야 카드가 나타납니다.

### 도움말에서 진단 정보를 한 번에 저장해요

메뉴 막대 Help에 `문제 해결` 메뉴가 생겼어요. 앱 안정성 기록, 이 PC 데몬의 최근 로그, 앱·OS·데몬 버전을 zip 하나로 저장해 지원 담당자에게 바로 건넬 수 있어요. 데몬이 켜지다 멈춰 상태 파일이 없어도 최근 로그는 담고, 비정상 종료로 남은 '실행 중' 기록은 그렇다고 표시해요. 토큰·키·이메일·주소의 쿼리·경로 속 사용자 이름은 가린 뒤 담고, 파일은 이 컴퓨터에만 저장돼요. 로그 폴더를 열거나 버전 정보를 복사하는 항목도 함께 있고, Help 메뉴 항목은 지금 고른 언어로 보여요. 메뉴 막대가 없는 Windows에서는 내 설정 → 정보의 `문제 해결`에서 진단 정보 저장과 버전 정보 복사를 쓸 수 있어요.

#### 사용 방법

메뉴 막대에서 Help → 문제 해결 → `진단 정보 저장…`을 고르거나 내 설정 → 정보 → 문제 해결의 `진단 정보 저장…`을 누르고 저장할 위치를 정하면 Finder(Windows는 탐색기)에서 zip을 보여 줘요. `로그 폴더 열기`(메뉴 막대에만 있음)는 안정성 기록이 있는 폴더를, `버전 정보 복사`는 앱·Electron·OS·데몬 버전을 클립보드에 넣어요. 설치 ID는 Windows 설치 패키지에서만 값이 있어 그때만 함께 들어가요.

### 독립 리뷰·검증 대화는 파일 편집 도구 없이 시작

독립 리뷰와 fan-out의 평가·검증 단계처럼 읽고 확인만 해야 하는 Claude 대화는 이제 파일 편집 도구(편집·쓰기) 없이 시작하고, commit·push·reset·PR 병합 같은 주요 git·gh 변경 명령과 파일 삭제, 새 대화 시작도 막힙니다. 테스트·빌드·조회 명령은 그대로 쓸 수 있습니다. 이 제한은 대화를 만들 때 정해지고 이후 이 앱이 보내는 어떤 메시지로도 풀리지 않습니다. 작업보드 카드에 `읽기 전용` 배지가 붙고, 배지에 마우스를 올리면 무엇이 막혔는지 보입니다. Codex 리뷰어에는 아직 적용되지 않으며 배지도 붙지 않습니다. 셸 명령(`sh -c`, 리다이렉트 등)을 거친 변경까지 막는 보안 장치는 아닙니다. 제한은 이 컴퓨터에서 만든 대화에 기록되므로, 다른 컴퓨터나 모바일에서 보낸 메시지에는 적용되지 않을 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 독립 리뷰를 실행하거나 fan-out 품질 파이프라인을 돌린 뒤 작업보드에서 리뷰어·평가·검증 대화 카드의 `읽기 전용` 배지를 확인하세요.

### 링크 하나로 대화·새 대화·답할 대화 목록 열기

saycode-desktop:// 링크로 앱의 특정 대화를 열거나, 폴더와 질문이 채워진 새 대화 화면을 열거나, 내 답을 기다리는 대화 목록을 열 수 있습니다. 셸 스크립트나 런처, 메신저 메시지에 링크를 넣어 두면 앱이 꺼져 있어도 켜진 뒤 그 화면으로 이동합니다. 링크로 받은 질문은 입력창에 채워지기만 하고 자동으로 보내지지 않으므로, 내용을 확인한 뒤 직접 보내세요.

#### 사용 방법

대화는 saycode-desktop://session/<대화 ID>, 새 대화는 saycode-desktop://new?folder=<폴더 절대 경로>&q=<질문>, 답할 대화 목록은 saycode-desktop://needs-input 링크로 엽니다. 경로와 질문은 URL 인코딩합니다. 이 컴퓨터에 등록된 프로젝트의 폴더면 그 프로젝트의 새 대화가 열리고, 아직 프로젝트가 아니면 프로젝트 추가 창이 열리며 추가를 마치면 새 대화에 질문이 채워집니다. 링크는 설치된 앱에서만 동작하고, 형식이 맞지 않거나 내 계정에서 찾을 수 없는 대화는 아무 화면도 바꾸지 않습니다.

### 변경 탭에서 턴별 변경 보기

Review의 변경 탭에 `턴별` 범위를 추가했습니다. `이 턴`은 AI가 마지막 턴에서 바꾼 것(진행 중이면 지금까지), `직전 턴 이후`는 마지막으로 끝난 턴 뒤에 바뀐 것(직접 고친 것 포함), `대화 시작 대비`는 대화를 시작한 뒤 바뀐 것 전체를 보여 줍니다. 턴이 시작하고 끝날 때 작업 폴더 상태를 저장소 안에 기록해 두고 비교하며, 다른 대화를 보고 있어도 기록됩니다. 내가 만든 대화만 기록하고, 같은 대화를 여러 Desktop에서 열어 두어도 한 턴은 한 번만 남습니다. 변경기록·브랜치·스테이징 상태는 바꾸지 않고, 무시 규칙에 걸린 파일과 서브모듈 안의 변경은 담지 않습니다. 대화마다 최근 200턴을 남기고, 대화를 지우거나 스냅샷을 남기고 작업트리를 지우면 그 기록도 지웁니다(작업PC가 꺼져 있을 때 지운 대화, 스냅샷 없이 지운 작업트리의 기록은 남습니다). 내용이 1MB를 넘으면 파일 목록만 보여 줍니다. 작업트리 스냅샷이 인덱스를 쓴 그 초에 같은 크기로 고친 파일을 놓칠 수 있던 문제, 작은 새 파일이 아주 많으면 내용이 작아도 크기 상한에 걸려 스냅샷을 만들지 못하던 문제도 함께 고쳤습니다. Windows 작업PC와 데모에서는 아직 기록하지 않습니다.

#### 사용 방법

프로젝트 대화에서 작업 패널 추가 → Review를 고르고 변경 탭 위의 `턴별`을 누른 뒤, 두 번째 줄에서 `이 턴`·`직전 턴 이후`·`대화 시작 대비` 중 하나를 고릅니다. 이 기능이 들어간 뒤 시작한 턴부터 볼 수 있습니다.

### 브라우저에서 개인 AI 계정 연결하기

ChatGPT 또는 Claude 계정을 명령어 입력 없이 브라우저에서 연결할 수 있는 안내 창을 추가했습니다. 온보딩 종료 후와 새 대화를 열 때 공용·개인 AI 계정이 모두 없으면 안내하며, 나중에 연결하도록 닫아도 작성 중인 질문은 유지됩니다.

이 컴퓨터의 계정 연결 상태가 미리 확인되어 있으면 새 대화 화면을 열자마자 안내가 표시됩니다.

내 설정 → AI Models의 공급사 카드에서 Claude·ChatGPT 연결 상태를 보고 연결하기로 개인 계정을 연결합니다. 아래 `연결된 AI 확인하기`에서 공급사 아이콘과 함께 AI·PC를 한 번에 확인할 수 있습니다.

#### 사용 방법

안내 창에서 `내 AI 계정 연결`을 누르고 ChatGPT 또는 Claude를 선택한 뒤 브라우저에서 로그인하세요. `내 설정 > AI Models > 연결하기`에서도 열 수 있습니다. 개인 계정은 이 컴퓨터에 연결됩니다.

이후 여는 새 Chat 탭에는 저장된 기본값을 바로 적용하고, 기존 초안의 입력과 AI 선택은 유지합니다.

#### 사용 방법

내 설정 > 일반 > AI Models > 새 대화 기본값에서 선택하세요.

### 새 작업트리에 지금 변경사항을 가져가기

새 대화를 작업트리에서 시작할 때 `지금 변경사항 가져가기`를 켜면, 프로젝트 폴더의 커밋하지 않은 변경(스테이징 여부와 관계없이)과 새 파일을 새 작업트리에 복사한 뒤 대화를 시작합니다. 원래 폴더의 변경은 그대로 남습니다. 기준 브랜치와 충돌한 파일은 충돌 표시와 함께 옮기고, 옮기지 못한 파일(바이너리 충돌, 이미 있는 파일, 서브모듈 등)은 화면 위 안내에 이름을 보여 줍니다. 동시작업으로 여러 후보를 만들 때도 각 작업트리에 같은 변경을 옮깁니다. Windows 작업PC에서는 아직 쓸 수 없습니다.

#### 사용 방법

새 프로젝트 대화에서 입력창 위 `작업트리`를 켜고, 옆의 조절 아이콘(작업트리 · 방식)을 눌러 방식이 `새로 만들기`인지 확인한 뒤 `지금 변경사항 가져가기`를 켜고 메시지를 보냅니다. 이 선택은 그 대화 한 번에만 적용되고 다음 새 대화에서는 꺼진 상태로 돌아갑니다.

### 시작준비에서 조직 Claude 메시지 테스트

시작준비의 AI 도구 단계에서 조직이 배정한 Claude Code 행에 `메시지 테스트` 버튼이 생겼습니다. 누르면 일반 Chat과 같은 입력창이 모달로 열리고, 조직 정책이 허용하는 가장 낮은 Claude 모델이 기본으로 선택되어 있습니다. 메시지를 보내면 실제 Chat으로 한 번 실행해 응답과 사용한 모델·걸린 시간을 보여 주고, 응답이 오면 그 Chat을 자동으로 보관한 뒤 `테스트 성공. 자동으로 보관처리됩니다.`라고 알려 줍니다. 실패하면 이유를 한 문장으로 알려 주고 `로그 보기`에서 단계별 기록을 확인하거나 복사할 수 있습니다. 조직 AI 연결이 끝나기 전에는 입력할 수 없습니다. 인증세트 연결 상태(예: `buzzni_dev 인증세트 연결됨`)는 AI 이름 오른쪽에 표시됩니다.

#### 사용 방법

시작준비 → AI 도구 → Claude Code 오른쪽의 `메시지 테스트`를 눌러 메시지를 보냅니다.

### 쓰지 않는 AI를 채팅 선택 목록에서 숨길 수 있어요

연결된 AI 도구(Claude Code·Codex·Opencode·Grok) 가운데 쓰지 않는 것은 새 대화, 홈 Chat, 대화 중 AI 전환, 병렬 실행, 자동화의 AI 선택 목록에서 숨길 수 있습니다. 자동 선택도 숨긴 AI를 고르지 않습니다. 숨겨도 그 AI의 로그인·계정 연결은 그대로이고, 이미 진행 중인 대화는 그대로 이어집니다. 최소 한 개의 AI는 항상 표시되고, 표시 중인 AI 중 쓸 수 있는 것이 없으면 숨긴 AI를 다시 표시하는 방법을 안내합니다.

#### 사용 방법

내 설정 > AI Models 또는 시작 준비 목록의 AI 도구 단계에서 `채팅에 표시할 AI`의 스위치를 끄면 숨겨지고, 다시 켜면 선택 목록에 돌아옵니다. 선택은 바로 저장되며 앱을 다시 켜도 유지됩니다.

### 알림에서 바로 권한 허용·이번 세션 허용·답장

macOS 데스크톱 알림에서 AI의 권한 요청에 `허용`, `이번 세션 허용`, `거절`로 바로 답할 수 있습니다. `이번 세션 허용`은 그 대화가 끝날 때까지 같은 요청(같은 명령이나 도구)을 다시 묻지 않습니다. 작업 완료 알림에는 답장 칸이 생겨, 답장을 보내면 그 대화에 이어서 메시지가 전송됩니다. 대화가 아직 답하는 중이면 입력창 대기열에 들어갑니다. 같은 알림이 여러 번 뜨지 않고, 권한·질문 알림은 Windows에서 저절로 사라지지 않습니다.

#### 사용 방법

macOS 알림에 마우스를 올리거나 알림을 펼쳐 버튼을 누르거나 답장을 입력합니다. 요청이 이미 처리됐거나 보내지 못하면 앱이 열리고 해당 대화로 이동합니다. 계획 승인과 여러 개의 질문은 알림을 눌러 대화에서 답합니다.

### 앱 밖에서 만든 작업트리의 변경을 충돌 미리보기와 함께 가져오기

터미널 등 앱 밖에서 만든 작업트리의 변경을 프로젝트 폴더로 가져올 수 있습니다. 적용하기 전에 그대로 들어갈 파일, 충돌할 파일, 건너뛸 파일(프로젝트 폴더에서 아직 커밋하지 않았거나 스테이징해 둔 변경이 있는 파일 등)을 먼저 보여 주고, 적용한 뒤에는 적용·충돌·건너뜀 개수와 충돌한 파일 이름을 알려 줍니다. 가져온 변경은 스테이징하지 않은 변경으로 남고, 충돌한 파일은 충돌 표시와 함께 들어갑니다. 점검한 뒤 작업트리나 프로젝트 폴더의 해당 파일이 바뀌면 아무것도 적용하지 않고 다시 점검하라고 안내합니다.

#### 사용 방법

프로젝트 도구 → 브랜치 → 작업트리 관리 창의 `앱 밖에서 만든 작업트리` 줄에서 `변경 가져오기`를 누르세요. 줄 아래에 점검 결과가 나오면 `적용`을 눌러 프로젝트 폴더에 넣습니다. Windows 작업PC에서는 아직 쓸 수 없습니다.

### 앱 밖에서 시작한 대화를 다시 열어도 중복 없이, 터미널에서 이어진 내용은 기존 대화에 반영

`앱 밖에서 시작한 대화 이어가기`로 가져온 대화를 기억해 두어, 목록을 다시 열어도 같은 대화를 또 이어가지 않게 했습니다. 가져온 뒤 터미널에서 그 대화를 더 진행했다면 목록에 `앱 밖 새 메시지 N개`로 표시되고, `기존 대화에 반영`을 누르면 앱의 그 대화가 새 메시지까지 읽고 이어집니다. 앱에서 이어 쓴 내용은 변경으로 보지 않고, 기록만으로 앱에서 쓴 것인지 터미널에서 쓴 것인지 알 수 없는 새 줄은 `건너뜀`으로 따로 표시합니다. 터미널이 줄을 쓰는 도중에 확인했다면 그 줄이 끝난 뒤에 판정합니다. 원본이 줄었거나 앞부분이 바뀌는 등 이어 붙인 것으로 볼 수 없는 변경은 가져오지 않고 `건너뜀`과 이유를 보여 줍니다. 가져오기 중에는 버튼에 `원본 확인 중…`·`대화 시작 중…` 단계가 보이고, 실패하면 그 대화 줄에 어느 단계에서 왜 실패했는지 남습니다.

#### 사용 방법

프로젝트 대화 화면의 `프로젝트 도구` → `앱 밖에서 시작한 대화 이어가기`에서 대화를 이어가거나, `앱 밖 새 메시지` 표시가 있는 줄의 `기존 대화에 반영`을 누릅니다. 반영하지 않으려면 눈 가림 버튼(`이번 변경 무시`)으로 지금 상태를 새 기준으로 삼습니다. 응답 중인 대화에는 반영하지 않으니 끝난 뒤 다시 시도하세요. 반영하기 전에 터미널의 그 대화를 먼저 종료하세요.

### 여러 대화가 같은 권한을 기다리면 한 번에 허용·거절

병렬로 띄운 내 프로젝트 대화 여러 개가 같은 PC·같은 폴더에서 똑같은 명령이나 도구 실행 권한을 동시에 기다리면, 알림 센터와 작업보드에 카드 하나로 묶어 보여 줍니다. 전부 허용이나 전부 거절을 누르면 각 대화에 따로 답이 전달되고, 처리하지 못한 대화가 있으면 카드 위에 알려 줍니다. 카드의 요청 내용 보기를 펼치면 허용할 명령과 인자 전체를 확인할 수 있습니다. 폴더나 명령이 조금이라도 다르면 묶지 않고, AI 심사가 아직 보고 있는 요청, 내용을 알 수 없는 요청, sudo·.env 읽기처럼 위험한 요청, 다른 사람의 대화도 묶지 않습니다.

#### 사용 방법

사이드바 최근 알림의 전체보기로 알림 센터를 열거나 작업보드를 열면 맨 위에 "대화 N개가 같은 권한을 기다려요" 카드가 보입니다. 전부 허용 (N) 또는 전부 거절을 누르세요. 대화별로 따로 답하려면 개별 보기를 눌러 대화마다 허용·거절하거나 대화 이름을 눌러 엽니다.

### 온보딩 뒤에도 조직 AI 계정 연결

시작준비의 AI 도구 단계(Claude Code·Codex 표시 아래)에 조직 계정 연결하기를 추가했습니다. 온보딩을 마친 뒤에도 내 설정 → 시작준비에서 조직에서 배정한 AI 계정을 이 컴퓨터에 다시 가져올 수 있습니다. 홈에서 AI 연결 상태를 확인하지 못했을 때 다시 확인을 누르면 AI Models가 열립니다.

#### 사용 방법

내 프로필 → 내 설정 → 시작준비 → AI 도구 → 조직 계정 연결하기를 누릅니다. 이 컴퓨터가 조직에 등록되어 온라인이어야 합니다. 개인 AI 계정은 내 설정 → AI Models → 연결하기에서 연결합니다.

### 응답을 중단하면 자식 대화도 함께 중단

프로젝트 대화의 응답을 중단하면, 그 대화가 띄운 자식·손자 대화 중 아직 응답 중인 것도 함께 중단합니다. 부모를 멈췄는데 자식 대화가 계속 작업하던 일이 없어지고, 몇 개를 중단했는지(실패한 것이 있으면 그 수도) 대화에 한 줄로 남습니다. 이미 끝난 대화, 다른 대화가 띄운 대화, "다른 AI도구로 이어가기"로 넘겨준 대화는 건드리지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 끄려면 내 설정 → 개발 → 개발 자동화의 자식 대화에서 "응답을 중단하면 자식 대화도 중단"을 끕니다.

### 작업트리를 지우기 전에 이 작업트리에만 있는 로컬 파일을 알려 주기

작업트리를 지우면 함께 사라지는 파일 중 스냅샷에도 담기지 않는 무시 규칙 파일(.env·로컬 설정·키 파일 등)을 지우기 전에 셉니다. 서브모듈 안의 파일도 셉니다. node_modules·빌드 결과처럼 다시 만들 수 있는 폴더, 프로젝트 루트에 같은 내용이 있는 사본(작업트리를 만들 때 복사한 .env 등)과 링크, Saycode가 남긴 기록(작업트리 준비 로그 등)은 수만 보여 주고 따로 묻지 않습니다. 작업트리 창의 삭제 확인창은 이 작업트리에만 있는 로컬 파일 수와 상위 폴더별 요약을 보여 주고, 확인한 뒤 파일이 늘었으면 같은 창에서 다시 확인합니다. 대화를 보관하거나 지울 때의 작업트리 삭제, 함께 시작한 대화 정리, 대화 헤더의 작업트리 삭제는 그런 파일이 있으면 한 번 더 확인합니다. 오래된 작업트리 일괄 정리는 해당 작업트리에 로컬 파일 N개를 표시하고 합계와 함께 건너뛰기(기본)/전부 삭제를 고르게 합니다. 자동 정리는 그런 작업트리를 지우지 않고 남깁니다. Windows 작업PC에서는 아직 세지 않고 이전처럼 지웁니다.

#### 사용 방법

프로젝트 도구 → 브랜치 버튼 → 작업트리…에서 작업트리 줄의 휴지통 버튼을 누르면 확인창에 함께 지워질 로컬 파일이 보입니다. 일괄 정리에서는 검토 목록 위의 건너뛰기/전부 삭제로 정합니다.

### 절전·재시작으로 끊긴 작업을 자동으로 이어가기

노트북이 절전에 들어가거나 네트워크가 끊기거나 앱이 다시 시작돼 응답이 중간에 끊긴 프로젝트 대화를, 그 대화로 돌아와 보고 있을 때 한 번 자동으로 이어갑니다. 보내는 메시지는 기존 "이어서 하기"와 같고, 이어간 턴 끝에 "절전에서 깨어나 끊긴 작업을 자동으로 이어갔어요." 같은 작은 표시가 남습니다. 질문·권한 요청이 기다리고 있거나 대화가 이미 정상적으로 끝났으면 보내지 않으며, 같은 대화를 30분 안에 두 번 자동으로 이어갔으면 멈추고 수동 "이어서 하기"를 보여 줍니다.

#### 사용 방법

기본으로 꺼져 있습니다. 내 설정 > 개발 > 개발 자동화 > 끊긴 작업 자동 이어하기에서 켭니다. 켜 두면 컴퓨터가 깨어나거나 앱이 다시 시작된 뒤, 창을 앞에 두고 그 대화를 보고 있을 때 자동으로 이어갑니다.

### 지문 대조 대신 버튼 하나로 이 PC를 조직 공용 PC로 확인합니다

서버가 조직 공용 PC로 승인했지만 아직 이 PC에 공용 표시가 없으면, 조직 기기 승인 카드가 지문 대조 대신 "이 PC를 조직 공용 PC로 사용" 버튼 하나를 보여 줍니다. 누르면 PC가 공용 표시를 남기고 조직 키를 스스로 대조해 확인합니다. 자동 확인이 거절되면 기존 지문 대조로 돌아갑니다.

#### 사용 방법

설정의 조직 기기 승인 카드에서 버튼을 누릅니다. CLI 1.1.10-aplus.350 이상이 필요하며, 오래된 CLI에서는 기존 지문 대조 화면이 그대로 보입니다.

### 지운 작업트리를 스냅샷 보관함에서 되살리기

작업트리를 지울 때(작업트리 창의 삭제·오래된 작업트리 일괄 정리·자동 정리·대화를 보관하거나 지울 때 작업트리 삭제) 지우기 직전의 작업 내용을 저장소 안에 스냅샷으로 먼저 남깁니다. 커밋하지 않은 변경, 스테이징한 변경, 새 파일(바이너리 포함)이 들어가고, 무시 규칙에 걸린 파일(node_modules·빌드 결과·.env 등)은 넣지 않습니다. 브랜치는 만들지 않으며 원래 폴더의 Git 상태도 바꾸지 않습니다. 스냅샷을 만들지 못하면 작업트리를 지우지 않고 이유를 알리며, 작업트리 창에서만 `스냅샷 없이 삭제`를 직접 골라 지울 수 있습니다. 다른 Git 작업 중이거나 연결이 끊긴 것처럼 잠깐의 문제면 `다시 시도`를 먼저 권합니다. 다른 작업PC에 있는 작업트리는 이 PC에서 스냅샷을 만들 수 없어 같은 확인을 거칩니다. 서브모듈이나 폴더 안의 별도 Git 저장소 내용은 담지 못하므로 그 사실을 스냅샷 옆에 표시합니다. 스냅샷은 30일이 지나면 지우고, 50개를 넘으면 변경 없는 것(정리된 깨끗한 작업트리)과 오래된 것부터 지웁니다. Windows 작업PC에서는 아직 스냅샷을 만들지 않고 이전처럼 지웁니다.

#### 사용 방법

프로젝트 도구 → 브랜치 버튼 → 작업트리…를 열고 위쪽의 스냅샷 보관함을 누릅니다. 목록에서 되살릴 스냅샷의 복원을 누르면 원래 경로(이미 쓰이면 restored 폴더)에 작업트리가 다시 생기고, 지울 때의 변경이 커밋하지 않은 변경으로 보입니다. 원래 브랜치가 지워졌으면 같은 이름으로 다시 만들고, 남아 있고 지울 때와 같은 커밋이면 연결하며, 그 밖에는 브랜치 없이 둡니다. 필요 없는 스냅샷은 휴지통 버튼으로 지웁니다.

### 프로젝트 MCP 서버의 위험 설정 경고와 연결 테스트

프로젝트 설정의 MCP 서버 목록에서 서버마다 설정 위험을 알려 줘요. 암호화되지 않은 http 주소, 주소에 들어 있는 토큰, 작업PC 자신을 가리키게 되는 localhost 주소, 사내망에서만 닿는 사설 주소, 모든 구성원이 같은 신원으로 접속하는 조직 공용 토큰을 표시해요. 경고는 연결이나 저장을 막지 않아요. 연결 테스트를 누르면 이 컴퓨터에서 10초 안에 MCP 연결을 확인해 연결됨과 도구 수, 또는 실패 이유(응답 없음, 인증 필요, MCP 주소가 아님 등)를 보여 줘요. 도구는 실행하지 않고, 조직에 저장된 토큰은 서버에만 있어 이 확인에는 쓰지 않아요.

#### 사용 방법

조직 프로젝트에서 프로젝트 설정 → 개발 → MCP 서버로 가면 각 서버 주소 아래에 경고가 보여요. 같은 자리의 연결 테스트를 누르면 옆에 결과가 나와요.

### AI 도구 사용 규칙 설정

설정의 보안 탭에 "AI 도구 사용 규칙"이 생겼습니다. AI가 앱 종류마다 할 수 있는 일(브라우저는 화면 보기만, 터미널은 클릭까지 등)을 보고, 특정 앱을 묻기·차단·허용으로 정하고, 열린 대화가 받은 MCP 서버마다 처리를 정하고, 만들기·수정 같은 쓰기 도구도 실행 전에 묻게 할 수 있습니다. 대화에서 "이 대화에서 허용"을 고른 앱도 여기서 확인합니다(대화가 끝나거나 30분 뒤 다시 확인하며, 허용 거두기를 지원하는 Saycode 런타임에서는 그 전에 거둘 수 있습니다). 규칙은 이 컴퓨터의 Saycode 런타임 폴더에 저장되고 다음 도구 호출부터 적용됩니다. 런타임이 도구 정책을 지원하지 않는 버전이면 규칙은 저장되지만 적용되지 않는다고 표시합니다. 허용으로 정해도 앱 종류의 허용 범위를 넘는 동작은 매번 확인합니다.

#### 사용 방법

내 설정 → 일반 → 보안 → AI 도구 사용 규칙에서 설정합니다. 앱은 macOS 번들 ID(예: com.apple.Terminal)나 Windows 실행 파일 이름(예: cmd.exe)으로 추가합니다. 이 컴퓨터가 작업PC로 연결되어 있어야 저장할 수 있습니다.

### AI 사용량 창에서 새 대화용 조직 계정 선택

AI 사용량 창에서 배정된 Claude 조직 계정을 새 대화용으로 선택할 수 있습니다. 기존 대화는 유지되며 PC 기본 로그인과 새 대화 선택을 구분합니다. 지원 런타임에서는 현재 대화의 실제 조직 계정과 그 사용량·한도 경고를 표시합니다. 실행 계정이 확인되지 않으면 PC 로그인을 사용 중 계정으로 표시하지 않습니다.

#### 사용 방법

앱과 작업PC의 런타임을 업데이트하고 AI 잔여량 보이기를 켠 뒤 입력창 아래 AI 사용량 버튼을 누르고 조직 계정 행을 선택합니다. 같은 조직에서 본인에게 배정된 온라인 전용 PC와 현재 배정이 확인된 계정에서 사용할 수 있습니다.

### AI 심사로 권한 요청 처리

새 설정 "AI 심사로 권한 요청 처리"를 켜면 Claude·Codex 프로젝트 대화가 명령 실행·파일 쓰기·네트워크·MCP 도구를 쓰기 전에 권한을 요청하고, 저비용 AI 모델이 프로젝트 지침(AGENTS.md·CLAUDE.md)과 내 지침에 비춰 허용하거나 거절합니다. 판정과 이유는 대화에 한 줄로 남고, 심사에 실패했거나 루트 삭제·sudo·강제 push·자격증명 파일 같은 고위험 규칙에 걸린 요청은 자동으로 허용하지 않고 지금처럼 승인 카드로 직접 확인합니다. 거절된 요청은 그 대화에서 `/approve`를 보내 확인 후 한 번 다시 허용할 수 있습니다. 꺼져 있을 때 권한 요청에 자주 답하면 AI 심사로 바꿀지 한 번 물어봅니다. 심사는 내가 만들고 이 기기에서 메시지를 보낸 대화에만 적용되며(공유 프로젝트의 동료 대화는 심사하지 않음), 판정 기록은 이 기기의 로컬 로그에만 남습니다(서버·다른 기기에 남는 영구 감사 기록은 없음). 조직 정책과 별개인 개인 설정이라 관리자가 켜거나 막을 수 없습니다. 끈 뒤 메시지를 보내면 원래대로 돌아가는데, 처음 만들 때의 권한을 알 수 없는 Codex 대화는 되돌리지 않고 대화에 안내만 남깁니다. 메신저로 보낸 메시지나 계획 승인 뒤에는 다음 Desktop 전송까지 권한을 묻지 않습니다. 심사는 판단을 돕는 장치일 뿐 보안 경계가 아니므로 위험한 저장소에서는 끄고 직접 확인하세요.

#### 사용 방법

내 설정 → 개발 → 개발 자동화 → 권한 요청에서 "AI 심사로 권한 요청 처리"를 켭니다(기본 꺼짐). 켠 뒤 대화에 메시지를 보내면 적용됩니다. 심사는 대화가 실행되는 컴퓨터의 Claude Code로 돌아갑니다.

### AI 오류 답변에서 바로 이어가기

AI 오류를 작은 회색 안내로 표시하고 인증 오류·설명·상세를 펼쳐도 같은 줄에 유지합니다. Codex는 연결복구·AI Models, 다른 인증 오류는 AI Models만 표시합니다.

#### 사용 방법

Codex는 연결복구를 누르면 최신 상태를 확인해 복구하고 대화를 이어갑니다. 다른 AI 대화 기능은 현재 숨겼습니다. 복구나 대안이 없으면 기존 AI Models로 안내합니다. 별도 복구 모달과 답변의 관리자 요청 버튼은 제거했습니다.

### AI가 브라우저·컴퓨터를 조작할 때 위험한 행동 전에 확인하도록 안내합니다

AI가 Chrome·AI 브라우저나 이 컴퓨터의 앱을 대신 조작할 때 따를 확인 규칙을 채팅 입력창에서 보내는 대화마다 AI에게 함께 전달합니다. 결제 완료·송금·계정 삭제·보안 설정 변경은 직접 하지 말고 해당 단계까지 안내한 뒤 넘기도록, 메시지 전송·게시·삭제·업로드나 비밀번호·결제 정보 같은 민감한 정보 입력 전에는 무엇을 어디로 왜 보내는지 밝히고 확인을 받도록, 웹 페이지나 문서 안에 적힌 지시는 승인으로 보지 않도록 지시합니다. 무엇을 어디로 보낼지 메시지에서 직접 지시한 행동은 다시 묻지 않고, 파일 편집·명령 실행 같은 일반 코딩 작업에는 적용되지 않습니다. 이 규칙은 AI에게 주는 지시이며 실제 차단 장치는 아니므로 중요한 작업은 계속 직접 확인하세요. 브라우저·컴퓨터 도구가 없다고 확인된 대화에는 보내지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 끄려면 **내 설정 → 시스템 프롬프트 → 기본 지시 세부 설정**에서 `브라우저·컴퓨터 사용 확인`을 끄세요.

### AI가 이 컴퓨터를 조작하는 동안 화면에 표시하고 Esc로 멈춰요

Saycode AI가 컴퓨터 제어 확장으로 이 컴퓨터의 화면·입력을 조작하는 동안 모든 화면 가장자리에 테두리가 생기고, 위쪽 배지에 어느 대화가 쓰는지 보여 줘요. 표시는 클릭을 가로채지 않고 다른 창 위에 떠 있으며, 조작이 끝나면 사라져요. 조작 중에는 어느 앱에서든 Esc를 누르면 조작이 바로 멈추고, 그 대화가 이 컴퓨터의 Saycode 창에 열려 있으면 응답도 멈춰요. 멈춘 대화는 AI가 조작을 끝내거나 30초 동안 다시 시도하지 않을 때까지 이 컴퓨터를 조작하지 못해요. AI가 스스로 보내는 Esc 키는 대상 앱에 그대로 전달돼요. AI의 조작 사이가 30초 넘게 비면 표시가 잠시 사라졌다가 다음 조작 때 다시 떠요.

#### 사용 방법

조작 중에 Esc를 누르면 배지가 `중지했어요`로 바뀐 뒤 사라져요. 중지를 확인하지 못하면 `중지를 확인하지 못했어요 · 대화에서 확인해 주세요`가 잠시 보여요. 테두리와 배지는 설정 > 알림의 `컴퓨터 사용 표시` 카드에서 끌 수 있고, 꺼도 Esc 중지는 계속 동작해요.

### PR이 끝났거나 오래 쉰 대화를 자동으로 보관

프로젝트 대화를 규칙에 따라 자동으로 보관할 수 있습니다. PR이 머지되거나 닫힌 대화, 정한 기간 동안 활동이 없는 대화가 대상입니다. 두 규칙 모두 기본은 꺼져 있습니다. 내가 시작한 것이 확인된 대화만 보관하고, 응답 중이거나, 입력을 기다리거나, 세션이 아직 연결돼 있거나, 방금 활동했거나, 화면에 열려 있거나, 고정했거나, 하위 대화가 진행 중인 대화는 보관을 미루고 그 이유를 사이드바에 보여 줍니다(대화 정보 막대가 보이는 화면에서는 그곳에도). 이 PC에서 보관을 해제한 대화는 다시 자동 보관하지 않습니다(다른 기기나 웹에서 해제한 대화는 아직 기억하지 못합니다). 창을 여러 개 열어도 보관은 한 창에서만 합니다. 작업트리는 지우지 않습니다.

#### 사용 방법

내 설정 → 일반 → 보관된 대화의 자동 보관에서 원하는 규칙을 켜세요. 기간은 1일부터 90일 중에서 고를 수 있고 기본은 14일입니다. 보관을 미룬 대화는 사이드바 대화 줄(또는 대화 정보 막대)의 보관 아이콘에 마우스를 올리면 이유가 보입니다. 다시 자동 보관 대상으로 돌리려면 자동 보관하지 않을 대화 목록에서 목록에서 빼기를 누르세요.

## 변경된 기능

### 내 AI 계정은 Saycode에 등록해야 사용

이제 이 컴퓨터에 Claude나 ChatGPT(Codex)가 로그인돼 있어도, Saycode 앱에서 내 AI 계정으로 등록한 공급사만 Saycode가 사용합니다. 조직이 배정한 AI는 지금처럼 자동으로 사용합니다. 등록 기록은 이 컴퓨터와 Saycode 계정 단위로 남아서 Saycode나 AI에 다시 로그인해도 다시 등록할 필요가 없습니다. 이전 버전에서는 등록 기록이 없으므로, 업데이트 뒤 개인 AI로 대화를 시작하려면 한 번 새로 등록해야 합니다. 버즈니 조직의 기존 개인 로그인은 본인 PC에서 계정 전환 목록에 자동으로 가져와 계속 사용할 수 있습니다. 이미 연결 해제한 공급사는 다시 등록하지 않습니다. 등록하지 않은 상태에서 대화를 시작하면 AI 고르는 창이 열립니다. 업데이트 뒤 목록에서 빠진 Claude·ChatGPT가 있으면 Chat·Project 홈 입력창 아래에 다시 연결하라는 안내와 `연결하기`가 보이고, 다른 AI로는 그대로 대화할 수 있습니다. 안내를 닫으면 다시 보이지 않으며 AI Models에서 언제든 등록할 수 있습니다. AI Models의 공급사 카드는 로그인만 되고 등록하지 않은 계정을 `로그인돼 있지만 Saycode에 등록하지 않았어요`로 보여 주고, `…` 메뉴의 `Saycode에 등록`으로 연결할 수 있습니다. 등록한 Claude·ChatGPT 계정은 `…` 메뉴의 `연결 해제`로 Saycode에서만 쓰지 않게 할 수 있으며, 이 컴퓨터의 로그인과 계정 전환 목록은 그대로 둡니다. 메신저 채널로 시작하는 대화에도 같은 기준이 적용됩니다. 모바일·웹에서 이 컴퓨터로 시작하는 대화에는 아직 적용되지 않습니다.

#### 사용 방법

내 설정 → AI Models → 공급사 카드의 `연결하기`(또는 행의 `…` → `Saycode에 등록`)에서 ChatGPT 또는 Claude를 고르고 로그인하세요. 그만 쓰려면 행의 `…` → `연결 해제`를 누르세요.

### 다른 대화로 전환하면 그 대화의 새 메시지가 바로 보입니다

다른 대화로 전환한 직후, 그 대화에 막 도착한 메시지가 최대 0.5초 늦게 나타날 수 있던 문제를 고쳤습니다.
이제 대화를 전환하거나 개인 채팅 패널로 열면 그 대화의 새 메시지가 바로 보입니다.

보고 있지 않은 대화들의 새 메시지는 0.5초마다 한 번에 모아 반영합니다. 전에는 대화마다 제각각의 시점에
화면 전체를 다시 그렸습니다. 대화 10개가 동시에 응답하고 보고 있는 대화는 조용한 경우, 화면을 다시 그리는
횟수가 초당 약 9회에서 2회 미만으로 줄었습니다(시뮬레이션 기준). 큰 작업 공간이나 느린 PC에서 입력·스크롤이
덜 끊길 것으로 기대합니다. 이 Mac의 실앱 측정에서는 입력 지연 차이가 드러나지 않았습니다.

메시지는 하나도 빠지지 않습니다. 답 완료·실패는 기다리지 않고 바로 반영합니다. 권한 요청·질문 대기 표시와
알림은 전과 같이 바로 나타납니다. 앱 창이 가려져 있는 동안에는 보고 있던 대화도 같은 방식으로 모아 두었다가,
창이 다시 보이는 순간 한꺼번에 반영합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 다른 컴퓨터에서 시작한 자동화 대화도 똑같이 숨겨집니다

예약 작업·GitHub 트리거·자동 리뷰·작업보드 오토파일럿 리뷰가 만든 대화에 "누가 시작했는지"가 대화와 함께 기록됩니다. 그래서 대화 목록·빠른 열기·작업보드의 자동화 대화 숨기기가 이 컴퓨터에서 시작한 것뿐 아니라 다른 컴퓨터에서 시작했거나 앱을 다시 설치하기 전에 시작한 자동화 대화에도 똑같이 적용됩니다. 직접 시작한 대화, 병렬 작업자, 메신저로 나눈 대화는 계속 보입니다. 기록이 없는 예전 대화는 지금처럼 이 컴퓨터의 기록과 작업 위치로 판별합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 작업PC의 실행 환경이 대화 출처를 기록하는 버전으로 업데이트된 뒤에 만든 대화부터 적용됩니다.

### 대화의 변경 문서 목록을 한 줄로 더 촘촘하게 표시

대화에서 AI가 고친 Markdown 문서 목록이 문서마다 두 줄을 차지하던 카드 대신 한 줄로 표시됩니다. 파일 이름 바로 뒤에 `문서 · MD`가 붙고, 오른쪽의 `파일 열기` 버튼은 다른 결과 파일 버튼과 같은 작은 둥근 버튼입니다. 같은 수의 문서를 절반 정도의 높이로 훑어볼 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 문서 행을 누르거나 `파일 열기`를 누르면 이전처럼 파일이 열립니다.

### 대화의 AI Models 진입을 통일

Chat과 Project의 현재·과거 오류에서 AI Models를 누르면 같은 작은 모달을 엽니다. 다시 연결 버튼은 일반 버튼으로 표시합니다. 과거 오류의 설정을 열어도 이전 요청을 자동으로 다시 보내지 않습니다. 내 설정의 전체 AI Models은 그대로 사용할 수 있습니다.

#### 사용 방법

대화에 표시된 AI Models를 눌러 연결 상태와 필요한 조치를 확인하세요. 전체 설정은 내 설정 또는 모달의 추가 설정에서 확인하세요.

### 데스크톱 알림 표시 설정과 보고 있는 대화 알림 생략

설정 > 알림에 `데스크톱 알림` 카드가 생겨 작업 완료·입력 요청 알림을 `항상`, `앱을 보고 있지 않을 때만`, `끄기` 중에서 고를 수 있습니다. 기본값은 `항상`입니다. 어느 설정에서든 지금 화면에 보이는 대화(분할 화면의 다른 영역 포함)는 데스크톱 알림을 띄우지 않으며, 대화를 열면 그 대화의 알림이 자동으로 닫힙니다. 알림 소리·알림 목록·모바일 푸시는 그대로입니다.

#### 사용 방법

내 설정 > 일반 > 알림 > 데스크톱 알림의 `알림 표시`에서 원하는 값을 고르면 바로 저장됩니다. 이 컴퓨터에만 적용됩니다.

### 모델 목록을 확인하지 못하면 "저장된 목록"으로 알려 줘요

서버에서 모델 목록이나 조직 AI 모델 정책을 확인하지 못해 마지막으로 받은 목록을 보여 주는 동안, 모델 선택 메뉴의 MODEL 제목 옆에 `저장된 목록`이 표시됩니다. 표시에 마우스를 올리면 그 목록을 언제 받았는지 볼 수 있고, 연결이 돌아와 목록을 다시 확인하면 표시는 사라집니다. 인터넷 연결이 돌아오면 바로 다시 확인합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 대화 입력창에서 모델 선택 메뉴를 열면 상태를 확인할 수 있습니다.

### 사이드바 대화 호버에 연결된 PR 번호 표시

프로젝트 사이드바에서 대화에 마우스를 올리면 나오는 안내에, 폴더와 브랜치 아래에 그 대화의 작업트리에 연결된 PR 번호(예: PR #2148)가 한 줄 더 표시됩니다. PR이 아직 없으면 줄이 나타나지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 프로젝트 사이드바의 대화 위에 마우스를 올리면 보입니다.

### 새 대화의 '작업트리'를 '워크트리'로 표기

새 대화 입력창의 워크트리 체크박스와 방식 창, 관련 안내 문구에서 '작업트리'를 '워크트리'로 바꿔 표기합니다. 동작은 그대로입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 새 소식 패널을 부드럽게 열고 닫기

새 소식 패널에 알림센터와 같은 열기·닫기 애니메이션을 적용하고 하단의 중복 닫기 버튼을 제거했습니다. 동작 줄이기 설정에서는 즉시 열고 닫습니다.

#### 사용 방법

업데이트 안내의 Release notes를 누르거나 Help > Release Notes를 선택하세요. 상단 X, Escape 또는 패널 바깥 클릭으로 닫을 수 있습니다.

### 설정에서 AI 연결을 바로 시작

AI Models의 연결하기는 제공자 선택을 바로 엽니다. 연결 확인에서 유효한 이 컴퓨터를 기본 선택하며 다른 작업PC로 바꿀 수 있습니다.

#### 사용 방법

내 설정 → 일반 → AI Models → 연결하기에서 ChatGPT 또는 Claude를 선택하세요.

### 시작준비 완료 표시를 파란색으로

시작준비 창에서 완료된 단계, 연결됨, 설치 완료 표시를 초록색 대신 앱의 파란색으로 보여 줍니다. 상단의 `필수 설정 완료` 안내 배경도 더 밝은 회색으로 바꿔 다른 화면의 회색과 맞췄습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 시작준비 AI 단계는 연결된 AI만 한 번 확인해 보여줌

시작준비의 AI 도구 단계가 열릴 때 한 번 연결 정보를 확인하며, 그동안 제목 아래에 `연결 정보를 확인 중입니다.`를 보여 줍니다. 결과에는 이 컴퓨터에 연결된 공급사만 한 줄씩 보이고(조직이 배정한 AI는 인증세트, 개인 로그인은 계정), 연결되지 않은 공급사와 로그인 안내, `상태 다시 확인` 버튼, 연결될 때까지 반복하던 자동 확인은 없어졌습니다. 공급사 사이의 구분선은 둘 이상일 때만 보입니다. 확인하지 못하면 조직 계정에는 관리자에게 확인한 뒤 `조직 계정 연결하기`를 누르라고 안내합니다.

#### 사용 방법

별도 설정 없이 적용됩니다. 개인 계정을 연결하려면 내 설정 → AI Models → 연결하기를 사용하세요.

### 시작준비가 개인 계정을 계정 전환 목록에 자동 등록하지 않음

시작준비의 AI 도구 단계에서 이 컴퓨터에 로그인된 Claude·Codex 계정을 계정 전환 목록에 자동으로 등록하던 동작을 없앴습니다. 개인 계정은 AI Models의 `연결하기`로 로그인할 때만 등록됩니다. 시작준비의 계속·완료 버튼이 계정 등록 때문에 잠기지도 않습니다. 이미 시작준비에서 등록된 계정은 그대로 남습니다.

#### 사용 방법

별도 설정 없이 적용됩니다. 계정 전환이 필요하면 내 설정 → AI Models → 연결하기로 계정을 연결하세요.

### 시작준비에서 내 AI 계정 연결로 바로 이어가기

개인 사용(로컬 전용 또는 조직 없는 계정)의 시작준비는 컴퓨터 준비가 끝난 뒤 AI 도구 단계에서 연결된 AI가 없으면 `내 AI 계정을 연결해 주세요.`를 보여 주고, 왼쪽 아래 `나중에 하기`, 오른쪽 아래 `내 AI 계정 연결하기`를 둡니다. `내 AI 계정 연결하기`를 누르면 시작준비를 닫지 않고 ChatGPT·Claude를 고르는 창이 바로 열립니다. 개인 사용에서 연결된 AI가 하나도 없으면 `아직 연결된 AI가 없어요.` 옆의 `내 AI 계정 연결 바로가기`로도 같은 창을 열 수 있고(조직 계정은 조직 AI가 연결되지 않았으면 관리자에게 확인한 뒤 `조직 계정 연결하기`를 누르라고 안내합니다), 로그인이 끝나면 AI 도구 단계가 다시 확인해 `계속`을 보여 줍니다. 고르는 창의 ChatGPT·Claude는 로고가 있는 카드로 구분해 보입니다. 이미 연결된 AI가 있으면 기존처럼 `계속`이 보입니다.

#### 사용 방법

시작준비의 AI 도구 단계에서 `내 AI 계정 연결하기` 또는 `내 AI 계정 연결 바로가기`를 누르고 ChatGPT 또는 Claude를 고르세요.

### 시작준비에서 조직 AI 연결을 한눈에 확인

시작준비의 AI 도구 단계는 `조직 AI 계정 연결을 확인합니다.` 아래에 연결 정보를 확인하는 동안 로딩을 보이고, 조직이 AI를 배정한 컴퓨터는 로그인 확인 대신 요약을 보여 줍니다. 배정받은 AI(Claude Code, Codex)만 한 줄씩 보이고, 이 컴퓨터가 로그인한 값과 `인증세트 연결됨` 상태를 확인할 수 있습니다. 전체 계정은 `계정 더보기`에, 조직 ID와 기기 ID는 접힌 `기기 승인 정보`에 있습니다. 이 단계에서는 로그인을 권하거나 다시 확인 버튼을 누르게 하지 않습니다. 이 컴퓨터의 기기 승인 확인이 필요할 때는 `기기 승인 정보`가 자동으로 펼쳐집니다.

#### 사용 방법

시작준비 → AI 도구에서 확인합니다. 조직이 배정한 AI가 없어도 이 컴퓨터에 로그인된 Claude Code·Codex만 같은 형식으로 보입니다. 별도 설정 없이 자동 적용됩니다.

### 실시간 연결이 끊긴 이유를 보여 주고 더 빨리 다시 연결

대화 화면 위쪽의 연결 상태 표시가 끊긴 이유를 알려 줍니다. 기기가 오프라인이면 `오프라인`, 서버가 응답하지 않으면 `서버 응답 없음 · 재연결 중…`, 절전에서 깨어난 직후면 `절전 후 다시 연결 중…`, 네트워크가 바뀌면 `네트워크 변경 · 재연결 중…`, 로그인이 거부되면 `로그인 확인 필요`로 표시합니다. 또 앱이 창이 보이는 동안 서버에 주기적으로 응답을 확인해, 절전·VPN 전환 뒤 응답 없는 연결을 1분 가까이 기다리지 않고 바로 다시 연결합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 앱 브라우저가 한 장의 브라우저 창처럼 보이도록 다시 디자인

앱 브라우저 패널의 탭 줄·도구 막대·페이지 영역을 하나의 브라우저 창처럼 다시 정리했어요. 가운데 주소창 앞에는 연결 표시(보안 연결, 이 컴퓨터에서 실행 중인 서버, 보안되지 않은 연결)가 붙고, 주소는 호스트가 진하게 보이며, 페이지를 불러오는 동안 주소창 아래에 진행선이 나타나요. 도구 버튼은 검사·보기·창 세 묶음으로 나뉘고, 좁은 패널에서는 주소창이 한 줄을 따로 써요. 주소 후보·화면 크기 메뉴, 오류 안내, 빈 화면, 주석 트레이와 마크업 편집기도 같은 모양으로 바뀌었어요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 기존 버튼과 단축키는 같은 자리·같은 동작으로 쓸 수 있어요.

### 오토파일럿이 요구사항마다 증거를 확인한 뒤에만 Commit & PR로 넘어갑니다

작업보드 오토파일럿의 셀프 리뷰가 카드의 요구사항을 항목별로 나열하고, 항목마다 테스트 결과·파일·커밋·PR 같은 증거를 대게 합니다. 증거가 없거나 "확인했다" 정도의 약한 근거만 있는 항목은 완료로 치지 않고 다음 리뷰 라운드에서 이어서 처리하며, 남은 라운드가 없으면 카드에 "미증명 요구사항"으로 멈춥니다. AI가 턴을 끝냈다는 사실만으로는 자동 Commit & PR이 진행되지 않습니다.

같은 장애가 세 라운드 연속 이어지면 리뷰를 더 반복하지 않고 카드에 "장애 반복, 답변 대기"를 표시한 채 답을 기다립니다. 독립 리뷰 방식의 판정은 바뀌지 않습니다.

#### 사용 방법

작업보드에서 오토파일럿을 켠 카드에 자동 적용됩니다. 카드에 "오토파일럿 · 장애 반복, 답변 대기"가 보이면 그 대화에 답을 보내세요. 오토파일럿은 꺼지지 않고 다음 작업이 끝나면 리뷰를 다시 시작합니다.

### 응답을 중단하면 대기 중인 요청을 자동으로 보내지 않아요

응답 중에 `중단`을 누르면 대기열에 넣어 둔 요청이 이제 지워지지 않고 그대로 남습니다. 다음 응답이 끝나도 자동으로 보내지 않습니다. 대기열 위에는 `중단됨 · 대기 중인 요청은 자동으로 보내지 않아요` 표시가 생깁니다. 다른 기기에서 응답을 멈춘 경우도 같습니다. 이렇게 멈춘 대화에서는 자동화 실패 뒤 이어가기도 하지 않습니다. 프로젝트 허브 대화라면 다른 대화의 완료·질문 알림도 바로 보내지 않고 대기열에 남습니다.

대기열과 작업보드 오토파일럿이 같은 응답 끝에 함께 이어 보내려 하면 대기열만 보냅니다.

#### 사용 방법

중단한 뒤 남은 요청을 보내려면 대기열 위 표시 오른쪽의 `이어서 보내기` 버튼을 누르세요. 가장 오래된 요청부터 하나 보냅니다. 입력창에서 직접 새 메시지를 보내거나 항목을 `즉시 요청`으로 보내도 멈춤이 풀리고, 그 응답이 끝나면 남은 요청이 차례대로 이어집니다. 필요 없는 요청은 각 항목의 삭제 버튼으로 지우세요.

### 입력창 위 줄을 더 간결하게 정리

입력창 위 줄의 Git 새로고침 아이콘을 없앴습니다. Git 상태는 브랜치 메뉴를 열 때 다시 확인합니다. 브랜치 이름 옆 상태 아이콘은 조금 작아졌고, 새 대화의 워크트리 '방식' 버튼은 글자 없이 아이콘만 보입니다.

#### 사용 방법

Git 상태를 다시 보려면 입력창 위의 브랜치 이름을 누르세요. 워크트리 방식은 워크트리 체크 옆의 조절 아이콘을 누르면 열리고, 마우스를 올리면 '워크트리 · 방식'이 보입니다.

### 입력창 위 Git 상태 아이콘과 새로고침 정렬

입력창 위 저장소 상태를 아이콘으로 표시하고 Git 새로고침을 줄 맨 오른쪽에 배치했습니다. 변경 있음·원격 없음·조회 오류 등 자세한 상태는 아이콘의 설명에서 확인할 수 있습니다.

#### 사용 방법

상태 아이콘에 마우스를 올려 설명을 확인하고 클릭하면 기존 저장소 상태·설정을 엽니다. 맨 오른쪽 새로고침으로 Git 상태를 다시 확인합니다.

### 조직 계정 목록에 Claude 로그인 표시값 함께 보기

조직에서 배정한 Claude(setup-token) 계정 목록에서 이메일 아래에 Claude가 실제로 로그인 계정으로 보여 주는 값(`managed-…@setup-token.local`)을 함께 표시합니다. 시작준비의 AI 계정 연결 확인에 적용됩니다. 목록의 이메일과 Claude Code 화면의 계정이 달라 보여 헷갈리던 부분을 바로 대조할 수 있습니다. 이 컴퓨터의 Claude가 지금 로그인해 있는 계정은 파란색과 `사용 중`으로 표시됩니다.

#### 사용 방법

내 프로필 → 내 설정 → 시작준비 → AI 도구의 조직 계정에서 각 Claude 계정 이메일 아래의 `managed-…@setup-token.local` 값을 확인합니다. 지금 쓰는 계정은 `사용 중`으로 표시됩니다. 별도 설정 없이 자동 적용됩니다.

### 조직 계정 연결하기·암호화키 확인을 시작준비로 이동

설정의 AI 연결 화면에 있던 `조직 계정 연결하기`와 `암호화키 확인`을 시작준비의 AI 도구 단계로 옮겼습니다. 조직이 AI를 배정한 컴퓨터는 Claude Code·Codex 요약 아래에, 그렇지 않으면 로그인 확인 줄 아래에 같은 두 버튼이 있고 동작은 그대로입니다. 설정의 AI Models에는 이 두 버튼이 없습니다.

#### 사용 방법

내 프로필 → 내 설정 → 시작준비 → AI 도구에서 `조직 계정 연결하기` 또는 `암호화키 확인`을 누릅니다.

### 커넥터 상태를 입력창 위 줄에서 확인

진행 중인 대화의 커넥터 상태 버튼이 대화 위쪽 헤더에서 입력창 위 줄의 오른쪽 끝으로 옮겨졌습니다. 웹과 같은 자리입니다. 글자 대신 플러그 아이콘으로 표시하며, 확인이 필요한 커넥터가 있으면 아이콘이 빨간색으로 바뀝니다.

#### 사용 방법

프로젝트 대화에서 입력창 위 줄 오른쪽 끝의 플러그 아이콘을 누르면 'MCP 연결 상태와 복구' 창이 열립니다. 아이콘에 마우스를 올리면 확인이 필요한 커넥터의 개수와 이름이 보입니다.

### 컴퓨터 제어 확장이 조작할 수 없는 앱을 거부

Saycode 컴퓨터 제어 확장으로 대화 중인 AI가 클릭하거나 글자를 입력할 때, 대상 앱이 Saycode 자신이면 항상 거부합니다. 작업PC의 Saycode 런타임이 앱 분류표를 갖춘 버전이면 같은 표로 브라우저·증권 앱의 클릭, 터미널의 글자 입력, 미디어 앱 조작도 거부합니다. 대상 앱을 확인하지 못한 경우도 거부합니다. 기존 동의·한 번에 한 조작자 규칙은 그대로이고, 확장 화면에서 직접 시작한 Chrome 확장 설치 준비 같은 설정 작업에는 적용하지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 브라우저 조작은 Saycode 브라우저 도구를, 터미널 명령은 AI의 명령 실행 도구를 쓰도록 안내됩니다.

### 프로젝트 대화의 작업 중 표시를 제목 뒤로 옮김

사이드바 프로젝트 아래 대화가 응답하거나 백그라운드 작업을 하는 동안 보이는 회전 아이콘이 제목 앞이 아니라 제목 뒤, 브랜치 아이콘 자리에 표시됩니다. 작업이 진행되는 동안 제목이 밀리지 않아 대화 제목들의 시작선이 맞춰집니다. 작업이 끝나면 그 자리에 브랜치 아이콘이 다시 표시됩니다. 대화에 마우스를 올리면 브랜치 아이콘처럼 메뉴와 고정 버튼에 자리를 넘깁니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 현재 대화 계정을 확인하는 작업PC 런타임 업데이트

앱에 포함되는 작업PC 런타임을 Happy CLI 1.1.10-aplus.352로 업데이트합니다. 지원되는 조직 계정으로 실행한 대화는 사용량 창에서 실제 계정을 확인할 수 있습니다. 새 대화용 계정 선택은 기존 대화를 바꾸지 않습니다.

#### 사용 방법

이 변경이 포함된 Desktop 버전으로 업데이트한 뒤 입력창 아래 AI 사용량을 열어 현재 대화와 새 대화용 선택을 확인합니다. 이미 실행 중인 이전 런타임 대화는 재시작하지 않으며 계정을 확인할 수 없다고 표시될 수 있습니다.

### AI 연결 문제를 한 곳에서 확인하고 해결

AI 오류 답변에는 AI Models만 표시합니다. 열면 해당 대화의 AI와 작업PC를 확인하고, 지원되는 개인 Codex 연결은 한 번 자동 복구합니다. 다시 로그인하거나 관리자가 확인해야 하는 경우 필요한 행동 하나를 안내합니다.

#### 사용 방법

오류 답변의 AI Models를 누르세요. 복구 후 대화 계속하기를 누르면 기존 대화에서 진행할 수 있습니다. 관리자에게 요청은 조직 관리 알림으로 전달됩니다. 자세한 오류와 추가 계정 설정은 펼쳐서 확인할 수 있습니다.

### AI 연결 설정을 AI Models로 바꾸고 공급사 카드 추가

내 설정의 `AI 연결 설정`이 `AI Models`로 바뀌었습니다. 맨 위 공급사 카드에서 Claude와 ChatGPT가 이 컴퓨터에 연결돼 있는지 한 줄씩 보이고(이 컴퓨터에 로그인된 계정 또는 조직 인증세트 이름), 마지막 행의 `연결하기`로 내 계정을 연결합니다. 확인하지 못했거나 컴퓨터가 오프라인이면 연결됨으로 보이지 않습니다. 대화 오류 카드의 설정 버튼과 설정 검색에서도 같은 이름으로 열리며 예전 이름(AI 연결)으로 검색해도 찾을 수 있습니다.

#### 사용 방법

내 프로필 → 내 설정 → AI Models에서 공급사 카드를 확인하고 `연결하기`를 누릅니다. 각 행의 `…` 메뉴에서 `다시 확인`으로 상태를 다시 읽을 수 있습니다.

서버(localhost, 127.0.0.1) 페이지에서만 허용됩니다.

### 연결이 끊겨도 메시지가 사라지거나 두 번 가지 않아요

메시지를 보내는 중에 연결이 끊기거나 응답이 늦어 전송 결과를 알 수 없으면, 예전에는 메시지가 화면에서 사라지고 입력창에 다시 채워졌어요. 그대로 다시 보내면 실제로는 이미 도착해 있던 메시지가 한 번 더 가서 AI가 같은 일을 두 번 할 수 있었어요.

이제는 메시지를 그 자리에 둔 채 아래에 `전달 확인 중…`을 보여 주고, 메시지가 실제로 도착했는지 확인해요. 도착했으면 그대로 이어서 답을 기다리고, 도착하지 않았으면 같은 메시지로 한 번만 다시 보내요. 이미 도착한 메시지는 다시 보내도 대화에 한 번만 남아요.

그래도 확인되지 않으면 메시지 아래에 `전달을 확인하지 못했어요`와 `다시 보내기`·`보내지 않기`를 보여 줘요. 이 상태는 앱을 새로고침하거나 다시 시작해도 남아요. 같은 대화에서 앞 메시지를 확인하는 동안 보낸 다음 메시지는, 확인이 끝난 뒤 보낸 순서대로 전달돼요. 확인은 길어도 90초 안에 끝나요. 확인하는 동안 `중단`을 누르거나 대화를 보관·삭제하면 자동으로 다시 보내지 않고, 메시지 아래에 `다시 보내기`만 남겨요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 메시지 아래에 `전달을 확인하지 못했어요`가 보이면 연결을 확인한 뒤 `다시 보내기`를 누르세요. 보내지 않으려면 `보내지 않기`를 누르세요.

#### 사용 방법

#### 사용 방법

서버에 예전에 적용됐다는 기록이 남아 있어도, 이 컴퓨터의 연결 확인이 진행 중이거나 실패했거나 컴퓨터가 오프라인이면 조직 AI가 `연결됨`으로 보이지 않습니다. 설정의 조직 계정 연결과 시작준비의 조직 AI 요약에 같은 기준을 적용했고, 실제 연결이 끝나기 전에는 `연결 대기` 또는 확인이 필요하다는 안내를 보여 줍니다.

### 첫 AI 연결이 막혀도 쉽게 다시 진행

시작준비를 이 컴퓨터 등록·온라인 확인과 AI 연결 확인으로 나눕니다. 서버에서 이미 적용한 내 PC의 조직 계정은 다시 적용하지 않고 확인하며, 기존 PC의 연결 키와 대화 신원을 보존합니다. 조직의 Claude 연결이 아직 준비되지 않아도 사용할 수 있는 배정 Codex가 있으면 이어갑니다. AI 준비가 실패하면 홈으로 돌아가거나 AI Models를 바로 열 수 있고, 브라우저 로그인 대기에서는 로그인 취소 후 다시 연결할 수 있습니다. 완료 화면과 이 컴퓨터 등록 화면의 안내도 간결하게 정리합니다.

#### 사용 방법

첫 시작 안내에서 다음을 눌러 이 컴퓨터를 준비합니다. PC 등록·온라인 확인이 끝나면 다음을 한 번 더 눌러 AI 연결을 확인하세요. 로그인 대기에는 로그인 취소, AI 준비가 실패하면 다시 연결·나중에 하기·AI Models를 사용하세요. 준비 완료 버튼은 기존대로 완료입니다.

### 최근 기능의 사용 안내를 현재 동작에 맞춤 (3차)

AI에게 Saycode 사용법을 물으면 참고하는 앱 안 안내서를 최근 기능의 현재 동작에 맞게 고쳤습니다. 도구 정책 확인 카드에서 보내기·삭제·결제 같은 도구도 "이 대화에서 이 도구 허용"을 고를 수 있다는 점(이전 안내는 이번만 허용할 수 있다고 잘못 안내함), 딥링크 needs-input이 여는 필터 이름(입력 대기), 링크로 연 프로젝트 추가 창에는 폴더가 미리 채워지지 않는다는 점, 허용을 미리 거두는 버튼은 아직 지원하는 런타임이 없어 보이지 않는다는 점을 바로잡았습니다. 컴퓨터 사용 표시가 조작이 끝난 뒤 최대 40초쯤 남는 점과 Windows에서는 화면 공유에 보이는 점, 절전 후 자동 이어하기가 기다리는 조건, 자동 보관이 처음 확인하는 시점과 이 PC에만 저장된다는 점, MCP 연결 테스트 결과의 종류, 다음 단계 카드에 필요한 런타임 버전과 기본 지시 설정, 앱 안 브라우저의 마이크·클립보드 차단과 로그아웃 시 로그인 삭제도 보강했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 대화에서 기능 사용법을 물으면 바뀐 안내로 답합니다.

### 현재 PC의 Claude 연결 상태 조회 개선

구버전 Claude 실행 파일이 먼저 검색되는 PC에서도 이미 설치된 사용자 Claude로 연결 상태를 확인할 수 있도록 개선했습니다. 확인된 로그아웃 상태는 유지하며, 다른 AI 도구의 조회 결과도 독립적으로 표시합니다.

#### 사용 방법

내 설정 → AI Models → 연결된 AI 확인하기에서 Claude와 PC를 선택하세요. 별도 설치나 업데이트 없이 적용됩니다.

### AI 연결 복구 후 같은 요청을 다시 시도합니다

AI 오류를 해결한 뒤 원래 질문과 첨부를 보존해 다시 시도합니다. 첨부를 확인하지 못하면 전송을 멈추고 해당 파일을 안내합니다. 작성 중인 새 초안과 첨부는 유지하며, 재시도 중 전송이 실패해도 복구 화면에서 다시 시도할 수 있습니다.

#### 사용 방법

실패한 답변의 AI Models에서 연결을 확인한 뒤 `같은 요청 다시 시도`를 누르세요. 첨부가 없어졌다면 다시 첨부하고, PC 연결이나 접근 권한 문제라면 표시된 안내에 따라 해결한 뒤 재시도하세요. 원래 질문을 찾을 수 없는 오류에서는 재시도 버튼을 표시하지 않습니다.

### AI 질문에 답변한 뒤 요청을 다시 시도합니다

확인 질문에 답변하는 동안 같은 요청의 재시도와 계정 변경을 막습니다. 연결 상태 확인과 오류 상세 보기는 유지합니다. 이미 답변한 질문의 오래된 상태는 새 요청을 막지 않습니다.

#### 사용 방법

AI Models에 질문 대기 안내가 보이면 창을 닫고 AI 질문에 답변한 뒤 다시 시도하세요.

### Windows에서 조직 AI 계정 재연결이 실제 저장 상태를 확인합니다

Swap 계정 저장소를 초기화했지만 Claude의 로그인 표시가 남아 있으면, 조직 계정 재연결이 이미 저장된 상태로 판단해 대화를 시작하지 못할 수 있었습니다. 현재 저장 슬롯을 기준으로 확인하고, 슬롯이 없으면 다시 적용하도록 보완했습니다. 상태 조회와 겹친 재연결 요청도 보존합니다.

#### 사용 방법

내 설정 → 시작준비 → AI 도구에서 조직 계정 연결하기를 다시 실행한 뒤 새 대화로 응답을 확인하세요.
