### 조직 Elasticsearch 검색

조직 owner/admin 이 조직 소유 Elasticsearch 를 등록하면 조직의 대화(제목·사용자 프롬프트·에이전트 응답)가 그 Elasticsearch 에 색인되고, 멤버는 전체 검색 패널의 새 `조직` 탭에서 형태소·부분일치·오타 허용 키워드 검색을 쓸 수 있습니다. 결과는 최근 대화, 제목 일치, 사용자 프롬프트 일치 순으로 우선하며, 입력한 단어를 모두 담은 대화가 더 최근의 부분 일치보다 앞섭니다. 따옴표로 감싼 오류 문구는 입력한 그대로 찾습니다. 각 멤버는 자기가 참여한 프로젝트의 대화만 볼 수 있으며, 이 제한은 Elasticsearch 가 멤버별 alias 와 API 키로 직접 강제합니다. 색인 진행률(전체·프로젝트별)과 권한 동기화 상태는 관리자 탭에서, 색인 중인 동안의 안내는 검색 탭에서 볼 수 있습니다. 관리자 탭의 `검색 품질 평가`는 내 프롬프트를 표본으로 변형 검색어를 만들어 Elasticsearch 와 로컬 인덱스의 회수율을 나란히 보여줍니다.

#### 사용 방법

조직 관리 콘솔 → `검색 (Elasticsearch)` 탭에서 URL·관리자 ID·비밀번호를 넣고 `연결 테스트` → `연결하고 인덱스 만들기`. 관리자 비밀번호는 전용 운영자 사용자를 만드는 데 한 번만 쓰이고 저장되지 않습니다. 이후 멤버는 전체 검색에서 `조직` 탭을 선택합니다. 보안이 꺼진 클러스터는 연결이 거부됩니다(프로젝트별 권한을 강제할 수 없기 때문).

### 파일 변경 체크포인트와 안전 복원

보호가 활성화된 macOS Claude remote 또는 Codex 세션은 에이전트가 파일을 변경하기 전에 턴별 체크포인트를 남깁니다. 프로젝트의 Git 기록과 작업 상태는 건드리지 않으며, 사용자가 나중에 수정했거나 출처를 확인할 수 없는 파일은 자동으로 덮어쓰지 않습니다. 복원 전에는 파일별로 복원·삭제·보존·충돌 여부를 미리 확인할 수 있고, 실제 복원은 사용자가 확인한 뒤에만 실행됩니다. 일부 항목이 실패하면 실패한 항목만 다시 시도할 수 있습니다. 기능은 자동으로 켜지지 않으며, 호환되는 공식 Happy runtime과 새 세션 작성 화면의 명시적 체크포인트 보호 opt-in이 필요합니다.

#### 사용 방법

새 세션 작성 화면에서 지원되는 실행 조건을 선택하고 `파일 체크포인트 보호`를 켠 뒤 세션을 시작합니다. 대화 상단의 세션 정보 바로 아래에 표시되는 `파일 체크포인트` 패널에서 원하는 기록의 `미리보기`를 선택합니다. 파일별 처리 내용을 확인하고 `이 미리보기의 파일 변경을 확인했습니다`를 선택한 뒤 `파일 상태 복원`을 실행합니다. 이 기능은 파일 상태만 복원하며 대화 메시지, 모델 상태, 이미 실행된 외부 서비스 작업은 되돌리지 않습니다.

### 자동 리뷰가 만든 수정 PR이 고아가 되지 않도록

#### 사용 방법

별도 설정 없이 자동 적용됩니다. GitHub 트리거 설정에서 "AgentTask 리뷰·후속 반영" 또는 "PR 리뷰 후속" 프리셋을 다시 넣으면 갱신된 문구가 반영됩니다.
