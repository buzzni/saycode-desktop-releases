## 새 기능

### 고정·작업 패널 탭 닫기 되돌리기

대화를 고정·고정 해제하거나 오른쪽 작업 패널의 터미널·브라우저·변경·파일·PR 탭을 닫으면 10초 동안 "대화를 고정했어요." 같은 알림이 보이고 되돌리기로 바로 원래대로 돌릴 수 있습니다. 같은 동작을 연달아 하면 알림 하나로 묶이고, 다른 동작을 이어서 했다면 최근 것부터 하나씩 되돌립니다. 닫았던 터미널은 실행 중이던 그 터미널로 돌아옵니다.

#### 사용 방법

동작 직후 알림의 되돌리기를 누르거나 Cmd+Z(Windows는 Ctrl+Z)를 누르세요. 입력창·터미널에서 누른 Cmd+Z는 지금처럼 글자 실행 취소로 동작합니다. 미리보기 탭, 열어 둔 파일 탭은 되돌리기 대상이 아닙니다.

### 기획안 답변 바로 아래에서 작업을 시작할 수 있습니다

기획모드에서 AI가 기획안을 정리하면 그 답변 바로 아래에 '작업 시작하기'와 '기획안 보기' 버튼이 나타납니다. 오른쪽 기획안 패널이 닫혀 있어도 버튼을 찾을 수 있습니다. 확인 창과 시작 동작은 기획안 패널의 버튼과 같습니다. 기획모드에서는 비슷한 이름의 계획 승인 '작업 시작' 버튼을 함께 띄우지 않습니다. 화면에 보이지 않는 기획안 원문 때문에 이 승인 버튼이 잘못 뜨던 문제도 고쳤습니다. AI 안내 문구도 실제 버튼 위치에 맞게 바꿨습니다.

#### 사용 방법

기획모드 프로젝트의 대화에서 AI가 기획안을 정리한 가장 최근 답변 아래의 '작업 시작하기'를 누르고, 확인 창에서 기획 파일을 확인한 뒤 '작업 시작하기'를 누릅니다. 전체 기획안은 '기획안 보기'로 엽니다.

### 내 메시지에서 "여기서 다시 쓰기"

Claude와 나눈 프로젝트 대화에서 내가 보낸 메시지를 고쳐 다시 보내고 싶을 때, 그 메시지 직전까지의 대화로 새 대화(갈래)를 만들고 입력창에 원래 메시지를 채워 줍니다. 원래 대화는 그대로 남습니다. 화면의 메시지와 AI의 기록이 맞지 않으면 엉뚱한 곳을 자르지 않고 안내합니다.

#### 사용 방법

내 메시지에 마우스를 올려 복사 아이콘 옆의 연필 아이콘(여기서 다시 쓰기)을 누르거나 메시지를 오른쪽 클릭해 "여기서 다시 쓰기"를 고르세요. 새 탭에 열린 대화의 입력창에서 메시지를 고쳐 보내면 됩니다. 응답 중이거나 첫 메시지, Codex 대화에서는 쓸 수 없습니다.

### 내 프롬프트를 계정에 저장해 다른 PC와 함께 사용

입력창의 "내 프롬프트"에 저장한 문장이 이 PC가 아니라 로그인한 계정에 저장됩니다. 다른 PC의 Saycode에서 같은 목록을 쓰고, 로그아웃했다가 다시 로그인해도 목록이 사라지지 않습니다. 업데이트 전에 이 PC에 저장해 둔 문장은 처음 동기화할 때 계정으로 옮겨집니다. 계정 저장에 실패하면 문장은 이 PC에 남고 메뉴에 안내가 표시되며, 앱으로 돌아올 때 다시 시도합니다.

#### 사용 방법

입력창의 책갈피 아이콘(Quick Commands)을 눌러 평소처럼 저장·선택·이름 변경·삭제합니다. 10,000자를 넘는 문장은 저장할 수 없습니다. 데모 모드처럼 계정이 없는 실행에서는 지금처럼 이 PC에만 저장됩니다.

### 대기 중인 요청을 제자리에서 고치기

AI가 답하는 동안 대기열에 넣어 둔 요청을 편집해도 이제 대기열에서 빠지지 않습니다. 고치는 동안 그 요청은 같은 자리에 강조되어 남고, 입력창에 쓰고 있던 글과 첨부는 따로 보관됐다가 편집이 끝나면 그대로 돌아옵니다. 그래서 입력창에 다른 글이 있어도 바로 편집할 수 있습니다. 편집하는 동안에는 이 창이 대기열을 자동으로 보내지 않고, 그사이 답이 끝났다면 저장하거나 취소한 뒤 가장 오래된 요청부터 보냅니다. 프로젝트 대화와 개인 Chat 모두 같습니다.

#### 사용 방법

대기 중인 요청 줄의 연필 아이콘(편집)을 누르고 입력창에서 고친 뒤 Enter(또는 Cmd/Ctrl+Enter)나 줄의 체크 아이콘(저장)을 누르세요. 그만두려면 줄의 X 아이콘(편집 취소)을 누르면 원래 내용이 남습니다. 편집하는 동안에는 새 파일을 붙일 수 없고, 다른 화면에서 보낸 코멘트·요소 선택은 편집이 끝난 뒤 쓰던 글 뒤에 붙습니다.

### 대화와 승인 카드에서 AI 브라우저의 승인 방식을 바꿀 수 있어요

프로젝트·Chat 대화 헤더와 브라우저 작업 도구의 승인 카드에 AI 브라우저 버튼을 추가했어요. 현재 대화의 작업만 열고, 작업이 없으면 다른 대화의 작업을 대신 고르지 않아요. 지원 런타임에서는 작업·사이트 범위를 확인한 뒤 Auto를 켜거나 끌 수 있어요. 도구 실행 권한과 현재 대기 요청의 승인은 별도예요. Auto 런타임은 별도 릴리스·설치가 필요하며 이 Desktop 변경만으로 설치판에 활성화되지 않아요.

#### 사용 방법

대화 오른쪽 위 또는 브라우저 작업 도구 승인 카드의 AI 브라우저를 누르세요. 지원 런타임에서는 작업을 고른 뒤 승인 방식 옆 Auto 또는 이 작업에서 Auto 켜기를 누르고 작업·사이트를 확인해요. 해제는 Auto 끄기를 누릅니다. 구 런타임에서는 미지원 안내의 수동 콘솔 열기로 기존 승인·인계를 계속할 수 있어요. 기존 AI 브라우저 버튼 표시 설정을 꺼도 승인 방식 진입점은 보입니다.

### 도구 정책 확인 카드에서도 거절할 때 이유를 함께 보낼 수 있어요

Claude 대화에서 AI가 컴퓨터 화면을 조작하거나 보내기·삭제 같은 도구를 쓰기 전에 뜨는 도구 정책 확인 카드에서도, 거절하면서 이유를 적어 AI에게 함께 보낼 수 있어요. 작업 PC의 happy-cli가 1.1.10-aplus.358 이상일 때 쓸 수 있고, 그보다 낮으면 카드에 업데이트하면 이유를 보낼 수 있다고 알려 줘요. 같은 버전 이상의 작업 PC에서는 일반 권한 요청의 거절 이유도 작업 PC가 직접 AI에게 전달해요. 작업 PC를 업데이트하기 전에 시작한 대화에서는 도구 정책 확인 카드의 거절 이유가 전달되지 않을 수 있어요. 대화를 다시 시작하면 전달돼요.

#### 사용 방법

도구 정책 확인 카드의 버튼 아래 ‘이유를 적고 거절’을 펼친 뒤 이유를 적고 ‘이유와 함께 거절’을 누르세요. 칸을 비워 두면 기존 거절과 같아요. 작업 PC의 happy-cli가 1.1.10-aplus.358 이상이어야 해요.

### 변경 목록에서 바뀐 내용으로 파일 찾기

변경(Review) 목록 위 찾기 칸이 파일명뿐 아니라 추가·삭제한 줄 내용으로도 파일을 찾아요. 내용이 맞은 파일에는 몇 줄이 맞는지 보이고, 맞는 파일이 없으면 "일치하는 파일이 없어요"가 보여요. 목록이 일부만 미리 받아 둔 긴 파일은 그 파일의 전체 diff를 불러와 잘린 부분까지 찾아요. 이런 파일을 열면 편집기의 diff와 diff에서 찾기도 전체 내용을 보여 줘서, 예전처럼 "미리보기 일부에서만 찾았어요"로 끝나지 않아요.

#### 사용 방법

작업 도구에서 작업 패널 추가 → 변경을 고르고, 목록 위 "파일명·바뀐 내용으로 찾기" 칸에 찾을 말을 입력하세요. 긴 파일은 2자 이상 입력하고 잠시 멈추면 불러와요. Windows 작업 PC나 꺼진 작업 PC처럼 전체 diff를 못 불러오면 파일명과 미리보기만 비교했다고 찾기 칸 아래에 알려 줘요.

### 보관·일괄 보관 되돌리기

대화를 보관하거나 여러 대화를 골라 한 번에 보관하면 10초 동안 "대화를 보관했어요." 알림이 보이고 되돌리기로 바로 되돌릴 수 있습니다. 확인창 없이 바로 보관되는 만큼 실수로 누른 보관을 그 자리에서 취소할 수 있습니다. 보관하면서 풀린 고정도 함께 돌아오고, 알림의 보관함으로 이동도 그대로 있습니다.

#### 사용 방법

보관 직후 알림의 되돌리기를 누르거나 Cmd+Z(Windows는 Ctrl+Z)를 누르세요. 보관을 되돌린 대화는 보관 해제와 같이 이후 자동 보관 대상에서 빠집니다. 자동 보관과 작업보드에서 옮긴 보관은 되돌리기 대상이 아닙니다.

### 복구 파일을 가입 이메일로 보내기

보안 설정에서 발급받은 대화 복구 키와 MFA 복구 코드를 기존 복사·파일 저장 외에 본인의 가입 이메일로 보낼 수 있습니다. 확인한 주소가 바뀌면 발송을 멈추며, 메일 발송이 키 보관 확인이나 설정 완료를 대신하지 않습니다.

#### 사용 방법

새 복구 자료의 `가입 이메일로 보내기`를 누르고 수신 주소와 원문 보관 안내를 확인합니다. 현재 비밀번호와 필요한 추가 인증을 마친 뒤 `이 주소로 보내기`를 누릅니다. 비밀번호가 없는 계정에서 추가 인증이 필요하면 `다시 로그인`을 이용합니다. 메일함에 원문이 남으므로 안전하게 보관하고 기존 키 재입력·완료 절차도 마쳐 주세요.

### 브라우저 앱 연결 기간과 자동 승인 관리

지원 런타임에서 로컬 앱 연결을 승인할 때 15분·1시간·1일을 선택하고, 같은 앱의 같은 범위 요청만 자동 승인할 수 있습니다. 연결 관리에서 자동 승인만 끄거나 연결과 자동 승인을 함께 철회할 수 있습니다. 구버전 런타임에는 새 승인 옵션을 제공하지 않습니다. OS 알림에서도 기간 선택을 생략한 승인을 막고, 연결 관리는 본인 소유 대화와 사용 가능한 AI 브라우저 PC에서 표시합니다.

#### 사용 방법

앱 이름을 지정해 브라우저 연결을 요청한 뒤 승인 카드에서 연결 기간을 고릅니다. 필요하면 ‘이 앱의 같은 범위 요청 자동 승인’을 선택하고 허용합니다. 대화 헤더의 ‘브라우저 앱 연결’에서 상태를 확인하고 철회합니다. 연결 관리에는 지원 런타임과 실행 중인 대화가 필요합니다. 런타임 배포는 별도입니다.

### 앱 안 PR 화면에서 바뀐 파일의 diff를 끝까지 읽을 수 있습니다

앱 안 PR 화면에 활동과 파일 탭이 생겼습니다. 파일 탭은 그 PR이 바꾼 파일마다 diff를 처음부터 끝까지 보여 줍니다. 미리보기처럼 일부만 잘라 보여 주지 않습니다. 내 PC에 그 PR의 작업트리가 없어도 동료나 다른 대화가 연 PR을 바로 읽을 수 있습니다. 새 파일·삭제·이름 변경·바이너리·권한 변경을 구분해 표시하고, 파일 편집기와 같은 좌우/한 줄 보기와 찾기(Cmd/Ctrl+F)를 쓸 수 있습니다. 읽기 전용이라 코멘트와 리뷰는 GitHub에서 남깁니다.

diff가 너무 크면 일부만 보여 주지 않고 GitHub의 파일 화면으로 안내합니다. Windows 작업PC와 관리형 작업PC에서는 아직 지원하지 않으며, 안내와 함께 GitHub에서 볼 수 있게 합니다.

#### 사용 방법

프로젝트 대화에서 GitHub PR 링크를 눌러 오른쪽 작업 패널에 PR 화면을 연 뒤 위쪽의 파일 탭을 누르세요. 파일 머리를 누르면 접거나 펼칠 수 있고, diff 안을 누른 뒤 Cmd/Ctrl+F로 그 파일 안에서 찾을 수 있습니다. 작업PC에 gh가 설치되고 로그인돼 있어야 합니다.

### 위험할 수 있는 작업은 승인 카드에서 미리 알려 드려요

AI가 파일을 크게 지우기, 관리자 권한 사용, 인터넷에서 받은 코드 바로 실행, 강제 push, 비밀번호·키 파일 접근처럼 위험할 수 있는 작업의 권한을 요청하면 승인 카드에 '주의가 필요한 작업' 표시와 이유가 함께 보입니다. 이런 카드는 Enter 한 번으로 허용되지 않고, 허용을 누른 뒤 한 번 더 확인해야 합니다. 자동 검사에 걸린 것이라 실제로는 안전한 작업일 수도 있어, 막지는 않고 알려 주기만 합니다. 플로팅 승인 패널 카드에도 같은 표시와 이유가 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 위험 표시가 있는 카드에서 허용을 누르면 '위험할 수 있어요 — 그래도 허용'으로 바뀌고, 한 번 더 누르면 허용됩니다. 거절은 한 번이면 됩니다.

### 이 컴퓨터의 개인 Claude 사용 허용 설정

AI 사용량 창에서 이 컴퓨터의 개인 Claude 계정 사용을 켜거나 끌 수 있습니다. 기존 허용 기본값은 유지합니다. 끄면 이 앱의 후속 전송과 대화 시작·재개에서 조직 실행 계정을 확인하며, 확인할 수 없으면 개인 계정으로 대신 실행하지 않고 안내합니다. 진행 중인 응답과 CLI 로그인은 유지됩니다.

#### 사용 방법

이 앱이 실행 중인 컴퓨터의 Claude 대화에서 입력창 아래 계정 표시를 누르고 ‘이 컴퓨터에서 개인 Claude 계정 사용 허용’을 변경하세요. 다른 PC·웹·서버 예약의 실행 정책에는 적용되지 않습니다. 계정을 확인할 수 없는 기존 대화는 새 조직 계정 대화로 시작하세요.

### 입력창에 /recap 을 적으면 지금까지의 요약과 다음 행동을 보여 줍니다

여러 대화를 오가다가 "이 대화에서 어디까지 했지?" 싶을 때, 입력창에 /recap 만 적어 보내면 지금까지 한 일과 다음에 할 일을 입력창 위의 짧은 카드로 보여 줍니다. 진행 중인 작업은 멈추지 않고, 카드는 대화 기록과 이후 대화 문맥에 남지 않습니다. 이미 시작한 Claude 대화에서 내가 보낸 메시지가 3개 이상일 때 쓸 수 있고, 쉬고 있는 대화나 Codex 대화에서는 이유를 안내합니다.

#### 사용 방법

대화 입력창에 /recap 을 적고 Enter를 누릅니다. 카드 오른쪽 X로 닫을 수 있습니다.

### 입력창에서 @로 다른 대화를 참조할 수 있습니다

Project 대화의 입력창에서 @를 입력하면 파일 제안 아래에 같은 프로젝트의 '대화' 목록이 함께 나옵니다. 대화를 고르면 입력창 위에 칩으로 붙고, 보내면 AI가 그 대화 내용을 읽고 답합니다. 대화 내용은 요청한 작업PC의 작업 폴더에 파일로 준비되며, 데스크톱이 실행 중일 때만 처리됩니다.

보관된 대화와 이 PC에서 열 수 없는 대화는 목록에 흐리게 보이고 이유가 함께 나옵니다. 이번에 열어 보지 않은 대화도 전체 기록을 불러와 준비합니다.

#### 사용 방법

Project에서 대화를 열고 입력창에 @와 대화 제목 일부를 입력한 뒤, '대화' 묶음에서 대화를 고르세요. 요청을 적어 보내면 됩니다. 칩의 X로 참조를 뺄 수 있습니다. 개인 Chat에서는 쓸 수 없습니다.

### 조직 한도 소진·연결 오류 시 개인 Claude로 같은 대화 이어가기

지원되는 작업PC에서 조직 Claude 계정이 모두 한도에 도달하거나 조직 Claude의 계정 조회·인증 오류가 발생하면 개인 계정의 사용량 차감에 동의하고 같은 대화를 이어갈 수 있습니다. 조직 계정이 다시 사용 가능하다고 확인되면 진행 중인 응답을 마친 뒤 다음 요청부터 자동으로 돌아갑니다. 실제 실행 계정과 전환 안내를 표시합니다. 개인 계정으로 이어가도 프로젝트 지침·hooks·권한 규칙을 유지하고, 선택한 인증을 확인하지 못하면 실행을 중단합니다.

#### 사용 방법

개인 Claude 사용을 허용한 이 컴퓨터의 본인 전용 PC에서, 대화 입력창 아래 개인 계정으로 이어가기를 누릅니다. 계정과 사용량 차감·자동 복귀 안내를 확인하고 개인 계정으로 이어서 실행을 누릅니다. 오류 안내의 다시 시도는 상태만 재조회합니다. 조직·대화 접근 권한이 확인되지 않으면 전환할 수 없습니다. 서버·CLI 지원이 필요하며 기존 설치판에는 기능을 표시하지 않습니다.

### 터미널 키보드 스크롤과 우클릭 메뉴

앱 안 터미널에서 Shift+PageUp/PageDown으로 한 화면씩 지난 출력을 오가고, Ctrl+Shift+Home/End로 맨 위·맨 아래로 바로 갈 수 있습니다. 터미널을 오른쪽 클릭하면 복사(선택한 글자가 있을 때), 전체 선택, 맨 아래로 메뉴가 열립니다. 로그인 셸이 fish이면 시작할 때 터미널에 보내는 질의를 꺼서 앱 터미널에서 안정적으로 시작합니다.

#### 사용 방법

터미널을 클릭한 뒤 단축키를 누르거나, 터미널 화면을 오른쪽 클릭하세요. vim·tmux처럼 마우스를 쓰는 프로그램 안에서는 Shift를 누른 채 오른쪽 클릭하면 메뉴가 열립니다.

### 터미널에서 이어가기 명령 복사

앱에서 하던 Claude·Codex 대화를 터미널에서 이어서 쓸 수 있도록, 그 대화를 여는 명령을 한 번에 복사합니다. 복사되는 명령은 작업 폴더로 이동한 뒤 `claude --resume`(Codex는 `codex resume`)으로 이 대화를 여는 한 줄입니다. 응답이 진행 중이면 먼저 이 대화를 멈추라는 안내가 함께 보입니다. 다른 컴퓨터의 대화, 작업PC가 오프라인인 대화, AI 대화 기록이 아직 연결되지 않은 대화는 쓸 수 없고 이유가 항목 아래에 보입니다.

#### 사용 방법

프로젝트 대화 머리글 오른쪽의 프로젝트 도구(⋮)에서 대화 이어가기를 누르고 "터미널에서 이어가기"를 고릅니다. 복사된 명령을 터미널에 붙여 넣어 실행하세요.

### 편집기의 diff 안에서 찾기

편집기에 연 파일의 변경 내용(diff)에서 글자를 찾을 수 있어요. 추가·삭제·그대로인 줄을 모두 찾고, 몇 번째 결과인지와 결과 없음을 보여 줘요. 좌우 비교와 한 줄 보기에서 개수가 같아요. 미리보기가 일부만 담긴 긴 diff에서는 "미리보기 일부에서만 찾았어요"가, 미리보기를 생략한 큰 파일에서는 찾을 수 없다는 안내가 보여요.

#### 사용 방법

Review 목록이나 대화의 변경 파일 요약에서 파일을 열고 diff를 클릭한 뒤 대화 내 찾기 단축키(기본 Cmd+F, Windows는 Ctrl+F)를 누르세요. Enter로 다음 결과, Shift+Enter로 이전 결과로 이동하고 Esc로 닫아요. 대화 입력창에서 누르면 지금처럼 대화 내 찾기가 열려요.

### 프로필 메뉴에서 사용 문의와 카카오톡 문의를 할 수 있습니다

사이드바 아래 프로필 메뉴에 사용 문의가 생겼습니다. 웹과 같은 문의 창에서 이름, 이메일, 휴대폰 번호, 답변 받을 곳, 문의 내용과 화면 이미지(최대 3장)를 보내면 담당자에게 바로 전달됩니다. 문의 보내기 바로 아래의 카카오톡으로 문의하기를 누르면 Saycode 문의용 카카오톡 단톡방 초대 링크가 브라우저로 열립니다.

#### 사용 방법

사이드바 맨 아래 프로필 버튼을 누르고 사용 문의를 고릅니다. 사용 문의는 Saycode 계정으로 로그인했을 때 보이며, 이 컴퓨터에서 개인 사용 중일 때는 같은 자리에 카카오톡 문의가 보입니다.

### Claude 대화에서 실제 실행 계정 확인

Claude 대화의 입력창 아래에 실행 중인 조직 계정명을 표시합니다. 새 대화용 선택과 PC 기본 로그인을 구분하며, 확인되지 않은 계정은 확인 불가로 표시합니다. 잔여량 표시를 꺼도 계정명은 유지됩니다.

#### 사용 방법

Claude 대화를 열고 입력창 아래의 계정명을 확인하세요. 누르면 AI 사용량 창에서 계정별 상태를 볼 수 있습니다.

### Claude 대화의 권한 요청을 거절할 때 이유를 함께 보낼 수 있어요

Claude 대화에서 AI가 도구 사용 권한을 요청할 때, 거절하면서 이유를 함께 적어 보낼 수 있어요. 거절 이유는 AI에게 함께 전달돼요. 알림 센터·작업보드의 묶음 카드에서도 묶인 대화가 모두 Claude 대화면 같은 이유를 한꺼번에 보낼 수 있어요. Codex·opencode 같은 다른 AI 대화는 이유를 받을 수 없어 카드에 그렇다고 알려 줘요.

#### 사용 방법

권한 요청 카드의 허용·거절 버튼 아래 ‘이유를 적고 거절’을 펼친 뒤 이유를 적고 ‘이유와 함께 거절’을 누르세요. 칸을 비워 두면 기존 거절과 같아요.

### PR 파일 탭에서 읽은 파일을 이 PC에 표시해 둘 수 있습니다

앱 안 PR 화면의 파일 탭에서 파일마다 이 PC에서 읽음을 체크할 수 있습니다. 체크한 파일은 접히고 목록 위에 읽은 파일 수가 보입니다. 탭을 닫거나 앱을 다시 켜도 남아 있어 긴 PR을 읽다가 돌아와도 어디까지 봤는지 알 수 있습니다. 읽은 뒤 그 파일의 diff가 바뀌면 체크가 풀리고 읽은 뒤 바뀜으로 알려 줍니다. 표시는 이 PC에만 저장되며 다른 PC나 GitHub에는 반영되지 않습니다. PR이 병합되거나 닫히면 그 PR의 표시는 지워집니다.

#### 사용 방법

프로젝트 대화에서 GitHub PR 링크를 눌러 PR 화면을 열고 파일 탭을 누른 뒤, 다 읽은 파일 머리 오른쪽의 이 PC에서 읽음을 체크하세요.

## 변경된 기능

### "이슈 해결 → PR" 프리셋이 화면 변경 스크린샷을 PR에 첨부

"이슈 해결 → PR" 프리셋으로 시작한 자동 세션이 화면을 바꾸는 수정을 하면, 수정 전과 수정 후 화면을 같은 조건으로 찍어 PR 본문의 "화면 변경" 섹션에 나란히 넣습니다. 리뷰어와 이슈를 올린 사람이 코드를 받아 실행하지 않아도 고쳐진 화면을 PR에서 바로 확인할 수 있습니다. 화면과 관계없는 수정이면 이 섹션은 생기지 않고, 앱을 띄울 수 없어 찍지 못하면 그 사유가 PR에 남습니다. 이미지는 PR 변경 내역에 섞이지 않도록 별도 브랜치에 올라갑니다.

#### 사용 방법

프로젝트 설정 → 실행 → GitHub 트리거에서 "이슈 해결 → PR" 프리셋을 넣어 트리거를 만들면 적용됩니다. 이미 저장해 둔 트리거의 프롬프트는 바뀌지 않으므로, 기존 트리거에 적용하려면 편집에서 프리셋을 다시 넣고 저장합니다.

### 계획 승인 버튼 이름을 '작업 시작'으로 바꿨습니다

AI가 계획을 세우고 진행 여부를 물을 때 답변 아래와 계획 승인 창에 나오던 '개발 진행' 버튼의 이름을 '작업 시작'으로 바꿨습니다. 기획모드의 '작업 시작하기'와 같은 말로 맞춘 것이고, 누르면 하는 일은 이전과 같습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 계획 답변 아래의 '작업 시작' 버튼을 누르면 계획대로 개발과 검증을 시작합니다.

### 내 프롬프트 메뉴 간소화

내 프롬프트 메뉴의 저장 버튼 두 개(「이 프로젝트에 저장」·「모든 프로젝트에 저장」)를 「입력 저장」 하나로 합쳤습니다. 저장한 프롬프트는 「이 프로젝트」·「모든 프로젝트」로 나누지 않고 한 목록으로 보여주며, 메뉴 상단의 안내 문구도 없앴습니다. 새로 저장한 프롬프트는 모든 프로젝트에서 보이고, 예전에 프로젝트 전용으로 저장한 프롬프트는 그 프로젝트의 같은 목록에 그대로 남습니다.

#### 사용 방법

입력창에 문장을 쓰고 책갈피 아이콘을 누른 뒤 「입력 저장」을 누릅니다.

### 대화 더보기 메뉴에서 보관을 맨 위로, 보관 후 보관함 바로가기

사이드바 프로젝트 대화와 Chat의 더보기(점 세 개) 메뉴에서 가장 자주 쓰는 보관을 맨 위에 두고, 메뉴 이름을 알기 쉽게 바꿨습니다(대화 내용 복사, 대화 ID 복사, 대화 삭제). 대화 삭제는 구분선 아래로 분리했습니다. 프로젝트 대화를 보관하면 "대화를 보관했어요." 알림 옆에 보관함으로 이동 링크가 함께 보이고, 보관 확인창도 보관한 대화를 어디서 다시 열 수 있는지 알려 줍니다. 보관을 "완료로 이동"이라고 잘못 안내하던 문구도 고쳤습니다.

#### 사용 방법

사이드바에서 대화에 마우스를 올리고 점 세 개 버튼 → 보관을 누릅니다. 알림의 보관함으로 이동을 누르면 내 설정 > 보관된 대화가 열립니다.

### 대화 머리글의 브라우저 앱 연결 아이콘은 연결된 앱이 있을 때만 보여요

대화 오른쪽 위의 브라우저 앱 연결(링크 아이콘)은 그 대화에 철회되지 않은 앱 연결이 있을 때만 보입니다. 연결이 없거나 모두 철회했으면 아이콘이 사라집니다. 또 대화 오른쪽 위 AI 브라우저를 한 번 열어 이 작업PC의 브라우저 런타임이 작업별 승인 방식을 지원하지 않는다고 확인되면, 그 뒤로는 버튼에 경고 아이콘이 붙고 툴팁에서 미리 알려 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 연결 상태는 대화를 열 때와 응답이 끝날 때 다시 확인합니다. 런타임을 지원 버전으로 올린 뒤 AI 브라우저를 다시 열면 경고 표시가 사라집니다.

### 대화 보관 알림을 하나로, 완료 알림은 초록색으로

예약 메뉴를 개발자 기능 설정에서 분리했습니다. 예전에 메뉴를 숨겼더라도 펼친 사이드바와 접힌 막대에서 항상 볼 수 있습니다.

### 응답을 중단하면 그 응답이 실행 중이던 명령도 종료

프로젝트 대화의 응답을 중단하면, 중단한 응답(함께 중단된 자식 대화의 응답 포함)이 AI가 결과를 실시간으로 보여 주며 실행하던 명령도 종료합니다. 이전 응답이 띄워 둔 개발·미리보기 서버는 그대로 둡니다. 몇 개를 종료했는지(종료하지 못한 것이 있으면 그 수도) 자식 대화 중단 안내와 같은 줄에 남습니다. AI도구가 자체적으로 띄운 백그라운드 작업(Claude의 백그라운드 실행, Codex 백그라운드 터미널)은 종료하지 않습니다. 작업PC의 CLI가 이 정리를 지원해야 하며, 지원하지 않으면 이전과 같이 동작합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 끄려면 내 설정 → 개발 → 개발 자동화의 자식 대화에서 "응답을 중단하면 자식 대화도 중단"을 끕니다.

### 일괄 보관 알림이 같은 문구를 두 번 띄우지 않음

여러 대화를 골라 한 번에 보관하면 "대화 N개를 보관했어요." 문구가 되돌리기 알림과 결과 알림에 한 번씩, 두 번 보였습니다. 이제 보관한 개수는 되돌리기 알림에만 나옵니다. 결과 알림은 연결된 작업트리를 지웠거나 남겼을 때만 뜨고, "작업트리 N개를 삭제했어요."처럼 작업트리 결과만 알립니다. 보관하지 못한 대화가 있으면 그 개수도 같은 알림에 덧붙습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 입력창 위 PR 버튼에서 PR 상태와 CI 실패를 바로 볼 수 있습니다

작업트리 대화의 입력창 위 `PR #번호` 버튼에 PR 상태 배지가 붙습니다. 열린 PR은 초록 `열림`, 병합된 PR은 파란 `병합됨`, 머지 없이 닫힌 PR은 빨간 `닫힘`으로 표시됩니다. 열린 PR의 CI가 실패하면 빨간 `CI 실패` 배지로 바뀌고, CI가 도는 중이면 작은 회전 아이콘이, 자동 머지가 켜져 있으면 번개 아이콘이 붙습니다. `CI 실패` 배지에 마우스를 올리면 실패한 CI 작업 이름을 볼 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 상태는 앱이 PR을 확인한 뒤 나타나며, 버튼을 누르면 지금처럼 PR 화면이 열립니다.

### 작업 마무리 요청을 대화에서 한 줄로 표시

작업 마무리에서 보낸 Commit & PR·변경기록 남기기·셀프 리뷰(반복 라운드 포함) 요청이 대화에 긴 지시문 대신 `Commit & PR 브랜치 → main`, `셀프 리뷰 · 1/7 라운드` 같은 한 줄로 표시됩니다. 보내기 전에 문구를 고친 요청은 지금처럼 전체가 보입니다.

#### 사용 방법

한 줄 표시를 누르면 AI에 전달된 지시문 전체를 펼쳐 볼 수 있습니다. 메시지 복사에는 지시문 전체가 담기고, 대화 검색으로 찾으면 자동으로 펼쳐집니다.

### 작업 마무리를 입력창 위 메뉴에서 바로 실행

프로젝트 대화의 `작업 마무리`가 큰 창 대신 입력창 위 줄의 메뉴로 바뀌었습니다. 메뉴에서 셀프 리뷰, 독립 리뷰 요청, Commit & PR, 완료로 이동을 고르면 바로 실행됩니다. 지난 리뷰 결과는 `리뷰 기록`에서 볼 수 있습니다. `고급 설정…`에서는 셀프 리뷰 반복 횟수, 독립 리뷰어(AI·모델·작업 강도·리뷰 초점), 그리고 Commit & PR 요청과 완료 이동 전에 확인할지를 정할 수 있습니다. 설정은 이 PC의 계정별로 저장됩니다.

#### 사용 방법

프로젝트 대화를 열고 입력창 위 줄 오른쪽 끝, 커넥터(플러그) 아이콘 왼쪽의 로봇 아이콘을 누르세요. 쓸 수 없는 항목에는 이유가 함께 보입니다. 입력창 위 줄을 `저장소` 버튼으로 접으면 아이콘도 함께 숨겨집니다.

### 작업 패널 탭을 닫을 때 되돌리기 알림을 띄우지 않음

오른쪽 작업 패널의 터미널·브라우저·변경·파일·기획·PR 탭을 닫아도 "작업 패널 탭을 닫았어요." 알림이 더 이상 뜨지 않고, Cmd+Z(Windows는 Ctrl+Z)로 되살리지도 않습니다. 대화 탭 닫기·보관·고정의 되돌리기 알림은 그대로입니다.

#### 사용 방법

닫은 탭은 작업 패널 오른쪽 위 ⋮(작업 패널 추가) 메뉴에서 다시 여세요. 탭을 모두 닫아 패널이 접혔다면 도구 펼치기 버튼으로 먼저 여세요.

### 작업 PC에서 실행되는 예약도 답을 기다리는 대화 위에 회차를 쌓지 않고, 결과를 요약 카드로 보여 줍니다

예약 대화가 질문 답변이나 권한·계획 승인을 기다리는 동안에는, 작업 PC에서 실행되는 예약(서버 예약과 기존 대화에 이어 쓰는 예약 포함)도 다음 회차를 실행하지 않고 건너뜁니다. 실행 이력에는 `답변·승인 대기 중이라 건너뜀`으로 남고, 대기가 시작된 회차에는 받은편지함에 알림이 한 번 옵니다. 알림을 누르면 기다리는 대화가 열려 바로 답할 수 있습니다.

회차마다 새 대화를 여는 예약은 실행이 끝나면 받은편지함 카드에 AI가 남긴 결과 제목과 요약이 보입니다. 같은 대화에 이어 쓰는 예약은 대화에 등록한 요청 그대로 보이도록 요약을 요청하지 않아, 지금처럼 일반 대화 알림으로 남습니다.

이 동작에는 작업 PC의 실행 도구 업데이트가 필요합니다. 업데이트 전에는 달라지는 것이 없습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 저장소가 없는 프로젝트도 입력창 위에서 연결 상태와 다음 할 일을 보여 줘요

기획으로 만든 프로젝트처럼 코드 저장소가 아직 연결되지 않은 프로젝트에서는 입력창 위 저장소 바가 비어 있거나 새 대화에서 아예 보이지 않았어요. 이제 새 대화와 기존 대화 모두 바에 "저장소 연결 안 됨"을 표시하고, 상황에 맞는 버튼 하나를 함께 보여 줘요. 저장소가 없으면 "저장소 연결하기", 작업 PC 폴더만 원격 저장소에 연결돼 있으면 "Saycode에 연결하기", 상태 확인에 실패하면 "다시 확인"이 나와요. 연결하지 않아도 대화와 미리보기는 그대로 쓸 수 있어요.

#### 사용 방법

입력창 위 저장소 바에서 "저장소 연결하기"나 "Saycode에 연결하기"를 누르면 프로젝트 설정의 코드 저장소 화면이 열리고, 바로 입력할 칸에 커서가 놓여요. "다시 확인"을 누르면 작업 폴더 상태를 다시 읽어요. 연결과 생성 버튼은 프로젝트를 만든 사람에게만 보여요.

### 접어 둔 저장소 바가 다른 대화에서도 접힌 채 유지돼요

입력창의 '저장소' 탭으로 저장소 바를 접으면, 다른 대화로 옮기거나 새 대화를 열거나 앱을 다시 켜도 접힌 상태가 유지돼요. 예전에는 대화를 옮길 때마다 다시 펼쳐졌어요.

#### 사용 방법

입력창 위쪽 테두리의 '저장소' 탭을 눌러 바를 접거나 펼쳐요. 한 번 정한 상태가 이 기기의 모든 대화에 적용돼요.

### 첨부와 결과물의 파일 정보를 보기 쉽게 맞췄어요

긴 파일명은 확장자를 남기며 줄여 표시하고 전체 이름은 마우스를 올려 확인할 수 있습니다. 첨부·준비 중인 요청·보낸 파일·AI 결과물의 글자, 아이콘과 작은 버튼의 크기·간격을 맞췄습니다.

#### 사용 방법

### 커넥터 상태 아이콘이 입력창의 '저장소' 탭 옆으로 옮겨졌어요

입력창 위 저장소 바 오른쪽 끝에 있던 플러그 모양의 커넥터 상태 아이콘을, 입력창 위쪽 테두리의 '저장소' 탭 바로 옆 작은 탭으로 옮겼어요. 저장소 바에는 저장소 관련 정보와 작업 마무리만 남아요. 저장소 바를 접어도 커넥터 탭은 계속 보여요.

#### 사용 방법

입력창 위쪽 테두리에서 '저장소' 탭 오른쪽의 플러그 탭을 누르면 지금처럼 커넥터 연결 상태 창이 열려요. 확인이 필요한 커넥터가 있으면 플러그가 빨간색으로 보여요.

### 커넥터 연결 상태를 입력창 옆에서 확인

MCP 연결 상태와 복구 창을 웹처럼 작은 팝오버로 바꿨습니다. 커넥터 이름 옆에서 상태를 확인하고, 저장소 계정 연결을 별도로 볼 수 있습니다. 확인된 실패 커넥터는 하단에서 다시 연결하며, 인증 필요·상태 미확인은 연결 완료와 구분합니다.

#### 사용 방법

프로젝트 대화의 입력창 위 플러그 아이콘을 누르세요. 하단 재연결은 응답 중이 아닌 Claude 대화에서 작업PC가 온라인이고 재인증이 필요 없는 실패 커넥터가 있을 때 활성화됩니다. 다른 MCP 진단은 고급 영역에서 확인할 수 있습니다.

### 코드 저장소 설정에서 작업PC의 git 연결 상태를 확인할 수 있습니다

프로젝트 설정의 코드 저장소 화면이 작업PC 폴더의 git origin과 현재 브랜치를 함께 보여 줍니다. 이미 origin이 연결된 폴더인데 Saycode 저장소 연결이 없으면, 빨간 "저장되지 않음" 대신 "로컬 git 연결됨 · Saycode 저장 미설정"으로 표시합니다. 브랜치는 항상 `main`으로 보이지 않고 실제 현재 브랜치를 표시합니다. Saycode 저장소와 origin이 서로 다르면 안내 문구를 보여 주고, 기존 저장소 검색 칸에 origin 저장소 이름을 미리 채워 둡니다. 화면을 여는 것만으로 저장소가 연결되거나 바뀌지는 않습니다.

#### 사용 방법

프로젝트 설정 → 개발 → 코드 저장소를 여세요. 작업PC가 연결되어 있어야 로컬 git 정보를 확인할 수 있습니다. Saycode로도 코드를 저장하려면 미리 채워진 이름으로 검색해 저장소를 고른 뒤 연결하세요.

### 파일 목록 탐색 방식과 정렬 통일

프로젝트 파일과 추가 디렉터리, 변경 파일의 행 정렬을 맞추고 키보드로 파일을 열지 않은 채 이동할 수 있게 했습니다.

#### 사용 방법

### 패널 경계와 크기 조절을 일관되게 맞췄어요

#### 사용 방법

별도 설정 없이 적용됩니다.

### 프로젝트 대화 더보기(⋮) 메뉴 정리

프로젝트 대화 오른쪽 위 세로 점 세 개 메뉴를 짧고 읽기 쉽게 정리했습니다. 묶음 제목 대신 구분선으로 작업 패널 열기, 이 대화, 프로젝트 세 묶음으로 나눴고, 모든 줄이 같은 크기의 아이콘과 글자로 보입니다. 작업 패널 이름은 오른쪽 탭과 같은 `파일`·`터미널`·`브라우저`·`변경`·`미리보기`로 바꿨습니다. Git과 프로젝트 공유는 `Git 작업`·`프로젝트 공유` 줄 오른쪽에 지금 브랜치와 공개 범위가 보입니다. 이 대화 알림 소리를 끄거나 켜면 메뉴가 닫히고 결과를 알려 줍니다.

다른 곳에 이미 있는 항목은 메뉴에서 뺐습니다. 모든 대화는 사이드바 프로젝트 줄의 더보기에서, 대화 닫기는 탭의 X나 Cmd+W로, 보관과 대화 내용 복사는 사이드바 대화의 더보기에서, 프로젝트 메모리 관리는 내 설정 > 메모리에서 할 수 있습니다. 파일 접근 상태 안내 카드도 메뉴에서 뺐습니다.

#### 사용 방법

프로젝트 대화 머리글 오른쪽의 세로 점 세 개 버튼을 누르세요.

### 프로젝트 메뉴를 정리하고 '모든 대화' 화면을 간결하게 바꿨습니다

사이드바 프로젝트 옆 더보기(세로 점 세 개) 메뉴에서 '대화 목록 접기/펼치기'를 뺐습니다. '최근 대화'는 실제로 그 프로젝트의 대화를 모두 보여 주므로 '모든 대화'로 이름을 바꿨습니다.

'모든 대화' 화면도 정리했습니다. 위쪽의 소스·브랜치·작업PC 같은 기술 정보 줄과 대화마다 붙던 AI 이름 표시를 없애고, 제목 아래에 대화 개수만 짧게 보여 줍니다. 영어로 나오던 문구와 버튼 설명을 한국어로 바꿨고, 고정·완료로 이동·삭제 버튼은 대화에 마우스를 올리거나 키보드로 이동했을 때 나타납니다(고정한 대화의 핀은 항상 보입니다). 검색 안내는 검색할 때만 나옵니다.

#### 사용 방법

사이드바에서 프로젝트 이름 옆 더보기를 누르고 '모든 대화'를 고릅니다. 대화 목록을 접거나 펼치려면 프로젝트 이름을 누릅니다.

### 프로젝트 설정을 간단하게 편집

이름과 설명을 한 줄에서 각각 저장·취소할 수 있습니다. 태그·색상은 맨 아래로 모으고 공개 범위는 프로젝트 공유 메뉴에서 관리합니다. 공유·환경변수·SSO의 중복 적용 단계를 줄이고, 함께 작업의 PC 준비 안내를 정리했습니다. 프로젝트 삭제는 표준 확인창을 사용합니다.

#### 사용 방법

프로젝트 설정에서 이름·설명 옆 저장을 누르세요. 태그·공유·시작 옵션은 선택하면, 색상은 입력 후 다른 곳을 누르면 적용됩니다. 전체 환경변수 편집은 변경사항 적용으로 저장합니다. 전용 PC의 초대는 PC 공유 설정에서 먼저 준비하세요. 삭제 확인창에서 취소하면 삭제하지 않습니다.

### 프로젝트 설정의 반복 안내와 적용 단계 줄이기

함께 작업에서 팀을 선택하거나 해제하면 바로 저장되고, 실패하면 같은 선택으로 다시 시도할 수 있습니다. 시작 옵션의 반복 설명을 줄이고 Electron 버전은 개발 정보로 옮겼습니다. 삭제 확인은 유지합니다.

#### 사용 방법

프로젝트 설정의 함께 작업에서 팀 체크박스를 선택하세요. 별도 팀 적용 버튼은 없습니다. 실패하면 다시 시도를 누르세요. Electron 버전은 개발 → 개발 정보에서 확인할 수 있습니다.

### 호버·선택 색상과 아이콘 버튼 모양 통일

화면 전반의 마우스 호버는 흰 배경에서 아주 옅은 회색, 회색 배경에서 흰색으로 맞추고, 선택한 항목은 옅은 파랑으로 통일했습니다. 단일 아이콘 버튼의 배경을 둥글게 맞추고 같은 영역의 버튼 크기와 정렬을 정리했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### AI 사용량 창을 AI별 탭으로 나눠 봅니다

AI 사용량 창이 Claude·Codex·Grok의 사용량과 계정을 한꺼번에 길게 펼치지 않고, 창 맨 위 작업PC 줄(이름·조회 시각·새로고침) 아래의 AI 탭으로 나눠 보여 줍니다. 탭마다 그 AI의 모든 PC 요약, 이 작업PC의 계정 목록, 자동 전환 안내만 나옵니다. 창을 열면 지금 쓰고 있는 AI의 탭이 먼저 열립니다.

#### 사용 방법

입력창 아래 AI 사용량 버튼을 누르면 입력창에서 고른 AI(진행 중인 대화는 그 대화의 AI) 탭이 열려 있고, 다른 AI는 작업PC 줄 아래 탭을 눌러 봅니다. 고른 AI가 없으면 첫 탭이 열리고, AI가 하나뿐이면 탭이 없습니다.

### Chat 더보기 메뉴를 프로젝트 메뉴처럼 정리했어요

Chat 대화 오른쪽 위 더보기(⋮) 메뉴가 프로젝트 대화의 메뉴와 같은 모양·순서로 바뀌었어요. 작업 패널, 이 대화, 프로젝트 묶음을 구분선으로만 나눠요. 여기서 바로 대화를 고정하거나 이 대화의 알림 소리만 끌 수 있어요. 같은 곳을 열던 두 번째 `파일`, 메뉴 안에 입력칸이 펼쳐지던 `이름 바꾸기`, Chat에서 쓸 수 없는 `미리보기`는 메뉴에서 뺐어요. 이름은 사이드바 Chat의 더보기 메뉴나 제목을 두 번 눌러 바꿀 수 있어요. `예약 작업`이나 `프로젝트로 전환` 창을 닫으면 더보기 버튼으로 돌아와요.

#### 사용 방법

Chat 대화를 열고 오른쪽 위 더보기(⋮)를 누르세요. `대화 고정`, `이 대화 알림 소리 끄기`, `예약 작업`, `프로젝트로 전환`이 있어요.

### CLI 업데이트 확인이 늦어질 때 다음에 할 일을 안내합니다

Aplus CLI 업데이트 창에서 머신을 업데이트하면 설치와 재시작에 1~2분 걸릴 수 있다고 함께 보여 줍니다. 새 버전 확인은 30초가 아니라 약 3분 동안 기다립니다. 재시작 때문에 PC가 잠깐 오프라인이 되어도 목록에서 사라지지 않습니다. 3분 안에 확인되지 않으면 빨간 '확인 시간 초과' 대신 '아직 새 버전이 확인되지 않았어요'와 그 이유를 보여 줍니다. 버튼은 설치를 다시 요청하지 않는 '다시 확인'입니다. 다시 확인했는데도 예전 버전이면 '업데이트되지 않았어요'와 '다시 업데이트'를 보여 줍니다. 'PC에서 직접 업데이트하는 방법'을 펼치면 터미널 명령을 복사할 수 있습니다. 요청 자체가 실패하면 '업데이트 요청을 보내지 못했어요'로 따로 알려 줍니다.

#### 사용 방법

사이드바의 CLI 업데이트 알림이나 업데이트 창에서 머신의 '업데이트'를 누릅니다. 확인이 늦어지면 잠시 뒤 '다시 확인'을 누르고, 그래도 안 되면 'PC에서 직접 업데이트하는 방법'의 명령을 복사해 그 PC의 터미널에서 실행합니다.

### Codex 대화의 / 명령 목록이 Codex에 맞게 바뀜

Codex 대화나 새 대화에서 Codex를 고른 뒤 입력창에 /를 치면, Codex에서 실제로 쓸 수 있는 명령만 보입니다. /clear·/goal과 설치된 Codex 스킬, Saycode 명령이 보이고, Claude에서만 되는 /compact·/model 같은 Claude Code 명령과 /btw·/recap·/skills·/mcp는 더 이상 보이지 않습니다.

#### 사용 방법

입력창 아래 AI도구 버튼에서 Codex(Chat에서는 ChatGPT)를 고르거나 Codex 대화를 연 뒤 빈 입력창에 /를 입력하세요. AI 자동을 고르면 지금처럼 Claude 기준 목록이 보입니다.

### Commit & PR을 중간 창 없이 바로 요청

작업 마무리 메뉴에서 `Commit & PR`을 누르면 요청 편집 창 없이 현재 대화의 AI에게 바로 요청합니다. 고급 설정의 Commit & PR 전송 전 확인 옵션은 제거했으며, 기존 설정에도 자동 적용됩니다. 전송에 실패하면 화면 위 알림으로 안내합니다.

#### 사용 방법

프로젝트의 작업트리 대화에서 입력창 위 로봇 아이콘(작업 마무리)을 누르고 `Commit & PR`을 선택하세요. 원격 저장소가 없으면 `변경기록 남기기`로 표시되며 커밋만 요청합니다.

### Quick Commands 팝오버 제목을 "내 프롬프트"로 변경

입력창 책갈피 버튼의 팝오버 제목이 "자주 쓰는 프롬프트"에서 "내 프롬프트"로 바뀝니다. 저장한 항목과 사용 방법은 그대로입니다.

#### 사용 방법

입력창의 책갈피 아이콘(Quick Commands)을 누르면 "내 프롬프트" 목록이 열립니다.

## 수정된 문제

### 개발 서버 명령 저장 수정

프로젝트 실행 설정에서 개발 서버 명령을 바꿔 저장해도 이전 값으로 돌아가던 문제를 수정했습니다. 실제 실행 서비스의 명령과 포트를 읽고 저장합니다.

#### 사용 방법

프로젝트 설정 → 개발 → 실행에서 명령과 포트를 수정하고 실행 설정 저장을 누르세요. 설정을 다시 열어 저장한 값을 확인할 수 있습니다.

### 고정 핀의 선택 배경 제거

사이드바와 홈 프로젝트 카드에서 고정된 핀 뒤에 파란 원형 배경이 표시되지 않도록 수정했습니다. 고정 상태는 채워진 핀 아이콘으로 구분하며 키보드 포커스는 그대로 표시합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 기존처럼 핀을 눌러 고정하거나 해제하세요.

### 관리형 실행 환경에서도 다른 대화 내용을 안전하게 가져옵니다

대화에서 다른 대화 내용을 읽어 오라고 하면 Desktop이 요청한 작업PC에 대화 파일을 만들어 줍니다. 지금까지는 관리형 실행 환경에서 이 파일을 만들지 못했고, 실패하면 이유와 상관없이 같은 오류만 보였습니다.

이제 요청한 대화가 직접 파일을 만들어 관리형 실행 환경에서도 동작합니다. 파일은 그 대화의 작업 폴더 안에 새 파일로만 만들고, 링크된 경로나 이미 있는 파일은 건드리지 않습니다. 일부 대화 파일을 만들지 못해도 나머지와 목록 파일은 만들고, 목록에 그 이유를 적습니다. 알림은 이미 만들어진 파일, 링크된 경로, 관리형 환경의 이전 대화, 작업PC 업데이트 필요, 작업PC 미연결, 파일 접근 범위 밖의 작업 폴더를 구분해 알려 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 관리형 실행 환경에서 이전 대화라는 안내가 보이면 새 대화에서 다시 요청하세요.

### 내가 보낸 말풍선에서 선택한 글자가 보입니다

내가 보낸 말풍선의 글자를 마우스로 선택하면 선택한 부분이 옅은 바탕 위의 흰 글자로 바뀌어 읽을 수 없었습니다. 이제 선택한 글자는 진한 색으로 표시되어 어디까지 선택했는지 바로 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 내가 보지 않는 남의 대화에는 "응답 지연" 알림을 띄우지 않습니다

함께 작업하거나 공유받은 프로젝트에서 다른 사람이 돌리는 대화가 90초 넘게 조용하면, 그 대화를 열어 보지 않았는데도 "AI가 90초째 새 응답을 보내지 않고 있어요" 알림이 뜨던 문제를 고쳤습니다. 이제 이 알림은 내 대화(내가 만든 대화, 개인 채팅, 이 컴퓨터에서 보낸 요청)나 지금 화면에 열어 둔 대화에만 뜹니다. 완료 알림을 받는 대화와 같은 기준입니다. 10분 동안 응답이 없어 기다리기를 멈췄다는 경고도 같은 기준으로만 뜹니다. 알림 없이 넘긴 대화도 나중에 열었을 때 여전히 멈춰 있으면 그때 한 번 알려 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 다른 창에서 답한 질문이 대화 기록에서도 끝난 상태로 보입니다

같은 대화를 두 창(또는 다른 기기)에 열어 두고 한쪽에서 AI 질문에 답하면, 답하지 않은 창의 대화 기록에는 그 질문이 계속 "답변 대기 중"과 선택지·제출 양식으로 남던 문제를 고쳤습니다. 이제 답하지 않은 창에서도 그 질문은 "답변 제출됨"으로 바뀌고 양식이 사라집니다. 답이 없이 끝난 질문(중지·턴 종료 등)은 "이 요청은 이미 끝났어요"로 보입니다. 승인 기록이 많이 쌓인 긴 대화에서 지난 턴에 끝난 질문도 다른 기기나 새 창에서 다시 양식으로 돌아오지 않습니다. 그 질문 때문에 입력창 위 질문 화면이 다시 뜨거나 탭에 "입력 대기"가 남는 일도 없습니다. 답한 창에서는 지금처럼 고른 답이 함께 보입니다.

#### 사용 방법

### 다른 창에서 질문에 답한 뒤에도 작업 중 표시가 보입니다

작업PC의 실행기가 도구 사용 규칙, 예약 작업 지원, 에이전트 브라우저, 파일 저장 확인처럼 제공하는 기능을 바꿔 알려도, 지금까지는 최대 1분 뒤 작업PC 목록을 다시 불러올 때에야 화면에 반영됐습니다. 이제 실행기가 알리는 즉시 반영됩니다. 예를 들어 실행기를 도구 사용 규칙을 끄고 다시 시작하거나 예약 작업 지원이 바뀌면, 1분 새로고침을 기다리지 않고 그 작업PC의 표시와 선택지가 바로 바뀝니다. 작업PC 이름·운영체제·홈 폴더·실행 도구 버전은 지금처럼 작업PC 목록 기준을 유지해 표시가 오락가락하지 않습니다.

### 첫 메시지 위에 '이전 대화' 버튼이 잘못 뜨거나 눌러도 아무것도 나오지 않던 문제를 고쳤습니다

#### 사용 방법

### 필수 샌드박스 세션의 에이전트 위임 안내와 보호 강화

필수 샌드박스 세션에서 에이전트 제어를 중계하는 broker가 없어 자격증명을 읽지 못하면, 자격증명 문제 대신 broker가 없다는 원인과 복구 방법을 안내합니다. 또한 자식 에이전트에 샌드박스를 유지할 수 없는 위임 요청을 거부합니다. 필수 샌드박스에서는 Claude·Codex만 위임 대상으로 허용하며, 전달할 샌드박스 정책이 없거나 잘못되었거나 꺼져 있으면 이들에게도 위임하지 않습니다.

#### 사용 방법

### AI 심사가 대화의 현재 권한을 보고 판단

AI 심사는 이 기기가 마지막으로 보낸 권한만 기억했기 때문에, 그 뒤 모바일·다른 PC·터미널에서 대화의 권한을 바꿔도 계속 심사했고, AI 심사를 끈 뒤에는 yolo로 만들어진 Codex 대화만 원래 권한으로 되돌렸습니다. 이제 대화가 실행되는 PC가 현재 권한을 알려 주면 그 값을 봅니다. 다른 기기나 앱이 권한을 바꾼 대화는 심사하지 않고 끌 때도 그대로 두며, Codex 대화는 AI 심사로 바꾸기 직전의 권한(전체 허용·읽기 전용·확인 요청)으로 돌아갑니다. 현재 권한을 알려 주지 않는 이전 버전의 PC에서는 지금처럼 동작합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. PC 쪽 런타임이 현재 권한을 알려 주는 버전으로 업데이트되면 효과가 납니다.

### AI가 응답을 시작하지 않거나 기다리기를 멈추면 경고가 남습니다

이 앱에서 보낸 메시지에 AI가 90초 동안 아무것도 보내지 않으면, 8초 뒤 사라지던 "계속 기다릴게요" 안내 대신 "AI가 응답을 시작하지 않았어요" 경고가 닫을 때까지 남습니다. 작업PC가 앞선 작업(백그라운드 명령 등)이 끝나기를 기다리는 중일 수 있다는 안내도 함께 보입니다. AI가 응답을 시작하면 경고는 저절로 사라집니다. 10분 동안 새 응답이 없어 기다리기를 멈출 때도 이전처럼 조용히 끝내지 않고 그 사실을 알려 줍니다. 이미 응답하던 중 빌드·테스트처럼 오래 걸리는 작업으로 조용해진 경우에는 이전과 같은 안내가 나옵니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 경고의 자세히에서 기다리는 시간과 응답을 멈추는 방법을 확인할 수 있습니다.

### AI가 질문하면 작업보드 "입력 대기"에 표시

AI가 대화에서 질문(선택지 질문·계획 승인·권한 요청)을 띄워도 작업보드의 "입력 대기" 칸에 나타나지 않고 응답 중으로 남던 문제를 수정했습니다. 이제 앱이 대화 상태를 다음에 다시 불러올 때 답을 기다리는 대화가 "입력 대기" 칸으로 옮겨지고, 대화 탭의 입력 대기 배지와 사이드바 대화 상태에도 함께 표시됩니다. 그 사이 들어오는 실시간 갱신이 선택지 질문·계획 승인 표시를 지우지도 않습니다. 질문이 생기는 순간 바로 옮겨지는 실시간 반영은 별도 수정으로 이어집니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

#### 사용 방법

### Windows에서 드라이브 문자 대소문자가 달라도 AI 심사가 작업 폴더 기준으로 실행

별도 설정 없이 자동 적용됩니다.
