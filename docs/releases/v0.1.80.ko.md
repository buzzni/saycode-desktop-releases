## 새 기능

### 개인 Claude 계정을 목록에서 직접 선택

계정 선택 창에서 조직 계정 아래에 개인 계정 영역을 따로 표시하고, 개인 계정 제목 옆의 작은 회색 문구로 나만 사용할 수 있는 계정임을 안내합니다. 개인 사용이 허용돼 있으면 사용할 계정을 직접 선택해 새 대화에 적용하거나 같은 기존 대화에서 이어갈 수 있습니다. 직접 고른 계정은 유지되며 조직 계정으로 돌아갈 수도 있습니다. 계정 확인 실패는 다시 시도할 수 있고, 계정이 목록에서 사라져도 조직 복귀가 가능합니다. 개인 사용을 해제하면 실행 전 선택도 지워집니다. 사라진 계정의 오래된 선택은 해제하고 다시 고르도록 안내하며 새로운 선택은 보존합니다.

#### 사용 방법

입력창 아래 AI 사용량 → Claude → 개인 계정 → 계정 행 → 개인 계정 선택을 누릅니다. 확인창에서 개인 사용량 차감과 적용 범위를 확인하세요. 이 컴퓨터의 본인 전용 PC와 새 기능을 지원하는 앱·CLI·서버가 필요합니다.

### 공개 링크 확장이 없어도 결과 파일에서 바로 설치하고 링크 만들기

공개 링크 확장을 아직 설치하지 않았어도 AI가 만든 HTML 결과 파일 옆에 `공개 링크` 버튼이 보입니다. 누르면 필요한 권한과 공개 범위를 알려 주고, `설치 진행` 한 번으로 확장 설치·권한 허용·켜기와 링크 만들기까지 이어서 진행합니다. 확장이 다른 권한도 요청하면 자동으로 허용하지 않고 설정 화면에서 확인하도록 안내합니다.

#### 사용 방법

HTML 결과 파일의 `PC에 저장` 옆 `공개 링크`를 누른 뒤 `설치 진행`을 누르세요.

### 공개 링크를 조직 구성원만 보게 하거나 기간을 정해 닫을 수 있습니다

AI가 만든 HTML 결과물의 공개 링크 창에서 공개 범위와 만료를 정할 수 있습니다. 새 링크는 지금처럼
링크가 있는 누구나 열 수 있고, 공개 범위에서 조직만을 고르면 현재 작업 조직 구성원이 로그인해야 열립니다.
다른 내 조직을 더하거나 뺄 수 있고, 조직만에서 누구나로 되돌릴 때는 한 번 더 확인합니다. 만료를 1일·3일·
7일·30일로 정하면 그때까지만 열리고 이후에는 찾을 수 없는 링크가 됩니다. 링크 주소는 바뀌지 않습니다.

#### 사용 방법

AI 답변에 붙은 HTML 결과물 옆의 링크 아이콘을 눌러 공개 링크 창을 연 뒤 공개 범위와 만료를 고르세요.
조직만은 속한 조직이 있을 때만 고를 수 있습니다. 서버가 이 기능을 지원하기 전에는 두 항목이 보이지 않습니다.

### 대화에서 허용한 앱을 30분이 지나기 전에 거둘 수 있습니다

Desktop에 내장된 Happy 런타임을 `.364`로 갱신했습니다. 이 런타임은 대화에서 "이 대화에서 허용"을 고른 앱의 실제 허용 목록을 알려 주고 거두기 요청을 받습니다. 그래서 설정 ▸ 보안 ▸ AI 도구 사용 규칙의 "이 대화에서 허용한 앱"에 런타임이 실제로 들고 있는 허용과 거두기 버튼이 보입니다. 거두면 그 앱은 다음 사용부터 다시 확인을 받습니다. 지금까지는 대화가 끝나거나 허용한 뒤 30분이 지나야 다시 확인했습니다.

이전 런타임으로 계속 실행 중인 대화나 관리형 실행 대화는 지금처럼 이 창에서 허용한 앱과 만료 안내만 보여 줍니다.

#### 사용 방법

내 설정 → 일반 → 보안 → AI 도구 사용 규칙 → 이 대화에서 허용한 앱에서 거둘 앱의 거두기를 누릅니다. 이 변경을 포함한 Desktop 업데이트를 설치한 뒤 새로 실행된 대화부터 적용됩니다. 원격 작업 PC는 그 PC의 런타임이 .364 이상으로 업데이트된 뒤부터 적용됩니다.

### 보내기 전 초안 카드에 받는 곳과 첨부가 보입니다

AI가 메일이나 메시지를 보내기 전에 보여 주는 초안 카드에 받는 곳·참조·숨은 참조·첨부가 제목 위에 따로 표시됩니다. 메신저·채널 게시글은 `메시지 초안` 카드로 나옵니다. `본문 복사`는 지금처럼 본문만 복사합니다. 내 설정의 기본 지시 세부 설정에 `발송 초안 카드` 항목이 생겼고, 기본으로 켜져 있어 AI가 이 형식으로 초안을 씁니다.

#### 사용 방법

AI에게 메일이나 메시지 초안을 부탁하거나 보내 달라고 하면, 보내기 전에 받는 곳과 첨부가 표시된 카드를 보고 확인할 수 있습니다. 이 안내를 끄려면 내 설정 → 일반 → 시스템 프롬프트 → 기본 지시 세부 설정에서 `발송 초안 카드`를 끕니다.

### 브라우저 작업 공간 관리와 자동 사용 한도

브라우저 콘솔에서 사용이 끝난 작업 공간을 닫고 진행 중인 작업을 중지할 수 있습니다. 지원 런타임은 머신과 브라우저 컨테이너의 자원 여유에 맞춰 사용 한도를 자동 조정합니다. 수동 상한도 안전 한도 안에서 적용되며 기존 공간을 강제 종료하지 않습니다. 공간 한도 오류에는 관리 진입과 원래 요청을 확인한 뒤 재전송하는 기능을 제공합니다.

#### 사용 방법

지원 서버·런타임·브라우저 이미지가 필요합니다. 대화의 AI 브라우저 → 작업 공간에서 목록을 확인하고 닫기 또는 작업 중지를 누릅니다. 사용 한도 설정에서 자동 또는 직접 상한 지정을 고르고 적용을 누릅니다. 공간 생성 한도 오류에서는 작업 공간 관리 후 원래 요청 다시 보내기 → 원문·실행 결과 확인 → 이 요청 보내기를 누릅니다. 이 변경 자체는 설치판 업데이트나 컨테이너 자원 증설을 수행하지 않습니다.

### 브라우저에서 고른 요소에 컴포넌트와 소스 위치가 붙습니다

앱 브라우저에서 요소를 고르면, 요소 선택 검사 권한을 허용한 확장이 그 요소를 그린 컴포넌트 이름과 파일·줄을 알려 줍니다. 주석 트레이 행 아래에 `컴포넌트 · 파일:줄`로 보이고, AI에게 보내는 요청 글에 `Source:` 줄로 들어가 AI가 고칠 파일을 바로 찾습니다. React 앱은 saycode-extensions의 React source locator 확장이 이 일을 합니다. 확장이 없거나 권한을 허용하지 않으면 지금과 같습니다.

#### 사용 방법

내 설정의 확장 관리에서 요소 선택 검사 확장을 설치하고 `요소 선택 검사` 권한을 허용한 뒤 켭니다. 프로젝트 대화의 앱 브라우저에서 개발 서버로 띄운 앱을 열고 요소 선택 버튼으로 요소를 고르면 트레이 행 아래에 소스 위치가 나타납니다. 권한을 철회하면 다음 선택부터 붙지 않습니다.

### 외부 연동 — DirectCloud, 커스텀 커넥터, 조직 MCP 개별 로그인

외부 연동에 DirectCloud가 추가되었습니다(서버에서 켜진 경우에만 보입니다). 회사 DirectCloud의 파일·폴더를 AI가 찾고 요약할 수 있습니다.

외부 연동에 "커스텀 커넥터"가 생겼습니다. OAuth 로그인을 지원하는 MCP 서버를 주소로 직접 추가해 연결할 수 있고(서버에서 켜진 경우), 조직이 개별 로그인으로 등록한 MCP 는 여기서 각자 로그인·로그아웃합니다. 프로젝트 설정의 MCP 탭은 개별 로그인 MCP 에 내 로그인 상태와 로그인 버튼을 보여 줍니다.

#### 사용 방법

DirectCloud는 외부 연동 → DirectCloud → 연결에서 브라우저로 로그인합니다. 커스텀 커넥터는 외부 연동 → 커스텀 커넥터 → + 로 이름과 MCP 주소를 넣어 추가한 뒤 연결하고, 조직 MCP 는 같은 곳이나 프로젝트 설정 → MCP 서버의 로그인을 누릅니다.

### 외부 연동에서 Figma 디자인 편집 연결

외부 연동의 Figma 항목에서 작업 PC의 Claude Code와 Codex에 Figma 공식 MCP를 연결하고 Figma 계정으로 허용할 수 있습니다. 연결한 PC의 새 대화에서는 AI가 Figma에 프레임과 화면을 직접 만들고 고칠 수 있습니다. 항목에는 이 컴퓨터의 AI별 상태(사용 가능·로그인 필요·설치 안 됨)가 보이고, 설정 창에서 다른 작업 PC를 골라 확인할 수 있습니다. 이전의 Figma 계정 연결(파일 읽기 전용)은 이 방식으로 바뀌었습니다.

#### 사용 방법

사이드바의 외부 연동에서 Figma 줄의 연결 버튼을 누르고, 작업 PC를 고른 뒤 Claude Code 또는 Codex 줄의 연결하기를 누릅니다. 브라우저에 열린 Figma 화면에서 허용을 누르면 됩니다. 다른 PC를 연결할 때는 허용한 뒤 주소창의 주소를 설정 창에 붙여 넣습니다. 연결 후 새로 연 대화부터 적용됩니다. AI 로그인은 다시 하지 않습니다.

### 외부 폴더 HTML 미리보기 접근 허용

프로젝트 밖 HTML 미리보기가 차단되면 폴더 읽기를 확인한 후 볼 수 있습니다. 허용은 현재 열린 대화의 파일 읽기에만 적용되며 AI 실행·쓰기 권한은 바뀌지 않습니다.

#### 사용 방법

차단된 HTML의 접근 허용을 누르고 폴더 경로를 확인한 뒤 읽기 허용을 누르세요. 미리보기가 자동으로 표시됩니다. 취소하면 읽지 않으며 대화를 닫으면 허용이 끝납니다.

### 유료 AI 계정 없이 무료 모델로 시작하기

Claude나 ChatGPT 유료 계정이 없어도 opencode를 이 컴퓨터에 설치해 무료 모델로 대화할 수 있어요. 설치 전에 설치 위치와 무료 모델의 조건(기간 한정, 모델마다 다른 입력 보관·학습 정책, 유료보다 낮을 수 있는 성능)을 보여 주고, 확인한 뒤에만 설치해요. 유료 AI가 있는 사용자도 함께 설치해 두고 대화마다 골라 쓸 수 있어요.

#### 사용 방법

시작준비 AI 단계의 `무료 모델로 시작하기`, 내 AI 계정 연결 창의 `무료 모델 (opencode)`, 또는 내 설정 → AI Models → opencode 행의 … 메뉴 → `설치하기`에서 시작해요. 준비가 끝나면 새 대화의 AI도구에서 Opencode를 골라요(유료 AI 없이 시작했다면 이미 골라져 있어요). Model을 고르지 않으면 메시지마다 추천 무료 모델이 쓰이고, Model 메뉴에는 무료 모델이 `무료`·`추천 무료` 표시와 함께 보여요. 쓸 무료 모델이 없으면 보내지 않고 다시 확인하라고 알려 줘요. 조직이 AI 모델을 제한하면 설치할 수 없고, Windows 시험판에서는 보이지 않아요.

### 이 PC에서 AI 브라우저를 바로 준비

개인 PC에서는 별도 설치 파일이나 명령어 없이 AI 브라우저를 준비할 수 있습니다. 로그인한 사용자 권한으로 개인 Chrome과 분리된 전용 프로필을 쓰며, 개인 Chrome의 쿠키·방문 기록은 가져오지 않습니다. 준비된 PC에서는 에이전트가 페이지를 열 때만 브라우저 창이 나타납니다. 이 PC에 Chrome이 없으면 설치를 안내하고, 준비하지 못하면 다시 시도할 수 있습니다. 작성 중인 요청은 바뀌지 않습니다.

#### 사용 방법

개발자 기능 설정에서 AI 브라우저 메뉴 보이기를 켠 뒤, 입력창의 + 메뉴에서 이번 요청에 브라우저 사용 항목을 확인합니다. 이 PC가 아직 준비되지 않았으면 같은 자리에서 준비 상태가 보이고, Chrome 설치 후 다시 확인 또는 다시 시도를 누릅니다.

### 입력창에서 AI 브라우저 작업 지정

AI 브라우저 버튼 표시를 켠 사용자는 Chat·Project의 새 대화와 기존 대화에서 대상 사이트를 선택하고 다음 요청을 브라우저로 실행하도록 지정할 수 있습니다. 작업PC를 사용할 수 없으면 안내하며 게시·삭제 등은 기존 확인 규칙을 유지합니다. 표시 설정을 끈 사용자의 기존 화면은 유지됩니다.

#### 사용 방법

개발자 기능 설정에서 AI 브라우저 버튼 보이기를 켠 뒤 입력창의 AI 브라우저를 누릅니다. 대상 사이트는 선택 사항입니다. 이번 요청에 적용을 누르고 요청을 작성해 보내세요. 실행 지정 옆 해제로 본문을 유지한 채 지정을 없앨 수 있습니다.

### 자주 쓰는 대화 탐색 단축키 추가

명령 팔레트 바로 열기, 열린 대화 탭 앞뒤 순환, 닫은 대화 탭 되돌리기를 추가했습니다. 작업 패널 접기와 터미널 열기 키도 설정에서 바꿀 수 있습니다.

기존에 바꾼 키는 업데이트 후에도 유지합니다. 새 단축키의 기본값과 겹치면 새 동작만 미지정으로 표시하며, 설정에서 다른 키를 지정할 수 있습니다.

#### 사용 방법

Cmd/Ctrl+Shift+P로 명령 검색, Ctrl+Tab과 Ctrl+Shift+Tab으로 현재 대화 탭 순환, Cmd/Ctrl+Shift+T로 되돌리기 기록이 남아 있는 최근 닫은 대화 탭 묶음을 복원합니다. 작업 패널은 Cmd/Ctrl+Shift+B, 터미널은 Ctrl+백틱입니다. 내 설정 → 일반 → 단축키에서 변경할 수 있습니다.

### 작업PC 리소스에서 의존성 정리 상태 확인

작업PC 리소스 상세에서 의존성 정리 상태와 자동 정리 허용 설정을 볼 수 있습니다. 지원 런타임 검증이 끝나기 전에는 미지원으로 표시하며 자동 삭제를 실행하지 않습니다.

#### 사용 방법

입력창 아래 CPU 표시를 눌러 의존성 정리 상태를 확인합니다. 자동 정리 허용을 끄면 다음 요청부터 적용되며 이미 진행 중인 정리는 계속됩니다.

### 지운 기억을 10초 안에 되돌릴 수 있습니다

메모리 기록 및 검색에서 기억을 지우면 바로 지워지지 않고 `기억을 삭제했어요.` 알림이 나타납니다. 알림의 `되돌리기`를 누르면 삭제가 취소되고 기억이 원래 자리로 돌아옵니다. 알림이 닫히거나 다른 기억을 지우거나 검색·페이지를 바꾸거나 화면을 닫으면 그때 실제로 지워집니다.

#### 사용 방법

내 설정 → 개발 → 메모리 → 메모리 기록 및 검색에서 기억의 `삭제`와 `정말 삭제`를 누른 뒤, 10초 안에 알림의 `되돌리기`를 누릅니다. 알림 위에 마우스를 올려 두면 시간이 멈춥니다.

### 채팅으로 "이 대화 보관해줘"라고 하면 대화가 보관됩니다

프로젝트 대화에서 AI에게 "이 대화 보관해줘"처럼 보관을 요청하면, AI가 응답을 마친 뒤 대화가 자동으로 보관되고 에이전트 보드 `완료`로 옮겨집니다. 버튼을 따로 누를 필요가 없습니다. 보관은 `보관&완료`와 같은 방식으로 이루어져 작업트리는 그대로 남고, 보관 직후 나타나는 알림에서 되돌릴 수 있습니다. AI가 응답 중이거나 질문·권한 승인을 기다리는 동안에는 보관하지 않고, 요청한 뒤 사용자가 다른 메시지를 보내면 보관하지 않습니다. 개인 채팅은 해당하지 않습니다.

#### 사용 방법

프로젝트 대화에서 "이 대화 보관해줘"라고 보내세요. AI가 "응답이 끝나면 보관됩니다"라고 답하고, 응답이 끝나면 보관됩니다. 작업PC의 실행기가 이 기능을 지원하는 버전이어야 하며, 아니면 AI가 `작업 마무리` 위치를 안내합니다.

### 파일 목록에서 Finder로 바로 열기

프로젝트 파일 목록의 파일이나 폴더를 Finder(Windows는 파일 탐색기)에서 바로 열 수 있습니다. 실제 경로를 직접 찾아가지 않아도 그 항목이 선택된 폴더가 열립니다. 프로젝트의 작업PC가 지금 쓰는 이 컴퓨터일 때만 메뉴가 보입니다.

#### 사용 방법

프로젝트 대화에서 도구 펼치기 → 파일로 목록을 열고, 파일이나 폴더 행의 더보기(⋮)를 누르거나 행을 오른쪽 클릭한 뒤 **Finder에서 보기**(Windows는 **파일 탐색기에서 보기**)를 누르세요.

### 프로젝트 링크에서 분석 질문이 채워진 새 대화 열기

POST로 발급한 ticket 링크도 지원합니다. 최대 20,000자의 질문은 서버에 암호화해 10분 보관하고, 로그인과 새 입력창 준비 후 한 수신자에게 전달합니다. 앱 열기 시도만으로 소비하지 않습니다.

프로젝트 ID가 담긴 링크로 새 대화를 열고 분석 질문을 입력창에 채울 수 있습니다. 질문은 자동 전송하지 않습니다. 프로젝트를 열 수 없으면 로그인 계정의 참여 권한과 현재 조직을 확인하도록 안내합니다.

#### 사용 방법

POST /api/conversation-links로 발급한 링크는 saycode-desktop://new?ticket=<ticket>으로 열 수 있습니다. 설치된 앱에서 saycode-desktop://new?projectId=<프로젝트 ID>&prompt=<URL 인코딩된 질문> 링크를 엽니다. prompt는 1,000자까지입니다. 현재 로그인한 조직에서 참여 가능한 프로젝트가 필요합니다. 기존 folder/q 링크도 계속 지원합니다. Windows의 전체 명령줄 8KB 제한은 유지되므로 긴 한글 질문은 웹 링크를 사용하세요.

### AI 브라우저가 사이트에 들어가면 그 사이트용 스킬을 AI에게 알려 줍니다

Desktop에 내장된 Happy 런타임 `.364`부터, AI 브라우저가 어떤 사이트를 열면 그 사이트용으로 적어 둔 스킬이 있는지 확인해 AI에게 스킬 이름과 설명을 한 번 알려 줍니다. 바로 가는 주소·단축키·누르면 안 되는 곳처럼 사이트마다 필요한 요령을 스킬에 적어 두면, AI가 그 사이트에서 작업할 때 스킬을 찾아 읽을 수 있습니다. 스킬 본문을 대신 보내지는 않고, 같은 작업에서 같은 스킬은 다시 알리지 않습니다.

#### 사용 방법

스킬의 `SKILL.md` 머리말에 `sites:` 목록(예: `'*.atlassian.net/wiki/**'`)을 적습니다. Claude 대화는 홈 폴더와 대화 폴더의 `.claude/skills`, Codex 대화는 대화 폴더의 `.agents/skills`와 Codex 홈의 `skills`에서 찾습니다. 스킬을 새로 넣으면 다음에 시작한 대화부터 적용됩니다.

### Claude나 Codex가 띄운 서브 에이전트가 도는 동안 대화에 "서브 에이전트 실행 중"이 보입니다

Claude나 Codex가 조사 같은 일을 서브 에이전트에게 맡겨 뒤에서 돌리는 동안, 입력창 바로 위에 AI가 답할 때의 "작업 중..." 표시와 같은 모양으로 "서브 에이전트 실행 중 · 작업 이름" 줄이 에이전트 아이콘과 함께 보입니다(여러 개면 개수도 함께). 대화를 스크롤하거나 이어서 메시지를 보내도 그 자리에 있습니다. 메인 답변이 먼저 끝나도 서브 에이전트가 끝날 때까지 줄이 남고, 끝나면 저절로 사라집니다. 대화 속에서 서브 에이전트를 띄운 줄도 띄우자마자 "완료"로 바뀌지 않고, 실제로 끝날 때까지 "실행 중"으로 보입니다. Codex 대화에서는 서브 에이전트를 띄울 때마다 대화 속에 그 이름이 붙은 "서브 에이전트" 줄이 생기고, 도는 동안 "실행 중", 끝나면 "완료"로 바뀝니다. 프로젝트 대화와 Chat 모두, 공용 PC와 내 PC 모두 같게 동작합니다. 프로젝트 대화는 다른 대화를 보고 있어도 왼쪽 목록의 대화 줄과 열린 탭에 "백그라운드 작업 중"이 함께 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. Claude 대화는 작업PC의 Aplus CLI가 2026년 9월 23일 이후 버전(1.1.10-aplus.237 이상)이어야 합니다. Codex 대화는 이 표시를 지원하는 Aplus CLI 업데이트가 나온 뒤부터 보이며, Codex가 0.105 이상이어야 합니다. 이보다 오래된 작업PC에서는 줄이 나타나지 않습니다.

### LLM 사용량·비용과 사용 명세서 안내

조직 관리의 LLM 사용량·비용 화면에서 공급사 원가·수수료·합계와 산정 범위를 확인하고 CSV·인쇄용 사용 명세서를 받는 안내를 추가했습니다. 기능이 반영된 웹 서버에서 사용할 수 있으며 실제 청구서와 구분합니다. 게이트 공통 수수료(기본 5%)와 조직별 상속·별도 비율 설정 안내도 추가했습니다.

#### 사용 방법

계정 메뉴 → 조직 관리 → 운영 → LLM 사용량·비용에서 기간과 필터를 고릅니다. 사용 명세서 탭에서 CSV 또는 인쇄용 파일을 받을 수 있습니다.

### OpenCode 무료 모델 한도 시 자동 전환·이어가기

OpenCode 무료 모델이 사용량 제한으로 멈추면 다른 무료 모델로 전환해 같은 대화에서 작업을 이어갑니다. 현재 가격과 허용 범위를 확인하고 서로 다른 무료 모델로 최대 세 번 전환합니다. 모두 사용할 수 없거나 안전하게 복구하지 못하면 이유를 표시하고 멈춥니다. 이 기능에는 함께 제공되는 Happy CLI 업데이트가 필요합니다.

#### 사용 방법

업데이트 후 Project·Chat에서 OpenCode 무료 모델로 요청하면 자동 적용됩니다. 대화의 전환 안내와 Model 메뉴에서 사용 모델을 확인할 수 있습니다. 중단하면 자동 이어가기도 멈춥니다.

## 변경된 기능

### 개별 로그인 MCP 에 로그인하면 이 프로젝트의 내 연결이 켜집니다

프로젝트 설정 → MCP 서버에서 개별 로그인 MCP 의 로그인 버튼을 누르면, 꺼져 있던 이 프로젝트의 "내 연결"을 함께 켭니다. 로그인한 뒤 스위치를 따로 켜지 않아도 대화에서 바로 쓸 수 있습니다. "내 계정으로 로그인됨"은 초록색으로 표시해 로그인 상태를 알아보기 쉽게 했습니다.

#### 사용 방법

프로젝트 설정 → MCP 서버에서 로그인을 누르고 브라우저에서 로그인을 마치면 됩니다. 이 프로젝트에서 쓰지 않으려면 "내 연결"을 다시 끄면 됩니다.

### 결과 파일의 공개 링크 버튼을 PC에 저장 버튼과 같은 모양으로 표시

AI 답변의 결과 파일 옆에 작은 링크 아이콘만 있던 공개 링크 버튼이, 이제 `PC에 저장` 버튼과 같은 모양의 `공개 링크` 버튼으로 나란히 보입니다. HTML 미리보기 아래 파일 카드에서도 같은 묶음으로 표시됩니다.

#### 사용 방법

공개 링크 확장을 켠 상태에서 결과 파일의 `PC에 저장` 옆 `공개 링크` 버튼을 누르세요.

### 고정한 대화가 다른 컴퓨터와 웹에서도 같은 목록으로 보입니다

Project 탭의 "고정된 대화"가 이 컴퓨터에만 저장되어 컴퓨터마다, 웹과도 목록이 달랐습니다. 이제 로그인한 계정으로 고정하면 서버에 저장되어 같은 계정·같은 개인/조직에서는 다른 컴퓨터와 웹에서도 같은 고정 대화와 같은 순서가 보입니다. 고정된 대화 영역에서 끌어 옮긴 순서도 함께 저장됩니다.

서버에 이미 고정한 대화가 있으면(웹이나 다른 컴퓨터에서 고정한 경우) 그 목록을 그대로 보여 줍니다. 서버에 고정이 없고 이 컴퓨터에만 고정이 있다면, 업데이트 뒤 첫 연결에서 이 컴퓨터의 고정을 보이던 순서대로 서버에 올리고 이후에는 서버 목록 하나로 씁니다. 지금 계정이나 조직에서 열 수 없는 대화는 올리지 않고 안내합니다. 이 컴퓨터에서 개인으로만 쓰는 경우는 지금처럼 이 컴퓨터에만 저장됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 고정 방법은 그대로입니다. 대화에 마우스를 올리고 핀 버튼을 누르세요. 고정을 저장하지 못하면 안내가 뜨고 서버의 목록을 다시 불러옵니다.

### 공식 확장 번들을 갱신했습니다

공식 확장 번들에 React Source Locator를 추가하고, Telegram·Discord·Slack과 Moai를 현재 앱과 호환되는 최신 발행본으로 갱신했습니다. Saycode CLI에도 같은 메신저 어댑터가 포함됩니다.

#### 사용 방법

내 설정의 확장 관리에서 필요한 확장을 설치하거나 업데이트하세요. React Source Locator는 요소 선택 검사 권한을 허용하고 켜면 개발 서버의 React 요소에 소스 위치를 붙입니다. 기존 설치본은 자동으로 바뀌지 않습니다.

### 날짜와 시각을 앱 언어에 맞춰 표시해요

대화·입력 기록·설정의 날짜와 시각이 앱에서 선택한 언어를 따릅니다. 최근 활동의 오래된 날짜에는 다른 연도도 표시하고, 잘못되거나 없는 시각은 ‘알 수 없음’으로 안내합니다. 예약 실행 PC의 시간 기준과 실행·만료 판단은 유지됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 최근 활동과 대화·입력 기록의 날짜에 마우스를 올리면 전체 날짜와 시각을 확인할 수 있습니다.

### 다운로드와 검색 색인의 진행률 표시 정리

업데이트 다운로드와 조직 검색 색인의 진행 막대·상태 글자 크기를 맞췄습니다. 전체 용량을 모를 때와 실제 0%를 구분하고, 색인 대상이 없을 때는 비율을 표시하지 않습니다. 색인 조회가 실패해도 마지막 수치를 유지하며 같은 영역에서 오류를 안내합니다. 처리 완료에 실패 항목이 포함되더라도 성공 비율을 100%로 바꾸지 않습니다. 업데이트 카드의 작업 버튼도 공용 버튼 색과 호버를 따릅니다.

#### 사용 방법

업데이트 안내 카드나 개발자 기능 설정의 조직 검색 설정에서 확인하세요. 색인 진행률은 조직 검색이 연결된 환경에서 보입니다. 기존 다운로드·재시작·검색 연결 절차는 그대로입니다.

### 단축키 안내를 최신 사용법으로 갱신

### 메신저의 /stop이 대기 중인 메시지까지 멈추고, 중단이 확인된 뒤에 다음 메시지를 보냄

메신저에서 /stop을 보내면 지금까지는 실행 중인 작업만 멈추고, 같은 스레드에서 이미 보내 두었던 메시지는 그 뒤에 그대로 실행됐습니다. 이제 /stop은 같은 스레드에서 내가 보낸 아직 끝나지 않은 메시지를 모두 멈춥니다. 아직 보내지 않은 메시지는 보내지 않고 "중단 요청으로 보내지 않았어요"라고 알려 주며, 이미 세션에 들어간 메시지도 시작 전이면 취소합니다. /stop 뒤에 새로 보낸 메시지는 앞선 중단이 확인될 때까지 기다렸다가 보내므로, 늦게 도착한 중단이 새 작업을 멈추지 않습니다. 기다리는 동안에는 "앞선 중단 요청을 확인하는 중"이라는 안내가 보이고, 작업PC가 응답하지 않아 중단이 끝내 확인되지 않으면 /stop을 한 번 더 보내 기다리던 메시지까지 멈출 수 있습니다.

#### 사용 방법

메신저 스레드에서 /stop을 보내면 됩니다. 다른 스레드나 다른 사람이 보낸 메시지에는 영향이 없습니다.

### 앱에서 업데이트할 수 없는 작업PC의 브라우저 런타임 직접 업데이트 안내

### 필요할 때만 브라우저 사용을 지정하세요

#### 사용 방법

### 허브 질문 결과의 전달 확인

허브가 CLI로 보낸 질문은 저장 여부와 AI가 실제로 받은 여부를 구분합니다. 확인 신호가 없으면 미확인으로 표시하며 다른 질문의 답변을 이번 질문의 결과로 인정하지 않습니다. 구조화 출력은 계속 반환하고 명시적 수신 거부는 실패로 구분하며, 백그라운드 후속 답변은 최초 답변을 바꾸지 않습니다. 현재 실행기의 Codex 명령 승인 대기는 요청 턴을 확인할 정보가 없어 미확인과 사유를 반환합니다. 입력 기록을 지원하지 않는 세션에는 이전처럼 보내지만, 결과는 받았는지 알 수 없다는 뜻으로 `delivered:false`와 `delivery.state:"unsupported"`를 표시합니다. 허브 자동 알림의 동작은 이전과 같습니다.

#### 사용 방법

허브에서 `happy agent prompt <id> <text> --wait`를 실행하면 결과에 `resultVersion:2`가 표시됩니다. `delivered:true`는 실제로 받은 증거가 있을 때만 나옵니다. 미확인 요청을 새 메시지로 자동 재전송하지 말고 `happy agent read <id> --since <저장 seq>`로 확인하세요.

### 응답을 멈춘 뒤 대기열의 즉시 요청이 실패하던 문제 수정

응답을 중단한 뒤 대기열에 남은 요청에서 즉시 요청(보내기 아이콘)을 누르면 `즉시 요청을 보내지 못했어요. 이유: No active Claude turn` 오류가 뜨고 요청이 보내지지 않았습니다. 이제 진행 중인 답이 없으면 누른 요청을 새 메시지로 바로 보내고, 중단 뒤 멈춰 있던 대기열도 다시 차례로 보냅니다. AI가 답하는 중에는 지금처럼 진행 중인 답에 바로 전달합니다.

#### 사용 방법

### 인증이 끊긴 조직 계정으로 새 대화가 계속 시작되던 문제 수정

#### 사용 방법

### 재시작 뒤 같은 ID 충돌에서 원래 요청 확인

허브가 CLI로 보낸 질문을 CLI 재시작 뒤 같은 입력 ID로 다시 확인할 때, 그사이 대상 세션의 실행기가 재시작되어 `localid_conflict`가 나오면 원래 저장된 요청의 위치(`storage.existing`)를 돌려주고, 본문이 같으면(`sameBody`) 확인 명령(`next.command`)도 함께 돌려줍니다. 본문이 다른 충돌은 다른 질문이라 확인 명령을 주지 않습니다. 이전에는 위치가 없어 원래 요청을 AI가 받았는지 확인할 방법이 없었습니다. 충돌한 요청은 여전히 새로 보내지 않습니다.

#### 사용 방법

`happy agent prompt <id> <text> --local-id <ID>` 결과가 `localid_conflict`이면 결과의 `next.command`(`happy agent read <id> --since <seq>`)를 실행해 원래 요청의 처리 결과를 확인하세요.

### Project 고정 대화 조회 실패 안내 개선

Project 탭의 고정 대화 조회 실패를 Chat과 같은 플로팅 알림으로 표시합니다. 고정한 대화를 불러오지 못했다는 문구와 다시 시도 버튼을 제공하며 프로젝트 목록을 밀어내지 않습니다. 재시도 기회를 놓치지 않도록 조회 성공 또는 직접 닫기까지 알림을 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 알림에서 다시 시도하거나 닫을 수 있습니다.

### Slack 답변 속 `<!channel>` 같은 표기가 알림 없이 글자 그대로 보입니다

AI 답변이나 승인 요청에 `<!channel>`, `<!here>`, `<@사용자>` 같은 Slack 표기가 들어 있으면, 지금까지는 Slack이 이를 실제 알림·멘션으로
처리해 채널 전체에 알림이 갈 수 있었습니다. 이제 Saycode가 Slack으로 보내는 답변·진행 표시·안내·승인 문구는 이런 표기를 글자 그대로
보여 줍니다. `&`, `<`, `>`도 원래 글자대로 보입니다.

긴 답변을 Slack 메시지 여러 개로 나누는 과정에서 Extension의 분할이 실패하면, 지금까지는 답변이 전달되지 않았습니다. 이제는 Saycode가
직접 나눠 보냅니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### Slack에서 링크가 들어간 질문도 거절되지 않습니다

Slack에서 링크를 붙여 넣거나 `&`가 들어간 질문을 보내면, 같은 대화의 일반 질문은 답하던 봇이 "이 명령을 처리하지 못했어요. 세션 선택과 연결 권한을 확인해 주세요."라고 거절하던 문제를 고쳤습니다. 이제 링크가 있는 질문도 같은 세션으로 전달되고, 에이전트는 `&amp;`나 꺾쇠가 붙은 링크 대신 읽기 쉬운 문장(`라벨 (주소)`)으로 받습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.
