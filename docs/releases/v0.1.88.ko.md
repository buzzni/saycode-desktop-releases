## 새 기능

### 대화에서 saycode 플랜 사용량 확인

saycode 플랜으로 실행한 Chat과 프로젝트 대화의 입력창 아래에서 내 플랜 등급(Basic·Plus·Pro), 실행 모델과 이번 달·이번 주·5시간 사용량, 재설정 시각을 확인할 수 있습니다. 창은 항목마다 이름·재설정 시각·사용률을 한 줄에 두고 막대를 아래에 둔 간결한 모양입니다. 플랜 대화에 작업PC 계정의 잔여량이 함께 표시되던 혼동을 줄였습니다.
현재 AI는 대화의 실제 실행 정보로 구분합니다. 다음 요청의 선택값으로 바뀌지 않으며, AI를 확인하지 못한 대화는 임의로 Claude나 PC 사용량을 표시하지 않습니다.

하단 saycode 플랜 버튼은 기존 사용량 버튼과 같은 높이·글자·여백과 호버 영역을 사용합니다.

실행 ID로 AI를 확인하는 오래된 Project 대화는 전송·재시도도 같은 AI를 사용하며, Codex 대화가 Claude 인증으로 잘못 진입하지 않습니다.

#### 사용 방법

플랜으로 실행한 대화를 열고 입력창 아래의 saycode 플랜을 누르세요. 열 때 최신 사용량을 확인하며, 조회 실패 시 다시 확인을 누를 수 있습니다.

### 어느 화면에서든 하단 터미널 패널 열기

현재 작업PC 터미널이 VS Code처럼 사이드바 오른쪽 전체 폭의 아래쪽 패널로 열립니다. 대화와 오른쪽 작업 패널 아래에 따로 놓여 둘의 너비와 분할은 그대로 두고 높이만 나눠 씁니다. 시작 화면 오른쪽 위 아이콘으로 열고, 프로젝트 대화와 개인 Chat을 포함한 어느 화면에서나 Cmd/Ctrl+J로 열고 숨깁니다. 패널 높이와 열림 상태는 이 기기에 기억합니다. 위·왼쪽·오른쪽으로 옮기던 기능은 아래쪽 패널 하나로 정리했습니다.

#### 사용 방법

시작 화면 오른쪽 위의 터미널 아이콘을 누르거나, 어느 화면에서나 Cmd/Ctrl+J를 누릅니다. 위쪽 경계선을 드래그해 높이를 바꾸고(최대 화면 높이의 70%), 같은 단축키나 패널 오른쪽 위 숨기기 버튼으로 숨깁니다. 단축키는 내 설정 → 일반 → 단축키의 하단 터미널 표시/숨기기에서 바꿀 수 있습니다.

### 연결한 다른 작업PC의 내 대화도 AI가 읽고 이어서 묻기

두 작업PC를 연결해 두면, 한 PC의 대화에서 AI에게 "다른 PC에서 하던 대화 확인해서 이어서 물어봐"처럼 부탁할 수 있습니다. 개인 계정이면 AI가 연결된 PC에서 내가 직접 연 대화도 그 PC의 프로젝트 안에 있을 때 목록에서 찾고, 내용을 읽고, 이어서 질문을 보낼 수 있습니다. 방향 바꾸기와 멈추기는 AI가 맡긴 대화에만 됩니다. 받는 PC에서 종단간 암호화된 대화도 그 PC가 직접 내용을 풀어 연결을 통해서만 보내 주므로, AI가 맡긴 대화의 결과를 읽고 이어서 지시할 수 있습니다. 다른 사람의 대화나 회사 계정 작업PC의 대화는 닿지 않습니다.

#### 사용 방법

먼저 내 설정 → 개발 → 작업PC에서 두 PC를 **다른 PC에서 작업 받기**로 연결합니다. 그다음 보내는 PC의 대화에서 AI에게 다른 PC의 대화를 읽거나 이어서 물어봐 달라고 부탁합니다. 두 PC 모두 이 기능이 들어간 Saycode여야 합니다.

### 오류 팝업에서 바로 오류 보고하기

오류 팝업의 `더보기`를 펼치면 진단 정보(오류 코드·원문·발생 시각·앱 버전)를 `복사`하거나 `오류 보고`로 Saycode 팀에 바로 보낼 수 있어요. 보고에는 팝업 문구와 진단 정보만 담기고 대화 내용은 보내지 않아요.

#### 사용 방법

오류 팝업 오른쪽의 더보기를 누른 뒤 진단 정보 상자 오른쪽 위의 오류 보고를 누르세요. 조직 계정으로 로그인했고 보낼 곳(그 대화, 열린 Chat·프로젝트, 등록된 이 PC)이 있을 때 보이며, 로컬 모드와 데모에서는 복사만 쓸 수 있어요.

### 컨텍스트 사용률을 눌러 바로 대화를 압축할 수 있어요

Claude 대화의 입력창 아래 컨텍스트 사용률 ‘N%’를 누르면 작은 창이 열려요. 사용 중인 토큰과 전체 창 크기, 80% 이상일 때의 경고를 보여 주고, 그 자리에서 대화 압축을 실행할 수 있어요. 압축 버튼은 /compact를 대신 보내 주므로 입력창에 쓰던 글은 그대로 남아요. 압축하는 동안에는 사용률 자리에 ‘압축 중’이 돌아가고, 직접 /compact를 입력해 시작한 압축에도 같은 표시가 나와요. 압축이 끝나면 사용률은 잠시 사라졌다가 다음 답변 뒤에 줄어든 값으로 다시 나타나요. 응답 중이거나 질문·승인 요청이 기다리는 동안에는 버튼이 꺼지고 이유가 함께 보여요.

#### 사용 방법

Claude 대화에서 입력창 아래 정보 줄의 컨텍스트 사용률 ‘N%’를 누른 뒤 대화 압축을 누르세요. Esc를 누르거나 창 밖을 누르면 닫혀요.

### 컨텍스트 창을 무엇이 차지하는지 보고, 압축 전에 남길 내용을 정할 수 있어요

Claude 대화의 컨텍스트 사용률 ‘N%’를 누르면 사용률 아래에 ‘구성’이 함께 보여요. 대화·기본 도구·시스템 프롬프트처럼 창을 많이 차지하는 항목부터 몇 토큰인지 보여 주고, 작은 항목은 ‘기타’ 한 줄로 합치고, 자동 압축 여유분을 덧붙여요. 마지막 응답이 끝난 시점의 추정이라 위의 사용률과 조금 다를 수 있어요. 대화 압축도 이제 바로 보내지 않고 한 번 확인해요. 확인 단계에서 요약에 남길 내용을 ‘압축 지침’에 적을 수 있고, 기본으로 켜진 ‘보존 지침 포함’은 확인되지 않은 가설은 가설로 표시하고 아직 답이 없는 질문과 내가 말한 제약을 요약에 남기도록 요청해요. 확인 단계를 연 사이에 응답이 시작되거나 다른 대화로 바꾸면 확인 단계는 닫히고 아무것도 보내지 않아요. 보내기에 실패하면 적은 지침을 그대로 둔 채 확인 단계로 돌아와요.

#### 사용 방법

Claude 대화에서 입력창 아래 정보 줄의 컨텍스트 사용률 ‘N%’를 누르면 ‘구성’이 보여요. 압축하려면 대화 압축을 누르고, 필요하면 압축 지침을 적은 뒤 압축을 누르세요. 취소나 Esc를 누르면 아무것도 보내지 않아요.

### 프로젝트 없이 현재 작업PC 터미널 열기

현재 작업PC의 터미널을 프로젝트와 관계없이 바로 열 수 있습니다. 작업PC 홈 폴더에서 시작하며 화면 아래 패널로 열려 나머지 화면을 계속 조작할 수 있습니다. 숨겼다 다시 열면 같은 터미널을 이어갑니다.

#### 사용 방법

연결된 작업PC를 선택한 뒤 시작 화면 오른쪽 위의 터미널 아이콘을 누릅니다. 아이콘을 다시 누르거나 터미널 오른쪽 위 숨기기 버튼으로 숨깁니다.

### Claude 대화가 컨텍스트 창을 얼마나 채웠는지 입력창 아래에서 보여줘요

Claude 대화의 입력창 아래 정보 줄 왼쪽에 컨텍스트 사용률 ‘N%’가 나타나요(AI 잔여량 표시를 켜 두었다면 사용량 버튼 바로 옆). 지금 대화가 모델의 컨텍스트 창을 얼마나 차지하는지 보여 주고, 마우스를 올리면 사용 중인 토큰과 전체 창 크기를 정확한 숫자로 볼 수 있어요. 80% 이상 차면 색이 바뀌고 설명에 새 대화를 시작하거나 /compact로 줄일 수 있다고 알려 줘요. 숫자는 Claude가 실제로 알려 준 값만 쓰고, 첫 답변이 끝나기 전이나 대화를 압축·초기화한 직후처럼 값을 모를 때는 표시하지 않아요. 이 업데이트에 함께 들어간 Saycode 실행 도구(1.1.10-aplus.346)부터 지원하므로, 다른 작업PC에서 실행되는 대화는 그 PC의 실행 도구도 이 버전 이상이어야 보여요. 이전 버전이나 Codex 대화에서는 나타나지 않고 기존 누적 토큰 표시는 그대로예요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. Claude 대화에서 첫 답변이 끝나면 입력창 아래 정보 줄에서 확인할 수 있어요.

## 변경된 기능

### 알림 팝업을 짧고 깔끔하게 바꿨어요

창 위쪽 가운데에 뜨는 알림 팝업이 알약 모양에 종류별 연한 색(정보 파랑·오류 빨강·완료 초록·주의 노랑)으로 바뀌었어요. 문구는 두 줄까지만 보이고, 넘치거나 원인·진단 정보가 있으면 `더보기`로 펼쳐 볼 수 있어요. `API error 500: …` 같은 서버 오류 원문은 "서버에서 오류가 났어요"처럼 쉬운 한 줄로 보이고, 그 아래 작은 글씨로 오류 코드와 서버가 보낸 말이 한 줄 보여요. 원문 전체는 더보기 안에 남아요. AI 응답이 10분째 없을 때 닫을 때까지 남던 빨간 경고는, 지금 보고 있는 대화에만 짧은 안내로 보이고 8초 뒤 닫혀요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 팝업 오른쪽의 더보기를 누르면 원인과 진단 정보를 볼 수 있어요.

### 앱에 포함된 실행 도구가 컨텍스트 사용률을 알려 줍니다

앱에 포함하는 Happy 실행기를 1.1.10-aplus.346으로 올렸습니다.

- 이 PC에서 실행되는 Claude 대화가 컨텍스트 창 사용률을 앱에 보내, 입력창 아래 컨텍스트 사용률 ‘N%’ 표시가 실제로 나타납니다.
- 공유 작업PC의 Claude 계정 자동 교체를 위한 기반(실행 기록·복구)이 들어갔습니다. 서버에서 이 기능을 켜기 전까지 기존 동작은 바뀌지 않습니다.

#### 사용 방법

사용자 조작 없이 앱 업데이트에 포함됩니다.

### 오른쪽 패널을 닫으면 보던 파일 제안 칩도 사라져요

오른쪽 작업 패널을 닫으면 입력창 위의 점선 파일 칩(`+ 파일이름`)이 함께 사라집니다. 패널을 다시 열면 그 파일이 다시 제안됩니다. 이미 첨부한 파일 칩은 그대로 남습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 이 턴 변경 보기를 누르면 바뀐 파일까지 바로 열려요

대화의 "이 턴 변경 보기"를 누르면 오른쪽 변경 탭이 그 턴으로 열린 뒤, 목록 맨 위의 바뀐 파일이 가운데에 바로 열립니다. 전에는 "파일 열기" 빈 화면에 멈춰 있어 파일 트리에서 파일을 한 번 더 눌러야 했습니다.

#### 사용 방법

Project → 대화 → "파일 N개를 편집했습니다" 줄의 "이 턴 변경 보기"를 누르세요.

### 입력창 아래 사용량 한도 경고 줄 제거

Claude·Codex 계정의 5시간·7일 한도가 가까워질 때 입력창 아래에 나타나던 "한도 N% 사용 · …후 초기화" 경고 줄이 더 이상 표시되지 않습니다. 사용량은 입력창 아래 AI 사용량 버튼에서 계속 확인할 수 있고, 한도에 닿은 모델은 모델 선택기에 "…까지 제한"으로 표시됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 입력창 커넥터 아이콘을 저장소 탭과 분리

입력창 위쪽 테두리의 커넥터(플러그) 아이콘이 `저장소` 탭 안에 붙어 있지 않고, 탭 오른쪽에 테두리 없는 아이콘으로 따로 표시됩니다. 확인이 필요한 커넥터가 있을 때 빨간색으로 바뀌는 동작과 눌러서 커넥터 연결 상태를 여는 동작은 그대로입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 저장소 계정을 연결하지 않았을 때 새로고침 아이콘 숨김

새 프로젝트의 Git 저장소 탭에서 GitHub·GitLab 계정을 하나도 연결하지 않았을 때 보이던 새로고침 아이콘을 없앴습니다. 브라우저에서 연결을 마치고 앱으로 돌아오면 연결 상태가 자동으로 반영됩니다.

#### 사용 방법

새 프로젝트 → Git 저장소에서 GitHub 연결 또는 GitLab 연결을 누르고 브라우저에서 인증을 마친 뒤 앱으로 돌아옵니다. 별도로 새로고침할 필요가 없습니다.

### 저장소가 없는 프로젝트의 저장소 바를 간단하게 정리

코드 저장소가 아직 없는 프로젝트에서는 입력창 위 저장소 바에 같은 내용이 세 번 나왔습니다. `저장소 연결 안 됨` 글자, 연결이 끊긴 구름 아이콘, `저장소 연결하기` 버튼입니다. 이제 바에는 `저장소 연결 안 됨`과 `연결하기` 버튼만 남습니다. 버튼에 마우스를 올리면 지금처럼 연결하지 않아도 대화·미리보기를 쓸 수 있다는 안내가 나옵니다.

#### 사용 방법

입력창 위 저장소 바에서 `저장소 연결 안 됨` 옆의 `연결하기`를 누르면 프로젝트 설정의 코드 저장소가 열립니다.

### 하단 터미널에 탭이 생기고 라이트·다크 모드를 따라가요

하단 터미널 위쪽이 탭 줄로 바뀌었습니다. +를 누르면 새 터미널 탭이 열리고, 탭을 좌우로 끌어 순서를 바꾸거나 X로 닫을 수 있습니다. 탭마다 셸이 따로 있어 탭을 바꾸거나 패널을 숨겨도 실행 중인 명령이 이어집니다. 마지막 탭을 닫으면 패널이 숨겨지고, 숨기기 버튼은 오른쪽 위 접기(⌄) 아이콘이 되었습니다. 터미널 색도 앱의 라이트·다크 모드를 따라 라이트 모드에서는 밝은 터미널로 보입니다. 오른쪽 작업 패널의 터미널은 그대로 어두운 색입니다.

#### 사용 방법

시작 화면의 터미널 아이콘 또는 Cmd/Ctrl+J로 하단 터미널을 연 뒤 탭 줄의 +를 누르세요.

### AI 브라우저 설정 불일치 경고를 대화에서 반복해 띄우지 않음

작업PC의 AI 브라우저 설정이 공용·전용 구분과 맞지 않을 때, 대화를 열 때마다 뜨던 빨간 경고를 없앴습니다. 브라우저를 쓰지 않는 대화에서도 반복해서 나왔고 사용자가 직접 해결할 수 없는 안내였습니다. 이제 브라우저를 쓰려고 할 때만 사용할 수 없는 이유와 관리자에게 작업PC 설정 확인을 요청하라는 안내를 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 입력창의 + 메뉴에서 이번 요청에 브라우저 사용 항목 아래 안내, 또는 내 설정의 AI 브라우저에서 상태를 확인할 수 있습니다.

### AI 브라우저 작업 공간이 대화 제목으로 보여요

AI 브라우저 콘솔의 작업 공간 목록이 `대화 mq3x…` 같은 세션 ID 대신 대화 제목으로 공간을 보여 줘요. 어느 대화의 공간인지 알고 닫을 수 있어요. 이 표시는 대화 제목을 지원하는 브라우저 런타임에서 보이며, 그 전 런타임에서는 지금처럼 세션 ID로 보여요.

#### 사용 방법

### AI 사용량 창에서 내 조직 계정만 먼저 보여요

AI 사용량 창의 조직 계정 목록은 지금 대화에 쓰는 계정과 새 대화용으로 고른 계정만 바로 보여 주고, 나머지 조직 계정은 `다른 조직 계정 N개` 아래로 접어 둡니다. 쓰거나 고른 계정이 없으면 지금처럼 모두 보여 줍니다. 목록 제목과 겹치던 행마다의 `조직계정` 배지, 계정에 마우스를 올렸을 때 보이던 원시 시각값도 뺐습니다.

### Claude 모델 선택에서 Fable 5.2 사용

Claude 모델 선택지의 `Fable 5.1`이 최신 모델인 `Fable 5.2`로 바뀌었습니다.

기존에 Fable 5나 Fable 5.1을 골라 둔 새 대화 설정, 세션별 모델 고정, 병렬 실행 슬롯, 저장된 리뷰 설정은 자동으로 Fable 5.2로 이어집니다. 다시 고를 필요가 없고, 선택이 기본값으로 되돌아가지도 않습니다. 골라 둔 Effort도 그대로 유지되며 `low`부터 `max`까지 쓸 수 있습니다.

막힌 대화를 최고 성능 모델로 승격하는 자동 라우팅, 독립 리뷰의 기본 모델도 함께 Fable 5.2로 옮겨졌습니다. 이미 Fable 5.1로 승격돼 있던 대화도 승격 단계를 잃지 않고 다음 메시지부터 Fable 5.2로 이어집니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 모델을 직접 고르려면 대화 입력창 위의 Model 선택에서 `Fable 5.2`를 선택합니다.

Figma 디자인 편집 창에서 사용 가능한 AI 줄에 다시 확인 버튼 대신 연결 완료가 표시됩니다. 연결이 끝났는데도 다시 확인하라는 것처럼 보이던 혼동을 줄였습니다.

saycode 플랜 대화는 AI 답변 한 번의 길이가 정해져 있어서, 리포트 같은 큰 파일을 한 번에 쓰다가 답변이 중간에 멈추고 같은 실패가 반복될 수 있었어요. 이제 플랜 대화의 AI는 큰 파일을 여러 번에 나눠 작성하도록 안내를 받아요.

#### 사용 방법

### 개인 Claude 선택 시 조직 연결 상태로 시작이 막히던 문제 수정

### 기존 대화만 계속 실패하던 조직 AI 계정 확인 오류 수정

조직 AI 계정 배정이 바뀌거나 작업PC 실행기가 다시 시작된 뒤, 새 대화는 되는데 기존 대화에서만 보내는 메시지마다 "조직 AI 계정의 사용 권한이나 실행 상태를 확인하지 못해 실행을 멈췄습니다"가 나오던 문제를 수정했습니다. 이제 확인이 한 번 실패해도 다음 메시지는 다시 확인을 받아 실행되고, 같은 대화가 계속 막히면 그 대화의 실행을 새로 시작합니다. 이 안내가 다시 나오면 끝에 붙는 오류 코드로 원인을 구분할 수 있습니다.

#### 사용 방법

별도 설정 없이 적용됩니다. 원래 입력과 첨부는 대화에 남아 있으니 같은 대화에서 다시 보내면 됩니다.

#### 사용 방법

### 답변 속 `600~750` 같은 범위 표기가 취소선으로 바뀌던 문제 수정

AI 답변에 `600~750Mi`, `150~250Mi`처럼 물결표 하나로 쓴 범위가 한 문단에 두 번 이상 나오면, 물결표가 사라지고 그 사이 글자가 취소선으로 표시됐습니다. 이제 물결표 하나는 글자 그대로 보이고, 취소선은 `~~글자~~`처럼 물결표 두 개로 감쌀 때만 표시됩니다.

#### 사용 방법

### 답변이 길이 제한에 걸려 멈추면 이유를 알려줘요

AI 답변이 한 번에 쓸 수 있는 길이를 넘어 중간에 멈추면, 지금까지는 `Codex 오류: Incomplete response returned, reason: max_output_tokens`라는 영어 원문과 `AI Models` 버튼이 보였어요. 이제는 `AI 답변이 한 번에 쓸 수 있는 길이를 넘어 멈췄어요. 큰 파일은 여러 번에 나눠 작성해 달라고 요청해 보세요.`라는 안내와 `다시 시도` 버튼이 보여요. 연결이 끊긴 것이 아니므로 `AI Models`로 안내하지 않아요. 원문은 접힌 상세에서 그대로 볼 수 있어요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 안내가 보이면 큰 파일을 나눠서 써 달라고 요청하거나 `다시 시도`를 누르세요.

### 대화를 열 때 파일 복원지점 오류 토스트가 잠깐 떴다 사라지지 않습니다

대화를 열 때 작업PC에서 파일 복원지점 상태를 처음 읽지 못하면, 입력창 위에 `파일 복원지점을 불러오지 못했어요` 토스트가 잠깐 떴다가 8초 뒤 사라졌습니다. 상태를 모르면 복원할 수 있는 것도 없어 이 알림은 눈길만 끌었습니다. 이제 첫 조회가 실패하면 알림 없이 패널을 숨기고, 다음 조회에 성공하면 접힌 패널이 나타납니다. 한 번 읽은 뒤의 재조회 실패는 지금처럼 패널 안에서 알려 줍니다.

### 업데이트 서버가 응답하지 않으면 오류 원문 대신 안내를 보여 줍니다

GitHub 업데이트 서버가 잠시 응답하지 않거나(504 등) 요청이 몰려 거절되면, 업데이트 안내와 설정의 업데이트 상태에 `504 "method: GET url: …"` 같은 서버 응답 원문이 그대로 보였습니다. 이제 두 곳 모두 서버 쪽 일시 장애라는 점과 잠시 후 다시 시도하면 된다는 안내를 보여 줍니다. 인터넷 연결이 끊겨 서버에 닿지 못한 경우에는 연결을 확인하라고 안내합니다. 그 밖의 오류는 지금처럼 짧은 오류 문구를 보여 줍니다.

### 에이전트가 사용자가 쓰는 언어로 답합니다

한국어로 요청해도 작업 중간의 진행 보고가 영어로 나오던 문제를 고쳤습니다. 이제 에이전트는 사용자가 직접 쓴 가장 최근 메시지의 언어로 진행 보고·질문·최종 보고를 작성합니다. 작업 중 들어오는 도구 결과나 시스템 알림이 영어여도 그 언어를 따라가지 않습니다. 메시지에 언어가 드러나지 않으면 이전 메시지의 언어를, 그것도 없으면 앱 표시 언어를 따릅니다. 코드·명령어·화면 문구는 그대로 둡니다.

### 오래된 AI 브라우저 런타임에도 업데이트 버튼이 보여요

AI 브라우저 콘솔은 열리지만 작업 공간 관리 기능이 없는 오래된 런타임에서는, 브라우저 런타임 업데이트 버튼이 보이지 않아 업데이트할 방법이 없었어요. 이제 이런 경우에도 'AI 브라우저' 패널에 "런타임이 오래됐다"는 안내와 브라우저 런타임 업데이트 버튼이 나타나요. 브라우저 작업 공간 한도에 도달했다는 안내도 이 PC의 런타임이 오래됐으면 업데이트부터 하라고 알려 줘요.

### 요금제 플랜 한도를 다 쓰면 대화에 플랜 한도 초과로 알려 줍니다

요금제 플랜으로 실행한 대화에서 플랜 사용 한도를 다 쓰면, 대화에 "Codex 오류: You've hit your

쉬웠습니다.

이제 같은 상황에서 "요금제 플랜 사용 한도를 초과했어요. 3:14 PM에 다시 쓸 수 있어요."처럼 플랜
한도를 초과했다는 안내와 다시 쓸 수 있는 시각을 보여 줍니다. Codex 원문은 "상세"를 펼치면 볼
수 있습니다. 대화가 이 한도 오류로 끝나 있으면 그 아래에 쓰고 있는 플랜 등급(예: Basic), 현재
사용량(이번 달·이번 주·5시간), 한도가 재설정되기까지 남은 시간도 함께 보여 줍니다. 내 Codex
계정으로 실행한 대화의 한도 오류는 지금처럼 원문 그대로 보입니다.

이제 목록을 다시 읽는 동안에는 마지막으로 읽은 목록을 그대로 보냅니다. 다른 기기에서 목록을 바꿨다면 그 변경은 다음 메시지부터 반영됩니다.

### API 토큰 대화에 이미지를 보내면 이유와 해결 방법을 알려 줍니다

API 토큰 연결로 시작한 대화에 이미지를 첨부해 보내면, 대화에 "Codex 오류: {"error":{"type":"agent_plan_error",
"code":"agent_plan_request_content-block-not-allowed",…}}"처럼 서버 원문이 그대로 나와 원인을 알기 어려웠습니다.

이제 같은 상황에서 "API 토큰 연결은 이미지·파일 입력을 받지 않아요"라는 안내와 함께, 이 대화에서는 다시 보내도
같은 오류가 나니 이미지 없이 새 대화를 시작하거나 작업PC 토큰으로 새 대화를 열라고 알려 줍니다. 다시 로그인하라고
안내하던 "AI Models" 버튼은 이 오류에서 더 이상 보이지 않습니다. 로그인으로는 해결되지 않기 때문입니다. 서버 원문은 "상세"를 펼치면 볼 수 있습니다.

### ChatGPT 앱에서 보관한 Codex 대화도 Saycode에서 이어서 쓸 수 있습니다

Saycode 플랜이나 이 PC의 Codex로 시작한 대화에 다시 메시지를 보내면 "Codex failed to start … is archived"가 뜨고 대화가 시작되지 않는 경우가 있었습니다. 같은 PC의 ChatGPT 앱(Codex)이 그 대화의 Codex 기록을 보관 처리하면 Codex가 이어가기를 거절했기 때문입니다. 대화 복제·되감기도 같은 이유로 실패할 수 있었습니다.

이제 보관된 Codex 기록을 자동으로 복원한 뒤 이어갑니다. 복원된 기록은 ChatGPT 앱의 Codex 목록에 다시 나타납니다.

#### 사용 방법

따로 할 일은 없습니다. 오류가 났던 대화에 다시 메시지를 보내면 이어서 진행됩니다.
