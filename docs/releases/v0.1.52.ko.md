## 새 기능

### 공용 머신에서도 에이전트 브라우저 콘솔을 쓰고, 남의 대화는 소유자의 브라우저로 동작함을 알려 줍니다

에이전트 브라우저가 공용(shared) 설치된 머신에서도 각 사용자가 자기 브라우저 프로필로 콘솔을 열 수 있습니다. 개인 채팅과 프로젝트 대화 위에 에이전트 브라우저 안내가 보이고, `브라우저 콘솔 열기`를 누르면 그 머신의 브라우저 패널이 콘솔로 열립니다. 다른 사람이 만든 대화에서는 브라우저 작업이 그 사람의 로그인으로 실행된다는 안내가 함께 보이고, 처음 보낼 때 한 번 확인합니다. 새 세션은 세션을 시작한 사람(개인 채팅은 대화 소유자)의 브라우저 프로필에 연결됩니다.

#### 사용 방법

에이전트 브라우저가 설치된 머신의 대화를 열면 대화 위 안내에서 `브라우저 콘솔 열기`를 누릅니다. 로그인이나 승인이 필요할 때 콘솔에서 직접 처리합니다. 다른 사람의 대화에 처음 보낼 때 뜨는 확인 창에서 `보내기`를 누르면 전송되고, `취소`하면 입력이 그대로 남습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1350)

### 내 설정에서 프로필 사진 업로드

프로필에서 사진을 업로드하거나 변경할 수 있습니다. 웹과 같은 원형 자르기를 제공하고, 진행 중 표시와 실패 후 재시도를 지원합니다. 저장된 사진은 사이드바와 홈에 바로 반영되며 작성 중인 표시 이름은 유지됩니다.

#### 사용 방법

내 설정 → 프로필 → 사진 업로드 또는 사진 변경을 선택합니다. 이미지를 선택하거나 드롭하고 원형 영역을 조절한 뒤 적용합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1345)

### 내 설정을 General과 Develop로 재편

데스크톱 설정을 내 설정으로 바꾸고 일반 사용자 설정과 개발 설정을 분리했습니다. 기존 설정 기능은 유지하며, 개발 자동화와 터미널 설정은 Develop의 전용 페이지에서 제공합니다. 웹과 같은 내 토큰 사용량·추정 비용·프로젝트별 및 모델별 내역을 조회할 수 있습니다.

#### 사용 방법

프로필 메뉴의 내 설정 또는 설정 단축키로 엽니다. General과 Develop를 전환하거나 설정 검색으로 전체 항목을 찾을 수 있습니다. 영역을 전환해도 작성 중인 설정은 유지됩니다. 메뉴 배경을 본문과 같은 흰색으로 맞추고 스크롤바를 메뉴 오른쪽 경계에 배치했습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1343)

### 대화의 결과 파일을 바로 저장할 수 있습니다

결과 파일 카드와 답변의 파일 링크 옆에 저장 버튼을 추가했습니다. 저장 위치를 선택하면 앱이 실행 중인 컴퓨터에 원본 파일을 저장합니다. 저장을 취소하거나 실패하면 다시 시도할 수 있습니다.

#### 사용 방법

결과 파일 옆의 `저장`을 누르고 폴더와 파일명을 선택하세요. 파일명을 누르면 기존처럼 미리보기를 엽니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1424)

### 머신 키 확인 상태를 보여 주고, 확인한 키와 다른 키를 쓰는 머신에는 아무것도 보내지 않습니다

머신 상세에 **머신 키**(확인 상태)와 **키 지문**이 표시됩니다. 머신 키는 이 앱이 그 머신에 보내는 자동화와 명령을 암호화하는 키입니다. 웹의 머신 카드에서 머신의 `happy datakey status` 지문과 비교해 한 번 확인해 두면, 이후 서버가 다른 키를 내밀어도 이 앱이 알아챕니다.

#### 사용 방법

머신 상세에서 상태를 확인합니다. '미확인'이나 '바뀜'으로 표시되면 웹의 머신 카드에서 키를 확인하세요. 머신을 strict로 전환하면(`happy datakey harden`) 키가 바뀌므로 다시 확인해야 합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1337)

### 메신저를 처음 연결할 때 Desktop을 꺼도 응답하는 머신에서 바로 실행

Telegram 같은 메신저를 처음 연결할 때 "어디서 실행할까요?"를 먼저 묻고, Desktop을 꺼도 계속 응답하는 머신을 기본으로 골라 둡니다. 그대로 봇 토큰만 붙여넣으면 그 머신에 바로 설정되고, 휴대폰에서 연결(페어링)하면 끝납니다. 예전처럼 Desktop에 먼저 연결했다가 머신으로 옮기며 토큰을 다시 넣고 다시 페어링할 필요가 없습니다. 고른 실행 위치는 기억해 다음에도 기본값으로 씁니다.

#### 사용 방법

설정 → 메신저 채널에서 연결할 메신저를 열면 실행 위치가 기본으로 선택돼 있습니다. 봇 토큰을 붙여넣고 확인을 누른 뒤 안내대로 휴대폰에서 연결하세요. Desktop이 켜져 있을 때만 응답해도 된다면 "이 Desktop"을 고르면 됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1316)

### 문서 양식 확장으로 채팅 입력창에 양식을 추가할 수 있습니다

#### 사용 방법

환경설정 → 확장에서 문서 양식 확장을 설치하고 요청 권한을 승인해 활성화합니다.

### 사이드바 대화 관리 메뉴 확장

프로젝트 대화와 개인 Chat 목록의 더보기 메뉴에서 이름 변경, 보관, 복사, 삭제 등 대화 관리 작업을 사용할 수 있습니다. 최근 대화 목록의 첫 대화에는 불필요한 `이전 대화` 버튼을 표시하지 않습니다.

#### 사용 방법

사이드바에서 대화 행에 마우스를 올리고 더보기 메뉴를 여세요.

### 사이드바 폭 조절

왼쪽 사이드바의 폭을 원하는 만큼 줄이거나 늘릴 수 있습니다. 정한 폭은 다음 실행에도 유지됩니다. 창을 잠시 좁혀도 저장해 둔 폭은 바뀌지 않습니다.

#### 사용 방법

사이드바 오른쪽 경계에 마우스를 올리면 파란 선이 나타납니다. 그 선을 좌우로 끌어 폭을 바꿉니다. 경계에 키보드 초점을 둔 뒤 왼쪽, 오른쪽 화살표 키로도 조절할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1383)

### 앱 안에서 디자인 가이드를 볼 수 있습니다

데스크탑 앱 화면을 만드는 기준을 앱 안에서 바로 볼 수 있는 디자인 가이드를 추가했습니다. 기초(색, 글자, 간격, 모서리, 그림자, 움직임), 부품(버튼, 입력, 메뉴, 대화상자, 알림 등), 채팅 화면(대화 폭, 말풍선, 진행 표시, 실행 행과 카드, 입력창), 규칙 네 장으로 나뉘어 있습니다. 예시는 앱의 실제 부품과 스타일 값을 그대로 불러와 보여 주며, 4개 언어로 볼 수 있습니다. 기존 화면의 모양은 바뀌지 않습니다.

#### 사용 방법

환경설정 > 앱 > 정보에서 "디자인 가이드 열기"를 누르세요. 위쪽 탭으로 장을 바꾸고, 섹션 바로가기 버튼으로 원하는 항목으로 이동할 수 있습니다. 닫기 버튼이나 Escape로 닫으면 정보 화면으로 돌아갑니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1312)

### 에이전트에서 파일 체크포인트 조회

체크포인트가 활성화된 대화에서 Claude·Codex 에이전트가 현재 사용 가능 상태와 기록 목록, 파일별 변경 후보, 현재 파일과 선택한 기록의 차이를 조회할 수 있습니다. 응답이 길면 페이지와 생략 여부를 알려 줍니다. 조회는 파일과 기록을 변경하지 않으며, 복원은 기존 사용자 확인 절차를 거칩니다.

#### 사용 방법

이 기능이 포함된 Happy 런타임이 적용된 머신에서 파일 체크포인트를 켜고, 에이전트에 이전 기록과 현재 파일을 비교해 달라고 요청하세요. 에이전트가 현재 대화의 읽기 전용 조회 도구를 사용합니다. 이번 소스 변경에는 런타임 릴리스·설치·Desktop pin 변경이 포함되지 않으며, 기본 활성화 설정도 유지됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1323)

### 온보딩에서 컴퓨터·브라우저 제어를 선택적으로 설정할 수 있습니다

온보딩의 마지막 선택 단계로 컴퓨터·브라우저 제어 설정을 추가했습니다. 설정을 나중에 진행해도 선택을 기억하며 기본 대화를 시작할 수 있습니다. 제어 권한과 이후 대화의 지속 제어 동의를 따로 관리하고, 철회가 저장됐지만 진행 중 작업의 종료를 확인하지 못하면 이를 안내합니다. 연결한 Chrome은 앱을 다시 실행해도 연결이 유지되며, 연결 해제·로그아웃·계정 전환·확장 중지 때 철회됩니다.

#### 사용 방법

온보딩 또는 설정의 온보딩 체크리스트에서 컴퓨터·브라우저 제어 단계를 확인하세요. 준비되지 않은 환경에서는 나중에 설정을 선택하고 대화를 계속할 수 있습니다. 호환 버전이 제공된 환경에서는 필요한 권한과 Chrome 프로필을 선택하고, 연결 확인이 성공한 뒤 사용하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1399)

### 조직에서 등록한 계정으로 바로 시작하기

조직 관리자가 등록한 신규 계정은 임시 비밀번호로 로그인한 뒤 앱에서 본인 비밀번호를 설정하고 조직 사용을 시작할 수 있습니다. 첫 설정 과정에서 대화 암호화에 필요한 계정 키도 준비합니다.

#### 사용 방법

조직에서 받은 메일의 다운로드 링크로 앱을 설치하고 안내된 이메일과 임시 비밀번호로 로그인하세요. 새 비밀번호를 설정한 뒤 기존 조직 시작 안내를 따라 진행합니다. 이 기능은 조직 사용자 등록을 지원하는 서버와 함께 제공됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1393)

### 첫 시작 화면과 알림 개선

앱을 열면 로그인 폼이 바로 표시되며, 계정 없이 시작할 때는 개인 사용 버튼으로 내 PC 연결을 선택할 수 있습니다. 언어 선택은 하단 중앙, 버전 정보는 오른쪽 하단에서 확인할 수 있습니다. 확인창과 토스트의 버튼·여백·표시 효과를 통일하고, 좁은 창을 확대했을 때 로그인 폼이 잘리는 문제를 수정했습니다.

#### 사용 방법

첫 화면에서 로그인하거나 개인 사용을 선택하세요. 계정 만들기는 saycode.ai/join으로 연결됩니다. 화면을 확대·축소하면 현재 배율이 오른쪽 위에 잠시 표시됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1380)

### 컴퓨터 제어 확장을 파일 선택 없이 공식 목록에서 설치합니다

온보딩의 컴퓨터·브라우저 제어 단계에서 `컴퓨터 제어 확장 설치`를 누르면 Desktop에 함께 배포되는 공식 확장(`buzzni.computer-control` 0.1.0)을 바로 설치합니다. 이전에는 공식 목록에 없어 `.saycode-extension` 파일을 직접 선택해야 했습니다. 확장 관리의 공식 확장 목록에도 `컴퓨터 제어 확장`으로 표시됩니다.

#### 사용 방법

설정의 온보딩 체크리스트 또는 확장 관리에서 컴퓨터 제어 확장을 설치한 뒤, 요청되는 권한을 확인하고 활성화하세요. Chrome 확장 로드와 OS 권한 승인 단계는 그대로입니다.

### 파일 공개 링크와 산출물 모아보기

프로젝트와 개인 Chat의 우측 파일 미리보기에서 HTML 공개 링크를 만들 수 있습니다. 프로젝트 산출물은 대화·프로젝트·전체 프로젝트 범위로 모아 검색하고 원본 파일을 열 수 있습니다. 같은 작업 폴더의 같은 파일은 최신 항목만 표시합니다.

#### 사용 방법

Artifact Publisher 확장을 설치·활성화하고 공개 발행 권한을 승인한 뒤 HTML 파일 미리보기의 링크 아이콘을 누르세요. 프로젝트의 Files에서 `산출물 모아보기`를 눌러 범위를 선택하고 검색하세요. 전체 프로젝트는 현재 계정·조직에서 접근 가능한 프로젝트를 뜻합니다.

### 파일 기록 보존 한도와 worktree 삭제 옵션

원격 터미널을 연 채로 다른 탭이나 화면으로 이동하면, 터미널이 보이지 않는 동안 원격 서버에 10열×5행 정도의 아주 작은 화면 크기가 전달됐습니다. 이때 `screen`이나 `tmux`처럼 화면 내용을 직접 관리하는 프로그램은 그 크기에 맞춰 내용을 잘라 버리기 때문에, 다시 돌아왔을 때 출력이 왼쪽 몇 글자만 남은 채로 보였습니다. 이제 터미널이 화면에 보이지 않는 동안에는 크기를 바꾸지 않고, 다시 보일 때 실제 크기만 전달합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 업데이트 전에 이미 잘린 `screen`·`tmux` 내용은 해당 프로그램이 지워 버린 것이라 되살아나지 않으며, 업데이트 이후의 새 출력부터 원래 폭으로 표시됩니다.

인증 브라우저를 닫았거나 다시 열어야 할 때 `패스키 인증 다시 열기`를 누르세요. 로그인 준비 중에는 완료될 때까지 기다려주세요. 준비 실패 시에는 입력값을 유지한 로그인 화면에서 다시 시도할 수 있습니다.
