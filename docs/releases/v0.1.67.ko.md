## 새 기능

### 데스크톱에서 조직 초대를 바로 확인하고 참여할 수 있어요

로그인 후 받은 조직 초대를 데스크톱에서 확인하고 수락하거나 거절할 수 있습니다. 처음 조직을 고르는 화면에서는 초대를 먼저 보여주며, 이미 작업 중인 경우에는 화면의 `받은 조직 초대` 버튼으로 알려줍니다. 수락한 조직은 이 컴퓨터 등록 전에 고르는 조직 목록에 바로 추가됩니다. 초대 조회가 느려도 자동 확인이 진행 중 조회를 다시 시작하지 않아, 결과를 받으면 로딩이 끝납니다.

#### 사용 방법

초대 카드에서 `수락` 또는 `거절`을 선택하세요. 나중에 처리하려면 대화상자를 닫을 수 있고, `받은 조직 초대` 버튼으로 언제든 다시 열 수 있습니다. 거절은 확인 후 처리합니다.

### 시작준비에서 바로 대화 암호화를 켤 수 있어요

대화 암호화(계정 키)를 켠 적 없는 조직 구성원이 작업PC를 설정하면, AI 연결이 `AI_GROUP_CUSTOMER_KEY_REQUIRED`로 멈추고 "다시 연결"을 눌러도 풀리지 않았어요. 이제 시작준비 화면 안에서 바로 대화 암호화를 켤 수 있어요.

- 현재 비밀번호를 먼저 확인한 뒤 복구 키를 보여 줘요. 복구 키는 복사하거나 원하는 위치에 파일로 저장할 수 있어요.
- 복구 키를 다시 입력해 확인하면 대화 암호화가 켜지고, 다시 로그인하지 않아도 이어서 AI 연결을 확인해요.
- 조직 키가 아직 배포되지 않았으면 배포를 기다리는 안내를 보여 주고, 배포되면 자동으로 이어서 진행해요.
- 대화 암호화는 켜져 있지만 이 컴퓨터에서 아직 열리지 않은 계정에는 다시 로그인하라고 안내해요.
- 비밀번호와 복구 키는 이 컴퓨터 밖으로 보내지 않고, 로그나 진단 정보에도 남기지 않아요.

#### 사용 방법

시작준비에서 이 컴퓨터 준비가 끝나고 다음을 누르면 "대화 암호화 켜기" 단계가 나와요. 현재 비밀번호를 입력하고, 보여 주는 복구 키를 안전한 곳에 보관한 뒤 다시 입력하면 돼요. 조직 AI 그룹에 배정된 계정에만 나오고, 이미 대화 암호화가 켜진 계정이나 조직 기본 AI를 쓰는 계정에는 나오지 않아요.

### 프로젝트에서 쓰는 확장을 작업 패널 더보기 메뉴에서 엽니다

확장이 프로젝트 단위 도구를 등록할 수 있게 됐습니다. 등록된 도구는 오른쪽 작업 패널의 더보기 메뉴에서 Files·Terminal·브라우저 열기·Review·미리보기 실행 아래에 구분선과 함께 나타나고, 고르면 다른 도구처럼 작업 패널의 탭으로 열립니다. 탭 안에서 항목을 눌러 보는 상세 화면도 같은 탭에 표시됩니다.

#### 사용 방법

프로젝트 도구를 제공하는 확장(예: Moai 작업 보드)을 확장 관리에서 설치·활성화한 뒤, 프로젝트 대화에서 오른쪽 작업 패널의 더보기(⋮) 메뉴를 열어 도구를 고르세요. 프로젝트가 없는 개인 대화에서는 표시되지 않습니다.

## 수정된 문제

### 미리보기 화면 잘림 수정

미리보기 실행 후 화면이 위쪽 일부만 보이던 문제를 수정했습니다. 미리보기는 오른쪽 패널의 전체 높이를 사용합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 작업PC 등록이 승인을 기다리다 끊기지 않습니다

새 작업PC에서 `happy auth login`을 실행한 뒤 승인을 기다리는 동안, 서버가 잠시 요청을 늦추라고 답하거나 네트워크가 끊겨도 로그인이 끝나지 않고 계속 기다립니다. 이전에는 셀프호스트 서버에서 승인까지 20초쯤 넘게 걸리면 작업PC 로그인과 서버의 승인 명령이 함께 실패했습니다. 연결 코드가 만료되면 다시 실행하라고 알려 주고, 터미널이 없는 환경에서는 대기 문구를 한 줄만 남깁니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 셀프호스트 서버는 `npm i -g @buzzni/saycode-cli`로 CLI를 0.9.1 이상으로 올린 뒤 `saycode server stop` → `saycode server init` → `saycode server start`로 새 서버 런타임을 받습니다.

### 작업PC 설정 화면의 영어 문구를 앱 언어로 바꿨습니다

설정의 작업PC 화면에서 새로고침·이름 변경·삭제·등록 코드 만들기 같은 버튼과 안내, 빈 화면 문구가 영어로만 보이던 문제를 고쳤습니다. 이제 앱 언어(한국어·영어·일본어·중국어)로 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 작업PC에 Claude 로그인이 없을 때 무엇을 해야 하는지 알려 줍니다

대화를 실행한 작업PC에서 Claude Code에 로그인되어 있지 않으면, 이전에는 "Not logged in · Please run /login"이라는 원문만 일반 답변처럼 보였습니다. 이제 그 작업PC의 daemon을 실행하는 사용자로 로그인한 뒤 다시 보내라는 안내 문장을 앱 언어로 보여 주고, 원문 답변은 인증 실패로 표시합니다(작업PC의 Happy 실행기가 1.1.10-aplus.318 이상일 때 안내 문장이 나옵니다).

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 안내가 보이면 해당 작업PC에서 `claude`를 실행해 `/login`으로 로그인한 뒤 메시지를 다시 보내세요.

### 프로젝트 카드에 내부 ID 대신 "나"로 표시합니다

셀프호스트 서버에 연결했을 때 프로젝트 카드의 소유자 자리에 `standalone-local` 같은 내부 ID가 보이던 문제를 고쳤습니다. 소유자 이름이 없는 내 프로젝트는 "나"로 표시합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### saycode CLI 0.9.1: 셀프호스트 서버 실행 정리와 새 서버 런타임

`saycode server init`이 작업PC 합류 승인 대기를 고친 서버 런타임 `@buzzni/happy-server` 0.1.2를 설치합니다. `saycode server run`은 내부 기록용 로그를 터미널에 섞어 출력하지 않고 데이터 디렉터리의 `logs/process-ledger.log`에 남깁니다. systemd를 쓸 수 없는 머신에서 `saycode server install`이 거절될 때 빈 설정 디렉터리도 만들지 않습니다.

#### 사용 방법

`npm i -g @buzzni/saycode-cli`로 업데이트한 뒤, 이미 운영 중인 서버는 `saycode server stop` → `saycode server init` → `saycode server start`로 새 서버 런타임을 받습니다.

### saycode CLI 0.9.2: 대화 출력 정리와 Claude 로그인 안내

`saycode chat` 대화 출력에 대화 제목을 붙이는 내부 도구 호출이 작업 단계처럼 보이던 문제를 고쳤습니다. 작업PC에 Claude 로그인이 없을 때는 실행기가 보내는 로그인 안내를 `!` 한 줄로 보여 줍니다(작업PC의 Happy 실행기가 1.1.10-aplus.318 이상일 때).

#### 사용 방법

`npm i -g @buzzni/saycode-cli`로 업데이트하면 자동 적용됩니다.
