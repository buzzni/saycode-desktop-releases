### 확장이 연결 머신에서 Moai 명령을 승인받아 실행할 수 있습니다

확장이 `machine.run` 권한으로, 미리 선언된 Moai 명령을 연결 머신에서 실행할 수 있습니다. 셸은 쓰지 않으며, 선언된 명령만 실행합니다.

#### 사용 방법

Moai 확장을 설치하고 `machine.run` 권한을 승인한 뒤, 확장 관리 화면에서 **이 머신에 설치**를 누르세요. 확장이 명령을 실행할 때 뜨는 확인 창에서 내용을 확인하고 허용하면 됩니다. 현재 macOS(Apple Silicon)와 Linux x64 머신을 지원하며, Windows 머신은 지원하지 않습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1577)

### Moai 작업 보드 확장을 공식 목록에서 설치합니다

확장 관리의 공식 확장 목록에 `Moai 작업 보드 확장`(`buzzni.moai` 1.0.2)이 추가됐습니다. 파일을 직접 고르지 않고 Desktop에 함께 배포된 공식 확장을 바로 설치할 수 있습니다. 이 확장은 연결 머신의 프로젝트 폴더에서 Moai 보드 상태를 보고 할 일을 추가하며, 실행할 때마다 머신과 폴더를 보여주는 확인 창을 거칩니다. 취소한 뒤 머신에 남은 프로세스가 정리될 때까지 패널이 "취소 처리를 마무리하는 중"을 표시하고 새 실행을 막습니다. 프로젝트에 Moai 보드가 없으면 그 머신에서 `moai init`을 한 번 실행하라고 안내하고, 할 일 제목을 입력한 뒤 Enter로도 추가할 수 있습니다.

#### 사용 방법

확장 관리에서 `Moai 작업 보드 확장`을 설치하고 `machine.run` 권한을 승인해 활성화하세요. 같은 화면의 **이 머신에 설치**로 머신에 Moai를 설치한 뒤, 머신 설정의 `Moai` 버튼으로 보드를 엽니다. macOS(Apple Silicon)와 Linux x64 머신을 지원합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1581)

## 변경된 기능

### 작업PC 리소스 수집 개선

작업PC의 자원 정보를 앱이 직접 수집합니다. Linux에서는 할당된 CPU(사용 시간 한도나 지정된 코어 집합)와 메모리 한도를 반영하며, 메모리는 플랫폼에 맞는 실사용 기준으로 측정하며, macOS는 활성 상태 보기(Activity Monitor)의 "사용된 메모리"와 같은 기준입니다. 같은 PC의 여러 대화와 창은 측정값을 공유하고, 보이는 대화가 없으면 주기 수집을 멈춥니다. 읽지 못한 값과 오래된 값은 정상 측정값과 구분합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 디스크 측정의 기준은 작업PC의 홈 폴더이며 프로젝트가 다른 볼륨에 있으면 해당 프로젝트 볼륨의 사용량을 나타내지 않습니다. 상세 표시 개선은 별도 변경에서 적용됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1565)

### 작업PC 리소스 요약과 상세 개선

대화 입력창 아래에 CPU·메모리·디스크 사용률을 표시합니다. 작업PC의 부하(1/5/15분 평균)는 상세에서 확인할 수 있고, 상세 제목에는 이 대화가 실행되는 작업PC 이름이 함께 나옵니다. 폭이 좁아지면 디스크 위치 표시를 먼저 줄이고, 전체 값은 툴팁과 상세에서 확인할 수 있습니다. 작은 상태 점과 접근성 안내로 정상·주의·위험을 구분합니다.

#### 사용 방법

개발자 기능 설정에서 CPU·메모리 표시를 켠 뒤, 입력창 아래 리소스 요약을 눌러 상세를 확인합니다. Escape나 바깥 클릭으로 닫을 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1565)

### 저장소에 커밋된 작업트리 준비 스크립트는 자동 실행하지 않음

새 작업트리를 만들 때 실행되는 준비 스크립트(`.aplus/worktree-setup.sh`)가 저장소에 커밋된 파일이거나 링크를 거쳐 다른 파일을 가리키면 더 이상 자동으로 실행하지 않습니다. 다른 사람이 커밋한 명령이 pull 한 번으로 들어와 이 컴퓨터에서 실행되는 것을 막기 위해서입니다. 실행하지 않은 경우에는 어떤 파일을 왜 건너뛰었는지 안내가 나옵니다. 이 컴퓨터에만 둔(커밋하지 않은) 스크립트는 지금처럼 실행됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 커밋된 준비 스크립트를 계속 쓰려면 저장소에서 git 추적을 해제하고(예: `git rm --cached .aplus/worktree-setup.sh` 후 `.git/info/exclude`에 추가) 이 컴퓨터의 파일로 두세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1584)

### 이어받은 대화가 쓰는 작업트리를 완료 처리로 지우지 않음

다른 AI로 이어받기를 하면 두 대화가 같은 작업트리를 함께 씁니다. 이때 원래 대화를 완료하거나 삭제하면 아직 쓰고 있는 작업트리까지 지워질 수 있던 문제를 고쳤습니다. 이제 다른 대화가 같은 작업트리를 쓰고 있으면 삭제 여부를 묻지 않고 작업트리를 그대로 두며, 그 이유를 안내합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 작업트리는 그것을 쓰는 마지막 대화를 완료하거나 삭제할 때 기존처럼 정리됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1584)

### CI 수정 프롬프트가 다른 대화 입력창에 들어가지 않음

작업보드 카드의 "AI로 CI 수정"으로 만든 수정 프롬프트가, 그 카드의 대화가 아니라 같은 프로젝트에서 먼저 연 다른 대화의 입력창에 들어가던 문제를 고쳤습니다. 이제 프롬프트는 버튼을 누른 카드의 대화를 열 때 그 대화의 입력창에만 채워집니다. 자동 수정 뒤 남은 실패를 넘기는 프롬프트도 같습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 작업보드에서 "AI로 CI 수정"을 누른 뒤 그 카드의 대화를 열면 입력창에 수정 프롬프트가 채워져 있습니다. 확인 후 직접 보내세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1584)

### CI 자동 수정이 큰 저장소에서 도중에 멈추지 않음

작업보드의 "자동 수정 먼저"(lint·포맷 자동 수정)가 큰 저장소에서 수정 명령의 출력이 많아지면 실행 도중 강제로 멈추고, 일부 파일만 고쳐진 상태인데도 AI 수정 프롬프트로 조용히 넘어가던 문제를 고쳤습니다. 이제 수정 명령은 출력량과 관계없이 끝까지 실행됩니다. 시간 초과 등으로 중간에 멈추면 AI 수정으로 넘어가지 않고, 일부 파일만 바뀌었을 수 있다고 알립니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. "자동 수정 명령이 끝나기 전에 멈췄습니다" 안내가 보이면 변경 내용을 확인한 뒤 다시 실행하거나 "AI로 CI 수정"을 사용하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1584)

### Intel Mac에서 시작 준비와 PC 연결이 멈추던 문제 수정

Intel Mac에서는 앱에 포함된 Node.js가 실행 직후 종료되어, 시작 준비의 Node.js/npm 확인이 "실행 확인" 오류로 멈추고 Codex·Claude Code 같은 AI 도구도 설치되지 않았습니다. Intel Mac용 앱에서 이 Node.js가 정상 실행되도록 서명 설정을 고쳤습니다. Apple Silicon Mac에는 바뀌는 점이 없습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. Intel Mac에서 시작 준비가 멈췄다면 새 버전으로 업데이트한 뒤 시작 준비 화면에서 "다시 시도"를 누르세요.

### Mac 시작준비가 필요한 도구를 한 번에 설치합니다

Mac 시작준비에서 uv가 없으면 `이 컴퓨터에 필요한 도구를 설치하지 못했어요`가 반복되고, 설치된 npm이 손상돼 실행되지 않으면 Node.js/npm·codex-multi-auth·Claude Code·Codex가 모두 `설치 실패`로 표시되던 문제를 고쳤습니다. 이제 Windows처럼 uv와 Node.js가 없거나 실행되지 않으면 Saycode 전용으로 자동 설치해 사용합니다. 기존 npm·uv와 셸 설정은 바꾸지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 시작준비에서 `다시 시도`를 누르면 됩니다.

### Windows 시작준비가 손상된 필수 도구 폴더 때문에 반복 실패하지 않습니다

Windows에서 Node.js 폴더의 npm 파일만 지워지고 실행 중인 node.exe가 남은 경우, 시작준비가 `이 컴퓨터에 필요한 도구를 설치하지 못했어요`를 반복하던 문제를 고쳤습니다. 이제 필요한 명령 파일이 없는 폴더는 다시 설치하고, 사용 중이라 바꿀 수 없으면 옆 폴더에 새로 설치합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 시작준비에서 `다시 시도`를 누르면 됩니다.
