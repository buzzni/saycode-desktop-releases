## 새 기능

### 개발자 모드를 끄면 대화 하나만 보입니다

계정 메뉴의 내 설정 바로 아래에 개발자 모드 스위치를 추가했습니다. 기본으로 켜져 있어 지금처럼 대화를 여러 탭으로 열고 작업합니다. 끄면 가운데에 대화 하나만 보이고, 탭 줄 대신 한 줄 머리글에 대화 제목과 더보기(⋮)가, 프로젝트 대화에서는 프로젝트 이름과 설정도 함께 표시됩니다. 꺼도 열어 둔 탭은 지워지지 않아 다시 켜면 그대로 돌아옵니다.

#### 사용 방법

사이드바 아래 프로필을 눌러 계정 메뉴를 열고 개발자 모드 스위치를 누르세요. 누르는 즉시 바뀌며 메뉴는 열린 채로 남습니다.

### 개발자 모드에서 대화를 4×4까지 나눠 볼 수 있습니다

개발자 모드에서는 가운데 대화를 VS Code 편집 그룹처럼 가로·세로 4개까지 창으로 나눠 여러 대화를 동시에 볼 수 있습니다. 나누기 전에는 대화 탭이 맨 위 머리글 줄에 있고, 나누면 머리글 줄에는 열린 대화 표시·새 대화·패널 버튼만 남고 창마다 자기 탭 줄이 생깁니다. 예를 들어 A B C D 중 B를 오른쪽으로 나누면 왼쪽 창 탭 줄에 A C D, 오른쪽 창 탭 줄에 B가 있습니다. 탭은 자기 창 안에서 고르고, 다른 창 탭 줄로 끌어 옮기며, 새 대화는 지금 창에 열립니다. 창마다 메시지 영역 맨 위에 그 대화의 제목·프로젝트·설정·⋮ 머리글이 있습니다. 창의 마지막 탭을 닫거나 옮기면 그 창이 사라지고, 창이 하나 남으면 탭이 다시 머리글 줄로 올라갑니다. 탭 우클릭 메뉴의 분할 닫기(모두 닫기 바로 아래)나 창 탭 줄 끝의 분할 닫기 버튼은 아무것도 닫지 않고 그 창의 탭을 왼쪽·위 창(없으면 오른쪽·아래 창)으로 순서대로 옮깁니다. 파일·터미널 탭도 같습니다. Ctrl+Tab은 지금 창의 탭을 오갑니다. 개발자 모드를 끄면 대화 하나만 보이며, 다시 켜면 나눠 둔 창이 그대로 돌아옵니다.

#### 사용 방법

가운데 머리글 줄의 패널 추가 아이콘에서(지금 창을 나눕니다) 오른쪽으로 분할 또는 아래로 분할을 고르세요. 탭을 우클릭하거나 대화 분할 단축키(오른쪽 Cmd/Ctrl+Alt+C)를 누르거나, 탭을 창 가장자리로 끌어도 됩니다. 방향마다 4개가 차거나 화면이 좁으면 메뉴가 비활성으로 바뀌고 이유를 알려 줍니다. 우측 작업 패널을 닫으면 더 나눌 수 있습니다.

### 다른 작업PC에 일 맡기기

작업PC 설정에서 두 작업PC를 연결하면, 한 PC의 대화(AI)가 연결된 다른 PC에 새 대화를 만들어 일을 맡기고 결과를 확인할 수 있습니다. 예를 들어 노트북 대화에서 공용 빌드 PC에 전체 테스트를 맡기거나, macOS 대화에서 Windows PC에 설치본 빌드를 맡길 수 있습니다. 맡겨진 대화는 받는 PC의 정책(샌드박스·AI 계정)으로 실행되고, 보낸 대화의 자식 AI도구 목록에 작업PC 이름과 함께 보이며, 권한 요청은 받는 PC의 대화에서 직접 답합니다. 대화가 받는 PC에서 종단간 암호화된 경우, 보낸 쪽 AI는 그 대화를 시작·중단할 수 있지만 내용을 읽거나 이어서 지시하는 일은 Desktop에서 직접 확인해야 합니다. 작업PC 연결과 AI가 다른 PC에 대화를 만들어 일을 맡기는 부분 모두 이 버전에 들어 있는 실행 도구에서 동작합니다.

#### 사용 방법

내 설정 → 개발 → 작업PC에서 일을 받을 PC의 행에 있는 **다른 PC에서 작업 받기**를 누르고, 일을 보낼 PC의 스위치를 켭니다. 두 PC 모두 켜져 있고 최신 Saycode여야 합니다. 끄면 받는 PC가 즉시 거절합니다.

### 대화에서 Saycode 플랜 사용량 확인

Saycode 플랜으로 실행한 Chat과 프로젝트 대화의 입력창 아래에서 실행 모델과 이번 달·이번 주·5시간 사용량, 재설정 시각을 확인할 수 있습니다. 플랜 대화에 작업PC 계정의 잔여량이 함께 표시되던 혼동을 줄였습니다.
현재 AI는 대화의 실제 실행 정보로 구분합니다. 다음 요청의 선택값으로 바뀌지 않으며, AI를 확인하지 못한 대화는 임의로 Claude나 PC 사용량을 표시하지 않습니다.

하단 Saycode 플랜 버튼은 기존 사용량 버튼과 같은 높이·글자·여백과 호버 영역을 사용합니다.

실행 ID로 AI를 확인하는 오래된 Project 대화는 전송·재시도도 같은 AI를 사용하며, Codex 대화가 Claude 인증으로 잘못 진입하지 않습니다.

#### 사용 방법

플랜으로 실행한 대화를 열고 입력창 아래의 Saycode 플랜을 누르세요. 열 때 최신 사용량을 확인하며, 조회 실패 시 다시 확인을 누를 수 있습니다.

### 보던 파일과 파일 트리 항목을 대화에 바로 붙입니다

오른쪽 작업 패널에서 마지막으로 눌러 본 파일이 그 대화의 입력창에 점선 칩(`+ 파일이름`)으로 제안됩니다. 입력창이나 다른 칸을 눌러도 제안은 남고, 칩을 누르면 그 파일 경로가 대화에 첨부됩니다. 파일 내용이 아니라 경로만 보내므로 AI가 필요한 부분을 직접 읽습니다. 첨부한 파일은 X로 뺄 수 있고 보낸 메시지에는 말풍선 위에 같은 칩이 남습니다. 오른쪽 패널 파일 트리에서 파일이나 폴더를 오른쪽 클릭하면 맨 위에 대화에 추가가 있어 그 경로를 입력창에 `@경로`로 넣습니다.

#### 사용 방법

오른쪽 작업 패널에서 파일 탭이나 편집기를 누른 뒤 입력창 위의 점선 칩을 누르세요. 파일 트리에서는 파일이나 폴더를 오른쪽 클릭 → 대화에 추가를 누르세요.

### 어느 화면에서든 하단 터미널 패널 열기

현재 작업PC 터미널이 VS Code처럼 사이드바 오른쪽 전체 폭의 아래쪽 패널로 열립니다. 대화와 오른쪽 작업 패널 아래에 따로 놓여 둘의 너비와 분할은 그대로 두고 높이만 나눠 씁니다. 시작 화면뿐 아니라 프로젝트 대화와 개인 Chat에서도 열 수 있고, Cmd/Ctrl+J로 어느 화면에서나 열고 숨깁니다. 패널 높이와 열림 상태는 이 기기에 기억합니다. 위·왼쪽·오른쪽으로 옮기던 기능은 아래쪽 패널 하나로 정리했습니다.

#### 사용 방법

입력창 아래 줄 오른쪽 끝의 터미널 아이콘을 누르거나 Cmd/Ctrl+J를 누릅니다. 위쪽 경계선을 드래그해 높이를 바꾸고(최대 화면 높이의 70%), 같은 단축키나 패널 오른쪽 위 숨기기 버튼으로 숨깁니다. 단축키는 내 설정 → 일반 → 단축키의 하단 터미널 표시/숨기기에서 바꿀 수 있습니다.

### 이 Mac의 AI 브라우저 페이지를 콘솔 안에서 확인

이 Mac에서 실행 중인 대화의 AI 브라우저 콘솔은 지원 런타임에서 현재 작업의 페이지를 화면 영역에 보여줍니다. Chrome 창으로 전환하지 않아도 페이지를 보고, 제어권을 가져와 직접 조작할 수 있습니다. 승인 방식(Auto)·승인·활동 기록은 그대로 사용합니다. 작업 공간 버튼은 별도 관리 화면을 열며, 대화 화면으로 버튼으로 돌아올 수 있습니다. 구 런타임은 기존처럼 전용 Chrome 창 안내를 보여줍니다.

#### 사용 방법

대화 오른쪽 위나 승인 카드의 AI 브라우저를 열면 화면 영역에 현재 작업의 페이지가 보입니다. 대화 오른쪽 위 버튼이 없으면 개발자 기능 설정에서 대화 상단 AI 브라우저 바로가기 표시를 켜세요. 구 런타임에서는 안내에 따라 Saycode가 연 전용 Chrome 창을 선택하세요. 직접 조작하려면 제어권 가져오기를 누르고, 마치면 제어권 반납과 계속 진행을 누르세요. 입력 결과를 확인해야 한다는 안내가 보이면 다시 연결을 누르세요. 작업 공간 → 대화 화면으로 순서로 관리 화면을 왕복할 수 있습니다.

### 작업 패널과 파일 트리를 왼쪽에도 둘 수 있습니다

대화 머리글이나 작업 패널 머리글의 빈 곳을 오른쪽 클릭하면 패널 배치에서 작업 패널을 대화 왼쪽으로 옮길 수 있습니다. 작업 패널 머리글의 파일 트리 버튼을 오른쪽 클릭하면 파일 트리를 편집기 왼쪽이나 오른쪽에 둘 수 있습니다. 기본은 둘 다 오른쪽이고 이 기기에 기억합니다. macOS에서는 사이드바 위 saycode 로고가 창 버튼 바로 오른쪽으로 붙습니다.

#### 사용 방법

머리글 빈 곳을 오른쪽 클릭 → 패널 배치에서 고르세요. 파일 트리는 폴더 아이콘 버튼을 오른쪽 클릭 → 왼쪽/오른쪽을 고르세요.

### 탭을 창 가장자리로 끌어 화면을 나눌 수 있습니다

대화 탭이나 우측 작업 패널의 터미널·파일 탭을 창 위로 끌면 놓을 자리가 표시됩니다. 왼쪽·오른쪽·위·아래 가장자리에 놓으면 그 방향으로 창을 나눠 탭을 옮기고, 다른 창 가운데나 그 창 탭 줄에 놓으면 그 창의 탭이 됩니다. 방향마다 4개가 차면 표시 안에 이유가 보이고 놓아도 바뀌지 않습니다. 탭 줄 안에서 끌면 지금처럼 순서만 바뀝니다.

#### 사용 방법

개발자 모드에서 대화 탭을 창의 본문 위로 끌어 원하는 가장자리에 놓으세요. 터미널·파일은 우측 패널의 그 탭을 터미널 창·파일 창 위로 끌면 됩니다.

### 파일 목록 너비를 끌어서 조절합니다

오른쪽 작업 패널에서 파일을 열었을 때 파일 본문과 폴더 목록 사이의 경계를 끌어 목록 너비를 바꿀 수 있습니다. 조절한 너비는 이 기기에서 기억합니다.

#### 사용 방법

파일 본문과 폴더 목록 사이의 경계를 마우스로 끌거나, 경계에 키보드 포커스를 두고 방향키를 누르세요.

### 파일 탭과 대화 탭을 우클릭해 한꺼번에 닫고 경로를 복사합니다

파일 탭과 가운데 대화 탭의 우클릭 메뉴가 VS Code 순서로 정리되었습니다. 닫기·다른 탭 닫기·오른쪽 탭 닫기·모두 닫기가 맨 위에 있고, 파일 탭은 저장된 탭 닫기·절대 경로 복사·상대 경로 복사·Finder에서 보기(Windows는 파일 탐색기)·파일 트리에서 위치 보기·오른쪽/아래로 분할·다운로드·디스크에서 다시 읽기를 더합니다. 대화 탭은 작업 폴더 경로 복사(작업트리, 없으면 프로젝트 폴더)·Finder에서 보기·분할·새 창에서 열기를 둡니다. 저장하지 않은 파일이 있으면 닫기 전에 그 파일들을 한 번에 묻고, 닫은 대화 탭은 되돌리기 알림으로 되살릴 수 있습니다. Finder 항목은 파일이나 폴더가 이 컴퓨터에 있을 때만 보이고, 쓸 수 없는 항목은 이유를 함께 보여 줍니다.

#### 사용 방법

파일 탭이나 가운데 대화 탭을 우클릭하세요. 키보드로는 탭에 포커스를 두고 Shift+F10이나 메뉴 키를 누른 뒤 위·아래 방향키로 고릅니다.

### 파일 트리에서 끌어 다른 폴더로 옮깁니다

작업PC가 이 컴퓨터일 때 오른쪽 작업 패널 파일 트리에서 파일이나 폴더를 끌어 다른 폴더 위에 놓으면 그 폴더 안으로 옮겨집니다. 목록의 빈 곳에 놓으면 프로젝트 최상위 폴더로 옮깁니다. 같은 이름이 이미 있으면 바꿀지 먼저 물어봅니다. 열어 둔 파일 탭은 옮긴 위치를 따라갑니다. 프로젝트 폴더 밖으로는 옮기지 않습니다.

#### 사용 방법

파일 트리에서 파일이나 폴더를 끌어 옮길 폴더 줄 위에 놓으세요.

### 파일 트리에서 끌어다 열고, 폴더에 바로 올립니다

오른쪽 작업 패널의 파일 트리에서 파일을 끌어 파일 보기 쪽에 놓으면 그 파일이 열립니다. 컴퓨터(Finder 등)에서 파일을 끌어 파일 트리의 폴더 위에 놓으면 그 폴더 안으로 올라가고, 놓을 폴더가 강조되며 올린 뒤 폴더가 펼쳐집니다. 폴더가 아닌 곳에 놓으면 지금처럼 보고 있는 목록의 폴더로 올라갑니다.

#### 사용 방법

파일 트리의 파일을 끌어 편집기 영역에 놓으세요. 컴퓨터의 파일은 원하는 폴더 줄 위에 놓으세요.

### 파일에서 고른 코드를 대화에 붙입니다

오른쪽 작업 패널의 파일 편집기에서 코드를 고른 뒤 대화에 추가하면 입력창 위에 `A  파일이름 2–4` 같은 칩이 붙습니다. 칩은 A, B… 순서로 이름이 붙고 X로 뺄 수 있습니다. 보낸 메시지에는 말풍선 위에 같은 칩이 남고, AI는 파일 경로·줄 번호·고른 코드를 함께 받습니다.

#### 사용 방법

파일 편집기에서 코드를 드래그해 고르고 오른쪽 클릭 → 대화에 추가를 누르거나 Cmd+L(Windows는 Ctrl+L)을 누르세요. 단축키는 내 설정 → 단축키에서 바꿀 수 있습니다.

### 파일이 작업 패널 머리글 줄의 탭으로 열리고 여러 창으로 나눠 볼 수 있습니다

우측 작업 패널에서 연 파일이 두 번째 줄이 아니라 작업 패널 머리글 줄의 탭(터미널·브라우저 탭 옆)으로 열리고, 수정 점·우클릭 메뉴·Cmd+W·끌어 나누기도 그 탭에서 됩니다. 파일을 VS Code 편집 그룹처럼 가로·세로 4개까지 창으로 나눌 수 있고, 나누면 파일 탭은 머리글 줄에서 빠져 창마다 자기 탭 줄(끝에 보기 전환과 분할 닫기 버튼)을 가집니다. 머리글 줄에는 파일 도구로 돌아가는 파일 탭이 남습니다. 탭은 자기 창 안에서 고르고, 다른 창 탭 줄로 끌어 옮기며, 트리에서 누른 파일은 지금 창에 열립니다(이미 열려 있으면 그 탭으로 이동). 창의 마지막 탭을 닫거나 옮기면 그 창이 사라지고, 창이 하나 남으면 탭이 다시 머리글 줄로 올라갑니다. 파일 트리는 그룹 오른쪽에 하나로 고정됩니다.

#### 사용 방법

작업 패널에서 파일을 연 뒤 머리글 줄의 파일 탭을 다른 그룹의 왼쪽·오른쪽·위·아래 가장자리로 끌어 놓으세요. 탭을 우클릭해 오른쪽으로 분할 또는 아래로 분할을 골라도 됩니다. 그 파일이 하나뿐이거나 방향마다 4개가 찼거나 공간이 모자라면 메뉴에 이유가 보입니다.

### 폴더 안에 바로 만들고, 단축키로 파일 트리를 엽니다

오른쪽 작업 패널 파일 트리에서 폴더를 오른쪽 클릭하면 새 파일·새 폴더가 있어 그 폴더 안에 바로 만들 수 있습니다. 만든 뒤 폴더가 펼쳐져 새 항목이 보입니다. Shift+Cmd+E(Windows는 Shift+Ctrl+E)로 파일 트리를 열고 숨길 수 있고, 작업 패널이 닫혀 있으면 함께 열립니다. 이 키를 쓰던 입력창의 작업 강도 바꾸기는 Shift+Cmd+L(Windows는 Shift+Ctrl+L)로 옮겼습니다. 파일 트리 위의 "프로젝트 파일" 제목 자리에는 열린 파일의 소스 보기 같은 보기 전환이 놓입니다.

#### 사용 방법

파일 트리에서 폴더를 오른쪽 클릭 → 새 파일 또는 새 폴더를 누르고 이름을 입력하세요. 파일 트리는 Shift+Cmd+E로 열고 닫습니다. 키는 내 설정 → 단축키에서 바꿀 수 있습니다.

### 프로젝트 없이 현재 작업PC 터미널 열기

현재 작업PC의 터미널을 프로젝트와 관계없이 바로 열 수 있습니다. 작업PC 홈 폴더에서 시작하며 화면 아래 패널로 열려 나머지 화면을 계속 조작할 수 있습니다. 숨겼다 다시 열면 같은 터미널을 이어갑니다.

#### 사용 방법

연결된 작업PC를 선택한 뒤 입력창 아래 줄 오른쪽 끝의 터미널 아이콘을 누릅니다. 아이콘을 다시 누르거나 터미널 오른쪽 위 숨기기 버튼으로 숨깁니다.

### 확장이 새 대화에 환경변수·MCP 서버를 넣고 새 작업트리를 준비합니다

확장(Extension API 4)이 `sessionHooks`로 새 대화·재연결마다 환경변수와 MCP 서버를, `worktreeHooks`로 새 작업트리에 원본의 Git이 무시한 파일을 복사하도록 선언할 수 있습니다. 확장 카드의 `sessions.launchEnvironment`·`worktrees.prepare` 권한 행에 넣을 이름, 비밀 표시, MCP 실행·접속 줄, 복사할 경로가 보이며 승인은 이 선언에 묶입니다. 값은 Saycode가 OS 키체인으로 암호화해 보관하고, 비밀 값은 화면·로그·대화 정보에 남지 않습니다. 훅이 실패하거나 이름이 겹쳐도 대화와 작업트리는 그대로 시작하고 안내만 표시합니다. 작업PC 실행 도구가 MCP 주입을 지원하지 않으면 환경변수만 넣습니다.

#### 사용 방법

내 설정 → 개발 → 확장에서 이 기능을 쓰는 확장을 설치하고, 권한 행에서 넣을 항목을 확인한 뒤 승인합니다. 값이 필요한 이름은 입력칸에 넣고 저장을 누릅니다. 새 대화 화면의 옵션 줄 '확장 · env N · MCP M'에서 이 대화에 들어갈 항목을 미리 볼 수 있습니다. MCP 서버 주입은 작업PC의 실행기가 Happy CLI 1.1.10-aplus.402 이상일 때 적용되고(이 Desktop에 들어 있는 실행기는 이 조건을 만족합니다), 그보다 오래된 원격 작업PC에는 환경변수만 들어갑니다.

### AI가 바꾼 파일이 열린 탭에 바로 반영됩니다

오른쪽 작업 패널에 열어 둔 파일을 AI가 고치면, 고친 직후 그 탭이 새 내용으로 바뀝니다. 로딩 화면 없이 그 자리에서 바뀌고 스크롤 위치도 그대로입니다. AI의 응답이 끝날 때도 열린 파일을 한 번 다시 읽어, 내용이 바뀐 파일만 새로 보여 줍니다. 저장하지 않은 수정이 있는 파일은 덮어쓰지 않고 "AI가 이 파일을 바꿨어요" 알림만 보여 주며, 편집기의 다시 읽기로 새 내용을 볼 수 있습니다.

#### 사용 방법

오른쪽 작업 패널에 파일을 열어 둔 채 AI에게 그 파일 수정을 요청하세요.

## 변경된 기능

### 가운데 대화 탭이 사이드바 Chat/Project를 따라갑니다

가운데 대화 탭 줄은 사이드바에서 고른 목록을 따라 Chat이면 개인 채팅 탭만, Project면 프로젝트 대화 탭만 보여 줍니다. 현재 프로젝트뿐 아니라 열어 둔 모든 프로젝트의 대화 탭이 함께 보입니다. 사이드바를 Chat과 Project 사이에서 바꾸면 그 종류에서 마지막으로 보던 대화로 돌아가고, 열린 대화가 없으면 그 종류의 시작 화면이 열립니다.

#### 사용 방법

사이드바 위쪽의 Chat 또는 Project를 누르면 가운데 탭 줄이 해당 종류의 대화로 바뀝니다.

### 기획 모드를 입력창 더보기로 이동

입력창의 ‘계획 먼저’를 ‘기획 모드’로 바꾸고 더보기 메뉴로 옮겼습니다. 켜짐 상태는 메뉴의 체크 표시로 확인합니다.

#### 사용 방법

기존 Claude 개인 Chat 또는 프로젝트 대화에서 입력창 더보기 → 기획 모드를 선택하세요. 계획 승인 뒤에는 기존처럼 자동으로 꺼집니다.

### 대화 더보기(⋮)에서 작업 패널 항목을 뺐습니다

프로젝트 대화의 프로젝트 도구(⋮)와 Chat의 대화 더보기(⋮)에 있던 파일·터미널·브라우저·변경·미리보기 항목을 뺐습니다. 이 도구들은 오른쪽 작업 패널의 작업 패널 추가 메뉴에서 그대로 열 수 있습니다. 더보기 메뉴에는 이 대화와 프로젝트 항목만 남습니다.

#### 사용 방법

파일·터미널 같은 도구는 대화 오른쪽 작업 패널 위쪽의 작업 패널 추가(⋮)를 눌러 엽니다.

### 대화 머리글을 나뉜 창과 같은 모양으로 맞추고 머리글 선을 정리했습니다

메시지 위 대화 머리글이 나뉘었을 때와 아닐 때 같은 모양이 됐습니다. 왼쪽에 프로젝트 이름과 설정(⚙), 오른쪽 끝에 ⋮가 있고, 대화 제목은 탭에만 보입니다(개발자 모드를 끄면 제목 뒤에 프로젝트 이름과 ⚙가 옵니다). 머리글이 좁으면 프로젝트 이름은 숨고 설정과 ⋮는 그대로 남으며, 설정 버튼에 마우스를 올리면 프로젝트 이름이 보입니다. 설정(⚙) 버튼은 평소에 흰 원·그림자 없이 아이콘만 보이고, 마우스를 올리면 ⋮와 같은 모양으로 바뀝니다. 맨 위 머리글 줄은 가운데와 작업 패널이 같은 높이의 선 하나로 이어지고, 나뉜 창의 탭 줄과 대화 머리글에는 선이 없습니다. 마우스로 누른 탭에는 키보드 초점 테두리가 생기지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 대화 요약을 ⋮ 메뉴에서 열고, 파일 패널 정리가 바뀌었습니다

프로젝트 대화 오른쪽 위에 떠 있던 대화 요약 아이콘을 없애고, 대화 머리글의 ⋮ 메뉴에 `대화 요약 보기`/`대화 요약 닫기`로 옮겼습니다. 오른쪽 작업 패널의 파일 화면은 위쪽 경로·저장 아이콘 줄 아래 구분선이 파일 목록 위까지 한 줄로 이어지고, 코드 영역은 이중 테두리 없이 하나의 테두리 안에 보입니다. 파일 목록 맨 위에 있던 `작업물 모아보기`는 아래쪽 `추가 디렉터리` 바로 위로 옮겨 목록이 파일 필터부터 시작합니다.

#### 사용 방법

계정 메뉴 → 개발자 기능 설정 → 대화 요약 메뉴 표시를 켠 뒤, 대화 머리글 오른쪽 ⋮ → 대화 요약 보기로 엽니다. 파일 화면 변경은 별도 설정 없이 자동 적용됩니다.

### 변경된 파일 카드가 펼친 채로 보입니다

AI 답변의 변경 파일 줄이 `변경된 파일 N개 · 눌러서 diff 보기`로 바뀌었고, 파일 목록이 처음부터 펼쳐져 있습니다. 목록의 파일을 누르면 diff가 열리고, 줄을 누르면 목록을 접을 수 있습니다.

#### 사용 방법

AI 답변 아래 변경된 파일 목록에서 파일을 눌러 diff를 확인하세요.

### 빈 작업 패널의 도구 목록이 넓으면 2열로, 단축키도 함께 보입니다

작업 패널을 열었는데 고른 도구가 없을 때 보이는 파일·터미널·변경 같은 도구 목록이, 패널이 넓으면 두 줄로 나란히 보입니다. 단축키가 있는 도구는 항목 오른쪽에 키를 함께 보여 줍니다(파일 트리 Shift+Cmd+E, 터미널 Ctrl+`). 작업 패널 추가 메뉴에도 같은 키가 보입니다.

#### 사용 방법

작업 패널을 열고 도구를 고르기 전 화면에서 목록과 단축키를 확인하세요.

### 사이드바를 접으면 아이콘 레일이 남습니다

사이드바를 접으면 왼쪽에 48px 너비의 세로 아이콘 막대가 남습니다. 펼치기, Chat, Project, 작업보드(표시 설정을 켠 경우), 예약, 외부 연동 아이콘과 아래쪽 알림 벨, 프로필 사진이 있습니다. 각 아이콘에 마우스를 올리거나 키보드로 이동하면 이름이 보이고, 지금 보고 있는 화면의 아이콘이 표시됩니다. 프로필 사진을 누르면 펼친 사이드바와 같은 계정 메뉴가 오른쪽으로 열려 내 설정도 여기서 엽니다.

#### 사용 방법

사이드바 맨 위의 사이드바 접기 버튼을 누르거나 Cmd+B(Windows는 Ctrl+B)를 누르세요. 다시 펼칠 때도 같은 단축키나 사이드바 펼치기 버튼을 누릅니다. macOS에서는 이 버튼이 창 왼쪽 위 빨강·노랑·초록 버튼 바로 오른쪽에 있고, Windows에서는 막대 맨 위에 있습니다.

### 새 대화의 기본 시작 폴더 표시 간소화

새 프로젝트 대화의 시작 폴더가 프로젝트 루트일 때 폴더 아이콘만 표시합니다. 하위 폴더를 선택하면 경로는 계속 표시됩니다.

#### 사용 방법

입력창 위 폴더 아이콘을 눌러 시작 폴더를 선택하세요.

### 선택한 탭을 흰색으로 표시합니다

가운데 대화 탭, 오른쪽 작업 패널 탭, 파일 편집 그룹 탭, 분할 창의 탭에서 지금 선택한 탭을 흰색(다크 모드는 편집 화면과 같은 어두운 면)으로 칠합니다. 선택하지 않은 탭에 마우스를 올리면 회색으로 바뀌어 선택한 탭과 헷갈리지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 알림 토스트가 색 배경 없이 깔끔해졌습니다

화면 위에 뜨는 알림(토스트)이 파란색·빨간색·초록색 배경 대신 메뉴와 같은 흰 배경(다크 모드는 어두운 배경)과 얇은 테두리로 보입니다. 안내·오류·완료는 앞의 아이콘 모양과 색으로 구분합니다.

#### 사용 방법

화면 위에 뜨는 알림에서 아이콘으로 종류를 구분하세요.

### 오른쪽 패널에서 파일마다 탭이 열립니다

오른쪽 작업 패널에서 연 파일은 각각 자기 탭이 됩니다. 탭에는 파일 아이콘과 이름이 보이고, 저장하지 않은 변경이 있으면 이름 옆에 점이 붙습니다. 이미 열려 있는 파일을 다시 누르면 그 탭으로 이동만 하고 다시 불러오지 않아 로딩 표시가 돌지 않고 고치던 내용도 그대로입니다. 저장하지 않은 파일 탭을 닫으면 닫을지 먼저 묻습니다. 파일 탭은 파일 도구 안의 그룹 탭 줄에 열리고, 오른쪽에 폴더 목록이 함께 보입니다.

#### 사용 방법

대화 오른쪽 작업 패널에서 파일 도구의 폴더 목록에서 파일을 누르면 새 탭으로 열립니다. 탭의 X로 닫습니다.

### 우측 패널을 넓혀 대화를 150px까지 좁힐 수 있습니다

대화는 좁게 두고 파일을 넓게 보고 싶을 때 우측 작업 패널을 창 끝 가까이까지 넓힐 수 있습니다. 대화는 150px까지 좁아지며, 좁은 대화에서는 탭이 줄어 이름이 잘리고 입력창은 글·추가·보내기만 한 줄에 남아 화면이 넘치지 않습니다.

#### 사용 방법

대화와 우측 작업 패널 사이 경계를 왼쪽으로 끄세요. 경계에 키보드로 이동해 방향키나 End로 조절해도 됩니다.

### 이 컴퓨터의 터미널은 "원격 터미널"로 표시하지 않습니다

작업PC가 이 컴퓨터일 때 작업 패널과 하단의 터미널 머리글이 "원격 터미널" 대신 "터미널"로 보입니다. 다른 PC의 터미널은 계속 "원격 터미널"로 표시합니다.

#### 사용 방법

이 컴퓨터를 작업PC로 쓰는 대화에서 작업 패널이나 하단 터미널을 여세요.

### 입력창 @가 프로젝트 전체 파일에서 찾습니다

입력창에서 @를 입력하면 지금 열어 둔 폴더가 아니라 프로젝트 전체 파일에서 후보를 찾습니다. 이름이 검색어로 시작하는 파일, 이름에 포함된 파일, 경로에 포함된 파일 순으로 최대 8개를 보여 줍니다. 전체 목록을 아직 불러오지 못했으면 이전처럼 열린 폴더의 파일에서 찾습니다.

#### 사용 방법

입력창에 @와 파일 이름 일부를 입력하고 목록에서 파일을 고르세요.

### 입력창 모델 버튼에 작업 강도도 함께 보입니다

입력창 아래 모델 버튼이 `Opus 5.5 High`처럼 모델 이름 옆에 지금 작업 강도를 흐린 글자로 함께 보여 줍니다. 메뉴를 열지 않아도 작업 강도를 확인할 수 있습니다. AI 자동일 때와 입력창이 아주 좁을 때는 보이지 않습니다.

#### 사용 방법

입력창 아래 모델 버튼에서 모델 이름 옆의 작업 강도를 확인하세요.

### 입력창 모델명 앞에 AI 로고 표시

입력창의 모델명 앞에 선택한 AI의 로고가 표시됩니다. AI 자동에는 자동 선택 아이콘이 표시됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 작업 패널 터미널은 방향마다 4개까지 나눕니다

오른쪽 작업 패널의 터미널은 가로·세로 방향마다 4개까지 나눌 수 있습니다. 새로 나누면 같은 방향의 터미널이 고르게 나뉘어 4개까지 읽을 수 있는 크기를 유지합니다. 한 방향이 가득 차면 그 방향 분할 메뉴가 비활성으로 바뀌고 이유를 알려 줍니다.

#### 사용 방법

작업 패널의 터미널 탭에서 분할 메뉴를 열고 오른쪽 또는 아래에 새 터미널을 고르세요.

### 터미널 머리글이 터미널과 같은 색으로 보입니다

우측 작업 패널의 나뉜 터미널 창 탭 줄, 터미널 위 상태 줄(원격 터미널·작업PC·connected·⋮), 아래쪽 터미널 패널 머리글이 모두 터미널 바탕보다 조금 밝은 같은 어두운 색으로 바뀌고, 머리글과 터미널 사이의 선이 없어졌습니다. 글자와 버튼은 터미널 글자색 계열로 읽기 쉽게 보이고, 선택한 터미널 탭은 터미널 바탕과 이어집니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 터미널 연결 상태 줄 간소화

현재 작업PC 터미널이 정상 연결되어 있으면 터미널 안의 connected 줄을 숨겨 화면을 넓게 사용합니다. 재연결·오류·입력 차단 등 필요한 상태 안내는 유지합니다. 터미널을 숨기면 열기 전에 쓰던 곳으로 포커스를 돌려줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 파일마다 있던 머리글 아이콘을 정리했습니다

파일을 열 때마다 위에 보이던 경로·저장·다운로드·새로고침·위치 보기 아이콘 줄을 없앴습니다. 저장하지 않은 변경은 파일 탭의 점으로만 표시하고 Cmd+S(Windows는 Ctrl+S)로 저장합니다. 저장에 실패하면 그 파일 안에 이유가 남습니다. 파일 하나에만 해당하는 다운로드·디스크에서 다시 읽기·트리에서 위치 보기는 파일 탭 우클릭 메뉴로 옮겼고, 새 파일·새 폴더·업로드·새로고침·모두 접기·Finder에서 보기처럼 목록 전체에 쓰는 아이콘은 파일 트리 머리글에 한 번만 둡니다. 마크다운·HTML의 소스 보기, CSV 표 보기, 변경 내용 보기 전환은 그 그룹의 탭 줄 끝에 남습니다.

#### 사용 방법

파일을 고친 뒤 Cmd+S(Windows는 Ctrl+S)로 저장하세요. 파일 탭에 마우스를 올리면 전체 경로와 저장 단축키가 보입니다. 목록 명령은 파일 트리 맨 위 아이콘을 쓰세요.

### 파일을 편집 버튼 없이 바로 고칩니다

오른쪽 작업 패널의 파일 보기에서 텍스트 파일은 편집 버튼을 누르지 않고 바로 고칠 수 있습니다. 내용을 바꾸면 파일 탭에 점이 붙고 Cmd+S(Windows는 Ctrl+S)로 저장합니다. 마크다운·HTML 파일은 소스 보기로 바꾸면 바로 고칠 수 있습니다. 저장하지 않은 변경이 있을 때 새로고침을 누르면 변경을 버릴지 먼저 묻습니다.

#### 사용 방법

작업 패널에서 파일을 열고 내용을 고친 뒤 Cmd+S(Windows는 Ctrl+S)를 누르세요.

### 프로젝트 대화 오른쪽 아이콘 정렬과 요약 버튼 표시 설정

프로젝트 대화 오른쪽의 더보기·요약·메시지 이동 아이콘을 같은 세로선에 맞췄습니다. 좁은 창에서도 요약 패널과 이동 버튼이 겹치지 않게 간격을 유지합니다. ⋮ 메뉴의 대화 요약 보기는 기본으로 숨기며 메시지 이동 점은 계속 사용할 수 있습니다.

#### 사용 방법

계정 메뉴 → 개발자 기능 설정 → 대화 요약 메뉴 표시를 켜면 프로젝트 대화 머리글 ⋮ 메뉴에 대화 요약 보기가 나타납니다.

### 하단 터미널이 지금 프로젝트 폴더에서 열립니다

하단 터미널(Cmd+J)이 열려 있는 프로젝트가 같은 작업PC에 있으면 그 프로젝트 폴더에서 시작하고, 프로젝트가 없으면 홈 폴더(~)에서 시작합니다. 다른 프로젝트로 옮기면 그 프로젝트의 터미널이 보이고, 돌아오면 앞의 터미널을 이어 씁니다. 머리글에는 `~/projects/app`처럼 실제 위치가 보입니다.

#### 사용 방법

프로젝트 대화를 연 채 Cmd+J(Windows는 Ctrl+J)나 입력창 아래 터미널 아이콘으로 하단 터미널을 여세요.

## 수정된 문제

### 나뉜 터미널이 창을 꽉 채워 보입니다

우측 작업 패널에서 나뉜 터미널 창이 둥근 점선 카드 대신 1px 구분선만 두고 창을 꽉 채워 보입니다. 터미널을 가로·세로 4개씩(4×4) 나눠도 1440×900 창의 기본 패널 폭에서 접히지 않고 모두 보입니다. 나누면 터미널 탭은 작업 패널 머리글 줄에서 빠지고(터미널 탭 하나가 남습니다) 창마다 자기 탭 줄을 가지며, 탭을 다른 창 탭 줄로 끌어 옮길 수 있습니다. 창이 하나 남으면 탭이 다시 머리글 줄로 올라갑니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 나뉜 파일 창 사이 선이 한 줄로 보입니다

우측 작업 패널에서 파일을 여러 창으로 나눴을 때 창마다 테두리를 그려 창 사이와 가장자리에 선이 두 겹으로 보이던 문제를 고쳤습니다. 이제 이웃한 창 사이에는 1px 선 하나만 있고, 패널 가장자리·탭 줄·파일 목록과 닿는 쪽에는 창 테두리가 없습니다. 터미널·대화 창도 같은 규칙을 따릅니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 대기열에 넣은 메시지가 조직 Claude 머신으로 전송되지 않던 문제 수정

조직의 공용·전용 머신에서 Claude와 대화할 때, 응답 중에 대기열에 넣어 둔 메시지가 차례가 와도 "API error 400" 오류와 함께 전송되지 않던 문제를 고쳤습니다. 이제 대기열 메시지도 바로 보낸 메시지와 똑같이 전송됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 데모 프로젝트의 파일 트리에서 하위 폴더가 펼쳐집니다

데모 작업공간의 우측 작업 패널 파일 트리에서 src·docs 같은 하위 폴더를 펼치면 비어 있던 문제를 고쳤습니다. 이제 하위 폴더의 파일을 열어 볼 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 브랜치 검색어의 처음과 끝에서 편집하기

작업트리 Base 등 검색형 선택창에서 Home·End가 검색어의 커서를 옮기지 않던 문제를 수정했습니다. 검색어가 비어 있을 때는 기존처럼 목록의 처음과 끝으로 이동합니다.

#### 사용 방법

새 프로젝트 대화에서 작업트리를 켜고 옆의 방식 → Base를 엽니다. 검색어를 입력한 뒤 Home·End로 커서를 옮기거나 Shift와 함께 눌러 글을 선택할 수 있습니다. Enter로 확정하고 Escape로 취소합니다.

### 비활성 연결 탭의 안내 추가

선택할 수 없는 API 토큰·작업PC 토큰 탭에 마우스를 올리거나 키보드로 이동하면 간단한 이유가 표시됩니다. 기존 대화의 연결이 고정된 경우 새 대화에서 변경하도록 안내하며, 비활성 탭은 계속 선택할 수 없습니다.

#### 사용 방법

모델 메뉴 아래 사용 연결에서 비활성 탭에 마우스를 올리거나 Tab 키로 이동하세요.

### 사용 연결 탭의 선택 표시 복원

모델 메뉴의 API 토큰·작업PC 토큰 탭에서 선택된 항목을 흰 선택 면과 파란색 굵은 글자로 표시해 회색 배경과 구분합니다. 선택된 탭에 마우스를 올려도 선택 표시를 유지하며 라이트·다크 화면에 같은 분할 탭 기준을 적용합니다.

#### 사용 방법

모델 메뉴 아래 사용 연결에서 현재 선택된 탭의 흰 선택 면과 파란색 글자를 확인하세요. 별도 설정 없이 적용됩니다.

### 사이드바를 접어도 대화 이동 단축키가 듭니다

왼쪽 사이드바를 접어 아이콘 막대만 남긴 상태에서 이전·다음 대화 이동과 고정한 대화 번호 단축키가 아무 일도 하지 않던 문제를 고쳤습니다. 이제 사이드바를 펼쳤을 때와 같은 순서로 이동합니다.

#### 사용 방법

사이드바를 접은 채로 이전·다음 대화 단축키나 고정한 대화 번호 단축키를 누르세요.

### 새 대화와 한글 입력 중에도 모델·작업 강도 단축키가 듭니다

새 대화 입력창에서는 모델 바꾸기(Cmd+Shift+M)·작업 강도 바꾸기(Cmd+Shift+L) 단축키가 아무 일도 하지 않던 문제를 고쳤습니다. 또 입력창에 한글을 쓰다가 마지막 글자가 아직 조합 중일 때 모델 바꾸기(Cmd+Shift+M)나 작업 강도 바꾸기 단축키를 누르면 무시되던 문제를 고쳤습니다. 응답 중지 단축키는 실수로 멈추지 않도록 조합 중에는 그대로 무시합니다.

#### 사용 방법

입력창에 커서를 두고 Cmd+Shift+M(모델)·Cmd+Shift+L(작업 강도)을 누르세요. Windows는 Ctrl을 씁니다.

### 새 브라우저가 빈 주소창으로 열립니다

작업 패널에서 브라우저를 새로 열면 미리보기 주소로 바로 이동하다가 "프리뷰 세션이 필요합니다" 화면이 뜨던 문제를 고쳤습니다. 이제 빈 화면에 "주소를 입력하세요" 주소창으로 열리고, 주소를 입력하거나 화살표에서 실행 중인 서버를 고를 수 있습니다.

#### 사용 방법

작업 패널에서 브라우저를 새로 열고 주소창에 주소를 입력하거나 화살표에서 서버를 고르세요.

### 시작 폴더 초기화 후 키보드 탐색 유지

시작 폴더를 프로젝트 루트로 되돌린 뒤 키보드 포커스가 사라지던 문제를 수정했습니다. 옆의 폴더 버튼으로 돌아와 다음 조작을 이어갈 수 있습니다.

#### 사용 방법

새 프로젝트 대화의 시작 폴더 옆 X를 누르면 프로젝트 루트로 돌아옵니다. 이어서 Enter를 누르면 폴더 선택 창을 다시 열 수 있습니다.

### 시작준비에서 조직 AI 연결 상태를 정확히 표시해요

조직 사용의 시작준비에서는 배정받은 조직 AI만 표시하고, 이 PC에 적용된 결과로 완료를 판단해요. 개인 로그인만으로 조직 AI가 연결됐다고 표시하던 문제와, 조직 행 아래에 이 PC의 개인 로그인이 보이던 문제를 고쳤어요. 조직 AI가 없을 때 창을 닫는 버튼은 완료로 표시해요. 계정 더보기를 펼치면 Codex도 현재 사용 중인 계정을 강조해요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 내 설정 > 일반 > 시작준비 > AI 도구에서 확인할 수 있어요.

### 업데이트 서버 오류가 나도 업데이트 안내를 닫을 수 있습니다

업데이트 서버가 일시적으로 응답하지 않으면 업데이트 안내에 서버 응답 원문 전체가 그대로 표시되었습니다. 그 긴 문구 때문에 안내 창이 옆으로 넓어져 닫기 버튼이 화면 밖으로 밀려나 창을 닫을 수 없었습니다. 이제 오류는 첫 줄만 짧게 보여 주고, 문구가 길어도 닫기 버튼은 항상 안내 창 안에 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 오류가 보이면 닫기 버튼으로 닫거나 `업데이트 확인`으로 다시 시도하세요.

### 열린 파일 탭을 오갈 때 다시 불러오지 않습니다

오른쪽 작업 패널에서 이미 열려 있는 파일 탭으로 돌아갈 때마다 편집기를 새로 그려 스크롤이 맨 위로 가고 다시 불러오는 것처럼 보이던 문제를 고쳤습니다. 이제 탭을 오가도 스크롤 위치·선택·강조 표시가 그대로이고, 파일을 다시 읽거나 새로고침할 때만 내용이 바뀝니다.

#### 사용 방법

오른쪽 작업 패널에서 파일 탭 여러 개를 열고 탭을 오가 보세요.

### 예약 저장과 관리의 빠른 반복 실행 방지

같은 예약의 저장·삭제·일시정지·바로 실행을 빠르게 여러 번 눌러도 처리 중에는 한 번만 접수합니다. 실패 후 초안은 보존하고, 취소하고 새로 작성한 초안을 이전 저장 결과가 닫지 않도록 수정했습니다. 계정·작업PC·폴더가 바뀐 뒤에는 이전 요청이 새 대상에 쓰이거나 화면을 덮지 않도록 보호합니다.

#### 사용 방법

프로젝트 설정 → 개발 → 실행에서 기존 예약 자동화를 사용하세요. 별도 설정 없이 적용됩니다.

### 오른쪽 작업 패널이 저절로 열리지 않고 대화마다 기억됩니다

오른쪽 작업 패널을 닫았는데 다시 열리거나, 열어 본 적 없는 대화에서 패널이 먼저 열리던 문제를 고쳤습니다. 이제 패널의 열림·닫힘과 마지막으로 본 도구는 대화마다 따로 기억되고 앱을 다시 켜도 유지됩니다. 처음 여는 대화는 패널이 닫힌 채 시작하며(기획으로 시작한 프로젝트의 기획안은 예외), 다른 대화에서 연 파일이나 자동으로 켜진 미리보기 때문에 열리지 않습니다. 프로젝트 설정의 시작 패널은 패널을 열었을 때 먼저 보일 도구만 정합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 패널은 도구 펼치기, 작업 패널 추가, 파일 링크처럼 그 대화에서 직접 연 경우에만 열립니다.

### 자식 대화 패널의 입력칸·중단 버튼·보기 창을 다듬었습니다

자식 대화 패널의 입력칸은 이제 보낼 때 일어나는 일을 이름으로 보여 줍니다. 자식이 응답 중이면 `현재 턴에 전달할 지시`, 응답이 끝났거나 중단된 뒤에는 `이어서 보낼 지시`로 바뀝니다. 중단 버튼은 아래 입력창의 중단 버튼과 같은 채운 사각형 아이콘으로 바꿨습니다.

자식 대화 보기 창에서 아래 입력창이 좁게 찌그러져 보이던 문제를 고쳐, 이제 대화 본문과 같은 폭으로 보입니다. 설정 검색에서 `자식 대화`·`연쇄 중단`으로 찾으면 응답 중단 시 자식 대화도 중단하는 설정이 있는 자동화 탭이 나옵니다. 자식 대화와 고정한 대화를 불러오지 못했을 때의 안내 문구도 다른 안내와 같은 말투로 맞췄습니다.

명령줄의 `agent wait`·`wait --any`·`prompt` 도움말에는 `--timeout`이 밀리초 단위라는 것을 적었습니다.

#### 사용 방법

대화 아래 `자식 대화` 패널에서 바로 확인할 수 있습니다. 설정 검색창에 `자식 대화`를 입력하면 해당 설정이 있는 탭으로 이동할 수 있습니다.

### 자식 목록과 부모 링크를 '대화'로 부릅니다

AI가 띄운 자식 목록의 제목이 `자식 AI도구 N개`에서 `자식 대화 N개`로, 자식 대화 위쪽 링크가 `부모 AI도구로 이동`에서 `부모 대화로 이동`으로 바뀌었습니다. 목록 안의 `자식 대화 열기`, 중단 알림, 설정의 `응답을 중단하면 자식 대화도 중단`과 같은 말로 맞췄습니다. 설정의 `자식 AI도구 호출`처럼 AI도구를 부르는 기능의 이름은 그대로입니다.

#### 사용 방법

사이드바 Chat이면 입력창 위의 `자식 대화 N개` 줄을, 프로젝트 대화면 머리글의 프로젝트 도구(⋮)에서 `자식 대화 N개`를 누릅니다. 앱 안내에서 예전 이름으로 검색해도 찾을 수 있습니다.

### 하단 터미널 높이 조절

현재 작업PC 터미널 패널의 위쪽 경계선을 드래그해 높이를 바꿀 수 있습니다. 기존 패널과 같은 경계 UI를 사용하며 열려 있는 터미널과 작성 중인 내용은 유지됩니다.

#### 사용 방법

터미널 패널을 연 뒤 위쪽 경계선을 위아래로 드래그하세요. Tab으로 경계에 이동해 방향키 또는 Home·End로도 조절할 수 있습니다.

### 홈·Chat에서도 API 토큰 연결 선택

조직 요금제가 설정된 계정은 홈·Chat·Project의 모델 메뉴에서 AI 자동이나 다른 AI를 선택한 상태에서도 사용 연결을 확인할 수 있습니다. API 토큰을 선택하면 ChatGPT로 전환하며, 새 Chat 시작에도 선택한 연결을 적용합니다. API 실행에는 개인 Codex 로그인을 요구하지 않습니다. 연결 조회 실패나 정책 변경은 다른 AI·작업PC 토큰으로 자동 전환하지 않고 중단하며, 새 초안과 이전 제출의 연결 선택은 분리합니다. AI 자동은 연결을 미확정으로 표시합니다. 홈 Build 시작이 실패한 뒤 재시도해도 제출할 때 고른 API 연결을 유지합니다.

#### 사용 방법

새 대화 입력창의 AI·모델 메뉴를 열고 맨 아래 사용 연결에서 API 토큰 또는 작업PC 토큰을 선택하세요. API는 Medium 강도를 사용하며 기존 대화의 연결은 바뀌지 않습니다.

### 홈의 최근 프로젝트가 최근 작업 순으로 보입니다

홈 Develop의 최근 프로젝트 목록이 고정한 프로젝트를 먼저 보여 주느라 최근 작업 순서가 맞지 않던 문제를 고쳤습니다. 이제 고정 여부와 상관없이 마지막으로 작업한 프로젝트가 맨 위에 옵니다. 사이드바의 고정 순서는 그대로입니다.

#### 사용 방법

홈의 Develop에서 최근 프로젝트 목록을 확인하세요.

### AI 브라우저 화면에서 직접 조작할 때 다시 연결을 누르지 않아도 됩니다

AI 브라우저 콘솔에서 제어권을 가져와 클릭했을 때 페이지가 이동하거나 스크롤되면, 그 뒤 입력이 페이지에 반영되지 않고 "입력 처리 상태를 확인했어요. 다시 연결을 눌러 이어가세요."가 떠서 다시 연결을 눌러야 했습니다. 바뀌기 전 화면 기준으로 쌓인 마우스 이동 입력이 페이지에 닿지 못한 것을, 결과를 알 수 없는 입력처럼 취급해 입력을 멈췄기 때문입니다.

이제 페이지에 닿지 않은 입력은 버리고 새 화면에서 이어서 입력받습니다. 클릭이나 키 입력이 버려졌을 때만 "화면이 바뀌어 마지막 입력은 보내지 않았어요"가 잠깐 보입니다. 입력 결과를 정말 알 수 없을 때나 제어권이 바뀌었을 때는 지금처럼 입력을 멈추고 다시 연결을 안내하며, 버린 입력을 자동으로 다시 보내지는 않습니다. 이 Mac과 원격 Mac 콘솔 모두에 적용되고, 원격 Mac은 그 Mac의 Saycode도 이 버전이어야 합니다.

#### 사용 방법

따로 할 일은 없습니다. 콘솔에서 제어권 가져오기를 누른 뒤 페이지를 클릭하고 입력하면, 페이지가 바뀐 뒤에도 그대로 이어서 조작할 수 있습니다.

### AI Models에서 이 컴퓨터의 계정을 정확하게 표시해요

AI Models 상단에서 조직 인증세트가 개인 계정을 대신 표시하던 문제를 고쳤어요. 이제 조직 배정과 상관없이 내가 허용한 개인 계정만 보이고, 계정 추가·연결 해제·다시 연결을 언제든 할 수 있어요. 제목을 `이 컴퓨터의 AI 계정`으로 바꾸고 카드 배경을 밝게 정리했어요.

#### 사용 방법

내 설정 → AI Models에서 개인 계정과 연결 상태를 확인하고 … 메뉴로 연결하거나 해제하세요.

### API 대화의 연결·모델·사용량 상태 갱신 수정

Project의 조직 허용 모델과 API 요청 모델을 일치시켰습니다. 새 API 대화의 연결 확인이 늦게 완료돼도 상태를 다시 확인하며, Luna에 상위 모델 사용량 소진을 한도로 표시하지 않습니다. 열린 API 대화의 사용량을 주기적으로 확인하고, 확인된 해제 시각 이후 정상 상태가 돌아오면 예전 한도 표시를 해제합니다. 긴 한도 안내는 메뉴 안에서 줄바꿈합니다.

#### 사용 방법

별도 설정 없이 적용됩니다. 기존 대화의 모델·연결은 유지하며 작업PC 토큰으로 자동 전환하지 않습니다.

### API 토큰 메뉴에서 사용 가능한 옵션만 표시

API 토큰에서는 ChatGPT와 요금제·조직 정책에 허용된 모델만 표시합니다. AI 자동·다른 AI·AI 프로필·작업 강도 선택과 더보기의 Auto Router는 숨깁니다. 작업PC 토큰으로 바꾸면 기존 옵션과 저장된 모델·강도가 복원됩니다.

#### 사용 방법

입력창의 모델 메뉴에서 API 토큰을 선택하세요. 다른 AI나 프로필을 쓰려면 작업PC 토큰으로 전환하세요. 기존 API 대화의 모델과 Medium 강도는 고정됩니다.

### API 토큰 모델 제한을 웹과 통일

API 토큰을 선택하면 요금제와 조직 정책에 허용된 모델만 고를 수 있습니다. 기존 API 대화는 시작한 모델과 Medium 강도로 고정되며 단축키로도 변경되지 않습니다. 작업PC 토큰으로 돌아오면 저장된 모델과 강도를 표시합니다.

#### 사용 방법

입력창의 모델 메뉴에서 API 토큰을 선택하세요. 기존 API 대화에서 다른 모델을 쓰려면 새 대화를 시작하세요.

### GitHub 다운로드 주소가 막혀도 업데이트를 받을 수 있습니다

GitHub의 릴리스 다운로드 주소가 계속 응답하지 않으면(504) `업데이트 확인`을 다시 누르거나 앱을 재시작해도 업데이트가 실패했습니다. 이제 그 주소가 실패하면 같은 릴리스를 GitHub API 경로로 다시 받습니다. 업데이트 정보와 설치 파일을 이 경로로 받습니다. 이 경로로 받을 때 Release notes에는 최신 버전의 내용만 보이고, 사이에 건너뛴 버전의 내용은 빠집니다. 문제가 확인된 버전의 업데이트를 멈추는 보류 설정도 같은 경로로 읽어, 장애 중에 보류된 버전이 설치되지 않습니다. GitHub가 정상일 때는 이전과 같은 주소를 씁니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### GitHub 트리거의 중복 저장·실행 방지

같은 GitHub 트리거의 저장·실행·일시정지·삭제·재연결을 빠르게 반복해도 요청을 한 번만 접수합니다. 설정을 닫고 다시 열어도 진행 상태를 유지하고, 실패한 초안과 저장 중 새로 작성한 초안을 보존합니다.

#### 사용 방법
