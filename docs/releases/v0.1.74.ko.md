## 새 기능

### /goal로 건 목표가 입력창 위에 보이고, 그 자리에서 바꾸거나 지울 수 있습니다

`/goal`로 목표를 걸어 둔 대화에서 입력창 바로 위에 "목표" 줄이 생겨 지금 목표를 한 줄로 보여 줍니다(단계 수를 알면 2/5처럼 함께 표시). 작업PC의 AI가 지원하면 줄의 연필 버튼으로 목표를 바꾸고, 휴지통 버튼으로 목표를 지울 수 있습니다. 작업PC가 변경을 받아들였을 때만 줄이 바뀌며, 받아들이지 못하면 그 이유를 짧게 알려 줍니다. 30분 넘게 새 소식이 없으면 줄이 흐려집니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 대화에서 /goal 뒤에 목표를 적어 보내면 입력창 위에 목표 줄이 나타납니다. Claude는 답하는 동안 목표를 바꿀 수 없어 버튼이 잠기며, 답이 끝나거나 멈춘 뒤 누를 수 있습니다.

### 내 설정에서 보관된 대화 확인

현재 조직의 Chat과 접근 가능한 Project 보관함을 설정에서 검색·열기·복원할 수 있습니다. Project 복원은 기존 확인과 작업 이어가기 동작을 유지합니다.

일부 대화 정보를 읽지 못한 경우는 빈 보관함과 구분하고, Project 복원 확인을 취소하면 실패로 표시하지 않습니다.

Chat을 복원한 뒤에도 다음 페이지의 대화를 빠짐없이 확인할 수 있고, 복원 중 다른 설정 탭을 다녀와도 최신 목록을 표시합니다.

#### 사용 방법

내 설정 > 일반 > 보관된 대화에서 검색하거나 복원을 선택하세요.

### 대화 속 PR 링크를 앱 안에서 바로 읽기

프로젝트 대화에서 GitHub PR 링크를 누르면 브라우저로 나가지 않고 오른쪽 작업 패널의 `PR` 탭에서 PR의 설명·코멘트·리뷰·리뷰 스레드·커밋을 시간순으로 볼 수 있어요. 같은 사람이 연달아 올린 커밋은 한 줄로 묶이고, 해결됐거나 이전 코드에 달린 스레드는 접혀 있어요. PR이 열려 있으면 그 자리에서 `리뷰 지적 고치기`로 이어 갈 수 있어요. 읽기 전용이라 GitHub에는 아무것도 쓰지 않아요.

#### 사용 방법

프로젝트 대화에 있는 GitHub PR 링크를 그냥 누르세요. Shift를 누른 채 누르면 브라우저로 열려요. 작업트리에 PR이 있는 대화에서는 작업 패널 추가(⋮) 메뉴의 `PR 보기`로도 열 수 있어요. 작업PC에 gh가 설치되고 로그인돼 있어야 해요.

### 대화 속 PR·이슈 링크를 상태와 제목이 보이는 칩으로 표시

대화에 GitHub PR·이슈 주소가 그대로 적힌 링크(또는 `#번호` 링크)가 있으면 상태 아이콘(열림·초안·병합됨·닫힘 등)과 제목을 담은 작은 칩으로 바뀝니다. 칩에 마우스를 잠시 올리거나 키보드로 이동하면 저장소·작성자·마지막 갱신 시각과, PR이면 브랜치와 바뀐 줄 수, 이슈면 댓글 수를 담은 카드가 열립니다. 정보는 대화가 도는 작업PC의 GitHub CLI(gh)로 화면에 보이는 링크만 묶어서 가져오며, 가져오지 못하면 원래 링크 그대로 둡니다.

#### 사용 방법

프로젝트 대화나 Chat에서 칩을 확인하고 마우스를 올려 카드를 봅니다. PR 칩을 누르면 오른쪽 작업 패널의 PR 화면이 열리고, Shift를 누른 채 누르면 브라우저로 열립니다(개인 Chat에서는 브라우저로 열림). 이슈 칩은 누르면 브라우저로 열립니다. 작업PC에 gh가 설치되고 로그인돼 있어야 합니다.

### 맡은 일이 있을 때 앱 종료 전에 확인해요

Cmd+Q나 메뉴의 종료를 누를 때 응답 중인 대화, 이 앱이 실행하는 예약 작업, 준비 중인 워크트리가 있으면 바로 끄지 않고 무엇이 멈추는지 먼저 알려 줘요. 클라우드로 쓰는 대화는 앱을 꺼도 작업PC의 데몬에서 계속 진행되고 완료 알림만 받지 못한다는 점, 이 앱의 예약 작업은 다시 열 때까지 실행되지 않는다는 점을 상황에 맞게 안내해요. 맡은 일이 없거나 업데이트 재시작·컴퓨터 종료로 꺼질 때는 묻지 않아요.

#### 사용 방법

확인 창에서 `종료`를 누르면 앱이 꺼지고 `취소`를 누르면 그대로 남아요. `다시 묻지 않기`를 체크하고 종료하면 다음부터 묻지 않으며, 설정 > 알림의 `앱 종료` 카드에서 `종료할 때 확인`을 다시 켤 수 있어요.

### 새 대화의 AI 기본값 관리

AI 연결 설정에서 앞으로 만드는 Chat과 Project의 기본 AI·모델·Effort를 각각 고를 수 있습니다. 열린 대화와 초안은 바뀌지 않습니다.

이후 여는 새 Chat 탭에는 저장된 기본값을 바로 적용하고, 기존 초안의 입력과 AI 선택은 유지합니다.

#### 사용 방법

내 설정 > 일반 > AI 연결 설정 > 새 대화 기본값에서 선택하세요.

### 설정에서 다른 조직 참여

초대 코드로 조직에 참여하고 확인된 조직을 직접 선택할 수 있습니다. 참여만으로 조직을 전환하거나 이 PC를 등록하지 않습니다.

#### 사용 방법

내 설정 > 일반 > 다른 조직 참여에서 초대 코드를 입력하고 조직에 참여를 누르세요.

### 앱 브라우저에서 요소 디자인을 직접 조정해 변경 요청 보내기

앱 브라우저의 주석 트레이에 담은 요소마다 디자인 조정 패널을 열어 안쪽·바깥 여백, 항목 간격, 방향·정렬, 글자 크기·굵기·색을 바꾸면 페이지에 바로 반영돼요. 바꾼 값은 속성별 전 → 후로 기록되고, 변경 요청 보내기를 누르면 그 요소의 선택자·텍스트와 함께 대화 입력창에 들어가요. 페이지를 새로고침하면 원래대로 돌아가요.

#### 사용 방법

프로젝트 대화에서 브라우저를 열고 요소를 골라 주석 트레이에 담기로 요소를 담은 뒤, 트레이 행의 조절 아이콘(디자인 조정)을 누르세요. 값을 적고 Enter를 누르거나 ↑↓ 키로 바꾸고, 변경 요청 보내기로 입력창에 넣은 뒤 확인하고 보내세요. 모두 보내기도 각 요소의 디자인 변경을 함께 넣어요.

### 에이전트가 대화의 오래된 지점과 오래된 세션을 읽을 수 있음

세션 안의 에이전트가 `happy agent read <id> --around <seq>`로 대화의 오래된 지점 앞뒤 메시지를 읽을 수 있습니다.
지금까지 `read`는 최근 메시지만 가져와서, 긴 대화의 앞부분으로 돌아가 읽을 방법이 없었습니다. 보여 주는 메시지마다
위치(seq)가 붙어 그 앞뒤로 이어 읽을 수 있고, 완료 신호와 `--since` 커서는 지금처럼 최신 메시지 기준입니다.
또 계정의 최근 150개 대화 목록에서 밀려난 세션도, 같은 프로젝트 범위 안이면 정확한 세션 id로 `read`할 수 있습니다.
범위 밖이거나 이 컴퓨터에서 열 수 없는 세션은 지금과 같이 거절합니다.

#### 사용 방법

Saycode 세션 안에서 `happy agent read <세션 id> --around <seq> --last 10`을 실행합니다. `--since`와는 함께 쓸 수 없습니다.
새 CLI 버전이 배포된 뒤부터 사용할 수 있습니다.

### 에이전트가 지난 대화를 검색할 수 있음 (기본 꺼짐)

세션 안의 에이전트가 `happy agent search <낱말>`로 같은 프로젝트의 지난 대화에서 "전에 이 문제를 어떻게 풀었는지"를 찾을 수 있습니다.
결과는 대화 본문이 아니라 위치 정보입니다 — 세션 id·제목·일치한 메시지 위치(seq)·짧은 발췌(240자 이하)와, 그 지점을 여는 `read --around` 명령입니다.
검색 범위는 `agent read`로 열 수 있는 범위와 같습니다: 같은 작업PC, 같은 프로젝트 폴더 아래의 대화이며, 그 폴더의 다른 사람 대화도 포함됩니다.
이 작업PC에서 열 수 없는 대화와 도구 실행 기록은 검색하지 않고, 기본 기간은 최근 90일입니다. 검색 내용은 디스크에 남기지 않습니다.
이 기능은 **기본으로 꺼져 있고**, 사람이 그 작업PC에서 직접 켜야 합니다. 에이전트는 켜거나 끌 수 없습니다.

#### 사용 방법

에이전트가 일하는 작업PC의 터미널(Saycode 세션 밖)에서 `saycode search enable`을 실행해 켭니다. saycode CLI를 따로 설치하지 않았다면 `npx @buzzni/saycode-cli search enable`을 실행합니다.
끄려면 `saycode search disable`, 상태 확인은 `saycode search status`입니다.
켠 뒤에는 세션 안의 에이전트가 `happy agent search 배포 롤백 --since 30d`처럼 검색합니다. 새 CLI 버전이 배포된 뒤부터 사용할 수 있으며, 서버가 새 목록 기능을 지원하기 전에는 최근 150개 대화만 검색합니다.

### 예약 작업 결과를 알림 카드의 제목·요약으로 보기

이 컴퓨터에서 실행되는 예약 작업은 AI가 응답 끝에 결과 제목과 한두 문장 요약을 함께 남깁니다. 알림 센터와 사이드바 최근 알림의 카드가 대화 제목 대신 그 제목·요약을 보여 주어, 대화를 열지 않고도 결과를 파악할 수 있습니다. 대화 화면에서도 요약 줄은 굵은 제목과 요약 한 문단으로 보입니다. 요약이 없으면 지금처럼 대화 제목과 상태를 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 예약 작업이 끝나면 사이드바 최근 알림이나 알림 센터에서 결과 카드를 확인하고, 카드를 누르면 해당 대화가 열립니다.

### 입력창에서 브랜치와 Git 작업을 더 정확하게 확인

입력창 위에 실제 작업 브랜치·Git 상태·현재 대화 PR·Git 재조회를 연결했습니다. 조회 실패 뒤에도 복구 입구를 유지하고, 기존 Git·작업트리·PR 관리 기능을 보존합니다. Git 작업과 조회가 겹쳐도 최신 상태를 다시 확인하며, 임시 잠금은 재시도하고 기준 반영 실패의 상세 원인을 유지합니다. 다른 Git 작업으로 커밋이 시작되지 못한 경우에는 완료 여부 불명과 구분해 다시 시도할 수 있도록 안내합니다. 커밋 성공 후에는 바의 Git 상태도 다시 확인합니다. 작업트리에서는 로컬 기준 브랜치의 변경을 반영할 수 있으며 미커밋 파일과 진행 중인 Git 작업을 보호합니다.

#### 사용 방법

데모에서도 기존 Pull 결과 확인과 브랜치 모의 동작을 유지합니다. 실제 기준 브랜치 반영에는 로그인된 온라인 PC와 저장소가 필요합니다.

프로젝트 대화의 입력창 위 브랜치 버튼에서 기존 Git 작업과 `로컬 기준 브랜치 반영`을 사용합니다. 상태 버튼은 저장소 설정, PR 번호는 현재 대화 PR, 회전 아이콘은 Git 상태 다시 확인을 엽니다. 충돌이 나면 상세 내용을 확인한 뒤 변경사항이나 터미널에서 해결합니다.

### Claude 대화가 컨텍스트 창을 얼마나 채웠는지 입력창 아래에서 보여줘요

Claude 대화의 입력창 아래 정보 줄 왼쪽에 ‘컨텍스트 N%’가 나타나요(AI 잔여량 표시를 켜 두었다면 사용량 버튼 바로 옆). 지금 대화가 모델의 컨텍스트 창을 얼마나 차지하는지 보여 주고, 마우스를 올리면 사용 중인 토큰과 전체 창 크기를 정확한 숫자로 볼 수 있어요. 80% 이상 차면 색이 바뀌고 설명에 새 대화를 시작하거나 /compact로 줄일 수 있다고 알려 줘요. 숫자는 Claude가 실제로 알려 준 값만 쓰고, 첫 답변이 끝나기 전이나 대화를 압축·초기화한 직후처럼 값을 모를 때는 표시하지 않아요. 이 업데이트에 함께 들어간 Saycode 실행 도구(1.1.10-aplus.346)부터 지원하므로, 다른 작업PC에서 실행되는 대화는 그 PC의 실행 도구도 이 버전 이상이어야 보여요. 이전 버전이나 Codex 대화에서는 나타나지 않고 기존 누적 토큰 표시는 그대로예요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. Claude 대화에서 첫 답변이 끝나면 입력창 아래 정보 줄에서 확인할 수 있어요.

### Codex 질문에도 선택지로 답하기

구조화된 질문을 지원하는 Codex 실행 도구가 적용된 작업PC에서는 개인 Chat과 프로젝트 대화에서 질문에 선택지나 직접 입력으로 답할 수 있습니다. 질문이 여러 개면 순서대로 답하거나 건너뛸 수 있고, 답변 전송에 실패하면 입력을 유지한 채 다시 보낼 수 있습니다.

#### 사용 방법

Codex가 질문한 대화를 열고 입력창 자리에 나타난 질문에 답한 뒤 보내기를 누르세요. 작업PC에는 이 기능을 포함한 실행 도구 업데이트가 필요합니다.

### CSV·TSV 파일을 표로 보기

프로젝트 파일 뷰어와 Chat 파일 미리보기에서 CSV·TSV 파일을 열면 머리줄에 `표로 보기` 버튼이 생깁니다. 누르면 같은 자리에서 열 문자와 행 번호가 붙은 표로 바뀌고, 다시 누르면 텍스트로 돌아옵니다. 파일은 지금처럼 텍스트로 먼저 열리고, 고칠 때는 기존 텍스트 편집기를 그대로 씁니다. 세미콜론으로 구분한 CSV도 칸을 나눠 보여 줍니다. 표는 1,000행·100열까지 보이며, 넘는 행과 열은 몇 개를 생략했는지 표 아래에 알려 줍니다. 열이 많은 큰 표는 행을 나눠 보여 주고, 표 아래 화살표로 다음 행을 넘겨 봅니다.

#### 사용 방법

프로젝트나 Chat 대화에서 도구 펼치기 → Files → `.csv`나 `.tsv` 파일을 연 뒤 머리줄의 `표로 보기`를 누르세요. 다시 누르면 텍스트로 돌아옵니다.

비밀번호 변경을 저장하는 동안에는 설정 닫기·웹 이동을 막고, 웹에서 계속하도록 전환돼도 계정 관리 버튼을 하나만 표시합니다.

#### 사용 방법

내 설정 > 일반 > 보안 또는 스킬에서 해당 웹 관리 버튼을 누르세요.

### 공용 PC의 조직 Claude 계정 전환 상태 안내

공용 PC 대화에서 조직 Claude 계정 전환 중·완료, 한도 소진, 적용 대기, 권한 회수와 재시도 상태를 선택한 언어로 표시합니다. 지원이 확인되지 않은 기존 대화는 자동 전환을 보장하지 않고, 확인된 미지원 대화에는 PC 연결 프로그램 업데이트 후 새 대화를 시작하도록 안내합니다.

#### 사용 방법

별도 설정 없이 대화의 기존 메시지와 입력창 아래 PC 상태 줄에서 확인합니다. 기존 대화는 보존됩니다.

### 사용량 추이와 이전 기간 비교

사용량 개요에 일별 그래프·표와 이전 기간 비교를 추가했습니다. 비용이나 비교 데이터가 없으면 확인 불가로 표시합니다.

#### 사용 방법

내 설정 > 일반 > 토큰 사용량 > 개요에서 일별 사용량 보기를 펼치세요.

### 사이드바 이름 변경을 모달로 통일했어요

Chat·프로젝트·프로젝트 대화의 이름을 중앙 이름 변경 창에서 수정합니다. 입력 위의 중복 라벨을 제거하고 저장·취소 버튼을 제공합니다. 저장 실패 시 이해하기 쉬운 재시도 안내를 표시하고 입력한 이름을 유지합니다.

#### 사용 방법

사이드바 이름을 두 번 누르거나 기존 더보기의 이름 변경을 선택하세요. 새 이름을 입력하고 저장 또는 Enter를 누르세요. 취소·닫기·Escape·창 밖 클릭은 저장하지 않고 닫습니다.

### 새 작업트리 설정을 간결하게 정리했어요

프로젝트 새 대화의 작업트리 이름 입력을 없애고 자동으로 이름을 정합니다. 방식과 Base 선택을 앱 테마에 맞게 통일했으며, Base 목록은 화면 안에서 검색하고 스크롤할 수 있습니다. PR·이슈 목록의 선택 표시와 줄바꿈을 통일했고, 이슈 방식을 다시 열거나 작업트리를 껐다 켜도 초안을 중복 삽입하지 않습니다. 이슈의 Base는 목록 위에서 고릅니다. 기존 작업트리가 없거나 선택한 항목이 사라졌을 때도 상태와 다시 선택하는 방법을 표시합니다.

#### 사용 방법

프로젝트 새 대화에서 작업트리를 켜고 옆의 방식 버튼을 누르세요. 새로 만들기를 고른 뒤 Base에서 브랜치를 검색하거나 기준 ref를 입력하고 Enter로 확정하세요. 붙여넣은 ref의 앞뒤 공백은 무시하며 한글 조합을 끝내는 Enter로 선택이 확정되지 않습니다.

### 시작 화면의 조직 관리 버튼을 하나로 정리했어요

시작 화면의 조직 관리 옆 초대 버튼을 제거했습니다. 조직 관리 버튼 하나로 관리자 화면을 열 수 있습니다.

#### 사용 방법

시작 화면 왼쪽 아래에서 조직 관리를 누르세요. 구성원을 초대하려면 관리자 화면에서 유저 관리 → 유저 초대를 선택하세요.

### 앱에 포함된 실행 도구가 컨텍스트 사용률을 알려 줍니다

앱에 포함하는 Happy 실행기를 1.1.10-aplus.346으로 올렸습니다.

- 이 PC에서 실행되는 Claude 대화가 컨텍스트 창 사용률을 앱에 보내, 입력창 아래 ‘컨텍스트 N%’ 표시가 실제로 나타납니다.
- 공유 작업PC의 Claude 계정 자동 교체를 위한 기반(실행 기록·복구)이 들어갔습니다. 서버에서 이 기능을 켜기 전까지 기존 동작은 바뀌지 않습니다.

#### 사용 방법

사용자 조작 없이 앱 업데이트에 포함됩니다.

### 에이전트가 지난 대화를 검색하는 기능을 켤 수 있습니다

앱에 포함하는 Happy 실행기를 1.1.10-aplus.347로, 그 안의 saycode CLI를 0.9.7로 올렸습니다.

- 에이전트의 지난 대화 검색(`happy agent search`)을 이제 쓸 수 있습니다. **기본으로 꺼져 있고**, 사람이 그 작업PC에서 직접 켜야 합니다. 에이전트는 켜거나 끌 수 없습니다. 연결한 서버가 최근 활동 순 대화 목록을 지원하기 전에는 최근 150개 대화만 검색합니다.
- 에이전트가 만든 암호화된 로컬 자식 대화에 후속 지시와 진행 중 방향 수정을 보낼 수 있습니다.
- 셀프호스트 서버(`saycode server`)의 기본 서버 패키지를 0.1.4로 고정했습니다. 다음 saycode CLI 발행부터 `saycode server init`에 반영됩니다.

#### 사용 방법

에이전트 대화 검색을 켜려면 앱을 업데이트한 뒤, 에이전트가 일하는 작업PC의 터미널(Saycode 대화 밖)에서 `npx @buzzni/saycode-cli search enable`을 실행합니다(saycode CLI를 설치했다면 `saycode search enable`). 끄려면 `search disable`, 상태 확인은 `search status`입니다. 켠 뒤에는 대화 안의 에이전트가 `happy agent search 배포 롤백 --since 30d`처럼 같은 프로젝트의 지난 대화를 찾습니다.

### 연결된 대화가 없는 PR에서도 리뷰 지적 고치기

앱 안 PR 화면의 `리뷰 지적 고치기`가 이제 PR에 연결된 대화가 없어도 보여요. 누르면 PR의 미해결 리뷰 지적을 읽어, `PR에서 시작`으로 그 PR이 골라진 새 대화 입력창에 고쳐 달라는 요청을 넣어 줘요. 같은 PR 번호의 작업트리 대화가 있으면 그 대화로 넣어요. 자동으로 보내지 않으니 확인한 뒤 보내면 돼요. 다른 저장소의 PR에는 버튼이 보이지 않아요.

#### 사용 방법

프로젝트 대화에서 그 프로젝트 저장소의 열린 GitHub PR 링크를 눌러 PR 탭을 열고, 위쪽의 `리뷰 지적 고치기`를 누르세요. 작업PC에 gh가 설치되고 로그인돼 있어야 해요.

### 예약 결과가 메신저로 실제 전송되고, Codex 대화의 질문에 답할 수 있습니다

앱에 포함하는 Happy 실행기를 1.1.10-aplus.345로, 함께 들어가는 saycode CLI를 0.9.6으로 올렸습니다.

- 예약의 `결과 보내기`·`실패 알림`이 이 앱이 설치된 PC에서 실제로 동작합니다. 예약을 실행한 PC가 답변 앞부분이나 실패 이유를 페어링한 Telegram·Slack 개인 대화로 보냅니다.
- Codex 대화에서 AI가 선택지가 있는 질문을 하면, Claude 대화와 같은 질문 카드에 답해 작업을 이어 갈 수 있습니다.
- 새 대화를 시작할 때 이미 실행 중인 백그라운드 연결을 다시 확인하다가 응답이 잠깐 늦어 대화가 시작되지 못하던 문제를 고쳤습니다.

#### 사용 방법

사용자 조작 없이 앱 업데이트에 포함됩니다. 예약 결과 전송은 예약 → 새 예약(또는 행의 더보기 → 편집) → 고급에서 켭니다.

### 예약 내용의 AI 예약과 스크립트 설정 구분

예약 내용의 AI 예약 조작을 상단 목록으로 통합하고 코드 작업은 고급으로 분리했습니다. 이름·코드·일정부터 입력하고 기술 옵션은 필요할 때 펼치도록 정리했습니다.

#### 사용 방법

예약 내용에서 지금 실행·재개 또는 더보기 메뉴로 AI 예약을 관리하세요. 코드 작업은 고급 → 코드 작업 추가에서 등록하며 파일명·외부 실행·입력 옵션은 세부 설정에서 바꿀 수 있습니다.

### 예약 작업이 답변·승인을 기다리는 대화 위에 쌓이지 않음

예약 작업의 직전 실행 대화가 질문 답변이나 권한·계획 승인을 기다리고 있으면, 이번 회차는 새 대화를 만들지 않고 건너뜁니다. 실행 이력에 "답변·승인 대기 중(스킵)"으로 남고, 대기가 시작된 회차에 알림함에 한 번 알려 줍니다. 다음 회차 시각은 평소처럼 다시 계산됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 알림함의 "예약을 건너뛰었어요" 알림을 누르면 기다리는 대화가 열리고, 답하거나 승인하면 다음 회차부터 다시 실행됩니다.

### 웹 용어로 내 설정 찾기

기존 메뉴와 일반·개발 구조를 유지하며 개인 메모리·머신 관리·외부연동·MFA 등 웹에서 쓰는 용어로도 설정을 검색할 수 있습니다.

아주 낮은 창에서도 탐색과 본문을 각각 스크롤하고, 긴 페이지 제목은 한 줄로 표시합니다.

#### 사용 방법

내 설정 검색창에 찾는 기능의 이름을 입력하세요.

### 입력창 아래 오른쪽에서 앱 버전과 칩 아이콘을 뺐어요

입력창 아래 오른쪽 정보 줄에서 앱 버전과 CPU 칩 아이콘·상태 점을 없앴습니다. 이제 `CPU`·`메모리` 사용률부터 보이고, 그 옆에 작업PC 이름과 연결 상태가 이어집니다. 사용률이 정상·주의·위험 중 어디인지는 사용률에 마우스를 올리면 나오는 설명에서 확인할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 앱 버전은 설정 > 정보에서 확인하세요.

### 입력창 아래 AI 사용량을 고른 AI 것만 보여 줘요

입력창 아래 왼쪽의 AI 사용량이 Claude·Codex를 항상 함께 보여 주던 것에서, 입력창에서 고른 AI의 사용량만 보여 주도록 바뀌었습니다. 이미 진행 중인 대화는 그 대화가 쓰는 AI의 사용량이 보입니다. AI를 자동으로 고르게 두었거나 고른 AI의 사용량 정보가 없으면 지금처럼 모두 보입니다.

#### 사용 방법

입력창에서 AI를 고르면 바로 적용됩니다. 다른 AI의 사용량과 계정 전환은 사용량을 눌러 여는 창에서 그대로 확인할 수 있습니다.

### 입력창 위 브랜치 줄과 대기 메시지를 한 모양으로 정리

입력창 위에 보이는 브랜치 줄이 바로 아래 대기 메시지 영역과 같은 폭·같은 배경색으로 바뀌었습니다. 대기 메시지 영역의 테두리는 없앴습니다. 입력창 위 영역이 한 덩어리로 정리되어 더 가볍게 보입니다.

#### 사용 방법

### 자동 리뷰가 서버 값의 빈 자리 채움 문제를 더 잘 찾도록

"에디터로 열기 안 돼요", "PR 미리보기", "탭 실수로 닫음"처럼 자주 묻는 말로도 해당 안내를 찾습니다.

### 최근 기능의 사용 안내를 현재 동작에 맞춤 (2차)

AI에게 Saycode 사용법을 물으면 참고하는 앱 안 안내서를 최근 기능의 현재 동작에 맞게 고쳤습니다. 백그라운드 작업 중 표시는 사이드바 행이 아니라 대화 탭 배지와 작업보드 카드에서 글자로 확인한다는 점, 코드 복사 뒤에는 글자가 아니라 아이콘이 체크로 바뀐다는 점, 선택한 답변의 인용 버튼은 마우스를 놓은 곳 위에 뜨고 스크롤해도 바로 사라지지 않는다는 점, CSV 표가 행을 나누는 기준(한 번에 5,000칸)을 정확하게 안내합니다. 하위 AI도구 목록을 프로젝트 대화에서 여는 위치와 상태의 뜻, 작업보드 필터의 지우기 버튼과 묶음 조합 규칙, 이슈에서 시작할 때의 작업트리 이름 규칙, 작업트리 일괄 정리에 GitHub CLI가 필요하다는 조건, 컨텍스트 사용률이 사이드바 Chat에도 보인다는 점도 보강했습니다.

### 컴퓨터 등록 오류 안내 개선

컴퓨터 등록 중 앱 파일을 찾지 못했을 때 개발 명령과 내부 경로가 길게 표시되던 문제를 수정했습니다. 이해하기 쉬운 안내와 로그 폴더 열기를 제공하며 다시 확인할 수 있습니다.

#### 사용 방법

내 설정 → 개발 → 작업PC → 내 컴퓨터 등록 또는 시작준비에서 확인할 수 있습니다. 앱 파일이 없다는 안내가 나오면 최신 Saycode를 다시 설치하고 다시 확인하세요.

### 편집 파일 행의 키보드 포커스 표시가 오른쪽 숫자에 붙지 않습니다

대화의 편집 요약 카드에서 파일 행을 키보드로 선택하면 나타나는 포커스 테두리가 오른쪽 끝의 변경 줄 수(예: −2)에 여백 없이 붙어 보였습니다. 이제 왼쪽 파일 경로와 같은 여백을 두고 숫자를 감쌉니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 프로젝트 대화 목록의 호버 표시 수정

프로젝트 하위 대화의 말풍선 아이콘을 제거했습니다. 작업 중 로딩 아이콘은 제목 앞에 표시되어 마우스를 올려도 가운데로 밀리지 않습니다. 클릭한 대화의 폴더·브랜치 툴팁은 마우스를 다른 곳으로 옮기면 닫힙니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 키보드로 대화에 이동하면 폴더·브랜치 정보를 확인할 수 있고 Escape로 닫을 수 있습니다.

### 프로젝트 대화 삭제 후 작업트리 정리 개선

프로젝트 대화를 삭제하거나 작업트리와 함께 보관할 때, 해당 대화의 연결이 남아 작업트리 정리가 실패하던 문제를 수정했습니다. 정리가 끝나지 않은 경우에도 대화 처리 결과와 함께 짧은 안내를 표시하며 내부 서버 오류는 표시하지 않습니다. 다른 대화가 사용 중인 작업트리의 보호는 유지합니다. 작업트리를 지우지 않는 경우에는 PC의 종료 응답을 기다리지 않고 대화 삭제·보관을 마칩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 정리 실패 안내가 나오면 프로젝트의 작업트리 관리에서 상태를 다시 확인해 주세요.

### 프로젝트 대화 화면에 커넥터 상태 표시가 다시 나타납니다

통합 워크스페이스에서 프로젝트 대화를 열면 커넥터 상태 표시가 보이지 않아, 커넥터 연결이 실패하거나 다시 인증해야 해도 대화 화면에서 알 수 없던 문제를 고쳤습니다. 커넥터 목록을 새로 불러오지 못했을 때 이전 결과로 경고 개수를 보여 주던 문제도 함께 고쳤습니다.

#### 사용 방법

프로젝트 대화 화면 오른쪽 위, 프로젝트 도구(⋮) 버튼 왼쪽의 '커넥터 상태' 또는 '커넥터 N건 확인 필요'를 누르면 'MCP 연결 상태와 복구' 창이 열립니다.

### 프로젝트 도구에서 연 창을 닫으면 메뉴도 함께 닫혀요

프로젝트 도구 메뉴에서 브랜치 전환·작업트리·프로젝트 프로세스 보기 같은 창을 열었다가 Esc나 닫기 버튼으로 닫으면, 그 창을 열었던 프로젝트 도구 메뉴가 열린 채 남던 문제를 고쳤습니다. 이제 창을 닫으면 메뉴도 함께 닫히고, 키보드 포커스는 프로젝트 도구 버튼으로 돌아옵니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 프로젝트 도구의 "대화 이어가기" 메뉴가 창 왼쪽 위로 튀지 않습니다

채팅 헤더의 프로젝트 도구(⋮) 메뉴에서 "대화 이어가기"를 열고 "다른 AI도구로 이어가기"를 누르면, 선택이 되지 않고 같은 메뉴가 창 왼쪽 위에 다시 떠 한 번 더 눌러야 하던 문제를 고쳤습니다. 이제 처음 누를 때 바로 이어가기 창이 열립니다. "같은 AI로 갈래 만들기"도 같습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 프로젝트 목록 더보기와 스크롤 개선

Project 목록을 30개씩 표시하고 Chat과 같은 가운데 더보기 버튼으로 추가로 펼칠 수 있습니다. 탭을 오갈 때 목록이 맨 아래로 튀던 문제를 수정했습니다. 고정 프로젝트와 현재 선택한 프로젝트는 계속 표시합니다.

#### 사용 방법

사이드바 Project 목록 하단의 더보기를 누르면 다음 30개를 표시합니다. 검색어·프로젝트 보기 범위가 바뀌면 표시 개수가 초기화됩니다. 목록 탭 왕복은 읽던 위치를 유지하고 상단 Project 메뉴는 목록 처음으로 돌아갑니다.

### 프로젝트를 바꿔도 대화 목록의 숨김 설정 유지

다른 프로젝트를 선택하면 이전 프로젝트 목록에 숨겨진 자동 실행·리뷰 대화가 다시 나타나던 문제를 수정했습니다. 이제 프로젝트 선택 여부에 관계없이 같은 숨김 설정을 따릅니다. 숨긴 대화가 입력을 기다리거나 완료 후 아직 확인되지 않았다면 상태 표시와 함께 다시 볼 수 있는 버튼을 남깁니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 하위 대화가 만든 HTML도 답변 안에서 미리보기

다른 대화에 맡긴 작업이 만든 HTML을 에이전트가 결과로 전할 때, 또는 이미 있는 HTML을 보여 달라고 요청할 때도 답변 끝에 미리보기가 뜹니다. 이전에는 에이전트가 이번에 직접 만든 파일이 아니라며 경로만 적었습니다. 파일이 그 대화의 작업 폴더에 있을 때만 미리보기를 띄웁니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 기존 HTML을 보려면 대화에서 "이 HTML 미리보기로 보여줘"라고 요청합니다.

### 하위 폴더 프로젝트도 에디터로 열기

모노레포의 한 폴더처럼 Git 저장소의 하위 폴더를 프로젝트로 쓰면, 프로젝트 도구와 빠른 열기의 에디터로 열기가 항상 "최상위 폴더만 열 수 있다"며 실패하던 문제를 고쳤습니다. 이제 그 폴더를 담은 저장소 최상위 폴더가 에디터에서 열리고, 프로젝트가 그 안의 어느 폴더인지 알림으로 알려 줍니다. 저장소가 홈 폴더 전체인 경우에는 홈 폴더를 열지 않고 이유를 알려 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 프로젝트 도구의 `에디터로 열기…`(또는 `<에디터>에서 열기`)나 빠른 열기(Cmd+P)의 `에디터로 열기`를 평소처럼 누르면 됩니다. macOS에서만 사용할 수 있습니다.

### CLI를 따로 업데이트해도 로컬 도구 실행이 막히지 않습니다

따로 설치해 쓰는 CLI가 Desktop보다 먼저 업데이트되어 요청에 새 정보를 더하면, Desktop이 그 요청을 거절해 에이전트의 로컬 도구 실행이 모두 막힐 수 있던 문제를 고쳤습니다. 이제 처음 보는 정보는 실행에 넘기지 않고 무시합니다.

#### 사용 방법

### Git 저장소 가져오기의 머신 clone 전환 오류 수정

GitHub·GitLab 웹 연결을 선택해 Git URL로 프로젝트를 만들 때 인증 구분값이 잘못 전달되어 가져오기가 막히던 문제를 수정했습니다.
자동 인증 선택으로 가져오거나 복구할 때 서버가 선택한 컴퓨터에서 직접 가져오도록 요청하면 해당 컴퓨터에서 이어갑니다.
사용자가 명시한 웹 연결을 다른 컴퓨터의 인증으로 자동 대체하지 않습니다. 이 응답만으로 프로젝트 생성이 부분 실패로 끝나던 문제를 수정했습니다.
기존 파일이 있는 폴더의 복구 보호와 저장소 접근 권한 확인은 유지합니다.

#### 사용 방법

업데이트 후 프로젝트 생성의 Git 저장소 가져오기를 사용하세요. 이미 생성된 프로젝트는 프로젝트 설정의
기존 Git 가져오기 복구 기능을 이용할 수 있습니다.
