## 새 기능

### 새 소식을 앱 언어로 보여줍니다

앱 언어를 영어로 쓰면 새 소식(릴리스 노트) 본문도 영어로 보입니다. 일본어·중국어 화면에서는 영어 본문을 보여주고, "새 기능"·"수정된 문제" 같은 섹션 제목은 앱 언어로 표시합니다. 업데이트를 받을 때 언어별 본문을 함께 받아 두며, 받지 못하면 지금처럼 한국어 본문을 보여줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 이번 버전 이후의 릴리스부터 적용되며, 언어를 바꾼 뒤 도움말 → Release Notes로 다시 열면 바뀐 언어로 보입니다.

### 셀프호스트 서버에 Desktop으로 연결할 수 있습니다

GUI 없는 서버에서 운영하는 Saycode 셀프호스트 서버에 Desktop 앱으로 연결할 수 있습니다. 서버에서 받은 연결 코드를 붙여넣으면
서버의 프로젝트와 대화를 그대로 사용하고, 앱을 다시 켜도 같은 서버로 자동으로 다시 연결합니다. 연결이 안 되면 시작 화면에서 이유를 알려 줍니다.

#### 사용 방법

1. 서버에서 `saycode server connect`를 실행해 연결 코드를 복사합니다.
2. Desktop 시작 화면의 `개인 사용` 아래에서 `셀프호스트 서버에 연결`을 누릅니다.
3. 연결 코드를 붙여넣고 `연결`을 누릅니다. 다른 서버로 바꾸려면 로그아웃한 뒤 다시 연결합니다.

### 쓰지 않는 AI를 채팅 선택 목록에서 숨길 수 있어요

연결된 AI 도구(Claude Code·Codex·Opencode·Grok) 가운데 쓰지 않는 것은 새 대화, 홈 Chat, 대화 중 AI 전환, 병렬 실행, 자동화의 AI 선택 목록에서 숨길 수 있습니다. 자동 선택도 숨긴 AI를 고르지 않습니다. 숨겨도 그 AI의 로그인·계정 연결은 그대로이고, 이미 진행 중인 대화는 그대로 이어집니다. 최소 한 개의 AI는 항상 표시되고, 표시 중인 AI 중 쓸 수 있는 것이 없으면 숨긴 AI를 다시 표시하는 방법을 안내합니다.

#### 사용 방법

내 설정 > AI 연결 설정 또는 시작 준비 목록의 AI 도구 단계에서 `채팅에 표시할 AI`의 스위치를 끄면 숨겨지고, 다시 켜면 선택 목록에 돌아옵니다. 선택은 바로 저장되며 앱을 다시 켜도 유지됩니다.

### 자동 배포 창이 열려 있으면 새 멤버에게 회사 키를 자동으로 공유

조직 관리자가 자동 배포 창을 열어 두면, 회사 키를 가진 멤버의 Desktop이 창 안에서 자격을 갖춘 새 멤버에게 회사 키를 자동으로 공유해요. 관리자가 멤버마다 직접 공유하지 않아도 새 멤버가 조직 PC에서 AI 계정을 연결할 수 있어요. 창이 닫혀 있거나, 관리자가 보류한 멤버이거나, 대기 시간이 끝나지 않은 멤버에게는 공유하지 않아요.

키를 아직 받지 못한 멤버의 Desktop은 조직 AI 연결 안내에서 상황을 나눠 보여 줘요. 곧 자동으로 공유될 때는 예상 시각을, 관리자 확인을 기다릴 때는 그 사실을, 열린 창이 없을 때는 관리자에게 키 공유를 요청하라는 안내를 보여 줘요.

#### 사용 방법

관리자가 웹 조직 관리 → 보안 → 조직 종단간 암호화에서 자동 배포 창을 열면, 회사 키를 가진 멤버가 Desktop을 켜 두기만 해도 자동으로 공유돼요. Desktop에서는 별도 설정이 필요 없어요. 키를 받은 멤버는 다음 연결 시도에서 바로 연결돼요.

### 확장이 연결 머신에서 Moai 명령을 승인받아 실행할 수 있습니다

확장이 `machine.run` 권한으로, 미리 선언된 Moai 명령을 연결 머신에서 실행할 수 있습니다. 셸은 쓰지 않으며, 선언된 명령만 실행합니다.

- 확장 관리 화면에서 선택한 머신에 Moai가 설치되어 있는지 보여주고, **이 머신에 설치** 버튼으로 설치할 수 있습니다. 머신이 GitHub 공식 릴리스를 직접 내려받아 SHA-256을 확인한 뒤 사용합니다.
- 확장이 명령을 실행하려 하면, 앱이 확장·실행 명령·머신·프로젝트 폴더·변경 범위·함께 실행될 수 있는 프로그램·승인 유효 기간을 항목마다 한 줄씩 보여주는 확인 창을 띄웁니다. 긴 실행 명령과 폴더 경로는 따로 한 줄에 표시합니다. 읽기 명령은 앱을 닫을 때까지, 프로젝트를 바꾸는 명령은 한 번만 승인됩니다.
- 실행하지 못했을 때 확장이 이유를 구분해 받습니다: 확인 창에서 거부함, 확인 창에 답하지 않아 시간이 지남, 같은 프로젝트에서 다른 변경 명령이 실행 중임, 머신에 도구가 설치되어 있지 않음, 머신의 운영체제를 지원하지 않음. 확장은 이 이유에 맞는 안내를 보여 줄 수 있습니다.
- 실행 중에는 확장이 진행 상태를 확인하고 결과를 받아 보여 줄 수 있으며, 필요하면 실행을 취소할 수 있습니다. 취소한 뒤에도 머신에 남은 프로세스가 정리될 때까지 상태를 계속 확인할 수 있습니다.
- 프로젝트를 바꾸는 명령은 확장 관리 화면에서 미리 한 번 승인해 둘 수도 있습니다. 확장을 끄거나 지우거나 `machine.run` 권한을 철회하면 승인이 함께 취소됩니다.
- 확장 패널이 OS 설정이 아니라 앱의 라이트/다크 테마와 색을 따릅니다. 패널이 열린 채 테마를 바꿔도 입력하던 내용을 유지한 채 색만 바뀝니다.
- 확장이 패널 크기를 작게·보통·넓게 중에서 정할 수 있어, 입력 칸 몇 개뿐인 패널은 큰 빈 창 대신 내용에 맞는 작은 창으로 열립니다.
- 연결 머신의 Saycode 런타임이 `1.1.10-aplus.304` 이상이고, 실행하려는 명령을 실제로 제한할 수 있다고 알려 줄 때만 실행합니다.

#### 사용 방법

Moai 확장을 설치하고 `machine.run` 권한을 승인한 뒤, 확장 관리 화면에서 **이 머신에 설치**를 누르세요. 확장이 명령을 실행할 때 뜨는 확인 창에서 내용을 확인하고 허용하면 됩니다. 현재 macOS(Apple Silicon)와 Linux x64 머신을 지원하며, Windows 머신은 지원하지 않습니다.

### AI가 내 앱을 직접 띄워 기능을 찾아 검증하는 스킬 추가

스킬 팩에 `create-verification`과 `maintain-verification` 두 스킬이 추가됐습니다.

- `create-verification`은 코드를 근거로 프로젝트의 기능 지도(어떤 기능이 어디에 있고 어떻게 도달하는지)와 앱 실행 절차를 만듭니다. 앱을 실제로 띄워 각 기능에 도달되는지 확인하고, 확인된 항목만 "검증됨"으로 표시합니다. 마지막으로 그 프로젝트 전용 검증 스킬을 만들어, 이후 AI가 "이 화면 확인해줘", "이 버그 재현해줘" 같은 요청이나 모호한 버그 리포트를 받으면 해당 기능을 찾아가 증거와 함께 확인할 수 있게 합니다.
- `maintain-verification`은 코드가 바뀐 뒤 영향받은 기능만 다시 확인해 기능 지도를 최신으로 유지합니다.

웹·Electron·CLI 앱을 지원합니다. 파일을 쓰기 전에는 목록을 보여 확인을 받고, 배포 명령은 실행하지 않으며, 비밀값은 기록하지 않습니다.

#### 사용 방법

프로젝트 설정 → 개발 → 실행 → 스킬에서 "1st-party 스킬 팩 사용"을 켠 뒤 새 대화를 시작합니다. 대화에서 "이 프로젝트에 검증 스킬 만들어줘"라고 요청하면 `create-verification`이 실행되고, 결과물은 `docs/agent-verification/`과 `.claude/skills/`에 저장됩니다. 코드가 바뀐 뒤에는 "기능 지도 갱신해줘"라고 요청합니다.

### saycode CLI 0.9.0: GUI 없는 머신에서 셀프호스트 서버 운영

`saycode server` 명령으로 GUI 없는 Linux·macOS 머신에서 Saycode 서버를 직접 운영할 수 있습니다. 서버 머신도 작업 머신이 되고, 휴대폰·Desktop·CLI와 다른 작업 머신이 연결 코드로 이 서버에 붙습니다. 상시 서비스 설치(Linux systemd, macOS LaunchAgent), 외부 공개용 주소 설정, 새 머신 승인, 토큰 교체를 지원합니다. 서버가 멈추면 프로세스가 종료되어 서비스 관리자가 다시 띄우고, 이 머신의 작업 실행기만 멈추면 자동으로 다시 시작합니다.

`saycode chat -s`로 오래 쉬어 정리된 대화를 다시 열면 그 대화를 원래 머신에서 다시 시작한 뒤 이어서 대화합니다. 에이전트가 시작하지 못하면 이유를 한 줄로 보여 주고, 이어서 연 대화의 이전 메시지는 시간 순서대로 표시됩니다.

#### 사용 방법

1. `npm i -g @buzzni/saycode-cli`로 설치하거나 업데이트합니다.
2. 서버 머신에서 `saycode server init` 후 `saycode server run`(또는 `saycode server install`)을 실행합니다.
3. `saycode server connect`가 보여 주는 연결 코드로 Desktop·휴대폰·CLI를 연결합니다. 자세한 절차는 CLI README의 "셀프호스트 서버" 절을 참고하세요.

## 변경된 기능

### 작업PC에 설치한 Moai를 터미널에서 바로 실행할 수 있는 경로가 생깁니다

내장 Saycode 런타임을 `1.1.10-aplus.309`로 올립니다. 작업PC에 "이 머신에 설치"로 설치한 Moai 같은 도구에 버전이 바뀌어도 그대로인 실행 경로(`~/.happy/managed-tools/<도구>/bin/<실행 파일>`)를 만들고, 확장 관리 화면의 머신 도구 카드가 이 경로와 복사 버튼을 보여줍니다. 앱이 실행하는 도구는 지금처럼 설치 때 확인한 버전과 해시만 씁니다. 같은 대화를 복구하거나 브라우저 대기 뒤 이어갈 때 앱이 보낸 환경변수도 다시 적용합니다.

#### 사용 방법

확장 관리 화면의 머신 도구 카드에서 경로를 복사해 그 작업PC의 프로젝트 폴더에서 `moai init` 등을 실행하세요. 경로는 작업PC의 Saycode 런타임이 `.309` 이상일 때 표시됩니다.

### 확장 관리 화면이 확장 이름과 상태를 알아보기 쉽게 바뀝니다

- 공식 확장은 카드 제목에 이름(예: `Moai 작업 보드 확장`)을 보여주고 id는 작게 함께 표시합니다. 상태는 배지 하나(비활성화됨·활성화됨·실행 중·격리됨)로 보여주며, 헷갈리던 "대기 중" 표시는 없앴습니다.
- 이미 승인한 권한은 활성화할 때 다시 묻지 않고, 아직 승인하지 않은 권한만 확인합니다.
- 머신 도구는 어느 작업PC의 상태인지 이름과 온라인 여부를 함께 보여주고, 설치된 도구는 터미널에서 직접 실행할 경로와 복사 버튼을 제공합니다.
- 작업PC 화면의 확장 버튼은 확장을 켜거나 끄면 설정 창을 다시 열지 않아도 바로 나타나거나 사라집니다. Moai처럼 선택한 프로젝트에서 실행되는 확장 버튼은 그 프로젝트의 작업PC에서만 누를 수 있고, 다른 작업PC에서는 이유를 안내합니다.

#### 사용 방법

내 설정 → 개발 → 확장과 작업PC 화면에서 그대로 사용합니다. 별도 설정은 없습니다.

## 수정된 문제

### 고쳐 올린 새 소식에 이전 번역이 붙지 않습니다

같은 버전의 새 소식이 수정되어 다시 올라왔을 때, 늦게 도착한 이전 본문의 번역이 수정된 본문 대신 표시될 수 있던 문제를 고쳤습니다. 이제 번역은 그 번역을 받은 본문에만 붙고, 수정된 본문은 자신의 번역을 받거나 원문으로 표시됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 다시 등록한 PC도 조직 종단간 암호화가 자동으로 켜져요

내장 Saycode 런타임을 `1.1.10-aplus.312`로 올려요. 같은 컴퓨터를 작업PC로 다시 등록하면, 이전 PC 신원이 남긴 대화 기록 때문에 새 신원의 종단간 암호화가 자동으로 켜지지 않고 조직 AI 연결이 막히던 문제를 고쳤어요. 이전 신원이 남긴 백업을 새 신원이 되돌린 흔적으로 잘못 읽던 문제도 함께 고쳤어요.

#### 사용 방법

따로 할 일은 없어요. 앱을 업데이트한 뒤 작업PC를 다시 등록하면 종단간 암호화가 자동으로 켜지고 조직 AI 계정이 연결돼요.

### 만료된 machine.run 승인으로 작업이 시작되지 않도록 수정

실행 승인 대기 중 승인이 만료되면 이미 수락된 작업을 계속 실행하지 않고 즉시 취소합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 사용량 창에 명령 전체가 오류로 표시되던 문제 수정

Windows 작업PC의 정보를 Desktop이 아직 읽지 못한 순간에 "AI 계정·사용량"을 열면, 사용량과 AI 로그인
상태 확인이 macOS용 명령으로 실행돼 실패했습니다. 이때 화면에는 실행한 스크립트 전체가 오류로 길게
표시됐습니다. 이제 작업PC의 운영체제를 모를 때도 Windows와 macOS 모두에서 동작하는 방식으로 실행하고,
실패하면 원인 한 줄만 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 새 소식 설명이 첫 줄에서 끊기던 문제 수정

새 소식의 변경 설명이 여러 줄이면 첫 줄만 보이고 문장 중간에서 끊겼습니다. 이제 설명 전체가 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 새 소식에서 열리지 않는 링크와 설치 안내 정리

새 소식 창에 누를 수 없는 다운로드 파일 이름과 체크섬이 더 이상 보이지 않습니다. 본문에 설치 안내만 있어도 숨긴 내용이 원문으로 다시 나타나지 않습니다. 이미 업데이트를 마친 뒤에 열리는 창이라 필요 없는 정보였습니다. 앞으로 나올 릴리스 노트에는 열어도 "Page not found"만 나오던 PR 링크도 넣지 않습니다. 릴리스 페이지에서 웹으로 볼 때는 다운로드 항목을 누르면 설치 파일이 바로 받아집니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 이름이 같은 작업PC를 구분해 보여 줍니다

작업PC 선택 목록과 프로젝트 만들기 화면에서 이름이 같은 작업PC가 둘 이상이면 이름 뒤에 ID 앞자리를 붙이고, 꺼져 있는
작업PC는 그 사실을 글자로 함께 보여 줍니다. 같은 컴퓨터를 다시 연결해 예전 항목이 남아 있어도 어느 쪽인지 헷갈리지 않습니다.
기존 폴더 사용과 Git 가져오기 안내는 이 컴퓨터가 아니라 선택한 작업PC를 기준으로 설명합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 조직 관리형 Codex를 새 Chat AI 메뉴에 표시

조직에서 Codex 계정을 현재 PC에 연결한 경우 개인 OAuth 로그인 상태와 관계없이 새 Chat의 AI 도구 메뉴에 Codex를 표시합니다.

#### 사용 방법

조직 계정을 현재 PC에 연결한 뒤 새 Chat을 열면 AI 도구 메뉴에서 Codex를 선택할 수 있습니다.

### 조직 키를 받은 직후 첫 재시도에서 AI 연결이 한 번 더 실패하던 문제 수정

관리자가 조직 종단간 암호화에서 이 계정에 조직 키를 배포한 뒤 다시 시도해도, 앱이 받은 조직 키를 최대 5분 동안 반영하지 못해 이 PC의 키를 열지 못했습니다. 그 사이 연결 프로그램을 불필요하게 재시작해 경고가 한 번 더 나오거나, 재시도해도 몇 분간 실패했습니다. 이제 조직 키를 받은 것이 확인되면 바로 반영해 한 번에 연결하고, 재시작이 필요한 경우에도 다시 연결될 때까지 기다립니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 조직 키를 배포받은 뒤 시작 준비에서 다시 시도하면 한 번에 연결됩니다.

### 조직 AI 계정 적용이 실패하면 시간 초과 대신 실제 원인 코드를 보여 줌

시작 준비에서 조직의 관리 AI 계정을 이 PC에 적용하지 못할 때, 이전에는 85초를 기다린 뒤 `AI_CONNECTION_TIMEOUT`만 보였습니다. 이제 이 PC가 돌려준 실패 코드(예: 이미 다른 적용과 겹침, 로컬 기록 손상)를 상세에 표시해 원인을 바로 확인할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 시작 준비의 AI 연결 항목 정보 아이콘에서 실패 코드를 확인하고, 계속되면 진단 정보를 복사해 전달해 주세요.

### 최신 회사 키를 열 수 있는 경우에만 자동 배포 상태 표시

최신 회사 키를 열지 못하고 이전 키만 가진 Desktop이 자동 배포 가능한 상태로 표시되던 문제를 수정했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### AI가 시작하지 못하면 이유를 보여 줍니다

작업PC에서 Claude Code가 시작하자마자 멈추면, 대화가 "답변 중"에 머무르지 않고 실패로 끝나며 이유를 알려 줍니다. 예를 들어
root 계정으로 실행한 작업PC에서는 일반 사용자로 실행하라는 안내가 보이고, 바로 다시 메시지를 보낼 수 있습니다. 또 오래 쓰지
않은 대화가 정리된 뒤에도 메시지를 보내면 이어서 대화할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### AI가 작업하는 동안에도 입력한 글자가 바로 보이도록 개선

AI가 응답하는 중이거나 다른 대화가 진행 중일 때 입력하면 글자가 늦게 나타나던 문제를 줄였습니다. 화면의 "작업 중" 표시와 진행 아이콘처럼 계속 반복되는 애니메이션이, 입력한 글자가 화면에 보이는 시점을 한두 프레임 늦추고 있었습니다. 이제 입력하는 동안에는 이 애니메이션이 잠시 멈추고, 입력을 1초 쉬면 다시 움직입니다. 애니메이션이 보이는 상황에서 입력이 화면에 보이기까지의 시간이 최대 절반으로 줄었습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### Chat에서 조직 공용 환경변수를 바로 사용합니다

조직 관리자가 `조직 공용 환경변수`에서 기본 로드로 설정한 값은 Chat 세션에도 들어가 있었지만,
AI가 어떤 키가 있는지 안내받지 못해 사용하지 않거나 키가 없다고 답하는 경우가 있었습니다.
이제 Chat에서도 프로젝트와 같이 사용 가능한 환경변수 이름과 조직이 적어 둔 API 사용 안내를
AI에게 알려 줍니다. 값 자체는 안내에 포함되지 않습니다.

도구 권한 응답이나 서브에이전트 대화를 이어갈 때 Chat 세션이 다시 시작되면 조직 공용
환경변수가 빠지던 문제도 함께 고쳤습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 관리자 콘솔의 `조직 공용 환경변수`에서 그룹의 `기본 로드`가
켜져 있어야 Chat에 포함됩니다.

### Windows에서 다시 설치할 때 남아 있던 AI 실행 프로그램 때문에 설치가 멈추던 문제 수정

Windows에서 앱을 닫은 뒤 설치 파일로 다시 설치하면, 백그라운드에 남아 있던 연결 프로그램과 AI 도구(Claude) 때문에 설치가 오래 기다리다가 "닫을 수 없음" 창에서 멈출 수 있었습니다. 이제 설치를 시작할 때 이런 프로그램까지 찾아 한 번 확인한 뒤 함께 닫고 설치를 이어갑니다.

#### 사용 방법

설치 중 "실행 중이니 닫을까요?" 안내가 나오면 확인을 누르세요. 남은 프로그램을 닫고 설치를 계속합니다.
