## 새 기능

### 변경 목록에서 lock·생성 파일·빌드 산출물을 접어 둡니다

변경 패널의 파일 목록에서 lock 파일(package-lock.json·yarn.lock 등), 생성된 파일(*.min.js·*.map·__generated__ 등), 빌드 산출물(최상위 dist·out, 빌드 결과인 build 파일, .next 등)이 직접 고친 파일을 덮지 않도록, 목록 끝의 `잠금 파일`·`생성된 파일`·`빌드 산출물` 그룹으로 모아 기본으로 접어 둡니다. 그룹 줄에 개수가 보이고, 펼치면 다른 파일과 같은 줄로 보입니다. 모든 범위(기록 안 한 변경·브랜치 전체·변경기록·턴별)에 적용됩니다.

#### 사용 방법

작업 패널 추가 → 변경에서 목록 끝의 그룹 줄을 누르거나, 키보드로 그룹 줄에서 오른쪽 화살표를 누르면 펼쳐집니다. 찾기 칸에 입력하면 맞는 파일이 있는 그룹은 저절로 펼쳐집니다.

### 예약을 내 시간대 기준으로 실행합니다

지금까지 예약은 실행 PC의 시계로 실행돼서, PC가 UTC로 설정돼 있으면 09:00 예약이 한국 시간 18:00에 실행됐습니다. 이제 새 예약은 예약을 만든 사람의 시간대(한국이면 대한민국 시간)를 함께 저장하고, 실행 PC가 어느 시간대든 그 시간에 실행됩니다. 예약 목록에는 `매일 09:00 · 대한민국 시간`처럼 표시됩니다. 이 기능은 실행 PC의 Saycode가 업데이트돼 있어야 동작하며, 업데이트 전 PC에는 지금처럼 PC 시계 기준으로 저장됩니다. 이미 만든 예약은 바뀌지 않습니다.

#### 사용 방법

사이드바 `예약`에서 새 예약을 만들면 자동으로 내 시간대가 적용됩니다. 다른 시간대나 실행 PC 시계를 쓰려면 예약창의 `고급` → `시간대`에서 고릅니다. 기존 예약도 편집할 때 같은 곳에서 시간대를 고르면 그 시간대 기준으로 바뀝니다.

### 응답 중단·모델 바꾸기 단축키와 고정 대화 5~9번

키보드만으로 응답을 멈추고 모델과 작업 강도를 바꿀 수 있습니다. 응답 중인 대화에서 ⌘.(Windows/Linux는 Ctrl+.)을 누르면 입력창의 중단 버튼과 같은 방법으로 응답을 멈춥니다. 대화 입력창에서 ⌘⇧M(Ctrl+Shift+M)을 누르면 모델 메뉴에 보이는 순서대로 다음 모델로, ⌘⇧E(Ctrl+Shift+E)를 누르면 다음 작업 강도로 바뀌고 바뀐 값을 알려 줍니다. 고정 대화도 ⌘5~9(Ctrl+5~9)로 다섯 번째부터 아홉 번째까지 열 수 있습니다.

일부 단축키는 쓰이는 곳이 정해져 있어, 단축키 설정에 "입력창에서"·"파일 편집기에서"·"터미널 밖에서"처럼 조건이 함께 표시됩니다. 입력창과 파일 편집기처럼 동시에 쓰일 수 없는 곳의 단축키는 같은 키로 지정할 수 있습니다.

#### 사용 방법

내 설정 → 일반 → 단축키에서 새 동작의 키를 확인하고 바꿀 수 있습니다. 이미 같은 키를 다른 동작에 지정해 두었다면 그 지정이 그대로 유지되고 새 동작은 미지정으로 남습니다.

### 조직 정책을 설정·대화에서 확인

조직 관리자가 정한 제한(사용할 수 있는 AI 모델, 묻지 않고 실행하는 범위, 도구 규칙, AI 승인 심사 끄기, 오토파일럿·자동 실행 끄기, 작업보드·예약·standalone 모드 메뉴 숨기기)이 Desktop에 보입니다. 내 설정 → 일반 → 보안에 "조직 정책" 요약이 생겨 항목마다 정해진 값을 보여 주고, 이 PC의 Saycode 런타임이 아직 집행하지 않는 항목에는 "미지원"이라고 알려 줍니다. 조직이 끈 설정 스위치는 조직 값으로 잠기고 "조직 정책으로 정해진 설정" 안내가 붙으며, 내가 고른 값은 지워지지 않아 정책이 풀리면 그대로 돌아옵니다. 조직이 오토파일럿을 끄면 작업보드 카드에 "오토파일럿 사용 불가 · 조직 정책"이 보이고 PR 지킴이·깨어난 뒤 이어서 하기도 시작하지 않습니다. 조직이 예약을 끄면 사이드바 예약 메뉴와 입력창의 예약으로 만들기가 보이지 않고, 예약 화면에는 "조직 정책으로 예약을 쓸 수 없어요."가 보입니다. 대화에서는 Saycode 런타임이 조직 정책으로 권한 모드를 줄이거나 허용되지 않은 모델의 메시지를 실행하지 않았을 때 입력창 위에 한 줄 안내가 뜨고, 조직 정책을 24시간 넘게 새로 받지 못하면 "조직 정책이 24시간 이상 갱신되지 않음" 표시가 붙습니다. 무인 실행에서 조직 권한 상한 때문에 거절된 도구 요청은 "조직 권한 상한 때문에 무인 실행에서 자동 거절됨"으로 표시되고, 프로젝트 MCP 설정에서 조직이 끈 서버는 "조직이 끔"으로 보입니다. 조직 정책이 있으면 Desktop 대화 입력창에서 보내는 메시지는 처음부터 조직이 허용한 권한 모드로 보냅니다(메신저 채널과 하위 에이전트 메시지는 Saycode 런타임이 자릅니다).

#### 사용 방법

조직 계정으로 로그인하면 자동으로 적용됩니다. 내 설정 → 일반 → 보안 → 조직 정책에서 정해진 항목을 확인하고, 조직 소유자·관리자는 웹 관리 콘솔 열기로 정책을 바꾸는 화면에 갈 수 있습니다. 입력창 위 안내는 닫기 버튼으로 닫을 수 있습니다. 실제 집행은 조직 정책을 지원하는 Saycode 런타임이 맡습니다.

### 턴별 변경에서 다른 브랜치에서 들어온 변경을 빼고 보여 줍니다

AI가 턴 중에 `git pull`·`merge`·`rebase`를 하면, 변경 패널의 턴별 범위(이 턴·직전 턴 이후·대화 시작 대비)에 다른 사람이 만든 변경까지 섞여 이 턴이 바꾼 것처럼 보였습니다. 이제 그 범위 안에서 다른 브랜치로부터 들어오기만 한 파일은 목록에서 빼고, 목록 위에 `다른 브랜치에서 들어온 변경 N개는 뺐어요`를 보여 줍니다. 그 범위에서 직접 고치거나 커밋한 파일은 그대로 남고, 판단이 애매하면 빼지 않습니다. 이 업데이트 전에 기록된 턴은 지금처럼 모든 변경을 보여 줍니다.

#### 사용 방법

프로젝트 대화에서 작업 패널 추가 → 변경 → 턴별을 고르세요. 뺀 파일이 있으면 목록 위 안내의 보기를 눌러 펼치고 숨기기로 접을 수 있습니다. 머리말의 파일 수와 +/− 합계는 뺀 뒤의 값입니다.

### 프로젝트 대화를 정한 시각까지 잠시 숨길 수 있습니다

지금 신경 쓰지 않아도 되는 프로젝트 대화를 1시간, 4시간, 내일 오전 9시, 다음 주 월요일 오전 9시까지 사이드바 목록에서 치워 둘 수 있습니다. 숨긴 대화는 프로젝트 목록 아래 `숨긴 대화`에 남은 시간과 함께 모이고, 정한 시각이 되면 원래 자리로 돌아옵니다. AI가 승인이나 답을 기다리기 시작하면 시각 전이라도 바로 다시 보입니다. 숨긴 동안에는 비활동 자동 보관을 세지 않습니다. 숨긴 상태는 이 컴퓨터에만 저장됩니다.

#### 사용 방법

사이드바에서 프로젝트 대화에 마우스를 올리고 점 세 개 버튼 → `잠시 숨기기`에서 시간을 고릅니다. 바로 뜨는 알림의 `되돌리기`로 취소할 수 있습니다. 숨긴 대화는 프로젝트 목록 아래 `숨긴 대화`를 펼쳐 열거나 눈 버튼(`다시 보이기`)으로 바로 돌려놓습니다.

### 회사 MongoDB로 여러 작업PC의 프로젝트 메모리 주고받기

회사 MongoDB 주소를 입력하면, 작업PC의 프로젝트 메모리를 MongoDB에 올리고 같은 프로젝트의 다른 작업PC가 올린 메모리를 내려받아요. 한 작업PC에서 해결한 내용을 다른 작업PC의 AI도 찾아 쓸 수 있어요. 켜기 전부터 있던 메모리도 올라가요. 앱이 켜져 있는 동안 10분마다 자동으로 동기화해요. 메모리는 MongoDB에 암호화하지 않고 저장되며, 주소와 비밀번호는 그 작업PC에만 저장되고 Saycode 서버로 보내지 않아요.

#### 사용 방법

내 설정 → 개발 → 메모리에서 대상 프로젝트를 고른 뒤, MongoDB 메모리 동기화 카드에 MongoDB 주소와 데이터베이스 이름을 입력하고 동기화 켜기를 누르세요. 같은 프로젝트를 쓰는 작업PC마다 같은 주소·데이터베이스로 켜야 서로 메모리를 주고받아요. 주소의 사용자 이름이나 비밀번호에 @ / ? #가 있으면 %40, %2F, %3F, %23으로 바꿔 넣으세요. 동기화 끄기를 누르면 진행 중인 동기화도 바로 멈춰요. 작업PC에 claude-memory-layer 2.4.17 이상이 필요하며, 낮으면 같은 화면에서 패키지를 먼저 업데이트하세요.

### OpenCode의 작업 상태와 모델 변경 이력을 확인할 수 있어요

OpenCode 대화의 입력창 위에서 연결 확인·실행·재시도·확인 필요·완료·실패·중단·상태 미확인을 구분합니다. 실제 실행을 확인한 모델을 표시하고, 작업 상세에서 모델 시도·실패 이유·자식 및 셸 작업의 상태와 경과 시간을 볼 수 있습니다. 부모 답변이 끝나도 실행 중인 작업은 남습니다.

#### 사용 방법

OpenCode Project 또는 Chat 대화에서 입력창 위의 `작업 상세`를 누르세요. 이 상태 보고를 지원하는 작업PC CLI 업데이트가 필요합니다. 현재 변경은 로컬 검증 단계이며 공식 CLI 발행과 앱 runtime 반영 후 사용할 수 있습니다.

### PR 파일 탭의 읽음 표시를 GitHub과 맞추고, GitHub에 올라온 새 커밋도 알려 줘요

PR 화면 파일 탭에서 ‘GitHub에도 읽음 표시’를 켜면, 파일마다 체크한 읽음이 GitHub의 viewed 표시에도 남아요. 그래서 다른 PC나 GitHub 웹에서도 어디까지 봤는지 이어 볼 수 있어요. GitHub에서 읽음으로 표시한 파일은 앱에서도 읽음으로 보여요. 기본은 꺼져 있어요. 켜면 GitHub 웹과 다른 PC의 내 계정에서도 읽음이 보인다고 알려 줘요. GitHub에 보내지 못하면 앱의 표시는 그대로 두고, 이유와 다시 시도를 보여 줘요.

파일 탭을 열어 둔 동안 GitHub에 새 커밋이 올라오면 30초 안팎에 ‘GitHub에 새 커밋이 올라왔어요’를 보여 줘요. 읽은 파일의 내용이 바뀌었으면 ‘읽은 뒤 바뀜’으로 알려 줘요. 이 알림은 GitHub에도 읽음 표시를 켜지 않아도 동작해요.

#### 사용 방법

PR 화면의 ‘파일’ 탭에서 목록 위 ‘읽음 N/M’ 옆의 ‘GitHub에도 읽음 표시’를 켜세요. 계정마다 따로 저장돼요. 새 커밋 안내가 보이면 ‘새로고침’으로 새 diff를 읽어요.

## 변경된 기능

### 계획 승인 카드에서도 거절할 때 이유를 함께 보낼 수 있어요

Claude 대화에서 AI가 계획을 보여 주고 승인을 기다리는 계획 승인 카드에서도, 거절하면서 이유를 적어 AI에게 함께 보낼 수 있어요. 일반 권한 요청 카드와 같은 자리에 같은 모양으로 있고, 작업 PC의 happy-cli 버전과 관계없이 쓸 수 있어요.

#### 사용 방법

계획 승인 카드의 버튼 아래 ‘이유를 적고 거절’을 펼쳐 같은 방법으로 보내세요.

### 내가 연 다른 대화도 에이전트가 방향 수정·중단할 수 있습니다

사람이 시작한 Claude·Codex 대화의 에이전트가, 같은 사용자가 따로 연 다른 대화의 응답에 방향 수정(steer)과
중단(stop)을 보낼 수 있습니다. 지금까지는 그 에이전트가 직접 띄운 하위 대화에만 됐습니다.
다른 대화의 중단은 그 대화를 끄지 않고 진행 중인 응답만 끊습니다. 터미널에서 쓰는 Claude 대화에는 방향 수정·중단을 보내지 않습니다.
에이전트가 띄운 하위 대화는 다른 대화를 제어할 수 없고, 다른 사람의 대화와 소유를 확인하지 못한 대화는 이전처럼 제어할 수 없습니다.
이번 변경은 개인 계정 PC에 적용됩니다. 회사 계정 PC는 이후 업데이트에서 지원합니다.

#### 사용 방법

에이전트에게 "다른 대화 ○○의 응답을 멈춰 줘"처럼 요청하세요. 에이전트는 `happy agent ls`에서
`ownership.relation`이 `own-sibling`인 대화에만 보내고, 보내기 전에 대상 제목과 ID를 알려 줍니다.
중단 결과에는 `mode: "turn-abort"`가 붙습니다.

### 모든 조직에서 작업물을 빠르게 모아보기

모든 조직에서 작업물 모아보기를 사용할 수 있습니다. 전체 메시지 이력을 기다리는 대신 일부 작업물부터 표시하고 아래로 스크롤할 때 이어서 불러옵니다. 추가 조회 중에도 기존 목록을 유지하며, 실패한 조회는 다시 시도할 수 있습니다.

#### 사용 방법

프로젝트 대화의 파일 패널에서 작업물 모아보기를 누르고 이 대화 또는 이 프로젝트를 선택하세요. 목록을 아래로 스크롤하거나 더보기를 누르면 이전 작업물을 가져옵니다.

### 예약 시각이 어느 시간대 기준인지 보여 줍니다

예약 작업은 실행 PC의 시계로 실행됩니다. 실행 PC가 UTC 같은 다른 시간대이면 입력한 09:00이 한국 시간 18:00에 실행되는데, 지금까지는 화면에 "PC 기준"만 보여서 한국 시간으로 오해하기 쉬웠습니다. 이제 시각 옆과 예약 목록에 실제 시간대(예: `UTC 기준`, `실행 PC 기준 (UTC)`)를 표시합니다. 실행 PC 시간대가 내 시간과 다르면 다음 실행 시각을 내 시간으로 바꿔 함께 보여 줍니다.

#### 사용 방법

사이드바 `예약`에서 새 예약을 만들거나 예약을 편집하면 실행 시각 옆에 시간대가 보입니다. 실행 PC 시간대가 다르면 그 아래에 `내 시간(대한민국 시간)으로 다음 실행: …`이 표시됩니다. 예약 목록의 각 행에도 같은 정보가 나옵니다.

### 오래된 작업트리 정리를 매시간 안전하게 실행

앱 실행 중 오래된 작업트리 정비를 매시간 실행하고, 산출물 회수 요청 후 전체 작업트리를 정리합니다. 정비가 겹치면 다음 주기를 건너뛰며 계정이 바뀌면 후속 작업을 시작하지 않습니다. 기존 7일 유예, 실행 중 대화·열린 PR·미커밋/미푸시 변경·로컬 파일 보호와 브랜치 보존을 유지합니다. 삭제 직전 갱신된 파일과 Git 메타데이터를 확인할 수 없는 상위 작업트리를 보존하며, FIFO 형태의 손상된 잠금에서도 정비가 멈추지 않도록 했습니다. 로컬 운영 도구는 20GiB 경고와 실제 필요 용량을 구분하고, 검증된 종료 소유자 잠금 복구와 크기가 제한된 용량 이력을 지원합니다.

#### 사용 방법

자동 정리는 앱 실행 중 적용됩니다. 수동 검토는 프로젝트 도구 → 브랜치 버튼 → 작업트리… → 오래된 작업트리 일괄 정리에서 합니다. 로컬 파일은 기본으로 남습니다. 호스트 운영 도구 설치는 별도로 수행하며 제품 원격 정비 게이트를 활성화하지 않습니다.

### 웹에서 같은 PC의 개인 AI 사용 설정 연동

웹의 사용량 패널에서 변경한 개인 AI 사용 허용 설정을 이 PC의 데스크톱과 함께 사용합니다. 동일 Saycode 계정으로 데스크톱이 실행 중이어야 합니다. 다른 PC나 다른 사용자의 설정은 변경하지 않습니다. 설정 파일을 읽거나 복호화하지 못했을 때는 허용 상태로 바꾸지 않고 오류를 표시하며, 읽지 못한 기록을 덮어쓰지 않습니다. 웹 서버와 데스크톱의 동반 업데이트가 필요합니다.

#### 사용 방법

대상 PC에서 업데이트한 데스크톱을 웹과 같은 Saycode 계정으로 실행하세요. 웹 채팅 입력창의 AI 사용량을 열고 Claude 탭에서 “이 PC에서 개인 계정 사용 허용”을 변경하면 데스크톱 사용량 패널에도 반영됩니다.

### 조직 Claude 작업이 한꺼번에 시작되지 않도록 조절합니다

조직에서 연결한 Claude로 짧은 시간에 여러 개발 작업을 시작하면, 다음 작업은 시작 여유가 생길 때까지 기다립니다. 같은 인증 정보를 사용하는 여러 작업 PC의 시작 횟수를 함께 계산하며, 대기 안내가 대화에 표시됩니다. 대기 중 취소한 요청은 나중에 실행하지 않습니다.

#### 사용 방법

이 기능을 지원하는 연결 프로그램으로 작업 PC를 업데이트하면 별도 설정 없이 적용됩니다. 대기 중인 요청은 기존 중단 기능으로 취소할 수 있습니다. 개인 인증으로 실행하는 작업에는 이 제한이 적용되지 않습니다.

### 채팅 HTML 미리보기가 앱 테마를 따릅니다

채팅 안 HTML 미리보기와 파일 뷰어의 HTML·DOCX 문서가 컴퓨터(OS)의 밝기 설정이 아니라 앱에서 고른
라이트/다크 테마를 따를 수 있게 됐습니다. 본문만 있는 HTML 조각과 DOCX 문서는 앱 테마로 그려져, 앱은 다크인데
컴퓨터가 라이트라서 미리보기만 하얗게 뜨던 일이 없어집니다. AI가 만드는 HTML은 앱과 같은 배경·글자·강조
색을 써서 앱 테마를 따를 수 있고, 테마를 바꾸면 열려 있는 미리보기도 곧바로 따라 바뀝니다. 스스로 색을
정하지 않은 완성된 HTML 문서는 지금처럼 밝은 바탕으로 그려지고, 자체 색을 정한 문서는 그 색을 유지합니다.

테마를 바꾸면 미리보기를 새로 그리므로, 미리보기 안에서 넘긴 슬라이드나 입력한 값은 처음 상태로
돌아갑니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 테마는 계정 메뉴의 '다크 모드'에서 바꿀 수 있습니다.

## 수정된 문제

### 권한 응답의 빠른 중복 실행 방지

일반·프로젝트 경로·정책 권한 카드의 같은 승인이나 거절을 빠르게 반복해도 한 번만 처리합니다. 같은 응답은 처리 중과 첫 수락 뒤 0.5초 동안 보호하며, 실패 이유는 그대로 남습니다. 새로 발행된 권한 요청은 이전 결과로 잠기지 않습니다. 다른 요청이나 새 응답은 독립적으로 처리하고 대화를 바꾸면 이전 카드의 상태가 남지 않습니다.

#### 사용 방법

별도 설정 없이 기존 권한 카드의 허용·거절을 사용하세요. 다른 패널의 처리가 끝난 뒤 재시도와 기존 카드 복구도 계속 사용할 수 있습니다.

### 권한 일괄 응답 중 개별 카드가 중복 응답하지 않도록 수정

같은 권한을 기다리는 대화에 일괄 응답하는 동안 개별 카드에서 같은 요청에 다시 답해도 중복 전달하지 않습니다. 알림 센터를 닫아도 진행 중인 응답을 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 응답 중 안내가 보이면 기존 응답이 끝날 때까지 기다려 주세요.

### 꺼진 메모리 대시보드를 오류로 표시하지 않음

예전에 켠 메모리 대시보드가 머신 재시작 등으로 꺼져 있으면, Memory 설정에 빨간 "Dashboard process is not running." 오류가 떴습니다. 메모리 동기화가 실패한 것처럼 보였지만 실제 문제는 없었습니다. 이제는 오류 없이 "실행 중 아님"으로만 표시합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 대시보드가 필요하면 Memory 설정의 대시보드 카드에서 "대시보드 시작"을 누르세요.

### 밀린 업데이트를 최신 버전으로 한 번에 설치해요

앱을 오래 켜둔 사이 여러 업데이트가 나와도, 내려받기와 재시작 직전에 최신 버전을 다시 확인합니다.
이미 내려받은 버전보다 새 버전이 있으면 바꿔 받아 한 번만 재시작합니다.
릴리스 노트에는 업데이트 피드가 제공하는 건너뛴 버전의 변경 내용도 함께 표시하며, 재시작 후에도 합산된 내용을 볼 수 있습니다.

#### 사용 방법

기존처럼 업데이트를 내려받고 `재시작해서 업데이트`를 누르세요. 더 새 버전이 있으면 자동으로 바꿔 받습니다.

### 변경기록 작업의 빠른 중복 실행 방지

변경기록 패널에서 파일 담기·변경기록 남기기·AI 생성의 빠른 중복 실행을 막습니다. 같은 작업은 첫 실행 후 최소 0.5초와 처리 완료까지 기다립니다. 처리 중 새로 적은 메시지는 이전 작업 결과가 덮어쓰지 않습니다. 확인이나 생성을 취소하면 바로 다시 시도할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 보내기 전 첨부도 앱 재시작 후 복원

프로젝트 대화와 Chat에서 업로드 전 파일·이미지·폴더를 이 기기에 자동 저장합니다. 앱을 다시 켜면 원래 입력창에 복원하며, 저장을 마친 파일은 원본을 옮겨도 복구할 수 있습니다. 첨부 제거와 업로드·전송 완료는 저장본에도 반영합니다. 첨부 조회가 잠시 실패하거나 저장 공간이 거의 찬 상태에서 새 대화로 넘어가도 기존 첨부를 보존하도록 보강했습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 일반 첨부는 이 기기에 총 1GiB까지 보관하며 저장에 실패하면 입력창에 안내합니다. 보안 문서 원본 첨부는 기존 보호 정책에 따라 재시작 후 다시 선택해야 합니다.

### 브라우저 주소 후보와 화면 크기 메뉴의 키보드 조작

내장 브라우저의 주소 후보와 뷰포트 메뉴를 열면 첫 항목 또는 현재 선택에 초점이 갑니다. 방향키와 Home/End로 항목을 이동하고 Enter/Space로 선택할 수 있습니다. Escape로 취소하거나 항목을 선택하면 원래 버튼으로 돌아옵니다. 비활성 항목은 방향키 이동에서 제외합니다.

#### 사용 방법

프로젝트 대화의 도구에서 브라우저를 열고 주소 후보 또는 뷰포트 버튼을 누르세요. 방향키·Home/End로 이동하고 Enter/Space로 선택하거나 Escape로 취소하세요.

### 브랜치 작업의 빠른 반복 실행 방지

브랜치 이동·생성·이름 변경·삭제의 동일 실행은 처음 누른 뒤 최소 0.5초와 실제 처리 중 반복을 막습니다. 무시된 재클릭은 입력과 확인창을 보존하며 처리가 끝난 뒤 다른 이름·브랜치는 대기 없이 실행할 수 있고 실행 전 확인 취소는 그대로 사용할 수 있습니다. 이전 프로젝트나 로그인에서 늦게 끝난 결과가 현재 브랜치 창을 덮지 않도록 수정했습니다.

#### 사용 방법

프로젝트 대화의 Git 메뉴에서 브랜치 전환을 열면 자동 적용됩니다. 별도 설정은 필요하지 않습니다.

### 빠르게 반복한 즉시 요청과 다시 보내기 중복 방지

대기 목록의 즉시 요청과 전달 확인 실패 메시지의 다시 보내기를 빠르게 반복해도 같은 요청은 최소 0.5초와 처리 완료까지 한 번만 수락합니다. 빠른 실패 뒤에도 원래 요청과 실패 이유가 남으며, 다른 대기 항목은 따로 보낼 수 있습니다. 재전송은 원래 메시지를 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 대기 중인 요청의 즉시 요청 또는 전달을 확인하지 못한 메시지 아래 다시 보내기를 사용하세요.

### 빠른 재시도에서 원래 실패 이유 유지

개인 Chat의 전송이 빠르게 실패해도 같은 재시도는 처음 누른 뒤 0.5초 동안 중복 전송되지 않습니다. 무시된 재클릭은 원래 실패 이유를 바꾸거나 AI 연결 창을 닫지 않으며, 자동 모델 혼잡 복구의 재시도 횟수도 소모하지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 기존 이어서 하기·다시 시도·AI 연결 설정의 재시도를 사용하세요. 새로운 다음 초안과 취소·중지는 계속 사용할 수 있습니다.

### 시스템 시계가 바뀌어도 재입력 보호 시간 유지

빠른 반복 실행을 막는 0.5초 보호가 컴퓨터 시계 변경으로 짧아지거나 길어지지 않도록 수정했습니다. 프로젝트 만들기, Chat 시작·보내기, 대기 요청과 다시 보내기의 진행 중 보호와 정상 다음 요청은 그대로 유지됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 기존 만들기·보내기·즉시 요청·다시 보내기를 사용하세요.

### 여러 Git 메뉴에서 같은 작업을 연속 실행하는 문제 수정

같은 계정·PC·폴더의 헤더와 입력창 Git 메뉴에서 파일 담기·변경기록 남기기·기준 브랜치 반영이 겹쳐 실행되지 않도록 했어요. 같은 실행은 최소 0.5초와 처리 완료까지 기다리며, 무시한 재클릭은 기존 오류와 작성 중인 메시지를 유지해요. 다른 폴더의 작업과 별도 편집기의 AI 메시지 생성은 계속 사용할 수 있어요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 입력창 화살표가 현재 대화의 요청만 불러오도록 수정

프로젝트와 Chat 입력창에서 위쪽 화살표를 누르면 다른 대화의 요청이 나타나던 문제를 수정했습니다. 새 대화에는 다른 대화의 기록이 나타나지 않습니다. 프롬프트 검색의 기존 복구 기록은 유지합니다.

#### 사용 방법

빈 입력창에서 위·아래 화살표로 현재 대화에 불러온 이전 요청을 탐색하세요. 다른 대화의 기록은 대화 추가 옵션 → 프롬프트 검색에서 찾을 수 있습니다.

### 잠긴 대화와 열람 오류 안내 및 자동 복구

대화의 잠금이나 접근 문제를 빈 대화처럼 표시하지 않고 원인과 해결 방법을 안내합니다. 이 기기의 키가 잠겼다면 보안 설정으로 이동할 수 있으며, 키가 준비되면 같은 대화의 제목과 본문을 다시 불러옵니다. 대화를 직접 다시 불러올 때는 늦게 배포된 조직 키도 즉시 확인합니다. 읽지 못한 대화에서는 초안을 유지하며 전송을 제한합니다.

#### 사용 방법

프로젝트에서 대화를 여세요. 잠금 안내의 **보안 설정에서 잠금 해제**를 눌러 기존 복구 키 또는 신뢰 기기 승인 절차로 해제하세요. 권한·키 배포 확인이 필요하면 안내에 따라 프로젝트 소유자나 조직 관리자에게 확인한 뒤 **대화 다시 불러오기**를 누르세요.

### 전송·고정·보관·대화 이동이 바로 반응해요

전송한 메시지가 준비 단계부터 보이고, 대화 고정과 보관은 서버 응답을 기다리지 않고 화면에 반영됩니다.
실패하면 입력과 목록 상태를 복구합니다. 이미 연 채팅은 기존 탭과 내용을 바로 보여주며, 처음 여는
채팅의 내용을 불러오지 못하면 이전 화면으로 돌아갑니다. 늦은 실패가 이후 선택을 되돌리지 않습니다.
전송 준비 중에도 다음 메시지 초안을 입력할 수 있습니다. 새 초안이 있으면 실패한 메시지를 대화에서
다시 보낼 수 있어 입력을 덮어쓰지 않습니다. 보관이 성공하면 해당 대화 탭도 닫힙니다.
준비 중 계정이나 조직을 바꾼 뒤 실패해도 원래 요청을 원래 계정에 보존합니다.
재전송이 성공한 뒤 이전 오류 안내가 남지 않고, 작성 중인 다음 초안에 입력 포커스가 유지됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 사이드바 채팅의 고정 버튼, 더보기 → 보관하기, 대화 선택과 대화 입력창의 보내기를 평소처럼 사용하세요.

### 전송한 글과 첨부를 입력 기록에서 복구

프로젝트 대화와 Chat에서 일반 첨부 업로드가 끝나면 글과 함께 파일 이름·업로드 경로를 로컬 입력 기록에 남깁니다. 전송 후 입력이 사라져도 기록에서 다시 불러올 수 있습니다. 저장 연결 실패 후 화면을 다시 열 때 이번 실행의 기록이 지워지는 문제도 수정했습니다. 다른 창에서 보낸 최신 요청과 함께 조회해도 입력한 시간순으로 복원합니다. 대화 시작 실패 직후 누른 다시 시도가 무시되는 문제도 수정했습니다. 진행 중인 요청의 중복 실행은 계속 막습니다.

#### 사용 방법

입력창의 `⋯ → 프롬프트 검색`에서 요청을 고르세요. 업로드된 파일 경로가 함께 복원되며 자동으로 전송하지 않습니다. 빈 입력창의 ↑는 현재 대화에 불러온 요청만 탐색합니다.

### 조직 계정 대화 시작 실패 후 다음 행동 안내

조직 AI 계정으로 첫 대화를 시작하지 못하면 계정 변경 또는 관리자 문의를 한 문장으로 안내합니다. 안내의 AI 사용량을 누르면 계정 선택 창이 바로 열립니다. 언어를 바꿔도 안내를 유지하며 키보드로 창이 중복해 열리지 않습니다.

#### 사용 방법

Chat 또는 Project의 시작 실패 아래 안내를 확인하세요. 안내 속 AI 사용량을 눌러 다른 계정을 선택한 뒤 다시 시도를 누르거나 관리자에게 직접 문의하세요. 원래 요청과 첨부는 유지됩니다.

### 질문 답변과 계획 응답의 빠른 중복 실행 방지

질문 답변과 계획 승인·수정 요청을 처리하는 동안 같은 요청이 중복 실행되지 않습니다. 빠르게 실패한 같은 응답은 첫 실행부터 0.5초 뒤 다시 시도할 수 있으며 기존 답변과 실패 이유를 유지합니다. 다른 세션·질문과 수정한 응답은 독립적으로 처리합니다.

#### 사용 방법

기존 질문의 보내기·건너뛰기, 계획의 작업 시작·수정 요청을 그대로 사용하세요. 선택·직접 입력·페이지 이동은 즉시 동작합니다.

### 파일 내용 검색의 확인 실패와 검색 실패 재시도

파일 내용 검색의 지원 확인 실패와 실제 미지원 상태를 구분합니다. 지원 확인이나 검색이 실패해도 검색어를 유지하며, 다시 확인 또는 다시 검색으로 복구할 수 있습니다. 프로젝트나 작업PC가 바뀌면 이전 대상의 지원 상태와 결과를 표시하지 않습니다.

#### 사용 방법

프로젝트 대화의 작업 도구에서 파일을 열고 내용 검색을 켜세요. 지원 확인 실패에는 다시 확인을, 검색 실패에는 다시 검색을 누르세요.

### 프로젝트 생성과 대화 전송의 연속 클릭 방지

같은 프로젝트 만들기 요청을 빠르게 반복하거나 대화 전송의 확인창이 열린 동안 다시 눌러도 중복 실행하지 않습니다. 처리 중에는 추가 실행을 막고, 같은 생성 초안은 최소 0.5초 동안 재실행하지 않습니다. 확인을 취소하거나 창을 닫은 뒤 다시 시도할 수 있으며, 수정한 초안·첨부 교체 후 재시도·대화 중단은 바로 사용할 수 있습니다. 메시지 전송 전의 첨부 확인이나 보관된 대화 복원 준비가 실패해도 초안을 유지하고 다시 시도할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 프로젝트 프로세스 목록의 전환과 새로고침 안정화

프로젝트나 작업PC가 바뀌거나 창을 다시 열 때 이전 조회 결과와 작업폴더 경로가 새 목록에 섞이지 않도록 고쳤습니다. 새로고침 중에는 마지막으로 확인한 목록과 진행 표시를 유지하며, 조회가 실패하면 다시 시도할 수 있습니다.

#### 사용 방법

프로젝트 도구 → 프로젝트 프로세스 보기에서 새로고침을 누르세요.

### 한국어 macOS에서도 완료 해제한 대화의 작업 폴더를 다시 만듭니다

완료한 대화를 다시 열면 지워졌던 작업 폴더(worktree)를 같은 브랜치로 다시 만듭니다. 같은 이름의 폴더가 이미 남아 있으면 이름 뒤에 `-2` 같은 번호를 붙여 만들어야 하는데, 시스템 언어가 한국어인 macOS에서는 이 재시도가 동작하지 않아 복원이 실패했습니다. 이제 시스템 언어와 관계없이 번호를 붙여 다시 만듭니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### AI 브라우저 설치판의 플랫폼별 파일 구성 수정

Mac 설치판의 불필요한 Windows 실행 파일을 제외하고, Mac 전용 브라우저 모듈 때문에 Windows 설치판 준비가 실패하던 문제를 수정했습니다. 각 운영체제의 AI 브라우저와 CLI에 필요한 파일은 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### AI 브라우저 준비 중 계정 전환과 키보드 복구 개선

AI 브라우저 준비 중 로그아웃하거나 계정의 서버·조직이 바뀌면 이전 요청으로 설치 설정을 저장하지 않습니다. 다른 설치가 먼저 만든 설정도 덮어쓰지 않습니다. 준비 메뉴에서 다시 확인하거나 다시 시도한 뒤에도 키보드로 계속 이동할 수 있습니다.

준비 요청이 응답하지 않아도 60초 뒤 다시 시도할 수 있으며, 늦게 도착한 이전 결과가 재시도 상태를 덮지 않습니다.

개인 PC에서 AI 브라우저 화면을 열 때 설치된 프로필을 사용하도록 수정했습니다. 이 수정은 해당 프로필 정보를 보고하는 CLI와 함께 적용됩니다.

#### 사용 방법

AI 브라우저 메뉴 표시를 켠 뒤 입력창의 + 메뉴에서 준비 상태를 확인하세요. Chrome 설치 안내에는 다시 확인, 준비 실패에는 다시 시도를 사용하세요.

### AI 사용량 창의 상단 정보와 탭 고정

AI 사용량 창에서 긴 계정 목록을 스크롤해도 작업PC 정보·새로고침 버튼·AI 탭이 상단에 유지됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. AI 사용량 창에서 탭 아래 내용을 스크롤하세요.

### Chat의 빠른 연속 전송으로 같은 요청이 반복되는 문제 수정

새 Chat 시작·메시지 전송·대기 요청 추가를 빠르게 반복해도 같은 요청을 한 번만 처리합니다. 같은 내용을 새로 입력하거나 빠른명령에서 다시 고른 요청은 따로 보낼 수 있습니다. 첫 Chat이 준비 중이어도 홈에서 다른 Chat을 시작할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 확인을 취소하거나 AI 정보 확인에 실패하면 같은 화면에서 다시 시도할 수 있습니다.

### Git 가져오기·보내기 연속 실행과 이전 대화 결과 혼선 수정

같은 계정·PC·폴더의 가져오기와 보내기는 처리 중 겹쳐 실행되지 않으며, 같은 실행은 첫 클릭부터 최소 0.5초 동안 반복되지 않아요. 인증을 기다리는 동안에도 중복을 막고 다른 폴더의 실행은 유지해요. 다른 폴더에서 시작한 작업의 늦은 완료가 현재 결과를 덮지 않도록 했어요. 실제 쓰기를 시작하기 전 준비가 취소되거나 실패한 경우는 바로 다시 시도할 수 있어요.

#### 사용 방법

대화 입력창 위 작업환경 메뉴 또는 프로젝트 도구의 Git 메뉴에서 가져오기·보내기를 사용하세요. 별도 설정 없이 자동 적용됩니다.
