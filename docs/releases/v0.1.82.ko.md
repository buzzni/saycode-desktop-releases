## 새 기능

### 내 메시지에서 이 시점으로 파일 되돌리기

파일 복원지점을 켠 대화에서 내가 보낸 메시지마다 `이 시점으로 파일 되돌리기`가 생겼어요. 누르면 그 메시지를 보내기 직전의 파일 상태로 바뀔 파일을 미리 보여 주고, 확인한 뒤에만 되돌려요. 되돌린 뒤에는 `다시 적용`으로 되돌리기 전 상태로 돌아갈 수 있어요. `여기서 다시 쓰기`를 누르면 파일도 그 시점으로 되돌릴지, 파일은 유지할지 먼저 물어요.

#### 사용 방법

Project 대화에서 되돌릴 시점의 내 메시지에 마우스를 올리고 시계 모양 아이콘(또는 오른쪽 클릭 → 이 시점으로 파일 되돌리기)을 누르세요. 미리보기에서 확인란을 선택하고 파일 상태 복원을 누르면 됩니다. 응답 중이거나 작업PC가 연결되어 있지 않으면 아이콘이 잠기고 이유가 보여요.

### 사이드바 대화를 상태순으로 정렬하고 상태별로 골라 볼 수 있어요

사이드바 프로젝트 대화를 상태순으로 정렬하면 내 입력을 기다리는 대화, 끝났지만 아직 안 열어본 대화, 응답 중인 대화가 차례로 위에 옵니다. 대화 상태 필터로 그중 한 상태의 대화만 골라 볼 수도 있어요. 상태는 대화 행의 상태 점과 같은 기준이라, 연결된 PR이 이미 병합된 대화는 안 열어본 대화로 치지 않습니다. 기본 보기(최근 활동순, 끌어서 바꾼 순서)는 그대로이고, 보기를 바꾸면 프로젝트 목록 맨 위에 지금 보기가 표시됩니다.

#### 사용 방법

Project 목록 맨 위에서 위로 스크롤해 검색창을 드러낸 뒤 오른쪽 점 세 개(프로젝트 보기 옵션)를 누르고, 대화 정렬에서 상태순을, 대화 상태에서 보고 싶은 상태를 고르세요. 목록 맨 위 줄의 기본 보기로를 누르면 처음 보기로 돌아갑니다.

### 새 Codex 대화를 조직 정액 플랜으로 시작할 수 있습니다

조직에서 정액 플랜(Saycode 플랜) 등급을 받은 구성원은 새 Codex 대화를 시작할 때 실행 방식을 고를 수 있습니다.
"Saycode 플랜 · 이번 주 남은 사용량 N%"를 고르면 그 대화는 정액 플랜으로 실행되고, "이 머신의 Codex 로그인"을
고르면 지금처럼 작업PC의 Codex 로그인으로 실행됩니다. 플랜을 쓸 수 없으면 대화를 시작하지 않고 이유를 보여 주며,
작업PC의 Codex 로그인으로 몰래 바꿔 실행하지 않습니다. 플랜 상태를 확인하지 못했고 직접 고른 것도 없으면
시작 전에 "플랜 상태를 확인하지 못해 이 머신의 Codex 로그인으로 시작합니다."라고 알린 뒤 Codex 로그인으로 시작합니다. 상위 모델의 이번 주 사용량이 다 찼으면 gpt-6-luna로
시작한다고 미리 알려 줍니다.

플랜 대화는 대화 위에 플랜 배지가 보이고, 사용량과 재설정 시각을 확인할 수 있습니다. 한도에 닿으면(사용률이 100%가 되기 전이라도 다음 요청을 감당할 수 없으면) 다시 쓸 수 있는 시각과
"구독으로 새 세션"이 나타나 이 머신의 Codex 로그인으로 이어서 대화할 수 있습니다. 플랜 대화는 터미널에서 이어가기를
막습니다.
플랜 대화는 이 PC의 개인 Codex 로그인을 쓰지 않으므로, 개인 Codex 연결을 해제했어도 플랜 대화의 시작·이어가기·재개는
막지 않습니다. 이 머신의 Codex 로그인으로 도는 대화는 지금처럼 확인합니다.

#### 사용 방법

Project에서 새 대화를 열고 AI를 Codex로 고른 뒤, 입력창 옵션 아래의 "대화 실행 방식"에서 고릅니다. 지금 고른 방식을
다음에도 쓰려면 "기본값으로 저장"을 누릅니다. 작업PC의 Saycode 실행기가 정액 플랜을 지원해야 보입니다.

### 예약 실행 실패 원인과 바로 할 일을 실행 이력에서 보여 줍니다

예약 작업 회차가 실패하거나 취소되면 "실행 실패"·"취소됨" 대신 작업PC나 서버가 남긴 원인을 보여 줍니다. 예를 들어 "커넥터 로그인이 필요해 실행하지 못함", "실행 계정이 연결되지 않아 실행하지 못함", "실행을 준비하지 못함 · 연결 재시도 2회 후", "대화가 보관되어 취소됨"처럼 표시됩니다. 커넥터 때문에 실패한 회차에는 "연결 설정" 버튼이 붙어 바로 커넥터 설정을 열 수 있습니다. 이전 실행 때문에 건너뛴 회차는 "이전 실행이 아직 진행 중이라 건너뜀"으로 표시합니다. 원인을 알 수 없는 회차는 예전 문구 그대로입니다.

#### 사용 방법

사이드바 예약에서 예약 행의 더보기(⋮) → 실행 이력을 엽니다. 예약 행 아래 최근 결과 줄과 프로젝트 설정 → 자동화의 실행 이력에도 같은 원인이 보입니다.

### 응답 중에 보낸 메시지를 어떻게 처리할지 고를 수 있어요

AI가 응답하는 동안 프로젝트 대화에서 보낸 메시지를 대기열에 넣을지(기본값, 지금과 같음), 지금 응답에 바로 반영할지, 응답을 중단하고 새로 보낼지 고를 수 있습니다. 중단하고 보내기는 응답이 멈춘 뒤에 메시지를 한 번만 보내고, 멈추지 못하면 대기열에 넣어 메시지를 잃지 않아요. 응답 중 보내기 버튼에 마우스를 올리면 지금 누를 때의 동작과 Cmd+Enter의 동작이 보이고, Cmd를 누르고 있는 동안 버튼 이름이 바뀝니다. 처음으로 지금 반영이 성공하면 짧은 안내가 한 번 나와요.

#### 사용 방법

설정 > 단축키 맨 위 응답 중 새 메시지에서 대기열에 넣기, 지금 반영, 중단하고 보내기 중 하나를 고르세요. 응답 중 Cmd+Enter(Windows는 Ctrl+Enter)를 누르면 다른 방식으로 보냅니다. 대기열에 넣기면 지금 반영, 나머지 둘이면 대기열에 넣기예요.

### 작업 시작 한도에 걸리면 여유 있는 다른 조직 계정으로 바로 이어서 실행합니다

조직 Claude 계정이 10분 안 작업 시작 한도에 도달하면 '계정의 작업 시작 한도에 도달해 기다리고 있습니다' 안내와 함께 대화가 멈춰 있었습니다. 이제 배정된 다른 조직 계정에 여유가 있으면 그 계정으로 옮겨 보낸 메시지를 바로 실행하고, '여유가 있는 다른 조직 계정으로 옮겨 바로 실행합니다'라고 알려 줍니다. 전용 PC와 공용 PC 모두 해당합니다. 모든 계정이 한도에 걸려 있을 때만 이전처럼 기다립니다. 계정당 한도도 10분 4건에서 8건으로 늘었습니다(서버에 이미 적용).

#### 사용 방법

별도 조작은 없습니다. 작업 PC가 이 버전의 런타임으로 갱신되면 자동으로 적용됩니다. 실행 중인 작업은 끊지 않고, 다음 메시지를 보내기 직전에만 계정을 옮깁니다.

### 컨텍스트 사용률을 눌러 바로 대화를 압축할 수 있어요

Claude 대화의 입력창 아래 ‘컨텍스트 N%’를 누르면 작은 창이 열려요. 사용 중인 토큰과 전체 창 크기, 80% 이상일 때의 경고를 보여 주고, 그 자리에서 대화 압축을 실행할 수 있어요. 압축 버튼은 /compact를 대신 보내 주므로 입력창에 쓰던 글은 그대로 남아요. 압축하는 동안에는 사용률 자리에 ‘압축 중’이 돌아가고, 직접 /compact를 입력해 시작한 압축에도 같은 표시가 나와요. 압축이 끝나면 사용률은 잠시 사라졌다가 다음 답변 뒤에 줄어든 값으로 다시 나타나요. 응답 중이거나 질문·승인 요청이 기다리는 동안에는 버튼이 꺼지고 이유가 함께 보여요.

#### 사용 방법

Claude 대화에서 입력창 아래 정보 줄의 ‘컨텍스트 N%’를 누른 뒤 대화 압축을 누르세요. Esc를 누르거나 창 밖을 누르면 닫혀요.

### 터미널에서 실행한 claude·codex가 응답을 끝내면 탭에 표시

이 컴퓨터의 터미널 탭에서 직접 실행한 claude나 codex가 응답을 끝내고 입력을 기다리면, 그 터미널 탭과 터미널이 있는 대화 탭에 초록 링 점이 나타납니다. 다른 대화를 보고 있어도 터미널 쪽 작업이 끝났는지 바로 알 수 있습니다. 터미널을 열어 보거나 입력하면 점이 사라집니다. 다른 작업PC의 터미널과 Windows는 아직 지원하지 않습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 끄려면 내 설정 → 개발 → 터미널 → AI 응답 상태 표시에서 사용을 끔으로 바꿉니다.

### 프로젝트 대화에서 샌드박스 없이 실행 중인지 표시

프로젝트 대화가 샌드박스 없이 돌고 있으면 입력창 바로 위에 "샌드박스 없이 실행 중"과 이유(예: Windows에서는 아직 샌드박스를 쓸 수 없음)를 한 줄로 보여 줍니다. 이 PC의 원격 대화처럼 원래 샌드박스를 쓰지 않는 대화는 경고가 아니라 안내로 알려 줍니다. 앱이 PC 종류나 AI를 보고 짐작하지 않고, 작업PC가 알려 준 상태만 표시합니다.

#### 사용 방법

프로젝트 설정에서 샌드박스를 켠 프로젝트의 대화를 열면 입력창 위에 나타납니다. 오른쪽 X로 닫으면 그 대화에서는 상태가 바뀔 때까지 숨겨집니다. 이 상태를 알려 주는 Saycode CLI 업데이트가 작업PC에 설치되어야 보입니다.

### Claude·Codex 공급자 장애를 사이드바에서 알려 줘요

Claude(Anthropic)나 Codex(OpenAI)의 공식 상태 페이지에 장애나 응답 지연이 올라오면, 사이드바 아래 계정 영역 위에 작은 안내가 나타납니다. 응답이 계속 실패하거나 느릴 때 SayCode 문제인지 공급자 쪽 문제인지 바로 알 수 있어요. 정상일 때나 상태를 확인하지 못했을 때(회사 네트워크에서 막힌 경우 등)는 아무것도 보이지 않습니다. 앱 창이 보이는 동안만 5분마다 공개 상태 페이지를 확인하며, 계정이나 대화 정보는 보내지 않아요.

#### 사용 방법

안내의 상태 페이지를 누르면 해당 공급자의 공식 상태 페이지가 브라우저로 열립니다. X를 누르면 같은 장애 안내는 다시 보이지 않습니다. 이 안내를 끄려면 설정 > 알림에서 AI 공급자 장애 안내 보이기를 끄세요.

### HTML 미리보기를 확대·축소할 수 있습니다

대화 안에 보이는 HTML 미리보기와 파일 보기에서 연 HTML 파일을 그 화면만 확대하거나 축소할 수 있습니다. 작은 글자를 키워 읽거나, 넓은 화면용 문서를 줄여 한눈에 볼 수 있습니다. 앱 전체 크기는 바뀌지 않습니다.

#### 사용 방법

HTML 미리보기 위에 마우스를 올리면 오른쪽 위에 − 100% + 버튼이 나타납니다. +와 −로 25%~300% 사이에서 키우고 줄이며, 배율 숫자를 누르면 100%로 돌아갑니다. 트랙패드에서 두 손가락을 벌리거나 오므려도, ⌘ 키(Windows는 Ctrl)를 누른 채 스크롤해도 확대·축소됩니다.

### macOS 메뉴 막대에서 실행기 상태와 확인할 대화를 볼 수 있습니다

macOS에서 설정을 켜면 메뉴 막대에 SayCode 아이콘이 생깁니다. 창을 모두 닫아도 아이콘 메뉴에서 이 컴퓨터 실행기의 상태(실행 중·시작 중·멈춤·오류·확인할 수 없음)와 Dock 배지와 같은 수의 확인이 필요한 대화를 볼 수 있습니다. 메뉴에서 SayCode 열기, 완료 알림함 열기, 실행기 다시 시작, SayCode 종료를 할 수 있고, 클라우드로 쓰는 컴퓨터에서는 확인을 거쳐 실행기까지 멈추고 끄는 `완전 종료`도 고를 수 있습니다. 아이콘은 기본으로 꺼져 있습니다.

#### 사용 방법

내 설정 → 일반 → 알림 → 메뉴 막대 카드에서 `메뉴 막대에 아이콘 표시`를 켜세요. 바로 메뉴 막대에 아이콘이 생기고, 끄면 바로 사라집니다. 아이콘을 눌러 메뉴를 엽니다.

### PR 화면에서 검사별 결과를 보고 실패한 GitHub Actions 검사를 다시 실행할 수 있습니다

앱 안 PR 화면 아래 머지 상태의 검사 줄(예: `검사 3개 실패`)을 누르면 검사 목록이 펼쳐집니다. 검사마다 이름, 상태(통과·실패·진행 중·대기 중 등), 걸린 시간, 로그 링크가 한 줄씩 보이고 실패한 검사가 맨 위에 옵니다.

실패한 검사가 GitHub Actions 작업이면 그 줄의 다시 실행을 누르거나, 목록 위의 실패한 검사 모두 다시 실행으로 실패한 작업만 한 번에 다시 돌릴 수 있습니다. 누르면 바로 실행되고, 요청이 받아들여지면 요청됨으로 바뀐 뒤 잠시 뒤 새 진행 상황을 다시 읽습니다. 권한이 없거나, 이미 실행 중이거나, GitHub 요청 한도를 넘으면 그 이유를 버튼 옆에 알려 줍니다. 다른 서비스가 보낸 외부 검사는 로그 링크만 보입니다.

PR이 연결된 대화가 있으면 목록 위에 작업보드와 같은 AI로 CI 수정도 보여, 실패 로그를 그 대화 입력창에 넣을 수 있습니다(자동으로 보내지 않습니다).

#### 사용 방법

프로젝트 대화에서 GitHub PR 링크를 눌러 PR 화면을 연 뒤, 아래 머지 상태의 검사 줄을 눌러 펼치세요. 실패한 Actions 검사 줄의 다시 실행 또는 실패한 검사 모두 다시 실행을 누르세요. 작업PC에 gh가 설치되고 로그인돼 있어야 하며, 다시 실행에는 그 저장소의 쓰기 권한이 필요합니다.

## 변경된 기능

### 개인 사용의 예약 화면에서 바로 로그인

로그인 없이 개인 사용 중에 사이드바 `예약`을 열면, 안내 한 줄 대신 예약으로 할 수 있는 일의 예시(오늘 업무 정리, 이메일 확인)와 `로그인` 버튼이 보입니다. 외부 연동 화면의 설명도 "Cloud 모드" 대신 "로그인하면 Notion, Slack 같은 온라인 계정도 연결할 수 있어요"라고 알려 줍니다.

#### 사용 방법

개인 사용 중 사이드바 `예약`을 열고 `로그인`을 누르면 로그인 창이 열립니다.

### 대기열의 '즉시 요청'을 '지금 반영'으로 이름 통일

AI가 응답하는 동안 대기열에 넣은 요청을 응답을 멈추지 않고 바로 전달하는 버튼의 이름을 입력창·응답 중 새 메시지 설정과 같은 `지금 반영`으로 바꿨습니다. 편집 중이라 쓸 수 없을 때의 안내와 전달이 거절됐을 때의 안내도 같은 이름을 씁니다. 버튼의 위치와 동작은 그대로입니다.

#### 사용 방법

AI가 응답하는 동안 입력창 위 대기열에서 항목 오른쪽의 보내기 아이콘(`지금 반영`)을 누릅니다. 입력창에서 Cmd+Enter(Windows는 Ctrl+Enter)도 기본 설정에서는 지금 반영합니다. 응답 중 새 메시지 설정을 바꾸면 Enter와 Cmd+Enter의 동작도 바뀌어요.

### 보관한 대화를 되돌리는 버튼 이름을 '보관 해제'로 통일했어요

에이전트 보드와 창 상단에서는 `완료 해제`, 설정 › 대화 보관함에서는 `복원`, 개인 대화 메뉴에서는 `복구`로 서로 다르게 보이던 버튼을 모두 `보관 해제`로 바꿨어요. 보드의 `완료` 열은 보관한 대화가 모이는 곳이고 `보관&완료`도 같은 보관이라, 되돌리는 동작도 하나의 이름으로 부릅니다. 확인 창 제목(`대화 보관을 해제할까요?`)과 진행·오류 문구도 같은 말로 맞췄어요. 동작은 바뀌지 않았습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 보관한 대화는 에이전트 보드 `완료` 열 카드, 창 상단, 설정 › 대화 보관함에서 `보관 해제`를 눌러 이어서 작업할 수 있어요.

### 브라우저 주석 트레이 버튼 이름을 실제 동작에 맞춤

앱 브라우저 주석 트레이의 `모두 보내기` 버튼이 `입력창에 담기`로 바뀌고, 종이비행기 아이콘도 대화에 더하기 아이콘으로 바뀌었습니다. 이 버튼은 처음부터 메시지를 바로 보내지 않고 대화 입력창에 주석과 스크린샷을 넣기만 했는데, 이름 때문에 바로 전송되는 것으로 오해하기 쉬웠습니다. 요소 선택 버튼의 안내도 `Shift+클릭: 바로 입력창에 넣기`로 바뀌어 Shift 경로 역시 입력창에 넣는 동작임을 알려 줍니다.

#### 사용 방법

브라우저 패널에서 요소를 골라 트레이에 담은 뒤 `입력창에 담기`를 누르고, 입력창 내용을 확인한 다음 전송을 누르세요.

### 새로 만드는 Slack 앱에 스레드 이전 글 읽기 권한이 포함됩니다

설정의 메신저 연결에서 Slack 앱을 새로 만들면, 봇이 불린 스레드의 이전 글을 읽는 권한(`channels:history`·`groups:history`·`mpim:history`)이 처음부터 함께 요청됩니다. 이 권한은 곧 들어올 스레드 참고 맥락 기능이 씁니다. 그 기능은 Slack 확장이 새 채널 API로 업데이트된 뒤에 동작합니다. 이미 만든 Slack 앱에 이 권한이 없으면, 기능이 켜진 뒤 봇이 Slack에서 필요한 권한 이름을 알려 줍니다.

#### 사용 방법

새 앱은 설정 → 메신저 연결 → Slack 빠른 설정의 앱 만들기 버튼이나 manifest 복사로 만들면 권한이 포함됩니다. 이미 만든 앱은 Slack 앱 설정의 OAuth & Permissions에서 세 권한을 추가한 뒤 워크스페이스에 다시 설치하세요.

### 앱 종료 확인에 실행 중인 대화 목록과 중단 선택지가 생겼어요

Cmd+Q나 메뉴로 종료할 때 응답 중이거나 입력을 기다리는 대화가 있으면, 확인 창에 개수뿐 아니라 그 대화 제목을 최대 5개까지 보여 줘요(입력을 기다리는 대화에는 `입력 대기`가 붙어요). 선택지는 `취소` / `대화 중단하고 종료` / `계속 실행한 채 종료`로 나뉘어요. 내장 서버로 쓰는(standalone) 앱은 종료하면 대화가 함께 멈추므로 `계속 실행한 채 종료` 없이 `취소` / `대화 중단하고 종료`만 보여요. 확인 창이 2초 안에 뜨지 않으면 같은 내용으로 OS 기본 대화상자를 띄워요.

#### 사용 방법

대화를 멈추고 끄려면 `대화 중단하고 종료`를 누르세요. 목록의 대화마다 입력창의 중단과 같은 방법으로 응답을 멈춘 뒤(최대 10초) 앱이 꺼져요. 작업 PC에서 대화를 이어 가려면 `계속 실행한 채 종료`를 누르세요.

### 에이전트가 VS Code 작업 영역 파일을 고치지 못하도록 기본 보호 확대

macOS에서 샌드박스 안에서 실행되는 에이전트는 이제 프로젝트 최상위의 VS Code 작업 영역 파일(`*.code-workspace`)에 쓸 수 없습니다. 이 파일은 사용자가 편집기로 열 때 명령을 실행할 수 있어, 에이전트가 고쳐 두면 다음에 샌드박스 밖에서 실행될 수 있었습니다. 이미 막혀 있던 `.vscode`·`.idea` 폴더도 기본 쓰기 금지 목록에 명시했습니다. 프로젝트에 저장된 쓰기 금지 목록은 그대로 유지되고 이 항목만 더해집니다. 커밋, 브랜치 생성, `git push -u` 같은 Git 작업은 이전과 같이 동작합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 업데이트 후 새로 시작하는 대화부터 적용되며, 에이전트에게 이 파일을 고치게 하려면 프로젝트의 샌드박스를 끄거나 직접 수정하세요.

### 원격 터미널을 열기 전 작업 폴더 준비 요청을 머신 키로 묶어 보냅니다

머신 키가 있는 작업PC에서 원격 터미널을 열 때, 작업 폴더를 미리 만드는 요청을 그 요청에만 쓰이는 값과 함께 머신 키로 묶어 보냅니다. 서버가 이 요청을 다시 보내거나 다른 요청으로 바꿀 수 없고, 엄격 모드 작업PC도 이 요청을 받아들일 수 있습니다. 작업 폴더를 준비하지 못하면 이제 터미널을 다른 위치에서 열지 않고 그 이유를 보여 줍니다. 이 기능이 없는 오래된 작업PC와 머신 키가 없는 작업PC는 지금처럼 터미널을 엽니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 원격 터미널이 터미널마다 따로 만든 키로 입출력을 봉인합니다

새 CLI가 이 방식을 알리는 작업PC에서 원격 터미널을 열면, 앱이 그 터미널에만 쓰는 키를 새로 만들어 머신 키로 묶어 보내고, 작업PC가 그 키로 응답을 증명해야 터미널이 열립니다. 입력·출력·크기 조정·닫기·다시 받기가 모두 이 키로 봉인되고 순번이 붙어, 연결 서버가 내용을 읽거나 바꾸거나 다시 보낼 수 없습니다. 그래서 보안 강화(strict) 작업PC에서도 원격 터미널을 열 수 있습니다. 작업PC의 응답을 확인하지 못하면 터미널을 열지 않습니다. 입력 일부가 가는 중에 사라지면 불완전한 명령이 실행되지 않도록 터미널을 닫고 그 이유를 보여 주며, 연결 서버만 연결이 끊겼다고 알리면 종료 코드 대신 "연결이 끊겼어요"로 보여 줍니다. 이 방식을 알리지 않는 작업PC는 지금처럼 열립니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 작업PC의 CLI가 1.1.10-aplus.375 이상이어야 합니다. 그보다 오래된 CLI로 보안 강화 작업PC나 이 방식을 알렸던 작업PC의 터미널을 열면, 작업PC에서 happy CLI를 최신 버전으로 업데이트하라는 안내가 보입니다.

### 준비 스크립트·검증 설정이 바뀌면 실행 전에 확인

`.aplus/worktree-setup.sh`(작업트리 준비 스크립트)와 `.aplus/verify.json`(검증 설정)은 이 PC에서 에이전트 샌드박스 밖으로 실행됩니다. 이제 처음 보는 내용이거나 마지막으로 허용한 뒤 바뀐 내용이면, 실행하기 전에 파일 경로와 전체 내용 또는 바뀐 줄을 보여 주고 `실행`/`건너뛰기`를 묻습니다. 에이전트가 고친 경우뿐 아니라 직접 고친 경우에도 한 번 확인합니다. 확인 창을 띄울 수 없는 자율 품질 게이트·오토파일럿 검증·머지 후 검증은 허용하지 않은 내용을 실행하지 않고 이유를 알립니다.

#### 사용 방법

새 대화에서 작업트리를 만들거나 작업보드 카드의 변경 검증을 누를 때 확인 창이 뜨면 내용을 보고 실행을 누르세요. 같은 내용은 다시 묻지 않습니다. 자동 실행이 멈췄다는 안내를 받았다면 변경 검증을 한 번 직접 실행해 확인하면 다음부터 자동으로 실행됩니다. 준비 스크립트는 확인한 내용으로 실행되므로 BASH_SOURCE가 비어 있습니다. 스크립트 자신의 경로는 $0으로 찾으세요.

### 프로젝트 만들기 창에서 저장 위치와 폴더 정보를 더 쉽게 확인할 수 있습니다

개인 사용 중 새 프로젝트나 ZIP·파일로 만들 때 이름 칸 아래에 프로젝트 폴더가 생길 저장 위치가 표시됩니다. 기존 폴더 목록은 점(.)으로 시작하는 숨김 폴더를 기본으로 접어 일반 폴더가 먼저 보이고, 보고 있는 폴더가 Git 저장소면 표시가 붙습니다. 직접 입력한 경로를 확인하는 버튼에는 아이콘 대신 이동·새로고침 이름이 보입니다.

#### 사용 방법

프로젝트 만들기 창의 새 프로젝트 탭에서 이름 칸 아래 저장 위치를 확인합니다. 기존 폴더 탭에서는 목록 끝의 숨김 폴더 보기로 숨김 폴더를 펼치고, 경로를 입력한 뒤 이동을 누릅니다.

### 한국어 화면의 옛 용어와 띄어쓰기를 정리했어요

같은 대상을 화면마다 다른 이름으로 부르던 한국어 문구를 맞췄어요. "환경설정"은 "내 설정"(접힌 사이드바 버튼, 단축키 이름, 시작 준비 안내, 설정 검색), "머신"은 "작업PC", "워크트리"와 "worktree"는 "작업트리"로 통일했어요. "Zip/파일"은 "ZIP·파일"로, 외부 연동 화면 제목은 사이드바와 같은 "외부 연동"으로, Git 메뉴의 "가져오기 (pull)"·"보내기 (push)"는 "가져오기"·"보내기"로 바꿨어요. 띄어쓰기가 틀린 문구("만들고싶은", "계정없이", "사용할수")도 고쳤어요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### AI 사용량 창의 5시간 표시 제거

Claude와 Codex의 AI 사용량 창과 입력창 아래 잔여량 요약에서 5시간 표시를 제거했습니다. 계정 목록과 모든 PC의 계정별 사용량은 7일 잔여량과 초기화 시간을 표시합니다.

#### 사용 방법

입력창 아래 AI 사용량 버튼을 누르고 Claude 또는 Codex 탭을 선택합니다.

### AI 자동일 때도 작업 강도 안내 표시

입력창 AI 선택이 "AI 자동"일 때도 메뉴에 "작업 강도" 행이 "자동"으로 보이고, 그 아래에 "모델을 고르면 강도를 정할 수 있어요."라는 안내가 나옵니다. 이전에는 모델을 직접 고르기 전까지 작업 강도 항목이 메뉴에 아예 없어서 강도를 바꾸는 방법을 알기 어려웠습니다.

#### 사용 방법

입력창의 AI 선택 메뉴를 열면 맨 아래에서 확인할 수 있습니다. 강도를 직접 정하려면 AI와 모델을 고른 뒤 같은 메뉴의 "작업 강도"에서 선택합니다.

### AI가 브라우저 조작에 계속 실패하면 같은 시도를 되풀이하지 않고 멈춰서 알립니다

AI가 브라우저나 이 컴퓨터의 앱을 조작하다 실패하면 같은 동작을 그대로 되풀이하지 않고 다른 방법을 시도하도록 안내합니다. 같은 단계에서 4번 실패하면 멈추고, 무엇을 시도했고 무엇이 막았는지 알려 줍니다. 막힌 채 같은 시도를 반복하며 시간과 사용량을 쓰는 일을 줄입니다. 이 규칙은 AI에게 주는 지시이며 실제 차단 장치는 아닙니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 설정 → 시스템 프롬프트 → 기본 지시 세부 설정의 `브라우저·컴퓨터 사용 확인` 항목을 끄면 이 안내도 함께 빠집니다.

### Chrome 확장 연결을 확장 화면의 연결 버튼 하나로

Chrome 브라우저 연결이 훨씬 간단해졌습니다. 이전에는 Saycode에서 Chrome 프로필을 조회해 고르고, 웹 스토어에서 설치한 뒤 프로필 연결과 연결 확인을 차례로 눌러야 했습니다. 이제는 Chrome 웹 스토어에서 Saycode Browser Extension을 추가하고 확장 화면에서 연결을 한 번 누르면 끝납니다. 브라우저 연결은 컴퓨터 제어 설정과 분리되어, 컴퓨터 제어 확장을 설치하지 않아도 쓸 수 있습니다.

#### 사용 방법

컴퓨터·브라우저 제어 화면의 Chrome 브라우저 연결에서 Chrome 웹 스토어 열기를 누르고 확장을 추가하세요. 확장 화면에 계정이 표시되면 연결을 누르세요. Saycode 화면이 자동으로 연결됨으로 바뀝니다. 끊으려면 연결 해제를 누르세요.

### CSV 표에서 첫 행을 열 머리로 보기

CSV·TSV 파일을 `표로 보기`로 열면 첫 줄이 열 머리(A, B, C 대신 장비명·분류 같은 이름)로 보이고, 행 번호는 그다음 줄부터 1행으로 셉니다. 첫 줄도 데이터인 파일은 표 위의 `첫 행을 열 머리로 사용`을 끄면 이전처럼 열 문자와 함께 모든 줄이 행으로 보입니다. 고른 값은 같은 파일을 새로 불러와도 유지되고, 다른 파일은 다시 켠 상태로 열립니다.

#### 사용 방법

CSV·TSV 파일을 열고 머리줄의 `표로 보기`를 누르세요. 첫 줄을 데이터로 보려면 표 위의 `첫 행을 열 머리로 사용`을 끄세요.

### Windows에서 컴퓨터 제어 자동 시작에 관리자 승인이 필요 없어집니다

Windows에서 컴퓨터·브라우저 제어를 설정할 때 `OS 권한 확인`을 눌러도 더 이상 관리자 승인 창이 뜨지 않습니다. Cua Driver는 로그인할 때 일반 사용자 권한으로 자동 시작됩니다. 예전 버전에서 관리자 권한으로 자동 시작을 등록해 둔 경우에는, 그 등록을 지우기 위해 관리자 승인 창이 한 번 열립니다. 승인하지 않으면 기존 방식으로 계속 동작하고, 다음 확인 때 다시 정리를 안내합니다. 관리자 권한으로 실행된 창은 컴퓨터 제어로 조작하지 않습니다.

#### 사용 방법

온보딩 또는 내 설정의 컴퓨터·브라우저 제어 단계에서 `OS 권한 확인`을 누르세요. 예전 등록을 지우는 승인 창이 열리면 `예`를 눌러 주세요.

### 다른 프로젝트가 쓰는 포트는 미리보기를 자동으로 열지 않음

로그인 없이 개인으로 사용할 때 에이전트가 "개발 서버를 켜 두었다"고 답하면 미리보기 탭이 자동으로 열립니다. 그런데 같은 컴퓨터의 다른 프로젝트가 이미 그 포트를 쓰고 있으면 다른 프로젝트의 화면이 아무 구분 없이 열렸습니다. 이제는 그 포트를 다른 프로젝트 폴더에서 실행 중인 서버가 쓰고 있으면 자동으로 열지 않습니다. Docker로 띄운 서버처럼 어느 프로젝트 것인지 알 수 없는 포트는 지금처럼 자동으로 엽니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 미리보기는 지금처럼 직접 열 수 있습니다.

### 다크 모드에서 선택한 글자가 잘 보입니다

### 대화 제어 요청을 작업PC의 지원 여부에 맞춰 묶어 보냅니다

### 메신저 대화의 세션 선택이 저장 실패 뒤에도 어긋나지 않음

메신저 채널(Slack·Telegram·Discord)에서 대화마다 어느 세션을 이어갈지와 누가 그 대화를 시작했는지를 저장할 때, 같은 연결의 변경을 한 번에 하나씩 끝까지 처리합니다. 그래서 다른 대화의 명령이 동시에 저장되더라도, 저장에 실패해 되돌린 선택이 디스크에 남아 재시작 뒤 엉뚱한 세션으로 이어지는 일이 없습니다. `/new` 로 만든 세션이나 첫 메시지로 연 개인 대화를 이 대화에 연결하지 못했을 때는 선택을 비우지 않고 이전에 따라가던 세션을 그대로 따라갑니다. 저장이 오래 멈추면 무한히 기다리지 않고 "잠시 후 다시 보내 주세요"라고 알려 줍니다. `/use`·`/clear`가 차례를 기다리는 동안 연결 권한이 바뀌어 그 세션이나 명령이 더는 허용되지 않으면, 선택을 바꾸지 않고 거절합니다.

#### 사용 방법

### 메신저 메시지를 보내지 못한 이유를 구분해 알려 줍니다

### Claude 모델을 직접 골라도 입력창 아래 사용량이 사라지지 않습니다

조직 계정 정보가 남아 있는 PC에서 개인으로 사용하거나 조직 전용이 아닌 PC를 쓸 때, 새 대화에서 AI를 Claude로 직접 고르면 입력창 아래 사용량이 `—/—`로 바뀌었습니다. 이 경우 새 대화는 PC에 로그인된 Claude 계정으로 실행되므로, 이제 그 계정의 남은 사용량을 그대로 보여 줍니다. 조직 전용 PC에서 다음 대화에 쓸 조직 계정을 아직 고르지 않은 경우에는 지금처럼 "자동" 안내와 함께 `—/—`가 보입니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### PR 머지와 자동 머지의 중복 실행 방지

PR 머지와 자동 머지를 빠르게 다시 눌러도 같은 PR에 중복 요청을 보내지 않습니다. 처리 중에는 완료까지, 같은 실행은 최소 0.5초 보호합니다. 취소하거나 대상을 바꾼 확인은 새 실행을 막지 않으며 이전 응답이 새 대상의 표시를 덮지 않습니다. 응답을 잃은 뒤 재시도하면 현재 PR 상태를 확인해 이미 적용된 작업을 반복하지 않습니다.

#### 사용 방법

프로젝트 대화의 Git 메뉴에서 머지 또는 자동 머지를 누르세요. 스택 PR이나 봇 확인 안내에서는 취소하거나 그래도 머지를 선택할 수 있습니다. 자동 머지는 서버에 연동된 저장소에서 사용할 수 있습니다. 별도 설정 없이 적용됩니다.

### PR 재시도에서 초안과 실행 상태 보존

Push & PR과 AI 생성의 빠른 중복 실행을 막고, 실패 후 직접 편집한 제목과 설명을 유지합니다. PR 생성 결과가 불확실하면 기존 PR을 먼저 확인하며 브랜치를 다시 보내지 않습니다. 로그인이나 작업 대상이 바뀐 뒤 도착한 이전 결과가 새 화면을 덮지 않습니다.

#### 사용 방법

프로젝트 작업트리 대화의 작업환경 메뉴에서 Push & PR을 누르고 제목과 설명을 확인한 뒤 Pull Request 만들기를 누르세요. 실패하면 남아 있는 초안에서 다시 시도하거나 취소할 수 있습니다.

### 컴퓨터 제어 드라이버가 Cua Driver 0.38로 바뀌어 다시 설치가 필요합니다

컴퓨터·브라우저 제어에 쓰는 Cua Driver가 0.32에서 0.38로 바뀝니다. 클릭 같은 조작의 응답이 빨라집니다. 새 드라이버는 자동으로 설치되지 않으므로, 컴퓨터 제어를 쓰던 경우 업데이트 후 드라이버를 한 번 다시 설치해야 합니다. 설치 전에는 AI 대화의 컴퓨터 제어가 "Cua Driver가 아직 설치되지 않았어요"로 멈춥니다.

#### 사용 방법

업데이트 후 온보딩 또는 내 설정의 컴퓨터·브라우저 제어 단계에서 `Cua Driver 0.38.0 설치`를 누른 뒤 `OS 권한 확인`을 누르세요.
