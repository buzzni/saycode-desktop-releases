## 새 기능

### 메신저 연결별 AI 설정

Telegram·Slack·Discord 연결마다 새 세션에 사용할 AI 제공자, 모델, 응답 수준을 따로 저장할 수 있습니다. 저장하지 않은 연결은 routine 기본값을 사용하고, 이미 실행 중인 세션에는 영향을 주지 않습니다.

#### 사용 방법

내 설정의 메신저 채널 연결 카드에서 AI 제공자·모델·응답 수준을 선택하고 저장합니다. 권한이 있는 메신저 대화에서는 `/settings --agent … --model … --effort …`으로 연결 기본값을 바꿀 수 있으며, 이후 `/new`와 개인 대화가 그 값을 사용합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1551)

### 확장이 연결 머신에서 Moai 명령을 안전하게 실행할 수 있는 런타임 반영

내장 Happy CLI를 `1.1.10-aplus.304`로 갱신하고 Windows x64 registry lock을 함께 고정합니다. 이 런타임은 확장이 셸 없이 미리 정해진 명령만 실행하는 `machine.run`, Moai v0.8.0 명령 목록, 공식 릴리스를 머신이 직접 내려받아 해시를 확인하는 도구 설치를 포함합니다. 엄격한 미리보기 실행의 시간 상한 조정도 함께 들어 있습니다.

#### 사용 방법

이 변경만으로 화면이 바뀌지는 않습니다. 확장 관리 화면의 Moai 설치·승인 기능은 별도 Desktop 변경으로 제공됩니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1575)

### 회사 PC에서 로그인 정보 저장 방식을 직접 선택해 시작 준비를 계속할 수 있음

회사 보안 설정 때문에 Windows에서 로그인·PC 연결 정보를 보호된 폴더에 저장할 수 없으면, 이전에는 시작 준비가 PC 연결 단계에서 멈췄습니다. 이제 원인과 차이를 설명하는 확인 창이 열리고, 사용자가 "이 PC에서 계속"을 고르면 일반 앱과 같은 수준(Windows 사용자 폴더의 기본 권한)으로 저장한 뒤 멈춰 있던 준비를 자동으로 다시 진행합니다. 로그인 정보는 계속 암호화되며, PC 연결 정보는 이 PC의 관리자가 읽을 수 있게 됩니다. 취소하면 이전처럼 저장하지 않습니다.

#### 사용 방법

확인 창에서 "이 PC에서 계속"을 누르세요. IT 담당자에게 원인을 알려야 하면 "IT 담당자에게 보낼 정보 복사"를 누릅니다. 나중에 되돌리려면 설정 > 일반의 "로그인 정보 저장"에서 "보호된 저장으로 되돌리기"를 누르면 다음 실행부터 보호된 저장을 다시 시도합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1572)

### 프로젝트에서 함께 작업을 관리하세요

프로젝트 설정에서 참여자와 초대 상태를 바로 확인하고, 개인 프로젝트에서도 함께 작업을 관리할 수 있습니다. 초대 수락 실패는 다시 시도하거나 나중에 처리할 수 있으며, 계정 전환과 인증 갱신 뒤에도 이전 요청이 현재 화면에 영향을 주지 않습니다. 팀별 참여를 관리하고 공유 PC의 연결 상태를 확인할 수 있습니다. 프로젝트에서 나가면 내 작업 목록과 열린 화면을 정리하며 작업 파일은 보존합니다.

#### 사용 방법

프로젝트 설정의 ‘함께 작업’을 열거나 프로젝트 상단 메뉴에서 관리 화면에 들어가세요. 초대받은 사용자는 안내에서 ‘확인’을 눌러 참여합니다. 팀 참여는 팀 선택 후 적용하며, 프로젝트에서 나갈 때는 확인 안내를 읽고 진행하세요. 탈퇴 뒤 접근 권한 정리를 보장하려면 서버의 탈퇴 권한 회수 개선도 먼저 반영되어야 합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1555)

### 예약 질문과 답변을 대화에서 함께 확인하세요

회사 시작준비에서 개인 AI 계정의 브라우저 로그인을 기다리지 않고 회사 공용 AI 인증을 적용하고 확인해요. 그룹 배정이 없는 본인 PC와 같은 PC의 재설치에서도 공용 인증을 다시 확인하며 기존 머신과 계정 선택을 유지해요. 공용 인증이 없거나 적용·확인에 실패하면 원인과 다시 연결 방법을 안내해요.

#### 사용 방법

회사 로그인 후 시작준비에서 자동으로 확인해요. 실패하면 상세 정보를 확인하고 `다시 연결`을 누르거나 조직 관리자에게 최신 공용 인증을 확인해 달라고 요청하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1558)

### AI 도구 설치 실패 정보 유지

도구 상태를 다시 확인해도 직전 설치 실패의 단계·오류·발생 시각을 유지합니다. 설치를 복구하면 이전 오류를 지우고, 새 설치 시도가 실패하면 새 오류로 갱신합니다.

#### 사용 방법

시작준비에서 실패한 도구의 정보 아이콘을 누르세요. 확인된 오류와 조치를 보고 진단 정보를 복사할 수 있습니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1562)

### Windows Native Messaging launcher를 포함한 Happy CLI 갱신

내장 Happy CLI를 `1.1.10-aplus.301`로 갱신하고 Windows x64 registry lock을 함께 고정합니다. 이 버전은 Chrome Native Messaging manifest가 Node로 실행해야 하는 `.mjs`를 직접 가리키지 않고 executable launcher를 사용하도록 해 Windows Chrome 연결의 실행 경계를 보강합니다.

#### 사용 방법

이 변경을 포함한 새 Windows 설치판을 사용해야 launcher가 포함된 Native Messaging host를 적용할 수 있습니다. 설치판에서 native host registry, Cua Driver lifecycle, Chrome 프로필 연결 및 실제 대화 제어는 별도 수락 절차로 확인합니다.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1552)

### Windows에서 로그인 정보 보호 실패 원인을 진단 기록에 남김

회사 PC처럼 보안 설정이 강한 Windows에서 로그인 정보나 PC 연결 정보를 보호된 폴더에 저장하지 못하면, 시작 준비 화면이 "구체적인 원인을 확인하지 못했어요" 대신 접근 권한 문제로 안내합니다. 거부된 이유(폴더 권한, 보안 프로그램에 의한 실행 차단 등)는 앱의 설치 진단 기록에 남아 문의 시 원인을 확인할 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 문제가 계속되면 데이터 폴더의 `standalone\logs\setup.log`를 관리자나 개발자에게 전달해 주세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1572)

### Windows에서 컴퓨터·브라우저 제어 설정 버튼이 모두 실패하던 문제 수정

Windows에서 컴퓨터·브라우저 제어 설정의 버튼(설치 확인, Cua Driver 설치, OS 권한 확인, Chrome 프로필 조회)이 작업을 끝내기 전에 시간 제한에 걸려 "설정을 완료하지 못했어요"만 표시되던 문제를 고쳤습니다. 이 컴퓨터를 확인하는 단계도 더 빨라졌습니다. 함께 들어가는 컴퓨터 제어 확장 0.2.1은 Cua Driver가 꺼져 있을 때 자동 시작을 등록하고 실행합니다.

#### 사용 방법

Windows에서 "OS 권한 확인"을 누르면 Cua Driver 자동 시작을 등록하기 위해 관리자 승인 창이 한 번 열립니다. "예"를 눌러 승인하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1573)

### Windows에서 Chrome 브라우저 제어 연결이 실행되지 않던 문제 수정

내장 Happy CLI를 `1.1.10-aplus.303`으로 갱신하고 Windows x64 registry lock을 함께 고정합니다. Windows에서 Chrome 확장을 연결할 때 ".mjs 파일을 열 앱을 선택하세요" 창이 뜨거나 응답 없이 끝나던 문제를 고칩니다. 이제 연결 설정이 Chrome이 실행할 수 있는 배치 파일을 가리킵니다.

#### 사용 방법

이 변경을 포함한 새 Windows 설치판을 설치한 뒤 컴퓨터·브라우저 제어 설정을 다시 진행하세요.

관련 변경: [PR 링크](https://github.com/buzzni/aplus-dev-studio-desktop/pull/1570)
