## 새 기능

### 요금제 플랜의 DeepSeek Eco 연결

관리자가 OpenGateway 플랜을 지정하면 saycode 플랜으로 DeepSeek Eco를 사용할 수 있습니다. 기존 OpenAI 플랜 대화는 시작한 모델을 유지합니다. 지원하지 않는 작업PC에는 업데이트가 필요하다고 안내합니다. Eco 대화에는 플랜 사용량을 표시하고 개인 Claude의 터미널 이어가기는 기존처럼 사용할 수 있습니다.

함께 제공하는 Happy CLI 런타임을 1.1.10-aplus.416으로 갱신해 Eco 플랜 실행을 지원합니다.

#### 사용 방법

최신 작업PC에서 새 대화의 사용 연결을 saycode 플랜으로 고릅니다. 관리자가 지정한 공급자와 모델이 적용됩니다. 플랜 대화는 앱 안에서 계속 사용합니다.

### 조직이 둔 공용 PC에서도 내부 AI로 새 Claude 대화를 시작할 수 있습니다

내 전용 PC뿐 아니라 조직이 직접 운영하는 공용 PC(내가 쓸 수 있는 PC)에서도 배정된 내부 AI로 새 Claude 대화를 시작할 수 있습니다. 공용 PC에서는 인증 없이 쓰는 내부 AI만 고를 수 있고, 토큰이 필요한 내부 AI는 "토큰 방식이라 공용 PC에서는 쓸 수 없어요"라는 이유와 함께 비활성으로 보입니다.

마지막으로 고른 사용 연결은 앱을 다시 켜도 다음 새 대화의 기본으로 선택됩니다. 내부 AI 대화에서는 공용 PC의 계정 자동 전환 안내가 더 이상 뜨지 않고, 메시지를 보낼 때 조직 Claude 계정 사용량 확인을 거치지 않아 공용 PC에서도 막히지 않습니다. 이 PC에서 쓸 수 있는 내부 AI가 있을 때만 Claude 로그인 없이 Claude를 고를 수 있습니다.

#### 사용 방법

조직이 운영하는 공용 PC로 새 대화를 열고 AI를 Claude로 고른 뒤, 모델 메뉴 맨 아래 사용 연결에서 인증 없이 쓰는 내부 AI를 고르고 메시지를 보냅니다. Saycode가 호스팅하는 공용 PC는 사내망에 닿지 않아 목록에 나오지 않습니다.

### 프로젝트를 테스트·실서비스로 배포할 수 있어요

미리보기로 확인한 프로젝트를 데스크톱에서 테스트하거나 실서비스로 배포할 수 있어요. 실서비스는 테스트와 서버 검증을 먼저 통과하며, 기존 데이터 교체 전에 확인할 수 있어요. 진행 중 창을 닫아도 배포를 이어가고 결과가 늦으면 상태를 다시 확인할 수 있어요.

#### 사용 방법

소유한 클라우드 프로젝트 대화의 배포를 누르고 테스트 배포 또는 실서비스 배포를 고르세요. 주소와 데이터 복사 여부를 확인한 뒤 배포를 시작하세요. 실서비스 배포는 조직의 허용과 서버 설정이 필요해요.

### Google로 데스크탑 로그인·가입

서버가 지원하는 환경에서 Google 계정으로 데스크탑에 로그인하거나 가입할 수 있습니다. 시스템 브라우저에서 인증과 기기 연결 승인을 마치면 별도의 비밀번호 생성 없이 앱으로 돌아옵니다. 암호화 키를 안전하게 저장할 수 없는 PC에서는 이번 실행 동안만 키를 보관합니다.

조직 초대와 다른 Google 계정을 선택하면 초대받은 이메일의 계정으로 로그인하도록 안내합니다.

#### 사용 방법

로그인 또는 계정 만들기에서 Google로 계속하기를 누릅니다. 앱의 확인 코드를 열린 브라우저에 직접 입력하고 승인한 뒤 앱으로 돌아오세요. 버튼은 서버에서 해당 운영체제의 지원을 켠 경우에만 표시됩니다.

## 변경된 기능

### 기획안 답변 아래 `작업 시작하기`가 바로 시작됩니다

기획모드 대화에서 기획안 답변 바로 아래의 `작업 시작하기`를 누르면 확인 창 없이 바로 구현을 시작합니다. 시작하지 못하면 확인 창에 이유와 다시 시작 버튼이 나타납니다. 기획안 탭의 `작업 시작하기`는 지금처럼 확인 창을 거칩니다.

#### 사용 방법

기획모드 대화에서 기획안을 반영한 가장 최근 답변 아래의 `작업 시작하기`를 누릅니다. 시작한 작업은 입력창의 정지 버튼으로 멈출 수 있습니다.

### 기획에서 작업을 시작하면 미리보기가 바로 열립니다

기획으로 시작한 프로젝트에서 `작업 시작하기`를 누르면, AI가 구현을 마치며 알려 준 서버 구성으로 바로 미리보기 서버를 실행합니다. 미리보기를 띄우려고 AI에게 프로젝트 분석을 한 번 더 맡기지 않아도 되고, 첫 실행 때 오른쪽 작업 패널의 미리보기가 저절로 열립니다. 실행에 실패하면 같은 자리에서 오류와 `1회 AI 복구 승인`을 볼 수 있습니다.

#### 사용 방법

기획모드 대화에서 `작업 시작하기`를 누르고 구현이 끝날 때까지 기다리면 됩니다. 미리보기를 닫은 뒤에는 오른쪽 패널의 `+` 메뉴에서 `미리보기`로 다시 엽니다.

### 기획으로 시작한 프로젝트는 대화 머리글에서 바로 미리보기를 엽니다

기획으로 시작한 프로젝트의 대화 머리글에 `미리보기` 버튼이 생겼습니다. 더보기(⋮) 바로 왼쪽에 있으며, 누르면 오른쪽 작업 패널에 미리보기를 엽니다. 미리보기가 화면에 보이는 동안에는 버튼이 숨겨지고, 패널을 닫거나 다른 탭으로 옮기면 다시 나타납니다.

#### 사용 방법

기획으로 시작한 프로젝트의 대화에서 머리글 오른쪽의 `미리보기`를 누릅니다.

### 내부 AI를 연결 탭 옆에서 바로 선택

내부 AI를 saycode 플랜·AI 계정과 같은 메뉴에서 바로 선택할 수 있습니다. 입력창에는 기존 AI 모델명과 작업 강도 대신 선택한 내부 AI 연결명이 표시되고, 메뉴의 간결한 목록에서 실제 모델과 혼잡도를 확인하고 오른쪽 체크 표시로 선택한 서버를 구분할 수 있습니다. 사용 가능한 AI가 없어도 연결 메뉴와 준비 안내를 함께 제공합니다. 세 연결 탭을 항상 표시하고 사용할 수 없는 항목은 비활성 상태와 사유 툴팁으로 안내합니다. 관련 없는 계정·모델 옵션, 기존 Claude 계정 사용량·복구 표시와 중복 선택창을 정리했습니다.

#### 사용 방법

내 전용 작업PC의 새 대화 입력창에서 모델 메뉴를 열고 내부 AI 탭을 누르세요. 배정된 연결이 바로 적용되며 여러 개면 목록에서 바꿀 수 있습니다. AI 계정이나 saycode 플랜 탭으로 돌아가면 내부 AI 선택이 해제됩니다. 내부 AI 탭으로 돌아오면 마지막 연결이 복원됩니다. 배정이 회수되면 연결과 안내를 유지하므로 다른 연결을 직접 고르세요. 시작한 대화의 연결은 바꿀 수 없습니다. 배정을 불러오지 못하면 메뉴에서 다시 확인을 누르세요. 내부 AI 대화의 컨텍스트 사용량과 압축 기능은 그대로 사용할 수 있습니다.

### 대화에 "미리보기 열어줘"라고 하면 미리보기 영역이 바로 열립니다

프로젝트 대화에서 `미리보기 열어줘`, `미리보기 띄워줘`처럼 짧게 요청하면, 보내는 즉시 오른쪽 작업 패널에 미리보기 탭이 열립니다. AI의 답변에 서버 설정이 있으면 답변이 끝난 뒤 그 설정으로 서버를 실행합니다. `미리보기가 안 열려`처럼 문제를 말하는 문장은 AI에게 맡깁니다.

#### 사용 방법

미리보기를 쓸 수 있는 프로젝트의 대화 입력창에 `미리보기 열어줘`라고 입력해 보냅니다.

### 미리보기 머리줄을 웹과 같은 구성으로 정리했습니다

프로젝트 미리보기 머리줄을 웹 미리보기와 같은 구성으로 정리했습니다. 왼쪽에 `재시작` 버튼과 `실행 중 · 5173`, `시작 중`, `응답 대기`, `확인 필요`처럼 지금 상태를 글로 보여 주고, 오른쪽에는 브라우저에서 열기·화면 크기와 배율(`100%`)·더보기(⋮)만 둡니다. 태블릿(768px)·모바일(375px) 폭과 배율 100%·75%·50%를 고를 수 있고, 고른 값은 이 컴퓨터에 기억됩니다. 화면 새로고침, AI로 문제 진단, 로컬 포트 연결은 더보기(⋮)에 있습니다.

#### 사용 방법

오른쪽 작업 패널의 `미리보기` 탭 머리줄에서 `재시작`, 화면 크기·배율 버튼(`100%`), `미리보기 더보기`(⋮)를 누릅니다.

### 배포 화면을 간결하게 정리했어요

처음 배포할 때 방식과 주소를 고르고 바로 시작할 수 있어요. 이전 테스트 배포 목록과 기술 설정은 필요할 때 펼쳐 보며, 완료 주소를 먼저 표시해요. 같은 프로젝트에서 창을 다시 열면 마지막으로 사용한 배포 방식을 유지하고 서비스 열기도 같은 대상을 열어요.

#### 사용 방법

프로젝트 헤더의 배포를 누르세요. 소스·범위·저장소는 고급 설정에서, 주소 열기·복사·재배포·삭제·새 배포는 테스트 배포 관리에서 확인하세요. 실행 결과의 빌드 로그는 펼쳐 볼 수 있어요.

### 보호 세션에서 외부 도구의 실행 범위를 확인하고 승인

지원하는 런타임에서 Chrome·외부 MCP·설치된 CLI를 사용할 때 프로젝트 밖 파일과 네트워크 접근 가능성, 대상과 인자를 확인하고 승인할 수 있습니다. 같은 범위 허용은 같은 대상·인자에만 적용되며 대화의 허용 목록에서 철회할 수 있습니다. 조직 정책 거부와 연결·버전 제한은 유지됩니다. 이번 변경을 포함한 Desktop과 Happy CLI 1.1.10-aplus.415 이상이 함께 필요합니다.

#### 사용 방법

대화의 도구 정책 확인 카드에서 범위를 읽고 이번만 허용 또는 이 대화에서 같은 범위 허용을 누릅니다. 철회하려면 내 설정 → 보안 → 이 대화에서 허용한 앱·도구에서 거두기를 누릅니다. 이미 실행된 작업은 철회로 되돌아가지 않습니다.

### 접은 사이드바 아이콘의 크기와 색을 맞췄어요

사이드바를 접었을 때 왼쪽 막대의 아이콘이 크기와 색이 제각각이었습니다. 사이드바 펼치기 버튼만 작고 흐렸고, 실행 중인 대화 수는 큰 테두리 원으로, 알림 종은 옅은 회색으로 보였습니다. 이제 막대의 모든 아이콘이 같은 크기·같은 색으로 한 줄에 맞춰 보이고, 실행 중인 대화 수도 다른 아이콘과 같은 크기의 원 안 숫자로 보입니다. 막대 가운데에 있던 Saycode 로고는 뺐습니다. 펼친 사이드바의 로고는 그대로 시작 화면으로 돌아갑니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 사이드바를 접으면(Cmd+B) 바뀐 막대를 볼 수 있습니다.

### 폴더 권한 승인 후 작업 이어가기 준비

지원하는 실행 환경에서 폴더 권한 적용 후 AI가 이전 작업을 이어가도록 연결합니다. 새 사용자 메시지를 우선하고 승인 실패나 철회 시 성공 재개를 보내지 않습니다. 실행 환경 업데이트 전에는 기존 동작을 유지합니다.

#### 사용 방법

대화의 폴더 권한을 검토해 허용하세요. 지원 실행 환경에서 적용이 확인되면 작업을 이어갑니다. 자동으로 이어지지 않으면 적용 상태를 확인하고 입력창에서 이어서 진행해 달라고 요청하세요.

### OpenCode 무료 모델 시작 메뉴를 개발자 설정에서 표시

새 대화 AI도구 메뉴의 `OpenCode · 무료 모델로 시작`을 ChatGPT 바로 아래로 옮겼습니다. 개발자 기능 설정에서 켠 경우에만 표시하며 기본은 꺼짐입니다.

#### 사용 방법

내 설정 → 개발자 기능 설정 → `OpenCode 무료 모델 시작 보이기`를 켠 뒤 새 대화의 AI도구 메뉴를 엽니다.

## 수정된 문제

### 가입 인증 메일 발송 실패를 정확하게 안내해요

서버가 인증 메일을 보내지 못한 경우, 연결 오류 대신 메일 발송 결과를 확인하지 못했음을 안내합니다. 이메일 입력 화면에서 다시 시도할 수 있습니다. 서버의 발송 결과 확인 수정과 함께 적용됩니다.

#### 사용 방법

계정 만들기에서 인증 코드 받기를 누르세요. 발송 실패 안내가 나오면 잠시 후 다시 시도해 주세요.

### 내부 AI 시작 화면에 실제 연결 표시

내부 AI 대화가 시작 중이거나 시작에 실패했을 때도 입력창 모델명 자리에 내부 AI와 연결명을 표시합니다. 이전 모델·작업 강도와 내부 AI 배지가 함께 보이던 혼동을 없앴습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 다시 시도는 원래 선택한 내부 AI 연결을 사용합니다.

### 내부 AI를 지원하지 않는 PC에서는 사용 연결 선택지가 보이지 않습니다

PC의 Saycode CLI가 내부 AI를 지원하기 전 버전(1.1.10-aplus.406 미만)인 것이 확실하면, 새 대화의 사용 연결에서 내부 AI를 보이지 않습니다. 지금까지는 이런 PC에서도 내부 AI를 고를 수 있었지만 보내면 "PC의 Saycode를 업데이트하라"는 안내로만 끝났습니다. CLI 버전을 알 수 없는 PC는 지금처럼 보이고, 시작할 때 PC가 직접 지원 여부를 답합니다.

#### 사용 방법

내부 AI가 보이지 않는 PC라면 그 PC의 Saycode를 업데이트하면 다시 보입니다.

### 다른 창에서 끝난 CLI 업데이트의 재설치 방지

오래 열어 둔 다른 창에서 CLI 업데이트를 눌렀을 때 현재 버전을 다시 확인합니다. 이미 요청한 버전 이상으로 업데이트된 PC에는 같은 설치를 다시 요청하지 않습니다.

#### 사용 방법

기존 Aplus CLI 업데이트 화면에서 업데이트를 누르면 자동 적용됩니다. 별도 설정은 필요하지 않습니다.

### 모델을 고른 뒤 바로 이어서 입력

대화 입력창에서 모델·작업 강도·AI 자동을 확정한 뒤 입력창을 다시 누르지 않아도 질문을 이어 쓸 수 있습니다. 작성하던 글과 커서 선택 범위가 유지됩니다. Escape로 취소하면 기존처럼 메뉴 버튼으로 돌아갑니다.

#### 사용 방법

입력창의 AI·모델 메뉴에서 모델이나 작업 강도를 고른 뒤 바로 입력하세요. 별도 설정 없이 적용됩니다.

### 무료 모델 설치 후 찾지 못하는 문제 복구

opencode 설치가 끝났는데 작업PC 연결 프로그램이 실행 파일을 찾지 못할 때, 연결 프로그램을 한 번 자동으로 다시 시작하고 무료 모델을 재확인합니다. 현재 계정의 이 컴퓨터에만 적용하며, 재시작에 실패하면 다시 시도할 수 있습니다. 확인 중 PC 신뢰·배정 정보가 바뀌어도 이전 요청 때문에 재시도가 잠기지 않고, 새 확인 결과에 맞는 안내를 표시합니다.

#### 사용 방법

클라우드 계정의 무료 모델 설치 화면에서 `설치하고 시작하기`를 한 번 누르세요. 이미 설치돼 있으면 `확인하고 시작하기`를 누르세요. 자동 복구가 실패한 경우에만 `연결 프로그램 다시 시작하고 확인`으로 재시도하세요. 진행 중인 응답이 있으면 기다릴 수 있습니다.

### 배포 방식 선택과 완료 후 사이트 열기를 바로잡았어요

처음 배포 창을 열 때 전체 테스트 이력의 최신 시각을 확인한 뒤 기본 방식을 골라요. 창을 닫은 동안 실서비스 배포가 완료돼도 헤더에서 사이트를 열 수 있고, 관리 목록에서 선택한 테스트 주소도 올바르게 열어요. 백그라운드 완료 후 테스트 이력을 갱신해 다음 배포에서 기존 테스트를 재사용해요.

#### 사용 방법

프로젝트의 배포에서 선택된 방식을 확인하고 시작하세요. 완료 후 배포된 서비스 열기를 누르면 마지막으로 확인한 주소가 열려요. 관리 목록에서 다른 테스트를 고른 경우에도 그 주소를 사용하며, 삭제한 주소는 저장된 열기 대상에서 제외해요.

### 배포 지연 후 상태 재확인과 데이터 보호를 개선했어요

응답을 받지 못한 배포를 기존 서비스의 성공으로 표시하지 않아요. 테스트 배포가 늦어져도 새 빌드를 만들지 않고 같은 작업을 확인하며, 실서비스 배포를 재개할 때 데이터 교체를 다시 확인해요. 경고가 있는 테스트 완료와 실서비스 완료 알림도 올바르게 유지해요.

#### 사용 방법

배포 창에서 결과가 지연되면 상태 다시 확인을 누르세요. 접수 여부가 불명확할 때 별도로 보이는 현재 서비스는 이번 요청의 완료를 뜻하지 않아요. 데이터 교체 확인은 내용을 읽고 확인하거나 취소하세요.

### 설치된 OpenCode 메뉴 중복 표시 수정

OpenCode가 설치된 뒤에는 AI도구 메뉴에 일반 OpenCode 모델 선택 행만 표시합니다. 중복되던 무료 모델 시작 준비 항목을 숨겼습니다.

#### 사용 방법

별도 조작 없이 설치 상태가 확인되면 적용됩니다. 미설치 상태의 무료 모델 시작 항목은 개발자 기능 설정에서 켠 경우에만 표시됩니다.

### 설치된 OpenCode의 무료 시작 안내 숨김

이 컴퓨터에 OpenCode가 설치되어 있어도 AI도구 메뉴에 무료 모델 시작 안내가 함께 남는 문제를 수정했습니다. 설치가 확인되고 OpenCode 모델 선택이 가능하면 중복 안내를 숨깁니다. 연결 프로그램이 아직 OpenCode를 찾지 못해 모델을 선택할 수 없으면 기존 재확인·복구 안내를 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 스크립트 실행의 빠른 재클릭 방지

스크립트 실행 요청 중 설정을 닫았다 다시 열어도 같은 항목의 중복 요청을 막습니다. 빠르게 완료된 뒤에도 같은 입력은 최초 요청부터 0.5초 동안 다시 접수하지 않습니다. 실제 처리 중인 상태와 취소·다른 입력의 정상 사용은 유지합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 프로젝트 설정 → 개발 → 실행 → 스크립트 자동화 → 이력·API key → 실행 요청에서 확인할 수 있습니다.

### 여러 백그라운드 작업의 최종 답변이 메신저에서 누락되는 문제 수정

Slack·Telegram·Discord에서 여러 백그라운드 작업을 요청했을 때, 첫 작업의 완료 안내 뒤에 나오는 최종 취합 답변이 전달되지 않던 문제를 수정했습니다.

#### 사용 방법

수정 버전으로 메시지를 받는 기기를 업데이트한 뒤 사용하세요. 별도 설정 없이 자동 적용됩니다.

### 처리된 폴더 권한 안내 접기

처리된 대화 폴더 쓰기 권한 안내가 계속 큰 카드로 남던 문제를 고쳤습니다. 결과는 접어서 표시하고, 권한 회수 확인이 필요한 경고는 계속 보여 줍니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 안내 제목을 누르면 상세와 권한 철회 버튼을 볼 수 있습니다.

### 쿠키 가져오기와 지우기가 서로 겹치지 않도록 수정

앱 안 브라우저에서 쿠키를 지우는 도중 다시 가져오면, 늦게 끝난 지우기가 새로 가져온 로그인 쿠키까지 지우던 문제를 수정했습니다. 같은 사이트의 가져오기와 지우기는 요청한 순서대로 처리됩니다.

#### 사용 방법

브라우저 도구 모음의 쿠키 가져오기 메뉴를 사용하세요. 지우는 동안에는 가져오기와 지우기가 잠시 비활성화되며, 실패하면 다시 시도할 수 있습니다.

### 파일 검색 방식을 바꿔도 검색어 유지

파일명 검색과 내용 검색을 전환할 때 입력한 검색어가 지워지지 않습니다. 내용 검색에서 고친 검색어도 파일명 검색으로 돌아올 때 그대로 유지됩니다.

#### 사용 방법

파일 목록 위에서 검색어를 입력한 뒤 내용 검색을 켜거나 끄세요. 전환만으로 새 내용 검색을 실행하지 않으며, Enter를 눌러 검색합니다.

### 파일 목록 재확인 중 중복 조회 방지

프로젝트 전환창에서 파일 목록을 다시 확인한 직후 버튼이 잠시 활성 상태로 남아 중복 조회되던 문제를 수정했습니다. 재시도하면 바로 조회 중 상태로 바뀌고 완료될 때까지 추가 요청을 막습니다.

#### 사용 방법

Chat의 대화 더보기 → 프로젝트로 전환에서 파일 목록 다시 확인을 누르면 자동 적용됩니다. 작성한 이름·공개 확인과 유효한 파일 선택은 유지됩니다.

### 파일을 끌어 놓은 뒤 바로 요청 이어쓰기

파일을 채팅 입력창이나 대화 영역에 끌어 놓은 뒤 포커스가 이전 버튼에 남아 첫 입력이 빠지던 문제를 수정했습니다. 첨부를 받으면 같은 입력창의 커서·선택 위치로 돌아옵니다.

#### 사용 방법

Project·Chat 대화 화면이나 Build 입력창에 파일을 놓은 뒤 바로 요청을 이어 쓰세요.

### 프로젝트 전환 파일 목록 재시도 후 키보드 이어가기

프로젝트 전환창에서 파일 목록을 빠르게 다시 확인할 때, 갱신 완료 후 키보드 포커스가 버튼으로 돌아오지 않던 문제를 수정했습니다. 재시도 중 이름 입력칸으로 이동한 경우에는 그 입력 위치를 유지합니다.

#### 사용 방법

Chat의 대화 더보기에서 프로젝트로 전환을 열고 파일 목록 다시 확인을 키보드로 실행하세요. 목록이 갱신되면 같은 버튼에서 이어갈 수 있습니다.

### AI 프로필 적용 후 바로 이어서 입력

저장한 AI 프로필을 적용한 뒤 입력창을 다시 누르지 않아도 작성하던 질문을 이어 쓸 수 있습니다. 본문과 커서 선택 범위를 유지하며, 같은 프로필을 다시 고를 때도 적용됩니다.

#### 사용 방법

새 대화의 AI·모델 메뉴에서 저장한 프로필을 고른 뒤 바로 입력하세요. 별도 설정 없이 적용됩니다.

### API 토큰 대화가 거절되면 거절된 이유에 맞는 안내를 보여 줍니다

API 토큰 연결로 시작한 대화가 서버에서 거절되면, 이유와 상관없이 "API 토큰 연결은 이미지·파일 입력을 받지 않아요"라는
안내가 나오거나 서버 원문이 그대로 보였습니다. 이미지를 보내지 않았는데도 이미지 때문이라고 안내하는 경우가 있었습니다.

이제 거절된 이유에 따라 다른 안내를 보여 줍니다. 대화 기록에 아직 전달할 수 없는 항목이 있을 때, 웹 주소나 저장된 파일로
연결된 이미지·파일을 보냈을 때, API 토큰 연결에서 쓸 수 없는 도구가 들어 있을 때, 대화가 너무 길어졌을 때, 작업PC의 AI 도구가
보낸 요청 설정을 받지 않을 때를 각각 구분해 무엇을 하면 되는지 알려 줍니다. 서버 원문은 "상세"를 펼치면 볼 수 있습니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### Chat을 프로젝트로 전환한 뒤 바로 이어쓰기

Chat을 프로젝트로 전환한 뒤 원본 Chat 목록에 남고 바로 입력한 글자가 들어가지 않던 문제를 수정했습니다. 완료하면 Project 목록과 새 프로젝트 대화가 열리고 메시지 입력창에서 이어 쓸 수 있습니다.

#### 사용 방법

Chat의 대화 더보기에서 프로젝트로 전환을 선택하고 파일과 공개 확인을 고른 뒤 전환하고 프로젝트 열기를 누르세요. 완료 후 바로 다음 질문을 입력할 수 있습니다.
