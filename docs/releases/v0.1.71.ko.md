## 새 기능

### 개발자 설정에서 standalone 모드 병행 사용

개발자 기능 설정에서 standalone 모드 전환 메뉴를 선택적으로 표시할 수 있습니다. 기본은 꺼짐이며, 켜면 로그아웃 없이 개인 사용으로 전환하고 계정으로 돌아올 수 있습니다. 설정을 꺼도 이미 전환한 창의 계정 복귀 메뉴는 유지됩니다.
전환 중 로그아웃하거나 로컬 런타임 시작에 실패해도 이전 계정이 다시 나타나지 않으며, 실패한 시작은 남은 로컬 프로세스를 정리합니다.

#### 사용 방법

왼쪽 아래 계정 → 개발자 기능 설정 → standalone 모드 같이 사용하기를 켭니다. 계정 메뉴의 이 컴퓨터에서 개인 사용으로 전환하고 계정으로 돌아가기로 복귀합니다.

### 대화로 반복 예약 생성·정지·재개

지원 서버와 CLI에서 현재 Chat의 AI에게 반복 예약을 만들거나 일시정지·재개하도록 요청할 수 있습니다. 예약 답변과 후속 질문은 같은 대화에 쌓이며 기존 예약 화면에서도 관리합니다. 종료 요청은 다음 실행을 막고 대화와 이력을 보존합니다.

#### 사용 방법

본인의 진행 중인 Chat에서 “15분마다 접속 상태를 확인해줘” 또는 “매일 오전 9시에 요약해줘”라고 입력하고 등록 결과를 확인하세요. “이 예약 그만해”로 일시정지하고 “이 예약 다시 시작해”로 재개합니다. 매일 시각은 실행 PC 기준이며 PC와 AI가 연결돼 있어야 합니다. 지원하지 않는 계정·PC에서는 기존 예약 화면을 이용하세요. 서버·CLI 적용 전에는 사용할 수 없습니다.

### 데스크탑에서 비밀번호 재설정

로그인 화면에서 이메일 인증코드를 받아 데스크탑 안에서 새 비밀번호를 설정할 수 있습니다. 코드 재전송·이메일 변경·오류 재시도를 지원하며 기존 웹의 링크 방식은 유지됩니다.

#### 사용 방법

로그인 → 비밀번호 찾기 → 이메일 입력 → 인증코드 보내기를 누릅니다. 메일의 6자리 코드를 입력하고 새 비밀번호와 확인을 입력한 뒤 비밀번호 변경을 누릅니다. 로그인으로 돌아가기에서 새 비밀번호로 로그인합니다.

### 메일 초대에서 데스크탑으로 참여

메일 초대에서 수신 계정으로 로그인하고 조직을 확인한 뒤 데스크탑에 참여할 수 있습니다. 기존 작업창은 유지하며 앱이 열리지 않으면 웹에서 이어갈 수 있습니다.

비밀번호 찾기 후에도 초대 이메일을 유지하고, 중복 수락을 막습니다. 웹 수락 응답 유실·새로고침·관리자 재인증 뒤에는 같은 조직의 서버 소속을 확인해 이어갑니다. 웹을 선택한 뒤에는 각 단계에 필요한 버튼만 표시하며, 조직명과 참여 완료 안내는 한 줄로 보여줍니다.

데스크탑 관리자 재인증 중 새로고침하거나 이미 참여한 초대를 다시 열어도 서버에서 같은 조직을 확인해 이어갑니다. 참여하지 않은 만료 초대는 새 초대 요청 안내를 표시합니다.

철회·삭제된 초대를 조회 오류와 구분하며, 이전 수락 기록이 남아 있어도 현재 만료 상태를 안내합니다. 초대용 로그인에서 비밀번호 찾기를 열 때 제목이 중복되지 않습니다.

#### 사용 방법

메일의 초대 버튼 → 데스크탑에서 열기 → 표시된 이메일로 로그인/가입 → 조직 확인 → 수락. 앱이 열리지 않으면 웹에서 계속을 선택하세요.

### 사용법 답변에서 설정 화면 바로 열기

AI에게 Saycode 사용법을 물었을 때, 답이 내 설정의 특정 화면으로 이어지면 답변 끝에 "개발 자동화 바로 열기" 같은 버튼이 붙습니다. 누르면 그 설정 탭이 바로 열립니다. 버튼은 화면만 열고 설정값은 바꾸지 않습니다.

#### 사용 방법

대화에서 "자동화 설정은 어디서 해?"처럼 물은 뒤 답변 끝의 바로 열기 버튼을 누르세요.

### 왼쪽 목록에서 여러 대화를 한 번에 보관·삭제

왼쪽 목록의 프로젝트 대화를 Shift를 누른 채 클릭하면 여러 개를 선택할 수 있습니다. 선택한 대화 중 하나의 더보기(⋮)를 열면 선택한 N개 보관·선택한 N개 삭제·선택 해제가 나오고, 한 번 확인하면 선택한 대화를 모두 처리합니다. 처리하지 못한 대화가 있으면 그 개수를 함께 알려 줍니다.

#### 사용 방법

Shift를 누른 채 대화를 클릭해 선택하고(다시 Shift-클릭하면 해제), 선택한 대화의 더보기에서 보관 또는 삭제를 고르세요. 일반 클릭이나 Esc를 누르면 선택이 풀립니다.

### Moai 2.0 보드와 미디어 미리보기 확장을 준비합니다

Moai 공식 확장을 2.0.0으로 갱신했습니다. 칸반·목록·위키와 검색·필터·읽음 표시를 제공하며 이전 할 일 추가 입력은 제거됐습니다. 관리 moai 0.17.0과 Happy 331을 함께 고정했습니다. 스킬 설치 버튼은 호환 CLI가 준비될 때까지 제공하지 않습니다. 영상·음성 파일용 Media Preview 1.0.0도 공식 설치 목록에 추가했습니다. 지원하는 코덱은 브라우저 환경에 따릅니다.

#### 사용 방법

확장 관리에서 Moai를 업데이트하고 machine.run 권한을 승인하세요. 머신 도구도 새 관리 moai로 설치한 뒤 프로젝트 작업 패널에서 Moai를 여세요. Media Preview는 공식 목록에서 설치하고 선택 파일 읽기 권한을 승인한 뒤 활성화하세요.

## 변경된 기능

### 내 컴퓨터에서 추가 디렉터리 바로 선택

프로젝트의 작업PC가 이 컴퓨터이면 디렉터리 추가에서 Windows 탐색기 또는 macOS Finder의 폴더 선택창을 바로 엽니다. 다른 작업PC의 기존 폴더 선택은 유지합니다.

#### 사용 방법

프로젝트의 Files → 디렉터리 추가를 누르고 폴더를 선택한 뒤 용도와 권한을 확인해 등록하세요. 취소하면 등록하지 않습니다.

### 동료 초대와 조직 관리 후 복귀 개선

조직 소유자의 시작 화면에서 혼자 사용 중이면 동료 초대를, 유효한 초대가 있으면 참여 대기를 안내합니다. 다른 구성원이 참여하면 안내가 사라집니다. 조회 실패나 불완전한 목록에서는 인원 상태를 추측하지 않습니다. 관리 화면에서 돌아오면 AI와 작업PC 상태를 다시 확인하며 작성 중인 내용을 유지합니다. 초대 수락 응답을 받지 못한 경우에는 소속을 조회해 확인하고 중복 수락 요청을 보내지 않습니다.

#### 사용 방법

시작 화면 오른쪽 아래의 초대 또는 초대 관리를 누르고 현재 앱 계정으로 재인증합니다. 구성원 관리에서 이메일 초대 또는 코드 발급을 진행합니다. 관리 후 앱으로 돌아오면 상태가 갱신됩니다.

### 메모리 대상과 상세를 명확하게 표시

대상 프로젝트와 작업PC·경로를 먼저 확인하고 프로젝트를 선택할 수 있습니다. 대상 없는 설치 조작을 숨기고 진단·보호 규칙·기록은 접었습니다.

앱 전체의 유사 대화 제안 설정은 프로젝트가 없거나 작업PC가 오프라인이어도 사용할 수 있습니다. 프로젝트별 대화 동기화 설정도 PC가 오프라인일 때 변경할 수 있습니다.

#### 사용 방법

내 설정 → 개발 → 메모리에서 대상 프로젝트를 고르세요. 필요한 진단·기억 보호 규칙·기록을 펼치세요.

### 메신저에서 요청을 처리하지 못하면 해결 방법을 알려 줌

Slack·Telegram·Discord에서 요청을 처리하지 못했을 때 항상 "세션 선택과 연결 권한을 확인해 주세요"라고만 답하던 것을 바꿨습니다. 메신저에서 바로 고칠 수 있는 경우에는 할 일을 알려 줍니다. 내용이 없는 메시지, 프로젝트 없이 보낸 `/new`, 더 이상 연결할 수 없는 세션을 이어가던 대화가 여기에 해당합니다.

#### 사용 방법

안내에 따라 진행하세요. 예를 들어 대화가 이어가던 세션에 연결할 수 없다는 안내가 오면 `/clear`를 보낸 뒤 메시지를 다시 보내면 새 대화로 시작합니다.

### 모달 알림을 플로팅 토스트로 통일

프로젝트 설정의 데모 안내를 비롯해 모달에 고정되어 내용을 밀어내던 부가 알림은 버튼과 입력칸을 피하는 플로팅 토스트로 표시합니다. 조회 실패로 본문이 비던 화면과 설치·연결 완료·검사 결과는 본문에 유지합니다. 숨긴 설정 탭·접힌 상세·뒤 모달의 알림은 조용히 유지하며 재시도·링크·키보드 조작을 보존합니다.

데모의 시작준비 화면에도 사용 제한 이유를 표시하며, 메신저 설정 오류의 다시 시도 버튼을 앱의 다른 버튼과 같은 모양으로 맞췄습니다. Git 계정의 최초 조회 실패는 각 제공자 행에 남고, 재조회 실패 알림에는 제공자 이름을 표시합니다.

추가 디렉터리의 폴더 선택에서 다른 경로 조회에 실패하면 이전 경로의 목록을 새 경로처럼 표시하지 않습니다. 입력한 경로와 오류 이유를 유지하고 새로고침으로 다시 확인할 수 있습니다. 같은 경로의 재조회 실패에서도 확인된 빈 목록 안내를 유지합니다.

#### 사용 방법

조직 목록 재조회 중에는 다시 확인 버튼을 잠가 중복 입력을 막고, 조회가 끝나면 다시 조작할 수 있게 했습니다.

좁은 내 설정 창에서도 본문을 스크롤할 때 탐색·검색창과 닫기 버튼의 위치가 유지됩니다. 다른 메뉴로 이동하면 본문 처음부터 보여 주며 작성 중인 입력은 유지합니다.

부가 알림은 모달 주변 빈 공간에 표시되며 알림 닫기로 닫을 수 있습니다. 낮은 창에서 긴 알림은 알림 안을 스크롤해 읽습니다. 일반 안내는 잠시 후 사라지고 읽는 동안에는 유지됩니다. 본문을 대신하는 오류 이유와 복구 버튼은 계속 표시되며 다시 시도 또는 새로고침으로 조회를 다시 확인할 수 있습니다.

### 보관할 때 작업트리도 함께 삭제하는 버튼

작업트리가 연결된 대화를 보관할 때 확인창에 취소·보관 외에 보관 & 작업트리 삭제 버튼이 추가됐습니다. 이 버튼을 누르면 보관과 함께 작업트리를 지우며, 커밋하지 않은 변경이나 올리지 않은 커밋이 있으면 한 번 더 확인합니다. 보관만 누르면 이제 작업트리 삭제 여부를 따로 묻지 않고 작업트리를 그대로 둡니다. 다른 대화가 함께 쓰는 작업트리는 지금처럼 삭제하지 않습니다. 작업PC가 오프라인이면 작업트리를 지우지 않고 유지했다고 알려 줍니다.

#### 사용 방법

대화 더보기에서 보관을 누른 뒤 확인창에서 보관 또는 보관 & 작업트리 삭제를 고르세요. 여러 대화를 선택해 한꺼번에 보관할 때도 같은 선택지가 나옵니다.

### 사이드바 검색을 위로 스크롤해 열기

Chat/Project 목록 탭 옆에는 생성 버튼만 표시합니다. 검색창은 처음에 목록 위로 가려져 있으며 목록 맨 위에서 위로 스크롤하면 나타납니다. 짧은 목록에서도 검색하고 목록 탭으로 전환할 때는 검색어와 읽던 위치를 유지합니다. 위쪽 Project 메뉴를 누르면 프로젝트 목록 처음으로 돌아가며 이전 하단 위치로 이동하지 않습니다.

#### 사용 방법

사이드바의 Chat 또는 Project 목록 맨 위에서 위로 스크롤해 검색창에 입력하세요. 프로젝트 검색은 기존 단축키로도 열 수 있습니다. Esc를 누르면 검색어를 지우고 검색창을 다시 가립니다. 프로젝트 보기 옵션은 검색창 오른쪽에 있습니다.

### 새 작업트리가 원격 최신 브랜치에서 시작해요

새 대화를 작업트리로 시작할 때 기준 브랜치(Base)를 고르지 않으면, 온라인 저장소가 연결된 프로젝트는 원격의 최신 기본 브랜치(예: origin/main)를 새로 받아 와 그 위에서 시작해요. 프로젝트 폴더의 main이 오래됐거나 다른 브랜치로 바뀌어 있어도 영향을 받지 않아요. 원격 최신을 받지 못하면 이유를 보여 주고, 로컬 브랜치 기준으로 시작할지 물어봐요. 원격 저장소가 없는 프로젝트는 이제 현재 브랜치가 아니라 로컬 main에서 시작해요.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 다른 기준이 필요하면 입력창 위 작업트리 방식 메뉴의 Base에서 로컬 브랜치나 다른 원격 브랜치를 고르세요. 목록의 원격 항목에는 '원격 최신'이 표시돼요.

## 수정된 문제

### 꺼진 세션으로 보낸 메신저 요청에 다시 시작하는 방법 안내

Slack·Discord·Telegram 대화가 이어가던 세션이 꺼진 뒤(PC 재시작, 백그라운드 서비스 재시작 등)에 메시지를 보내면, 지금까지는 "세션 선택과 연결 권한을 확인해 주세요"라는 안내가 나와 권한 문제처럼 보였습니다. 이제는 그 세션이 실제로 꺼졌는지 다시 확인해, 꺼졌으면 더 이상 연결할 수 없다고 알리고 `/clear`를 보낸 뒤 다시 보내라고 안내합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 이 안내를 받으면 `/clear`를 보낸 뒤 메시지를 다시 보내면 새 대화로 시작합니다.

### 내용 없이 봇만 멘션해도 메신저 연결이 멈추지 않음

Slack 채널에서 봇을 멘션만 하고 내용을 적지 않으면, 그 뒤로 이 Slack 연결의 모든 메시지에 답이 오지 않던 문제를 고쳤습니다. 이제 내용이 없는 메시지에는 보낼 내용이 없다는 안내가 오고, 다음 메시지는 평소처럼 처리됩니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다.

### 다른 대화의 본문 읽기 복구

Desktop에서 다른 대화 내용을 읽어 달라고 요청했을 때 본문 파일이 만들어지지 않던 문제를 수정했습니다. 앱이 실행 중이면 다른 대화 탭을 보고 있어도 처리하며, 접근할 수 없거나 읽기에 실패한 대화는 결과 목록에 구분해 표시합니다.

#### 사용 방법

### 현재 PC의 Claude 연결 상태 조회 개선

구버전 Claude 실행 파일이 먼저 검색되는 PC에서도 이미 설치된 사용자 Claude로 연결 상태를 확인할 수 있도록 개선했습니다. 확인된 로그아웃 상태는 유지하며, 다른 AI 도구의 조회 결과도 독립적으로 표시합니다.

#### 사용 방법

내 설정 → AI 연결 설정 → 연결된 AI 확인하기에서 Claude와 PC를 선택하세요. 별도 설치나 업데이트 없이 적용됩니다.

### 환경 변수 추가와 저장을 한 번에 완료합니다

환경 변수는 추가하고 저장 또는 변경 저장에서 바로 저장됩니다. 실패하면 작성 내용을 유지하며 삭제는 삭제 확인에서 적용됩니다. 화면 문구도 선택한 앱 언어로 표시합니다.

#### 사용 방법

내 설정 → 개발 → 환경 변수에서 변수 이름과 값을 입력하고 추가하고 저장을 누르세요. 기존 값은 수정 후 변경 저장을 누르세요.

### AI가 만든 미리보기 HTML을 바로 공개 링크로 공유할 수 있습니다

AI가 만든 보고서·미리보기 HTML이 채팅 안에서는 열리는데 공개 링크를 만들면 "숨김 폴더 안의 파일은
공개할 수 없습니다"라며 실패하던 문제를 고쳤습니다. AI가 이런 파일을 처음부터 공개 링크를 만들 수 있는
위치(프로젝트는 `.aplus/verification` 폴더, 개인 채팅은 일반 폴더)에 저장하도록 안내합니다.

#### 사용 방법

별도 설정 없이 자동 적용됩니다. 업데이트 전에 만들어진 파일은 안내대로 옮기거나 AI에게 다시 만들어
달라고 요청한 뒤 공개 링크를 만드세요.

### AI가 오토파일럿·GitHub 트리거 등 더 많은 기능의 사용법을 안내

AI에게 Saycode 사용법을 물었을 때 오토파일럿, GitHub 트리거(PR 자동 리뷰 같은 반응 자동화), 예약 만들기, 독립 리뷰 요청 방법을 "안내에 없다"고 답하던 문제를 고쳤습니다. 이제 이 기능들의 위치와 순서를 안내합니다. 스크립트 자동화, 동시작업 그룹, 작업보드 품질 게이트·변경 검증, 프로젝트 허브, 대화별 알림 소리, 실행 중인 포트, .env 일괄 편집, PR에서 대화 시작, 첨부 이미지 크게 보기, 시맨틱 검색, 태그 필터, Claude 계정 자동 순환, 조직 검색 연결 방법도 안내합니다.

#### 사용 방법

대화에서 "오토파일럿이 뭐야?", "github 리뷰 자동화는 어떻게 설정해?"처럼 물어보세요. 별도 설정 없이 자동 적용됩니다.
