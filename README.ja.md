## なぜ Saycode なのか？

社員はすでに ChatGPT や Claude で素早く働いています。しかし、サブスクリプションと API 契約は部署・個人ごとに
散らばり、誰がどのモデルをどれだけ使っているか会社にはわかりません。**制限すれば生産性が止まり、
野放しにすれば統制を失います。** 成果物は個人の PC に残ったまま、退職とともに消えていきます。

Saycode は**モデルと競合する製品ではありません。** チームがすでに知っている最新モデルをそのまま使いながら、
組織に必要な管理・セキュリティ・デプロイをその上に加える**運用レイヤー**です。

| | 個人で直接契約する場合 | **Saycode で一緒に使う場合** |
|---|---|---|
| アカウント・コスト | 個人ごとの支払い・アカウントが分散し、管理者は利用状況を把握できない | **同じモデルを中央管理・監査・コスト統制のもとで利用** |
| プロンプト・成果物 | 個人アカウントに紐づき、退職すると消える | **組織の資産として蓄積 — 担当者が変わっても引き継がれる** |
| モデル選択 | 一つのモデルに縛られ、より良いモデルが出ても切り替えにくい | **リクエストごとに最適なモデルを自動選択、ベンダーロックインなしで新モデルをすぐ利用** |
| コード・データ | 外部クラウドへ流出 | **会社が指定した実行マシンに常駐 + エンドツーエンド暗号化(E2EE)** |
| 複数エージェントの運用 | チャットウィンドウをひとつずつ Alt-Tab | **カンバン型エージェントボードで艦隊全体を一画面で指揮** |
| 成果物 | レビュー待ちのブランチ | **作業完了 → レビュー → Commit & PR → 社内 URL へデプロイ** |

一人で使うなら、個人契約が正解です。**組織で一緒に使う瞬間、必要なものが変わります。**

### 会社の管理者が実際にコントロールする4つのこと

| | 何を | どうやって |
|---|---|---|
| **誰が使えるか** | アカウント・シート | 従業員ごとにアカウントを発行・回収します。会社が持つ AI サブスクリプションや API を誰に割り当てるかも会社が決めます。異動・退職時は即座に回収。 |
| **どの AI を使えるか** | モデル・マシンポリシー | チーム・マシンごとに使える AI を選んで開放し、個人ごとに例外を設定できます。会社アカウントでシングルサインオン(SSO)。 |
| **どれだけ使っているか** | 利用量・コスト | 誰がどれだけ使い、コストがいくらかかったかを一画面で確認。予算上限に近づくと通知し、超えると自動停止。 |
| **何が起きたか** | 監査ログ | 誰がいつ何をしたかの記録が残ります。検索してファイルへ書き出せます。 |

### 私たちが先に導入し、測定しました

Buzzni の開発組織が Saycode 上で開発・運用しながら実測した結果です。

| **49%** | 単純なリクエスト **~90%** | 日常的な作業 **~80%** |
|:---:|:---:|:---:|
| 月間 AI 実行コスト削減 — 作業量はそのままに、コストだけを削減 | 誤字・文言修正は軽量モデルが処理 | 機能実装・リファクタリングは中位モデルが処理 |

> 測定条件: Buzzni 開発組織 35名 · 2026年6〜7月 · サブスクリプション・API 実行コスト基準 · 同一作業量を維持。
> ターンあたりの削減率は全体の削減率とは異なる指標です。お客様の環境での削減率を保証するものではなく、
> 導入初月に一緒にベースラインを測定します。

## Agent IDE(Orca など)とは何が違うのか？

[Orca](https://www.onorca.dev) のようなツールは **Agent IDE** であり、開発者のコーディングループに
集中しています — worktree 単位での並列エージェント実行、diff、レビュー、エディタとの深い統合。その領域を
非常によくこなしており、一部は組織単位の導入とガバナンスまで提供します。そのループが皆さんの課題であれば、
良い選択です。

Saycode が向き合う問いは異なります。エージェントがコードを作り終えた*その後*に始まる問いです:

> **Agent IDE は開発者がより多くのエージェントを動かせるようにします。
> Saycode はそのエージェントが作った成果物を会社の資産にします。**

| | Agent IDE(Orca など) | **Saycode** |
|---|---|---|
| 主な焦点 | 開発者のコーディングループ | **会社のデリバリーループ** — 制作 → レビュー → デプロイ → 共有 → 引き継ぎ |
| 管理の単位 | Repo · worktree · エージェントセッション | **組織 · チーム · プロジェクト · マシン · シート · デプロイ済み成果物** |
| 「デプロイ」の意味 | エージェントツールを組織に安全に導入・展開すること | **作った成果物をチームが開く社内 URL でサービスすること** |
| 一般的なゴール | レビューを経て Git にマージされた変更 | **共有・引き継ぎ可能な、実際に稼働中の社内サービス** |
| AI モデルコスト | 利用量の追跡、アカウント切り替え | **難易度ベースの自動ルーティング + サブエージェント委任 — 組織全体で49%削減を実測** |
| 届く相手 | 主に開発者 | **会社の全構成員** — 開発者、企画者、運用担当者 |

両者は並列エージェント、worktree、リモート実行、ローカルファーストのセキュリティという点で重なっています。
したがって、それらは選択の決め手にはなりません。Saycode がその上に加えるのは**運用レイヤー**です:

- **会社の所有権** — プロジェクト、セッション、企画ドキュメント、マシンは個人のノート PC ではなく組織に
  帰属します。担当者が退職したりチームを異動しても、成果物は検索でき、引き継がれます。
- **社内デプロイ** — ワンクリックで固定の社内 URL(SSL 自動)にデプロイされます。成果物は
  レビュー待ちのブランチではなく、チームが今日すぐ開ける実際のツールになります。
- **共有・引き継ぎ** — 同僚が閲覧し、複製し、磨き上げ、変更を反映し直します。他のチームが完成させた
  プロジェクトは作り直す対象ではなく、出発点になります。
- **コスト運用** — リクエストの難易度に応じて最も安価で適切なモデルへ自動ルーティングし(セッションが
  行き詰まったときだけ上位モデルへ昇格)、機械的なサブタスクはより軽量なモデルのサブエージェントに
  委任し、これらすべてが中央管理された組織共用マシンの上で動きます。メッセージごとにどのモデルが
  なぜ選ばれたかがバッジで表示されます。会社全体の AI コストを「確認する」のではなく「運用する」のです。

**いつ何を使えばいいか:** 自分のリポジトリで最も深い並列エージェントコーディング体験を求めるなら、
Agent IDE も良い選択です — 両方を併用しない理由もありません。AI が作ったソフトウェアが
**会社のインフラ**になること — 社内にデプロイされ、チーム間で共有され、引き継ぎを経ても生き残り、
コストまで管理される — それが目標なら、それが Saycode が解決する課題です。

データの1バイトまですべてあなたの Mac の中にあり、インターネットには何も出ていきません。チーム機能が
必要になったら、そのときログインすれば十分です。
